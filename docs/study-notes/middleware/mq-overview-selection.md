# 消息队列概述与选型

> **核心定位**：消息队列（MQ）是分布式系统的核心中间件，用于异步解耦、削峰填谷、最终一致性。本文对比主流 MQ 的特点与选型。

## 1. 为什么需要消息队列

```
┌─────────────────────────────────────────────┐
│ 消息队列的三大核心价值                        │
├─────────────────────────────────────────────┤
│                                              │
│ 1. 异步解耦                                  │
│    用户注册 → 写数据库 → 发短信 → 发邮件 → 积分 │
│    同步：500ms+（用户等待）                   │
│    ★ 异步：写库 50ms + 发 MQ → 用户立即返回   │
│                                              │
│ 2. 削峰填谷                                  │
│    秒杀：10万请求/秒 → 数据库扛不住           │
│    ★ MQ 缓冲 → 消费者按数据库能力消费          │
│                                              │
│ 3. 最终一致性                                │
│    跨服务数据一致性 → 本地消息表 + MQ         │
│    ★ 事务消息（RocketMQ）保证原子性           │
└─────────────────────────────────────────────┘
```

│ 事务消息  │ ❌       │ ★ 支持   │ ❌        │

### 选型建议

```
┌─────────────────────────────────────────────┐
│ 选型决策树                                    │
├─────────────────────────────────────────────┤
│                                              │
│ 吞吐量 > 百万/秒？                            │
│   → ★ Kafka（日志收集、流计算、大数据）       │
│                                              │
│ 需要事务消息 / 延迟消息？                     │
│   → ★ RocketMQ（电商订单、金融交易）          │
│                                              │
│ 需要复杂路由 / 低延迟？                       │
│   → ★ RabbitMQ（企业级应用、复杂路由）        │
│                                              │
│ 团队技术栈？                                  │
│   Erlang 熟练 → RabbitMQ                      │
│   Java 熟练 → RocketMQ（源码可读、可扩展）     │
│   大数据团队 → Kafka                          │
│                                              │
│ ★ 国内互联网企业首选 RocketMQ                 │
│ ★ 大数据/日志场景首选 Kafka                   │
│ ★ 传统企业/复杂路由首选 RabbitMQ              │
└─────────────────────────────────────────────┘
```

## 3. 消息模型

```
┌─────────────────────────────────────────────┐
│ 消息队列核心概念                              │
├─────────────────────────────────────────────┤
│                                              │
│ Producer（生产者）→ 发送消息                  │
│      ↓                                       │
│ Broker（代理）→ 消息服务器                   │
│   ├── Topic（主题）→ 消息分类                │
│   │   └── Queue/Partition（队列/分区）        │
│   │       └── Message（消息）                 │
│      ↓                                       │
│ Consumer（消费者）→ 接收处理消息              │
│                                              │
│ 消费模式：                                    │
│   ★ 集群消费（CLUSTERING）：一条消息只被一个   │
│       消费者消费（负载均衡）                  │
│   ★ 广播消费（BROADCASTING）：所有消费者都消费  │
│                                              │
│ 投递语义：                                    │
│   At Most Once（最多一次）：可能丢消息        │
│   At Least Once（至少一次）：★ 主流，可能重复 │
│   Exactly Once（恰好一次）：★ Kafka Stream    │
└─────────────────────────────────────────────┘
```

## 4. 消息队列常见架构

```
┌─────────────────────────────────────────────┐
│ 生产环境中消息队列的典型架构                   │
├─────────────────────────────────────────────┤
│                                              │
│  ┌──────────┐    ┌──────────┐               │
│  │ 用户服务  │───→│          │               │
│  └──────────┘    │          │    ┌──────────┐│
│                  │  MQ集群   │───→│订单服务  ││
│  ┌──────────┐    │(3节点HA) │    └──────────┘│
│  │ 商品服务  │───→│          │               │
│  └──────────┘    │          │    ┌──────────┐│
│                  │          │───→│库存服务  ││
│  ┌──────────┐    │          │    └──────────┘│
│  │ 支付服务  │───→│          │               │
│  └──────────┘    └──────────┘    ┌──────────┐│
│                                  │通知服务  ││
│                                  └──────────┘│
│                                              │
│  特点：                                       │
│  - 生产者和消费者完全解耦                     │
│  - 消费者可独立扩缩容                         │
│  - MQ 高可用（3节点集群）                     │
│  - 消息持久化（宕机不丢消息）                 │
└─────────────────────────────────────────────┘
```

## 5. 常见问题

```
┌─────────────────────────────────────────────┐
│ 消息队列常见问题                              │
├─────────────────────────────────────────────┤
│ 1. 消息丢失                                   │
│    - 生产者发送失败                           │
│    - MQ 宕机未持久化                          │
│    - 消费者处理失败                           │
│    → 详见 [[消息可靠性与常见问题]]            │
│                                              │
│ 2. 消息重复                                  │
│    - 网络重传                                │
│    - 消费者重平衡                            │
│    → 消费者必须幂等                          │
│                                              │
│ 3. 消息积压                                  │
│    - 消费速度 < 生产速度                     │
│    → 扩容消费者 / 临时扩容 / 降级            │
│                                              │
│ 4. 消息顺序                                  │
│    - 同一业务的消息需要顺序消费               │
│    → 同 key 路由到同一队列                   │
│                                              │
│ 5. 延迟消息                                  │
│    - 订单超时关闭                             │
│    → RocketMQ 延迟级别 / Redis ZSet          │
└─────────────────────────────────────────────┘
```
