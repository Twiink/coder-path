# MySQL 学习路线

MySQL 是数据库世界里那位表面沉默、内心戏很多的老前辈：平时安安静静替你保管用户、订单和余额，遇到一条没索引的查询，立刻把磁盘、CPU 和你的周末一起叫来开会。它可以从几行增删改查起步，也可以一路带你钻进 B+Tree、MVCC、锁、WAL、复制、故障切换和分片的地下迷宫。

这条路线不负责把你哄进“学完就无敌”的童话，也不要求你一上来就给数据库盖一座云上宫殿。它会按难度和依赖关系安排探索顺序：先把数据存得明白，再把数据查得漂亮；先理解单机里的秩序，再决定什么时候请复制、分片和高可用登场。每一站都是一个方向牌，真正的深坑会在你准备好之后出现。

**推荐顺序** ---- 数据库心智模型 → 安装与工具 → 数据类型与建模 → SQL 基础 → 多表与复杂查询 → MySQL 8 现代 SQL → 索引与执行计划 → 优化器与性能 → 事务、MVCC 与锁 → InnoDB 内部 → 安全与运维 → 备份恢复 → 复制与高可用 → 分区、分库分表与架构演进

**这条线怎么用** ---- 每一站先看“知识点清单”，再按顺序逐层下潜；遇到一个概念，不只问“它是什么”，还要追问“它解决什么问题、付出什么代价、在哪种故障里会露馅”。数据库最怕只背结论，因为生产环境很喜欢拿反例敲门。

## 第一站：先认识这位数据管家

第一站不急着敲 SQL，先把数据库放回系统全景里。应用负责业务规则，MySQL 负责持久化与并发控制，缓存负责短期记忆，消息系统负责排队传话；谁该负责什么，边界不清楚时，最后都会变成数据库的加班单。

**数据库、数据库管理系统与存储引擎** ---- 区分“数据放在哪里”“谁负责管理数据”“表具体怎么存和读”；理解 MySQL Server、客户端、连接器、SQL 层与 InnoDB 之间的分工，不要把 MySQL 想成一个会执行 SQL 的黑色盒子

**关系模型的基本词汇** ---- 认识关系、行、列、主键、候选键、外键、约束、事务与视图；学会把业务里的“一个用户有很多订单”翻译成可以被数据库验证的结构

**OLTP 与 OLAP** ---- 区分在线事务处理与分析查询的目标、访问模式、数据规模和延迟要求；业务库不是报表仓库，别让一个月度统计把订单系统拖去参加耐力赛

**SQL、方言与版本意识** ---- 知道 SQL 是标准语言，MySQL 又有自己的语法、优化器行为和版本差异；重点关注 MySQL 8.0 及后续 8.x 的行为变化，同时养成查官方文档与验证实验的习惯

**数据库在一次请求中的位置** ---- 串起浏览器、API、连接池、事务、SQL、索引、存储引擎、日志和响应的链路；“接口慢”只是症状，真正的嫌疑人可能在连接池、锁等待、磁盘或一条没有索引的查询里

**数据的生命周期** ---- 从创建、读取、修改、归档、删除、备份、恢复到审计，理解数据不是插入表里就退休了；字段的寿命、敏感等级和保留期限都会反过来影响表设计

**实践工具箱** ---- 熟悉命令行客户端、图形化客户端、数据库迁移工具、执行计划查看、慢查询分析、备份工具和容器化环境；工具是手电筒，不是替你思考的侦探

## 第二站：安装、连接与服务器地图

第二站把 MySQL 请到本地。安装不是“点下一步直到出现欢迎界面”这么简单：你要知道服务如何启动、连接从哪里来、配置在哪里生效，以及为什么一台机器上的数据库突然拒绝所有人进门。

**版本与发行方式** ---- 了解社区版、商业支持、Linux 包管理器、Homebrew、Docker 和云数据库的差异；掌握版本号、升级路径、兼容性和生命周期，别把开发机上的“最新版”直接当成生产策略

**服务端与客户端连接** ---- 理解主机、端口、用户名、认证插件、默认数据库、字符集和连接协议；知道命令行客户端、GUI 客户端、应用驱动和连接池各自站在链路的哪一段

**实例、数据库与对象** ---- 理解一个 MySQL 实例可以承载多个数据库，数据库里又有表、索引、视图、触发器、存储过程、事件和用户权限对象；这些对象的命名空间和生命周期不要混着记

**配置文件与参数层级** ---- 认识服务端配置、会话变量、全局变量、动态参数、启动参数和持久化配置；学会判断“当前连接生效”与“重启后仍生效”不是一回事

**字符集与排序规则** ---- 掌握服务器、数据库、表、列、连接各层字符集的关系；理解 utf8mb4、排序规则、大小写与重音敏感性，知道乱码有时不是前端在捣鬼，而是数据进门时就穿错了鞋

**连接池与连接生命周期** ---- 学习连接创建、复用、空闲、超时、失效重连、事务归还和连接数上限；连接池过小会排队，过大会把数据库变成“连接数集体蹦迪”

**数据库元数据与自检** ---- 会查看表结构、索引、变量、进程、状态、锁和引擎信息；先建立观察能力，再学习调参，否则调优容易变成“把所有旋钮都拧一圈”

**本地实验纪律** ---- 准备可重复的初始化脚本、样例数据、两个以上并发连接和可恢复的测试库；破坏性 SQL 先在实验库练习，生产库不适合拿来培养胆量

## 第三站：数据类型与表设计

第三站是数据库建模的地基。表结构一旦上线，改起来就像给行驶中的列车换轮胎；现在多花一点时间判断类型、约束和关系，未来就少写很多数据修复脚本。

**数值类型** ---- 学习整数的范围、有符号与无符号、整数宽度、定点数与浮点数；理解金额、计数、比例、状态码和高精度计算分别该怎么表达，别让浮点数替你保管财务账

**字符串类型** ---- 掌握 CHAR、VARCHAR、TEXT 家族的存储特征、长度语义、字符集影响和索引限制；长文本、短标识、固定格式编码和可搜索字段，不要只按“看起来都是文字”处理

**日期与时间类型** ---- 区分 DATE、TIME、DATETIME、TIMESTAMP 与小数秒精度；学习 UTC、业务时区、服务器时区、展示时区、夏令时和时间范围问题，“今天”在跨时区系统里并不是一个没有争议的词

**布尔、枚举与位类型** ---- 理解 BOOLEAN 在 MySQL 中的实际表现，比较 ENUM、状态码和位字段的可维护性；短期省下几个字节，不应换来长期的迁移地狱

**JSON 与半结构化数据** ---- 学习 JSON 数据校验、路径访问、数组与对象、生成列或表达式索引、部分结构化与完全结构化的边界；JSON 是弹性抽屉，不是把整个关系模型塞进一个纸箱

**空间与特殊类型** ---- 了解 GEOMETRY 等空间类型的定位、坐标系和索引方向，知道它适合什么场景、何时应交给专业空间数据库或搜索系统；偏门知识也要知道它存在，关键时刻才不会只会存经纬度字符串

**NULL 与三值逻辑** ---- 理解 NULL 不是零、空字符串或 false，掌握比较、聚合、连接、排序和唯一约束中的 NULL 行为；SQL 的世界有真、假和“我不知道”，这第三种答案经常让业务方意外

**主键与候选键** ---- 学习自然键、代理键、自增整数、UUID、组合主键和业务编号的取舍；重点观察长度、局部性、可读性、分布式生成、迁移与索引代价，而不是只问“哪个更潮”

**唯一性与完整性约束** ---- 掌握 PRIMARY KEY、UNIQUE、NOT NULL、DEFAULT、CHECK 与 FOREIGN KEY 的语义和边界；约束是数据库的门卫，应用校验是前台登记，两者不是互相替班

**外键的取舍** ---- 理解外键带来的引用完整性、级联行为、锁与运维影响；学习不同团队为什么会选择数据库外键、应用保证或混合策略，结论要由数据一致性和组织能力共同决定

**三大范式与反范式** ---- 认识函数依赖、第一至第三范式、冗余、更新异常和读性能；反范式不是“设计失败”，而是用明确的写放大、回填和一致性成本交换查询效率

**通用表设计模式** ---- 了解软删除、审计字段、版本号、乐观锁字段、状态机、关联表、树结构、快照表、历史表、事件表和多租户字段；模式不是模板拼贴，要结合查询与生命周期落地

**视图与数据库对象** ---- 认识视图、临时表、存储过程、存储函数、触发器、事件调度器、游标和用户自定义变量；知道哪些能力适合封装稳定的数据访问，哪些能力会让业务逻辑躲进数据库后变得难测、难迁移

**数据库内逻辑的边界** ---- 比较约束、触发器、应用代码、定时任务和消息消费者对数据规则的承载方式；数据库可以替你守门，但不一定适合替你写完整的业务流程

**大表与冷热数据** ---- 估算行宽、行数、增长速度、索引体积、热点分布和归档周期；数据量还没长大时先做容量预测，数据长大以后再测算通常会附赠告警声

**命名与 schema 规范** ---- 统一表、列、索引、约束、时间字段、状态字段和版本迁移的命名；命名规范不是审美比赛，而是让排障和协作不必进行考古

## 第四站：SQL 基础与安全的 CRUD

第四站正式让数据动起来。CRUD 很容易让人产生“数据库我会了”的错觉；真正的基本功包括语义、边界、事务、返回结果、空值、分页、安全和失败后的行为。

**SQL 的四大分类** ---- 认识 DDL、DML、DQL、DCL 与事务控制语句；知道建结构、改数据、查数据、授权限和提交回滚分别属于哪类责任，排查问题时先判断是在动房子还是搬家具

**SELECT 的逻辑执行顺序** ---- 建立 FROM、JOIN、WHERE、GROUP BY、HAVING、SELECT、DISTINCT、ORDER BY、LIMIT 的心智模型；书写顺序与逻辑处理顺序不同，很多“为什么别名不能用”的疑惑从这里开始解锁

**条件与表达式** ---- 掌握比较、逻辑、范围、集合、模式匹配、NULL 判断、CASE、条件函数和类型转换；尤其要理解隐式转换、字符集比较和三值逻辑对结果与索引的影响

**插入与批量写入** ---- 学习单行、多行、从查询写入、默认值、生成值、冲突处理和幂等写入；批量不是把很多语句挤在一条线上，而是要同时考虑事务大小、日志、锁和失败重试

**更新与删除** ---- 掌握带条件更新、部分更新、批量修改、软删除、物理删除与归档；任何 UPDATE 或 DELETE 都要先确认过滤条件、影响行数、事务边界和恢复方案

**TRUNCATE、DROP 与 DELETE** ---- 区分逐行删除、清空表、删除对象在日志、锁、事务、自增值、权限和恢复方面的差异；“都是删东西”是它们最不重要的共同点

**事务控制语句** ---- 认识开始事务、提交、回滚、保存点、自动提交和隐式提交；应用代码里要明确事务的开始与结束，不能让一个连接带着上个请求的情绪进入下个请求

**分页与排序** ---- 了解 LIMIT 分页、偏移分页、游标分页、稳定排序、复合排序键和深分页代价；数据越大，越不能把 offset 当成一张免费电梯票

**参数化查询** ---- 理解占位符、绑定参数、动态条件、动态列名、排序白名单和 ORM 查询边界；值可以参数化，不代表表名、字段名和排序方向也能无脑塞进字符串

**SQL 注入与最小暴露** ---- 学习注入成因、参数化、输入校验、错误信息、权限隔离和审计；防注入不是“给字符串多加一个引号”，而是让用户输入永远不要获得 SQL 语法的方向盘

**结果集与应用映射** ---- 关注列别名、NULL 映射、时区、精度、枚举、分页元数据、重复列名和大字段传输；数据库返回正确，不等于应用接收后仍然正确

## 第五站：连接、聚合与复杂查询

第五站从“查一张表”进入“把多张表说清楚”。JOIN 像数据库里的社交关系：连得好是协作，连错了是重复数据、错误统计和一夜之间长大的结果集。

**INNER JOIN 与 OUTER JOIN** ---- 理解内连接、左连接、右连接和交叉连接的行保留规则；通常优先掌握 INNER 与 LEFT，并能说清“哪张表必须保留”

**ON 与 WHERE 的边界** ---- 重点研究外连接中连接条件与过滤条件的位置差异；把右表过滤写错，LEFT JOIN 会悄悄变成 INNER JOIN，SQL 不会提醒你，它只会安静地错

**一对一、一对多与多对多** ---- 学习关系基数、关联表、重复行来源和结果集粒度；写报表前先说清“一行代表什么”，否则 COUNT 可能正在数订单，也可能正在数订单和商品的偶遇次数

**JOIN 顺序与驱动表** ---- 了解优化器如何选择连接顺序、嵌套循环、哈希连接或其他执行方式；SQL 写出来的先后不等于数据库执行的先后，执行计划才是现场录像

**聚合与分组** ---- 掌握 COUNT、SUM、AVG、MIN、MAX、GROUP BY、HAVING 与聚合中的 NULL 语义；理解“先过滤再分组”和“分组后过滤”的区别，别让 HAVING 兼职 WHERE

**ONLY_FULL_GROUP_BY** ---- 理解非聚合列不在分组键中时的语义问题、函数依赖与严格模式；严格模式不是数据库故意较真，而是在阻止一个没有唯一答案的问题伪装成报表

**子查询** ---- 认识标量、列表、相关与非相关子查询，区分 IN、EXISTS、NOT EXISTS 的语义与 NULL 陷阱；学会判断什么时候子查询更清楚，什么时候 JOIN 或 CTE 更容易优化

**集合操作** ---- 掌握 UNION、UNION ALL、去重、列对齐、类型兼容和排序边界；UNION ALL 通常更直接，但前提是你真的不需要去重，不是因为名字短

**条件统计与行列转换** ---- 学习 CASE 配合聚合做条件计数、状态汇总、透视与反透视；报表需求经常换皮，底层仍然是把行分组、把条件变成列

**派生表与临时结果** ---- 理解 FROM 子查询、临时表、物化与否、结果复用和生命周期；复杂查询拆开有助于阅读，但拆成十层不自动获得性能奖章

**查询结果的确定性** ---- 为分页、排名、去重和聚合选择稳定的排序键与唯一键；不稳定排序今天看起来没事，明天数据量变了就开始随机发挥

## 第六站：MySQL 8 的现代 SQL 工具箱

第六站是 SQL 的进阶大厅。MySQL 8 不只是“把版本号改大了”，CTE、窗口函数、JSON 查询和递归能力让很多旧式绕路写法终于可以下班；但新语法不是免死金牌，计划和数据分布仍然要看。

**公用表表达式 CTE** ---- 学习 WITH、多个 CTE 串联、作用域、可读性、复用和优化器处理方式；把复杂查询拆成有名字的步骤，让 SQL 从一锅面条变成一张流程图

**递归 CTE** ---- 掌握锚点、递归成员、终止条件、层级字段、路径、防环与深度限制；组织树、菜单树、评论树和图状关系都值得练习，递归不是只在算法课里出现的幽灵

**窗口函数的心智模型** ---- 理解窗口分区、排序、窗口帧与“保留明细行但做组内计算”的特点；它与 GROUP BY 都能分组，但不会把明细一锅端走

**排名函数** ---- 覆盖 ROW_NUMBER、RANK、DENSE_RANK、分组 TopN、并列名次和稳定排序；先说清并列是否占名额，再决定排名函数，别让前三名突然变成五个人

**窗口聚合** ---- 学习累计值、移动平均、分组总计、占比、滑动窗口与 frame 边界；默认窗口帧经常比想象中更有脾气，边界必须明确

**偏移与取值函数** ---- 了解 LAG、LEAD、FIRST_VALUE、LAST_VALUE 与同比、环比、相邻记录分析；它们让“上一条记录是谁”不必再写一场自连接马拉松

**JSON 查询与修改** ---- 掌握 JSON 路径、对象、数组、包含判断、提取、更新、聚合与类型转换；同时理解 JSON 字段的校验、可查询性、索引和迁移成本

**JSON_TABLE 与关系化** ---- 认识把 JSON 数组展开成关系行的方式，学会判断数据是暂存 payload、灵活属性还是本来就应该拆成表；灵活结构也要有边界，否则 schema 只是躲到了字符串里面

**公共表表达式与窗口函数的组合** ---- 练习“先过滤候选集，再分组排名，再取每组结果”的常见分析模式；复杂报表要先明确中间粒度，再组合工具

**函数与表达式的代价** ---- 了解日期、字符串、数值、条件、JSON 函数对 CPU、索引和隐式转换的影响；语法短不代表执行便宜，函数有时是方便，有时是索引的拦路虎

## 第七站：索引与执行计划

第七站来到性能的交通枢纽。索引不是“加了就快”的魔法符文，而是用额外存储、写入成本和维护成本，换取更少的数据访问；索引太少会堵车，索引太多会让每次写入都背着一排书架。

**为什么是 B+Tree** ---- 理解页、节点、键值有序、叶子链表、树高、磁盘 I/O 和范围扫描；索引的价值不是数学上看起来很快，而是减少昂贵的随机访问和无谓的行检查

**聚簇索引** ---- 掌握 InnoDB 主键索引叶子节点保存整行数据的特点，以及主键选择如何影响数据组织、二级索引体积和写入局部性；主键不是身份证号码那么简单，它还负责安排座位

**二级索引与回表** ---- 理解二级索引叶子节点保存索引列与主键，查询需要回到聚簇索引取完整行的过程；回表次数、选择性和结果集大小是判断索引收益的重要线索

**覆盖索引** ---- 学习让查询所需列都由索引提供，减少回表；同时警惕为了覆盖查询把索引做成一条过长的火车，索引本身也会占空间和拖慢写入

**联合索引与最左前缀** ---- 掌握复合索引的列顺序、等值与范围条件、排序与分组协同、跳列和前缀匹配；列顺序要从查询模式、选择性、排序和写入代价一起判断

**索引下推 ICP** ---- 了解存储引擎在回表前利用更多索引条件过滤候选行的优化；它能减少回表，但不能把一个错误的索引设计变成优秀设计

**索引类型与变体** ---- 认识普通索引、唯一索引、主键索引、前缀索引、全文索引、空间索引、函数或生成列相关索引；不常用的索引也要知道边界，关键时刻才不会拿错工具

**全文检索与空间索引** ---- 了解 FULLTEXT 的分词、相关性、语言与中文检索边界，以及空间索引的几何对象、坐标系和范围查询；搜索需求变重时，能判断继续使用 MySQL 还是交给专用搜索或空间系统

**生成列与表达式查询** ---- 掌握生成列、JSON 路径提取、表达式索引的设计思路和写入代价；把查询结果“提前算好”可以换速度，但也会增加存储和变更成本

**索引失效与不生效** ---- 覆盖函数、运算、隐式类型转换、前导模糊、低选择性、OR、负向条件、字符集不一致、统计信息偏差和优化器主动放弃索引等场景；“建了索引但没用”不是一个原因，而是一整个家族

**EXPLAIN 的核心字段** ---- 学习 id、select_type、table、type、possible_keys、key、key_len、ref、rows、filtered、Extra 与 partitions；重点从访问路径、预估行数、实际索引和额外操作读计划，不要只盯着一个 ALL

**EXPLAIN ANALYZE** ---- 理解估算行数与实际行数的偏差、真实耗时、迭代次数和执行节点；计划是地图，ANALYZE 是带你走一遍，二者都要看才知道地图有没有画错

**排序、分组与临时表** ---- 研究 filesort、temporary、索引顺序、内存与磁盘临时结果；filesort 不等于一定坏，关键是数据量、频率、延迟和是否有更合适的路径

**分页索引设计** ---- 对比 offset 分页与基于游标或书签的分页，学习稳定排序、复合游标和上一页边界；深分页的痛苦不会因为把变量名改成 pageNo 而消失

**索引生命周期** ---- 关注重复索引、冗余索引、未使用索引、在线创建、重建、统计信息和版本升级；索引是一种长期资产，要有清理和评估机制

## 第八站：优化器、执行器与慢查询

第八站把“SQL 为什么这么跑”拆开。优化不是凭感觉把 SQL 改短，而是发现真实瓶颈、提出假设、修改一个变量、重新测量。没有基线的优化，往往只是把问题换了一个更漂亮的姿势。

**SQL 请求生命周期** ---- 理解连接认证、解析、预处理、优化、执行、存储引擎访问、结果返回和连接复用；每个阶段都有可能耗时，别一见慢查询就立刻去改索引

**基于成本的优化器** ---- 认识统计信息、选择性、基数、成本估算、连接顺序、访问路径与计划缓存；优化器不是全知全能，但它通常比人类凭肉眼猜索引更有资格先发言

**统计信息与直方图** ---- 学习索引统计、列分布、数据倾斜、直方图和统计信息更新；平均值会掩盖热点，数据分布变化会让昨天优秀的执行计划今天突然失忆

**执行计划漂移** ---- 关注数据增长、参数变化、版本升级、统计信息变化、索引变更和缓存状态导致的计划切换；线上调优要记录环境与样本，不能只截一张计划图当证据

**连接算法与访问方式** ---- 了解全表扫描、索引扫描、范围扫描、嵌套循环、批量键访问、索引合并和半连接等思路；知道它们解决什么访问模式，也知道何时会因为数据量而反转优劣

**查询改写方法** ---- 练习减少无关列、提前过滤、避免重复计算、拆分复杂查询、改写子查询、控制返回行数和批量读写；先改语义清晰且风险低的地方，再碰优化器提示

**优化器提示与强制索引** ---- 了解使用提示、固定连接顺序、忽略索引和强制索引的适用边界；提示是临时拐杖，不是把错误统计永久钉死在墙上

**慢查询日志** ---- 掌握开启条件、阈值、未使用索引记录、采样、脱敏、归并指纹和按总耗时排序；慢查询不只看平均耗时，还要看调用次数、总耗时、尾延迟和业务影响

**Performance Schema 与 sys schema** ---- 了解等待事件、语句、表、索引、锁、内存、线程和 I/O 观察方式；让数据库自己留下证词，排障时不必只问“刚才是不是卡了一下”

**性能指标与容量** ---- 建立 QPS、吞吐、P50/P95/P99、错误率、锁等待、连接、缓冲池命中、磁盘 I/O、日志写入和复制延迟指标；性能是预算和约束，不是一个孤零零的“快”字

**优化验证闭环** ---- 记录基线、样本、数据规模、并发、硬件、计划、改动与前后结果；线上优化要可回滚、可解释、可重复，不要靠“我感觉现在好多了”结案

## 第九站：事务、隔离级别与 MVCC

第九站进入一致性的核心区域。事务的任务不是让 SQL 看起来更有仪式感，而是在并发、失败、重试和崩溃的世界里，尽量保证数据不会出现“钱扣了，订单还在思考人生”的状态。

**ACID** ---- 理解原子性、一致性、隔离性和持久性的含义，以及它们分别依赖日志、约束、锁、MVCC 和恢复机制的哪些部分；ACID 是目标集合，不是四个可以独立打勾的营销词

**事务边界** ---- 学习如何按业务不变量划定事务范围，区分数据库事务、应用请求、消息消费和跨服务操作；事务越大不代表越可靠，可能只是把锁和回滚成本养肥

**自动提交与隐式提交** ---- 理解 autocommit、DDL、连接复用、异常路径和未提交事务；连接池里的事务必须明确归还状态，否则下一个请求可能继承一份不该继承的历史

**并发异常** ---- 覆盖脏读、不可重复读、幻读、丢失更新、写偏差、读偏差和死锁；不要只背名称，要能用两个并发事务描述“谁先读、谁后写、哪里出了问题”

**四种隔离级别** ---- 理解 READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ 与 SERIALIZABLE 的可见性、锁行为、并发能力和代价；默认级别是历史选择，不代表所有业务都该照抄

**快照读与当前读** ---- 区分普通 SELECT 的一致性读，以及加锁读、UPDATE、DELETE 等读取最新版本并参与锁竞争的当前读；同一条“读”在不同语句和隔离级别下可能是两种性格

**MVCC 的版本链** ---- 理解隐藏事务信息、undo log、版本链、Read View 与可见性判断；MVCC 的魔法不是“没有锁”，而是让很多读操作不必与写操作正面相撞

**RC 与 RR 的快照差异** ---- 研究 READ COMMITTED 按语句建立快照与 REPEATABLE READ 在事务内保持快照的差别；同一个事务里两次 SELECT 看到什么，是理解隔离级别的实验证据

**一致性与业务幂等** ---- 了解唯一约束、状态机、版本号、幂等键和条件更新如何与事务配合；数据库事务不能自动解决重复请求，重试也不是把同一条写入再扔一次

**日志在事务中的角色** ---- 预览 redo log、undo log、binlog 和两阶段提交，理解持久性、回滚、复制与崩溃恢复之间的关系；三种日志名字像三胞胎，职责却完全不同

## 第十站：锁、并发与死锁现场

第十站是数据库的交通指挥部。锁不是坏东西，没有锁会乱，有太多锁会堵；真正要学的是锁住了什么、为什么被锁、锁多久、谁在等待，以及如何让事务更快下班。

**锁的粒度与模式** ---- 区分表级锁、行级锁、共享锁、排他锁、意向锁和元数据锁；锁的名字只是入口，必须结合语句、索引、隔离级别和执行计划理解实际范围

**行锁锁的是索引记录** ---- 建立“行锁实际落在索引访问路径上”的关键认知；没有合适索引时，一次更新可能检查和锁住远超预期的范围，SQL 逻辑看起来很小，物理动作却很大

**记录锁、间隙锁与 Next-Key Lock** ---- 掌握记录本身、索引间隙以及记录加间隙的锁定语义，理解它们如何参与防止幻读；间隙锁看不见但会阻止插入，是并发排障里的隐身人

**意向锁** ---- 理解表级意向标记如何让表锁与行锁快速判断冲突；它不是替代行锁，而是给锁管理系统提前挂一块“里面有人”的牌子

**元数据锁 MDL** ---- 了解查询、写入、ALTER TABLE、发布和长事务之间的关系；一条卡住的 DDL 可能不是 DDL 自己慢，而是在等一个几小时前忘记提交的事务

**AUTO-INC 锁与自增** ---- 研究自增值分配、并发插入、批量写入、锁模式和主键间隙；自增列解决编号问题，但不保证业务连续、不保证分布式唯一，也不负责解释缺号

**锁等待** ---- 学习如何识别阻塞者、被阻塞者、等待时长、事务开始时间、持有锁的 SQL 和应用请求；“数据库变慢”常常只是有人在门口拿着钥匙聊天

**死锁成因** ---- 覆盖不同加锁顺序、范围锁交叉、大事务、缺索引、隐式锁冲突和应用重试放大；死锁不是数据库坏了，而是并发图里出现了环

**死锁处理策略** ---- 掌握固定访问顺序、缩短事务、缩小范围、补充合适索引、分批处理、捕获死锁并安全重试；死锁无法保证绝迹，应用必须把它当作一种可恢复失败

**乐观锁与悲观锁** ---- 比较版本号、条件更新、SELECT FOR UPDATE、冲突检测与重试；选择取决于冲突概率、业务损失、读写比例和用户体验，不是“乐观一定现代”

**并发实验** ---- 用多个会话重现不可重复读、幻读、锁等待、死锁和 MDL 阻塞；并发问题只看单线程代码像看监控录像的单帧，热闹全在下一帧

## 第十一站：InnoDB 的发动机舱

第十一站下潜到存储引擎。SQL 层说“我要查订单”，InnoDB 还要操心页、缓冲、日志、刷盘、恢复、版本和空间；理解这层，很多看似玄学的性能与故障就会开始说人话。

**存储引擎的职责** ---- 区分 SQL 层与存储引擎层，理解为什么 MySQL 可以支持多种引擎，以及为什么现代事务业务通常以 InnoDB 为主；引擎不是换主题皮肤，而是换了一套数据与并发实现

**表空间与页** ---- 学习表空间、段、区、页、行、页目录、页分裂和行溢出；InnoDB 以页为重要 I/O 单位，字段设计和索引设计最终都会在页里相遇

**行格式** ---- 认识 Compact、Redundant、Dynamic、Compressed 等行格式的历史与影响，理解变长列、溢出页、行大小和压缩；“字段没超类型上限”不代表一行真的能舒服地住进一页

**Buffer Pool** ---- 理解数据页、索引页、脏页、淘汰、预读、热页、命中率和内存配置；数据库性能经常取决于数据是在内存里散步，还是每次都去磁盘排队

**Redo Log 与 WAL** ---- 掌握预写日志、日志缓冲、日志文件、刷盘策略、checkpoint、崩溃恢复和持久性之间的关系；先写日志再写数据页，是数据库在断电世界里保住尊严的重要手段

**Undo Log 与 Purge** ---- 理解回滚、MVCC 版本链、历史版本清理、长事务和 undo 空间增长；一个不提交的事务可能像一位占着旧报纸不还的读者，让清理工作一直等

**Binlog 的位置** ---- 区分 Server 层逻辑日志与 InnoDB 物理恢复日志，理解 binlog 在复制、审计和时间点恢复中的作用；它们可能一起出现，但不是同一本账

**两阶段提交** ---- 理解 redo log 与 binlog 在事务提交时如何协调，以及崩溃后如何避免“主库提交了，复制日志没记上”这类不一致；这是日志三兄弟关系最紧张也最关键的一幕

**Doublewrite Buffer** ---- 认识页半写、双写缓冲与数据页完整性；磁盘写入不是永远一笔成功，数据库要为“写了一半就停电”预留剧本

**Change Buffer** ---- 理解非唯一二级索引变更的缓冲与合并、随机 I/O 的代价和它的适用限制；这项机制偏底层但很有用，知道它存在，就不会把所有写放大都归咎于应用

**自适应哈希索引** ---- 了解 InnoDB 对热点访问可能进行的内部优化，以及它与显式索引、B+Tree 的关系；自动优化不是万能加速器，观察证据比迷信名字可靠

**页分裂与主键局部性** ---- 研究随机主键、趋势递增主键、插入热点、页分裂、碎片和二级索引膨胀；主键设计会一路影响写入、缓存、复制和备份

**崩溃恢复与启动时间** ---- 理解恢复扫描、重做、未完成事务、刷盘策略和大事务对恢复时长的影响；RTO 不只在故障切换时决定，平时的事务尺寸也在偷偷投票

## 第十二站：权限、安全与日常运维

第十二站负责把数据库从“能用”送到“敢让别人用”。安全不只是密码，运维也不只是重启；权限、配置、日志、容量和变更流程共同决定数据库是否可靠。

**账户、认证与授权** ---- 学习用户、主机匹配、认证插件、角色、GRANT、REVOKE、默认权限和权限刷新；先判断用户是谁，再判断它从哪里来，最后才讨论它能做什么

**最小权限原则** ---- 为应用、迁移、只读报表、运维、备份和管理员划分不同身份；业务服务用 root 是把万能钥匙挂在门外，方便是真的，风险也是真的

**权限边界与对象暴露** ---- 关注库级、表级、列级、例程级权限，读写分离账号与敏感字段；不要让一个报表账号顺便拥有删库的想象力

**密码、秘密与连接安全** ---- 学习密码轮换、秘密管理、TLS、证书、内网访问、审计和连接来源限制；配置文件里出现明文密码，通常不是“临时调试”，而是未来的泄露材料

**SQL 模式与严格性** ---- 理解严格模式、ONLY_FULL_GROUP_BY、日期与非法值校验、截断行为和兼容性；让坏数据尽早失败，比让坏数据顺利落库再写一篇事故复盘更省事

**字符集、排序与时区排障** ---- 建立从客户端到列的核对顺序，处理乱码、大小写、排序差异、时间偏移和连接设置；同一条文本在不同排序规则下可能有不同的比较结果

**连接与线程管理** ---- 认识最大连接数、空闲连接、线程、连接池、线程缓存、超时和连接泄漏；连接打满时，先找谁在占位置，不要第一时间把上限调到一个更大的灾难

**日志体系** ---- 了解错误日志、通用日志、慢查询日志、binlog、审计日志与应用日志的分工、保留、脱敏和轮转；日志不是越多越好，能回答故障问题才有价值

**Performance Schema 与监控** ---- 观察语句、等待、锁、内存、表 I/O、文件 I/O、线程和复制状态；监控指标要能对应行动，例如连接耗尽该限流，复制延迟该改变读策略

**容量与空间治理** ---- 跟踪数据增长、索引增长、表空间、binlog 保留、临时文件、备份占用和磁盘水位；磁盘满不是单一故障，通常会同时影响写入、日志、恢复和运维命令

**变更与回滚** ---- 学习配置变更、索引变更、DDL、数据修复、迁移审批、灰度、备份前置和回滚方案；没有回滚路径的生产变更，只是把勇气写进了发布记录

## 第十三站：备份、恢复与数据保命

第十三站是数据库的保险柜。备份不是“某个目录里有几个文件”，恢复也不是“以后有空试一下”；只有被定期验证、能在目标时间内恢复、有人知道怎么操作的备份，才算真正存在。

**备份目标** ---- 先明确 RPO、RTO、数据保留、合规要求、恢复粒度和可接受停机时间；“要备份”只是愿望，“丢多少、多久恢复、恢复到哪里”才是方案

**逻辑备份** ---- 了解按 SQL 或逻辑对象导出、跨版本迁移、备份粒度、字符集、触发器、例程和大表导入的特点；逻辑备份可读性好，但大库恢复通常比较有耐心

**物理备份** ---- 学习数据文件级别的热备、冷备、全量、增量、压缩、校验与版本兼容；物理备份恢复快，但更依赖实例环境与工具链

**一致性备份** ---- 理解在线备份如何获得一致性视图、如何处理正在写入的事务和大表；备份期间数据仍在变化，快照边界必须说得清楚

**Binlog 与时间点恢复 PITR** ---- 掌握全量备份加连续 binlog 的恢复思路，定位误删或误更新前的时间点，并处理日志缺失、保留期和顺序问题；“昨天有备份”不等于“能恢复到事故前一秒”

**恢复演练** ---- 实际演练全量恢复、增量恢复、单库恢复、单表找回、校验、应用切换和权限重建；恢复演练是备份的体检报告，不是可选的团建活动

**备份安全** ---- 关注加密、访问权限、异地存储、保留策略、密钥管理、脱敏和删除保护；备份里通常住着生产的全部秘密，不能把它当普通压缩包

**误操作与数据修复** ---- 设计删除前确认、软删除、审计、延迟副本、只读恢复环境、修复脚本和逐步校验；修复数据要有证据链，不能靠“感觉这几行应该是这样”

**版本升级与回滚** ---- 评估备份恢复、兼容性检查、系统表变化、复制拓扑、应用驱动和降级路径；升级能前进，回滚也要有现实可行性

**灾难场景** ---- 覆盖误删、磁盘损坏、实例宕机、区域故障、日志丢失、备份损坏、凭据泄露和恢复容量不足；灾难恢复的敌人通常不是技术名词，而是没演练过的细节

## 第十四站：复制、读写分离与高可用

第十四站开始进入多实例世界。单机数据库的问题是机器会坏，多实例数据库的问题是机器坏了以后大家还要对“谁是主、谁的数据更新到哪、谁可以接流量”达成共识。

**二进制日志复制链路** ---- 理解源库写 binlog、复制线程拉取、relay log 落盘、回放线程执行和副本提供读取的完整路径；复制不是瞬间克隆，而是有延迟、有积压、有失败重试的流水线

**复制格式** ---- 对比 statement、row 与 mixed 的记录方式、确定性、日志体积和安全边界；生产选择要结合版本、业务语句、审计和恢复目标，不要只背“默认是什么”

**GTID** ---- 学习全局事务标识、自动定位、复制拓扑变化、故障切换和新副本接入；GTID 的价值在于少依赖具体文件位置，但不代表拓扑切换从此不需要人类

**复制通道与过滤** ---- 了解多源复制、通道、过滤规则和跨库复制的风险；过滤会让拓扑更灵活，也可能让数据完整性变成一道隐藏题

**异步、半同步与组复制** ---- 比较性能、确认时机、丢数据窗口、网络抖动和复杂度；高可用不是“副本数量越多越高”，而是故障时能按目标完成切换并保护数据

**复制延迟** ---- 分析大事务、从库查询压力、单线程回放、DDL、磁盘、网络和冲突造成的延迟；读写分离最经典的坑就是刚写入的数据被送去读取旧世界

**读写分离** ---- 设计应用层路由、中间件路由、强制读主、会话粘滞、读后写一致性、延迟感知和故障降级；读写分离改变的不只是连接地址，还有业务对一致性的假设

**故障切换** ---- 学习探活、选主、脑裂、旧主隔离、VIP 或 DNS、连接串、应用重连、未完成事务和切换后校验；自动切换不是按下按钮，而是一套状态机

**MGR 与集群化思路** ---- 了解组成员、组通信、认证、单主或多主、冲突检测、成员状态和网络分区；知道工具的能力边界，不把“集群”当成免维护的三个数据库

**RTO、RPO 与演练** ---- 用恢复时间目标和恢复点目标评价方案，演练主库故障、副本故障、网络分区、延迟积压和回切；架构图只能展示愿望，演练才能暴露现实

## 第十五站：分区、分库分表与分布式数据

第十五站是高难地图，不建议刚学会 JOIN 就来申请分片。分库分表会把单机数据库替你处理的排序、聚合、事务、唯一性和运维问题，分发到应用、中间件和人的脑袋里。

**先判断是不是真的需要** ---- 依次评估 SQL、索引、缓存、归档、冷热分离、读写分离、硬件和容量治理；分片不是性能优化的第一站，而通常是单体数据库已经被真实约束逼到墙角后的结构性选择

**分区表** ---- 学习 RANGE、LIST、HASH 分区、分区键、分区裁剪、分区生命周期、分区维护和跨分区查询；分区能管理大表与冷热数据，但不会自动修复所有慢 SQL

**垂直拆分** ---- 按业务域、访问模式、冷热程度或数据敏感性拆分库表；目标是边界、隔离和独立扩展，不是把一张表切成几张更难理解的表

**水平分表与分库** ---- 理解同构表按行切分、分片数量、路由、扩容、迁移、跨分片查询、跨分片聚合和唯一性；拆完之后，应用要学会面对“数据可能在别的抽屉”

**分片键选择** ---- 结合最常见查询、数据均匀性、写热点、租户隔离、范围查询、扩容和数据生命周期选择分片键；分片键选错，后面的中间件再聪明也只能礼貌地叹气

**哈希、范围与时间分片** ---- 对比均匀性、范围查询、热点、扩容、迁移、历史归档和跨片统计；没有一种策略同时拿满所有属性，取舍要写进设计记录

**全局唯一 ID** ---- 掌握数据库自增、号段、雪花、时间有序 ID、UUID、随机性、时钟回拨、机器标识和索引局部性；ID 既是业务标识，也可能是写入性能和数据迁移的支点

**分布式事务** ---- 了解两阶段提交、三阶段提交、TCC、Saga、可靠消息、Outbox、补偿、幂等和最终一致性；跨库事务不是把 BEGIN 复制到两台机器上就结束了

**跨分片 JOIN 与聚合** ---- 学习应用聚合、冗余字段、预计算、路由约束、异步汇总和分析库；如果每次查询都需要横跨所有分片，说明分片模型正在和查询模型吵架

**在线迁移与扩容** ---- 掌握双写、回放、校验、增量同步、影子流量、读切换、停写窗口、旧数据清理和回滚；迁移的难点不在“复制数据”，而在新旧世界同时营业

**中间件与代理层** ---- 了解分片中间件、代理、连接路由、SQL 改写、结果归并、事务限制与故障边界；工具可以隐藏复杂度，但不能消灭复杂度

**多租户与数据隔离** ---- 比较共享表、共享库、独立 schema、独立库和独立实例的隔离、成本、迁移与运维；租户边界既是数据设计问题，也是权限和合规问题

## 第十六站：架构取舍与生产系统串联

最后一站不是“学完所有名词，然后把数据库拆成十二片”。真正的进阶，是能把数据模型、请求链路、性能证据、一致性要求、故障边界和团队能力放在一张桌子上，做出能运行、能观察、能恢复、能演进的决定。

**单体数据库的边界** ---- 评估单机规格、连接上限、存储容量、写入能力、锁竞争、备份窗口和故障半径；知道什么时候优化现有系统，什么时候才需要拆分

**模块化单体与数据边界** ---- 按业务能力划分模块、表所有权、访问接口和迁移责任；先把边界画清楚，再谈服务化，能省下许多“拆开后才发现大家共用一张表”的惊喜

**数据库与缓存** ---- 学习缓存旁路、读写穿透、失效、击穿、雪崩、穿透、热点、双写一致性和回源保护；缓存是加速器，不是第二个永远正确的数据库

**数据库与消息** ---- 了解事务提交与消息发送之间的间隙、Outbox、可靠投递、重复消费、顺序、重试、死信和补偿；消息系统能削峰，但不能替你定义数据最终应该长什么样

**数据库与搜索** ---- 判断什么时候使用 B+Tree、全文索引、JSON 查询、专用搜索引擎或分析系统；“能搜出来”只是起点，相关性、更新延迟、权限过滤和数据同步才是后半场

**数据库与 API 契约** ---- 处理字段演进、默认值、可空性、枚举、分页、排序、软删除、版本兼容和数据脱敏；数据库迁移不能脱离应用发布顺序单独设计

**数据访问层** ---- 比较原生驱动、查询构建器、ORM、Repository、读模型与写模型；抽象的目标是管理变化和边界，不是把 SQL 藏到大家都找不到

**故障域与降级** ---- 设计数据库不可用、只读、延迟升高、复制落后、连接耗尽、磁盘不足和锁风暴时的超时、限流、降级、重试与人工开关；重试没有上限时，善意会变成放大器

**可观测性与证据链** ---- 把请求 ID、用户或租户、SQL 指纹、执行计划、锁等待、慢查询、复制延迟、磁盘和版本关联起来；排障要让“哪一次请求、哪条 SQL、等了谁、影响多少人”都能回答

**成本与容量规划** ---- 估算数据增长、索引增长、QPS、并发连接、备份空间、网络、磁盘 IOPS、副本数量和恢复窗口；架构不是只算 CPU，账单和恢复时间也会参加评审

**ADR 与演进路线** ---- 记录选型背景、约束、被拒绝的替代方案、迁移步骤、验证指标和回滚路径；未来的自己不应该靠通灵来理解今天为什么选了某个分片键

**毕业项目** ---- 做一个带用户、订单、库存或内容流的完整系统，经历建模、迁移、CRUD、复杂查询、索引、事务、锁、慢查询、备份恢复、复制或分片模拟；项目不必大，但必须让数据真的经历过几次风雨

## 通关标准

**基础通关** ---- 能安装并连接 MySQL，设计合理的表结构，解释常见数据类型与约束，写出安全的 CRUD、JOIN、聚合和分页查询；遇到 NULL、字符集或时区问题，不会先把锅甩给前端

**进阶通关** ---- 能使用 CTE、递归 CTE、窗口函数和 JSON 查询解决真实问题，能解释查询粒度与结果正确性；复杂 SQL 不再靠复制粘贴祈祷，而是能拆成可验证的步骤

**性能通关** ---- 能阅读 EXPLAIN 与 EXPLAIN ANALYZE，理解聚簇索引、二级索引、回表、覆盖索引、联合索引和索引失效；面对慢 SQL，会先收集基线和证据，再决定改 SQL、改索引还是改架构

**并发通关** ---- 能画出隔离级别、快照读、当前读、MVCC、记录锁、间隙锁、Next-Key Lock 与死锁的关系；能重现阻塞并设计事务缩短、加锁顺序和安全重试策略

**引擎通关** ---- 能说清 Buffer Pool、页、redo log、undo log、binlog、Doublewrite、Change Buffer、checkpoint、purge 和两阶段提交各自解决什么问题；不再把所有日志都统称为“日志”然后面带微笑

**运维通关** ---- 能配置最小权限、监控连接和磁盘、定位慢查询、查看锁与复制状态，设计全量备份、binlog 增量和 PITR，并实际完成恢复演练；备份文件存在磁盘里，不算恢复能力

**架构通关** ---- 能根据一致性、吞吐、延迟、容量、团队、成本和故障目标选择单库、读写分离、分区、分库分表或其他存储；能说明为什么选择，也能说明什么时候应该撤回选择

MySQL 学到这里，数据库这张地图就从“会查”长成了“能设计、能调优、能恢复、能演进”。接下来可以按问题继续走，不必把所有技术都收集成数字宠物：

- **[PostgreSQL](/learning-paths/database/postgresql)** ---- 对照学习更丰富的 SQL、JSONB、物化视图、GIN/GiST、VACUUM 与扩展生态
- **[Redis](/learning-paths/database/redis)** ---- 学缓存、数据结构、持久化、分布式锁、集群和高并发访问模式
- **[MongoDB](/learning-paths/database/mongodb)** ---- 研究文档模型、聚合、复制集、分片与关系模型之外的取舍
- **[Kafka](/learning-paths/middleware/kafka)** / **[RabbitMQ](/learning-paths/middleware/rabbitmq)** ---- 进入消息、削峰、重试、顺序、幂等与最终一致性的世界
- **[Elasticsearch](/learning-paths/middleware/elasticsearch)** ---- 把全文检索、倒排索引、相关性和搜索架构单独学深
- **[微服务模式](/learning-paths/architecture/microservices/patterns)** ---- 继续研究服务边界、数据所有权、Saga、Outbox 与分布式系统的代价
- **[全链路性能](/learning-paths/fullstack/performance)** ---- 把浏览器、服务、缓存、数据库、网络和基础设施串成一条性能证据链

## 结语

MySQL 最有趣的地方，是它从来不只是在回答“这条 SQL 能不能执行”。它还在追问：数据是否完整，事务是否互相影响，索引是否值得，磁盘是否撑得住，副本是否追得上，故障之后能不能回来，以及三个月后的你是否还看得懂今天的设计。

先学会把数据存对，再学会把数据查快；接着理解它如何在并发里保持秩序，最后再决定是否需要把它搬进更大的架构。数据库不会因为你画了一张宏伟架构图就自动变聪明，但会因为你认真理解了它的边界，少给你发几次凌晨通知。

**慢慢学，认真测，先理解取舍，再追逐规模。** 当你能从一条慢 SQL 追到索引、锁、页、日志和架构边界，也能把一次误操作恢复到正确时间点——恭喜，你不只是会用 MySQL，而是开始和它合作了。
