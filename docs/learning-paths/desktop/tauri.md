# Tauri 学习路线

Tauri 用 Web 技术做界面，用 Rust 连接系统能力，再借助系统 WebView 把应用送到 Windows、macOS 和 Linux。它像 Electron 的轻量邻居：少带一份 Chromium 行李，换来 Rust 学习、WebView 差异和生态选择题。

这条路线从 Web 与 Rust 地基开始，依次学习 Tauri 的进程模型、命令、事件、权限、插件、文件、窗口、数据、性能、安全、测试、打包与更新。它是知识索引，不把命令写法和插件参数抄成操作手册。

**路线定位** ---- 适合已有前端基础，又在意包体、启动、内存和系统安全，希望用 Rust 写桌面系统层的人

**推荐总顺序** ---- Web 与 Rust → Tauri 项目骨架 → 命令与事件 → 权限模型 → 窗口与系统能力 → 数据与网络 → 安全 → 性能 → 测试 → 打包更新

**先记住一句话** ---- Tauri 的轻量来自系统 WebView 与 Rust，不代表桌面工程变轻了；它只是把重量从安装包搬到你的学习清单里

**本页怎么用** ---- 把粗体条目当作后续笔记入口，把每站验收当作项目关卡；先理解前端、Rust、权限和通信的边界，再开始收集插件

## 第一站：Tauri、WebView 与 Rust 边界

第一站先弄清 Tauri 的交易。前端页面仍然熟悉，但 UI 跑在系统 WebView，系统能力由 Rust 处理，跨平台行为就不再由同一份 Chromium 统一兜底。

**Tauri 组成** ---- 认识前端 Web、系统 WebView、Rust 核心、插件、命令、事件和操作系统的关系

**系统 WebView** ---- 对照 Windows WebView2、macOS WKWebView 和 Linux WebKit 的版本、能力、渲染和安装依赖差异

**Rust 地基** ---- 掌握所有权、借用、生命周期、结构体、枚举、Trait、Result、错误、泛型、模块和异步

**Web 地基** ---- 补齐 HTML、CSS、JavaScript、TypeScript、Vite、网络、存储、可访问性和浏览器调试

**Tauri 与 Electron** ---- 比较包体、内存、启动、生态、系统能力、开发效率、原生模块和更新分发

**Tauri 与原生** ---- 理解 Tauri 适合业务工具与跨平台应用的边界，以及专业图形、驱动和极深系统集成的替代方案

**目标矩阵** ---- 记录系统版本、WebView 依赖、CPU 架构、窗口、文件、离线、权限、包体与内存预算

**选型验收** ---- 能说明为什么选 Tauri、哪些能力用插件、哪些下沉 Rust、哪些需要原生或其他框架

## 第二站：项目骨架、运行时与生命周期

第二站认识 Tauri 项目的骨架。前端、Rust、配置、权限和资源各有住址，住址混乱时，开发模式能跑并不代表打包后还能找到家。

**项目结构** ---- 了解前端目录、Rust 源码、配置、能力声明、资源、图标、测试和构建产物

**开发与生产模式** ---- 区分开发服务器、调试窗口、生产资源、环境变量、更新地址和日志级别

**Rust 入口** ---- 理解应用初始化、插件注册、命令注册、窗口创建和运行时事件

**WebView 生命周期** ---- 处理创建、加载、显示、隐藏、导航、崩溃、重载和销毁

**应用生命周期** ---- 关注启动、激活、全部窗口关闭、托盘驻留、睡眠、恢复、退出和单实例

**多窗口模型** ---- 设计主窗口、设置窗口、弹窗、辅助窗口的身份、焦点、状态和资源

**资源路径** ---- 处理开发路径、打包路径、应用资源、用户目录、临时目录和外部资源

**平台配置** ---- 管理应用标识、图标、窗口、权限、协议、文件关联、更新和系统能力

**骨架验收** ---- 能在开发与生产模式启动、创建窗口、读取配置并定位资源或 WebView 问题

## 第三站：命令、事件与通信契约

第三站是 Tauri 的核心通道。前端调用 Rust 命令、Rust 返回结果或发出事件，这套通信和小型分布式系统很像：会失败、会超时，也会遇到不速之客。

**命令模型** ---- 理解前端调用、Rust 执行、返回值、错误、序列化和异步命令

**参数与返回** ---- 用结构体、枚举、Result 和 Schema 表达输入、成功、失败、空和部分结果

**事件模型** ---- 处理进度、下载、文件变化、系统通知、后台任务和窗口之间的事件

**方向与订阅** ---- 区分窗口到 Rust、Rust 到窗口、窗口到窗口和全局广播，明确事件订阅和取消

**序列化** ---- 关注 serde、JSON、二进制、日期、路径、错误、大对象和兼容版本

**异步与取消** ---- 设计超时、取消、重试、幂等、任务 ID、进度和关闭时的收尾

**并发与背压** ---- 处理多个窗口、高频事件、大文件、日志和任务队列，学会批处理、节流和限并发

**错误边界** ---- 区分用户提示、业务错误、系统错误、诊断信息和日志脱敏

**类型契约** ---- 让 TypeScript、Rust 类型、命令白名单、错误码和版本策略同步演进

**通信验收** ---- 完成一个可取消、有进度、能恢复的文件或计算任务，并测试非法参数与重复调用

## 第四站：Capabilities 权限与安全模型

第四站是 Tauri 的护城河，也是最容易被“默认能调”误导的地方。前端能调用哪些命令、哪些插件、哪些路径，都应该是明确授权，而不是碰运气。

**Capabilities 模型** ---- 理解窗口、权限、插件、命令、作用域和默认拒绝的关系

**最小权限** ---- 只开放业务需要的文件、窗口、网络、进程、通知和系统能力

**作用域限制** ---- 为文件目录、URL、窗口、命令和资源设置范围，避免权限从一条缝长成车库门

**前端不可信** ---- 把 Web 页面、远程内容、用户输入、导入文件和第三方脚本视为不可信来源

**命令校验** ---- 验证参数、路径、URL、文件类型、长度、窗口来源和返回数据

**导航与外链** ---- 限制页面导航、新窗口、危险协议、远程页面和外部应用唤起

**凭据与秘密** ---- 使用系统安全存储，避免令牌、密钥、用户文件和构建秘密进入前端

**插件权限** ---- 审查官方插件与第三方插件的能力、版本、数据、许可证和安全边界

**更新安全** ---- 校验更新源、签名、完整性、版本、降级和回滚

**安全验收** ---- 完成路径穿越、非法命令、危险 URL、远程内容、权限越界和更新篡改测试

## 第五站：窗口、插件与系统集成

第五站让应用从 Web 页面变成桌面工具。Tauri 插件提供了捷径，但窗口、菜单、托盘和文件的用户习惯仍然需要你亲自设计。

**窗口管理** ---- 处理尺寸、位置、最小最大、置顶、全屏、透明、无边框、标题栏和窗口状态

**菜单与托盘** ---- 设计应用菜单、上下文菜单、系统托盘、托盘驻留、菜单状态和退出

**快捷键** ---- 处理窗口级、应用级、全局快捷键、输入法、冲突和可访问性

**对话框** ---- 规划打开、保存、消息、错误、权限和用户取消流程

**文件系统插件** ---- 了解文件读写、目录、作用域、流、权限、临时文件和大文件

**通知插件** ---- 管理通知权限、标题、内容、点击、系统勿扰和重复消息

**剪贴板与外部链接** ---- 支持文本、图片、文件、浏览器打开、危险协议和 URL 白名单

**文件关联与协议** ---- 处理双击打开、启动参数、单实例接管、自定义协议和参数校验

**系统信息与后台** ---- 关注系统主题、屏幕、网络、睡眠、进程、开机启动和系统事件

**系统验收** ---- 完成窗口、托盘、菜单、文件、通知、快捷键和外部唤起的至少一组完整流程

## 第六站：数据、网络与离线任务

第六站让 Tauri 应用长期工作。系统 WebView 负责界面，Rust 可以负责文件、网络和计算，但所有长任务都要有状态、取消和恢复。

**网络请求** ---- 掌握前端请求、Rust HTTP、HTTPS、代理、证书、超时、重试和错误

**认证与会话** ---- 设计登录、刷新、退出、多账号、设备身份、系统凭据和跨窗口同步

**本地存储** ---- 比较配置文件、键值、SQLite、IndexedDB、系统安全存储和日志目录

**数据库与迁移** ---- 处理 schema、索引、事务、版本、迁移、损坏、备份和恢复

**离线优先** ---- 设计缓存、草稿、操作队列、同步、冲突、版本、幂等和网络恢复

**后台任务** ---- 管理下载、导入、导出、索引、同步、备份、扫描和更新检查

**进度与取消** ---- 提供进度、暂停、恢复、取消、重试、失败和结果领取

**睡眠与唤醒** ---- 处理时钟变化、网络变化、任务恢复、重复执行和过期状态

**流与大数据** ---- 关注大文件、二进制、批量、分片、背压、内存峰值和磁盘空间

**数据验收** ---- 在断网、睡眠、重启、重复提交、数据库升级和任务中断后保持状态可解释

## 第七站：Rust 性能、WebView 差异与资源管理

第七站研究 Tauri 的轻量到底如何落地。Rust 能承担计算与 IO，但跨边界传数据、系统 WebView 版本和前端渲染依然会决定用户体感。

**前端渲染性能** ---- 关注资源加载、长任务、布局、列表、图片、动画和 WebView 主线程

**Rust 计算性能** ---- 处理解析、压缩、索引、加密和模型推理，选择异步、线程或进程

**命令通信性能** ---- 减少频繁调用、大对象复制和事件广播，使用批量、流式和分页

**WebView 差异** ---- 测试浏览器内核版本、CSS、字体、媒体、Web API、GPU 和系统代理

**启动与资源** ---- 优化 Rust 初始化、插件注册、窗口创建、前端资源、字体和后台预热

**内存与句柄** ---- 管理窗口、事件监听、数据库、文件、网络、线程、任务和临时资源

**包体优化** ---- 裁剪依赖、资源、语言包、调试信息、原生库和平台产物

**电量与后台** ---- 控制轮询、长连接、扫描、定位、后台任务和系统唤醒

**性能工具** ---- 使用浏览器性能面板、Rust 分析器、系统监控、日志和真实设备对照

**性能验收** ---- 在低端设备、大文件、多窗口、长时间运行、睡眠恢复和不同 WebView 上测量

## 第八站：测试、调试与跨平台质量

第八站让 Tauri 应用经得起不同系统的问候。自动化测试验证逻辑，真实系统验证权限、WebView、安装与更新。

**Rust 单元测试** ---- 覆盖领域逻辑、路径、解析、权限、任务状态、错误和同步

**前端测试** ---- 验证组件、路由、表单、键盘、拖放、主题和可访问性

**命令测试** ---- 检查参数、返回、错误、权限、文件、数据库和取消

**集成测试** ---- 验证页面、命令、插件、文件、网络和本地数据的边界

**端到端测试** ---- 覆盖启动、登录、打开保存、导入导出、托盘、窗口、更新和退出

**系统矩阵** ---- 按 Windows、macOS、Linux、WebView、架构、缩放、主题、代理和权限选取覆盖

**故障测试** ---- 注入断网、文件损坏、磁盘满、权限拒绝、主任务失败、窗口关闭和系统睡眠

**安装更新测试** ---- 验证全新安装、覆盖升级、数据迁移、签名、无网络、更新失败和回滚

**日志与现场** ---- 保留版本、系统、窗口、任务、命令、错误、截图和脱敏路径

**质量验收** ---- 能从失败现场判断是 WebView、Rust、插件、权限、系统还是发布产物的问题

## 第九站：构建、签名、分发与更新

第九站是交付课。小体积安装包如果没有签名，用户仍会把它当成可疑快递；轻量不等于可以跳过信任链。

**构建配置** ---- 区分开发、测试、生产、架构、系统、渠道、环境和更新源

## 第十站：生产运维与项目主线

最后一站把 Tauri 应用交给真实用户。桌面应用的生命周期很长，发布后要知道它在哪些系统上崩了、哪些更新没装上、哪些任务没有收尾。

**崩溃与无响应** ---- 监控 WebView 崩溃、Rust panic、启动失败、白屏、卡死、内存和磁盘问题

**日志与遥测** ---- 关联版本、系统、窗口、命令、任务、网络和更新，同时保护用户文件与凭据

**隐私与合规** ---- 明确崩溃、诊断、使用数据、保留期限、同意和关闭方式

**功能开关** ---- 为新功能、系统能力、更新和远程配置准备关闭、降级和离线默认值

**事故响应** ---- 处理签名失效、更新失败、插件漏洞、数据迁移错误和远程服务故障

**第一阶段项目** ---- 做一个文件搜索、Markdown 笔记、图片压缩或下载工具，完成窗口、命令、文件和本地数据

**第二阶段项目** ---- 加入离线、后台任务、进度、托盘、通知、权限、同步和跨窗口通信

**第三阶段项目** ---- 完成性能、安全、测试、签名、更新、监控、灰度和回滚

## 结语

Tauri 把浏览器体重减了下来，却把系统 WebView、Rust 和权限模型的学习价值凸显出来。它最适合那些既想要 Web 开发效率，又不愿让包体和内存无限膨胀的产品。

先掌握命令、事件和 Capabilities，再做文件、窗口和后台任务；**轻量不是少做工程，而是把工程的重量放在更值得控制的地方。**
