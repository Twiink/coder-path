# Electron 学习路线

Electron 用 Chromium 负责界面，用 Node.js 连接操作系统，让前端技术栈拥有窗口、文件、菜单和安装包。它的交易条件也很坦白：背上一份不轻的浏览器体重，换来成熟生态、跨平台一致性和极高的开发效率。

这条路线不把 Electron API 写成字典，而是按桌面应用真正会遇到的顺序建立索引：Web 基础 → 进程模型 → IPC → 窗口与系统集成 → 数据与网络 → 安全 → 工程化 → 性能 → 测试 → 打包发布 → 生产运维。每一站都应该在学习笔记里继续深挖。

**路线定位** ---- 适合已经掌握 JavaScript、TypeScript、HTML、CSS、Node.js 和一个前端框架，想把 Web 应用交付为 Windows、macOS、Linux 桌面应用的人

**推荐总顺序** ---- Web 与 Node 地基 → 三进程模型 → IPC 契约 → 窗口与交互 → 系统能力 → 数据与网络 → 安全 → 工程化 → 性能 → 测试 → 签名发布 → 生产运维

**先记住一句话** ---- Electron 不是“网页套壳然后结束”，而是 Web UI、操作系统能力、进程边界和分发体系的组合；最容易写的是页面，最容易出事的是边界

**本页怎么用** ---- 把粗体条目当作知识索引，把每站结尾的验收当作项目检查点；不要从托盘图标开始炫技，先把进程和 IPC 吃透

## 第一站：桌面应用与 Electron 的边界

第一站先回答“为什么做桌面端”。桌面应用不是把浏览器窗口放大，而是要面对文件、窗口、键盘、离线、安装、更新、权限和不同操作系统的生活习惯。

**桌面应用形态** ---- 区分效率工具、内容创作、开发工具、企业客户端、通信软件、媒体应用、离线应用和系统辅助工具，理解它们对性能与系统集成的不同要求

**Electron 的组成** ---- 认识 Chromium、Node.js、Electron 主进程、渲染进程、预加载脚本和操作系统之间的关系，知道每一层能做什么、不能做什么

**Web 与桌面差异** ---- 对照浏览器标签页与安装应用在窗口、文件、协议、菜单、快捷键、通知、后台运行、离线和更新上的不同责任

**跨平台现实** ---- 了解 Windows、macOS、Linux 的窗口、菜单、路径、权限、安装包、字体、WebView 行为和系统通知差异，跨平台不是把三个 logo 贴在同一张海报上

**Electron 与替代方案** ---- 比较 Tauri、Flutter Desktop、Qt、.NET MAUI、原生开发和 PWA 的体积、生态、性能、原生深度、团队成本与分发方式

**选型边界** ---- 识别极致低内存、实时音视频、重度 3D、系统级驱动、硬件控制和强原生体验场景，判断 Electron 是否值得它的体重

**基础能力清单** ---- 补齐 JavaScript、TypeScript、HTML、CSS、浏览器调试、Node.js、异步、文件系统、网络、进程和 Git，先把地基补平再盖阳台

**选型产出** ---- 写出目标系统、窗口模型、离线要求、系统能力、包体预算、内存预算、更新渠道和团队技能，避免项目做到一半才发现需要另一门语言

## 第二站：三进程模型与应用生命周期

第二站是 Electron 的第一道大门。主进程、渲染进程和预加载脚本的边界一旦混乱，应用就会从“桌面工具”变成“拥有你电脑权限的网页”。

**主进程** ---- 学习应用入口、单实例、窗口创建、应用菜单、系统托盘、对话框、文件和系统事件，理解它是系统能力的协调者而不是业务垃圾桶

**渲染进程** ---- 把它当作运行在 Chromium 中的 Web 页面，掌握 DOM、路由、组件、状态、渲染、浏览器 API 和页面生命周期

**预加载脚本** ---- 理解它如何在隔离边界附近提供受控桥接，学习暴露最小能力、封装参数、返回类型、错误和事件的设计方式

**窗口与进程关系** ---- 了解一个应用多个窗口、一个窗口一个渲染进程、隐藏窗口、销毁窗口、后台窗口和辅助窗口的生命周期与资源成本

**应用生命周期** ---- 掌握准备就绪、窗口创建、全部窗口关闭、退出、激活、挂起、恢复、崩溃和单实例唤醒等阶段

**平台生命周期差异** ---- 关注 macOS 关闭窗口后应用仍可能运行、Windows 托盘常驻、Linux 桌面环境差异和系统关机等场景

**同步与异步边界** ---- 理解主进程事件循环、渲染线程、后台任务、文件 IO 和网络 IO，避免同步操作把全应用堵在门口排队

**生命周期验收** ---- 能做出多窗口、关闭、隐藏、重新激活和单实例行为，并能解释每个动作会影响哪些进程与资源

## 第三站：IPC 通信与跨进程契约

第三站学习主进程和渲染进程如何对话。IPC 不是“把任意函数丢给另一边调用”，而是一次小型分布式系统通信：有边界、有协议，也会超时、失败和重复。

**调用式通信** ---- 理解渲染进程发起请求、主进程处理并返回结果的调用模型，规划命令名称、参数、返回值、异常和取消

**事件式通信** ---- 区分一次性请求与持续事件，处理窗口状态、下载进度、文件变化、系统通知和后台任务消息

**发送方向** ---- 梳理渲染到主、主到渲染、窗口到窗口和主进程广播的方向，避免所有消息都走广播，最后没人知道是谁在喊

**数据序列化** ---- 关注可传输的数据类型、对象复制、二进制、文件路径、错误对象、日期、循环引用和大对象传输成本

**类型化契约** ---- 用 TypeScript 类型、Schema、命令白名单、版本字段和统一错误结构维护通信协议，让改动在编译或测试阶段露出水面

**超时、取消与重试** ---- 设计文件读取、下载、导入、导出和长任务的超时、取消、进度、重试、幂等和恢复

**并发与背压** ---- 处理大量 IPC 消息、批量文件、实时日志、渲染频繁请求和主进程队列，学会合并、节流、批处理和限制并发

**错误与安全边界** ---- 区分用户可见错误、可重试错误、系统错误和开发诊断信息，防止把堆栈、路径和秘密原样塞回页面

**IPC 验收** ---- 完成一次文件或系统能力调用，并补齐参数校验、错误返回、进度、取消和重复点击处理；能解释为什么不把整个 Node API 暴露给页面

## 第四站：窗口、导航与桌面交互

第四站让应用真正有“桌面感”。桌面用户不只会点击按钮，他们会拖文件、按快捷键、开多个窗口、调整尺寸、切换显示器，然后期待应用记住自己刚才的姿势。

**窗口配置** ---- 掌握尺寸、最小最大尺寸、居中、置顶、无边框、透明、全屏、最小化、最大化、隐藏、恢复和窗口状态持久化

**多窗口架构** ---- 设计主窗口、设置窗口、关于窗口、编辑器窗口、弹窗和辅助窗口的路由、数据同步、焦点和生命周期

**Web 路由与桌面路由** ---- 区分页面导航、窗口导航、外部链接、深链接、自定义协议和文件关联，避免用一个路由器解决所有空间问题

**菜单与上下文菜单** ---- 了解应用菜单、窗口菜单、右键菜单、macOS 菜单约定、动态菜单、菜单状态和快捷键绑定

**键盘与快捷键** ---- 处理应用级快捷键、窗口级快捷键、全局快捷键、冲突、输入法、无障碍键盘路径和平台惯例

**拖放与剪贴板** ---- 规划文件拖入、文本拖放、复制粘贴、图片、富文本、安全路径校验和跨窗口传递

**高 DPI 与多显示器** ---- 关注缩放、像素比、窗口移动、屏幕边界、刘海式显示区域、字体、截图和不同缩放设置

**桌面可访问性** ---- 处理语义、键盘焦点、读屏、对比度、动态字体、减少动画、系统主题和平台辅助技术

**界面状态** ---- 完整设计加载、空、错误、禁用、离线、更新中、权限不足和未保存修改状态，让应用在坏天气里也有表情

**交互验收** ---- 做出可调整窗口、菜单、快捷键、拖放、剪贴板和多窗口流程，并在 Windows、macOS 或 Linux 中分别检查平台习惯

## 第五站：文件、系统能力与本地数据

第五站开始摸到操作系统。浏览器里一次文件选择，到了桌面端可能牵涉路径、权限、编码、锁、软链接、临时文件和用户误操作，文件系统绝不是一个更大的输入框。

**文件与路径** ---- 掌握路径拼接、绝对与相对路径、用户目录、应用数据目录、临时目录、符号链接、大小写和不同系统分隔符

**打开与保存流程** ---- 设计打开、另存为、覆盖确认、未保存修改、自动保存、恢复、最近文件、文件类型过滤和大文件处理

**文件安全** ---- 防护路径穿越、任意文件读写、恶意文件、软链接绕过、扩展名伪装、权限错误和来自外部内容的危险路径

**文件流与性能** ---- 区分一次性读取、流式读取、分片、进度、暂停、取消、内存峰值、临时文件和磁盘空间不足

**系统对话框** ---- 使用打开、保存、消息、错误和权限对话框，理解它们的异步行为、平台差异和用户取消路径

**托盘与通知** ---- 规划托盘菜单、气泡通知、通知点击、后台任务、系统勿扰、权限和应用退出行为

**系统打开与外部链接** ---- 处理浏览器打开、文件打开、邮件、应用协议、外部程序和不可信 URL，所有跳转都要经过白名单与确认

**文件关联与自定义协议** ---- 理解安装注册、启动参数、单实例接管、已有应用唤醒、协议参数校验和版本兼容

**本地配置与数据库** ---- 比较配置文件、键值存储、IndexedDB、SQLite、加密存储和日志目录，规划 schema、迁移、备份与损坏恢复

**密钥与敏感数据** ---- 了解系统密钥链、凭据存储、令牌生命周期、加密边界和“打包进客户端的秘密不算秘密”

**系统能力验收** ---- 完成打开保存、拖入文件、托盘通知、本地配置和数据迁移中的至少一组闭环，能处理取消、权限不足和磁盘异常

## 第六站：网络、离线与后台任务

第六站把桌面端从“本地工具”带进真实网络。桌面应用经常要长时间运行，网络断开、电脑睡眠、用户合盖和服务端升级都不是异常新闻，而是日常天气。

**网络请求** ---- 掌握 HTTP、HTTPS、代理、证书、超时、重试、连接复用、下载、上传和大响应处理，区分浏览器请求与主进程请求的边界

**认证与会话** ---- 设计登录、令牌、刷新、退出、多账号、系统凭据、设备标识、过期、撤销和跨窗口同步

**离线优先** ---- 规划本地缓存、离线编辑、操作队列、网络恢复、同步状态、冲突、版本、最终一致性和用户可见的同步提示

**后台任务** ---- 处理下载、索引、导入导出、同步、备份、扫描、更新检查和定时任务的进度、取消、重试与资源限制

**睡眠与唤醒** ---- 关注系统睡眠、网络变化、时钟跳变、任务暂停、任务恢复、重复执行和用户离开期间的数据变化

**实时通信** ---- 了解 WebSocket、长连接、心跳、断线、重连、后台窗口、消息顺序、重复和多窗口订阅

**队列与幂等** ---- 对导入、上传、同步、通知和远程操作建立任务 ID、状态、重试次数、去重和失败恢复

**代理与企业网络** ---- 认识系统代理、认证代理、证书替换、内网域名、防火墙和企业环境下的诊断方式

**更新网络** ---- 规划更新检查、下载、校验、断点、安装、重启、失败回退和网络受限环境下的提示

**后台验收** ---- 做出可暂停、可恢复、可取消的下载或导入任务，在断网、睡眠、重启和重复点击后保持状态可解释

## 第七站：安全模型与最小权限

第七站是 Electron 的红线区域。桌面应用一旦拿到文件与系统能力，渲染页面里的一个漏洞就可能升级成真实系统事故；“页面能显示”与“页面值得信任”是两门课。

**威胁建模** ---- 识别远程内容、本地文件、插件、更新包、用户输入、第三方依赖、IPC、系统权限和供应链的信任边界

**渲染进程隔离** ---- 理解沙箱、上下文隔离、禁用 Node 集成、内容安全策略、同源、导航限制和远程内容的风险

**预加载最小暴露** ---- 只提供业务需要的窄接口，避免暴露任意文件、任意命令、任意 URL 或整套 Node 能力

**IPC 输入校验** ---- 对命令、路径、参数、文件类型、URL、窗口来源和返回数据进行白名单、Schema、权限和长度校验

**导航与外部内容** ---- 限制页面跳转、阻止危险协议、区分本地页面和远程页面、控制新窗口和外部浏览器打开行为

**文件与路径安全** ---- 防护路径穿越、任意写入、符号链接、危险扩展名、宏文件、恶意压缩包和不可信导入内容

**凭据与秘密** ---- 使用系统安全存储，避免日志、渲染页面、源码、配置和安装包中出现长期密钥；客户端能被分析，秘密就不能只放客户端

**第三方依赖与原生模块** ---- 审查 npm 包、原生模块、构建脚本、安装钩子、许可证、漏洞、ABI 和更新来源

**自动更新安全** ---- 校验更新来源、签名、完整性、版本、回滚和降级策略，更新器本身不能成为应用的后门

**安全观测与响应** ---- 记录必要的安全事件、版本、平台和错误，不记录密码、令牌、个人文件内容和过度详细的本地路径

**安全验收** ---- 能说明每个系统能力从页面到操作系统经过哪些边界与校验，并完成远程内容、恶意路径、非法 IPC 和危险链接的测试

## 第八站：前端框架与 Electron 工程化

第八站把 Electron 项目从“能启动”整理成“可维护”。主进程、预加载和渲染进程像三个小团队，最好有各自的职责、构建产物和沟通协议，不要共用一张无限延长的全局变量表。

**主进程、预加载与渲染构建** ---- 理解三套代码的入口、依赖、打包、环境变量、资源路径、开发服务器和生产产物

**Vite 与框架集成** ---- 了解 Vite、React、Vue、Svelte、electron-vite、Electron Forge 和 Electron Builder 的定位，选择能被团队长期维护的组合

**TypeScript 契约** ---- 为 IPC、窗口状态、配置、任务、错误、事件和持久化数据建立类型，避免跨进程数据靠字符串和祈祷传递

**模块边界** ---- 拆分领域逻辑、系统适配、窗口管理、数据访问、IPC 处理、渲染组件和平台差异，保证核心业务可以脱离桌面壳测试

**环境与配置** ---- 区分开发服务器、生产资源、公开配置、主进程秘密、更新地址、日志级别和渠道标记

**资源与路径** ---- 处理开发与打包后的资源位置、应用目录、用户数据目录、ASAR、外部资源、原生库和临时文件

**原生模块与 ABI** ---- 了解 C++ 原生模块、预编译、Electron 版本、Node ABI、重编译、平台架构和安装失败后的诊断

**多平台构建矩阵** ---- 规划系统版本、CPU 架构、构建机器、依赖、签名环境、安装包类型和产物命名

**代码质量与协作** ---- 接入格式化、静态检查、类型检查、提交规范、变更记录、依赖更新和安全审计，让三套代码不各自发展成三个宇宙

**工程化验收** ---- 能在开发和生产模式启动应用，定位资源路径、环境变量、预加载和原生模块问题，并保持主进程与页面逻辑可独立测试

## 第九站：性能、内存与稳定性

第九站处理 Electron 最常被吐槽的体重。优化不是把应用强行饿瘦，而是让启动、渲染、IPC、文件、网络和后台任务把资源花在用户真正需要的地方。

**启动性能** ---- 分析主进程初始化、窗口创建、预加载、前端资源、字体、首屏请求和后台任务，区分首屏可用与完整功能准备

**渲染性能** ---- 复习浏览器资源加载、长任务、布局、绘制、列表、动画、图片、内存和 GPU，桌面窗口大了，Web 性能问题也会放大

**进程与内存** ---- 关注窗口数量、隐藏窗口、渲染进程常驻、缓存、监听器、定时器、WebSocket、原生对象和页面销毁后的资源释放

**IPC 性能** ---- 减少高频、小颗粒和大对象跨进程传输，使用批量、节流、分页、流式和后台任务，避免主进程成为单车道收费站

**后台计算** ---- 区分渲染线程、主进程、Worker、Worker Threads、子进程和原生模块的适用边界，避免把压缩、解析和索引丢在界面线程上

**文件与数据库性能** ---- 处理大文件流、索引、分页、事务、批量写入、锁等待、磁盘空间和数据库连接，桌面端也会拥有自己的慢查询

**网络与缓存** ---- 关注资源缓存、接口缓存、离线数据、下载并发、断点、代理和长连接，缓存要有失效策略，不是永久收纳箱

**包体与安装体验** ---- 优化依赖、资源、语言包、原生模块、压缩、按平台裁剪和增量更新，包体大小会影响下载、磁盘和首次信任成本

**稳定性指标** ---- 记录启动失败、崩溃、卡死、无响应、内存、CPU、磁盘、网络失败、更新失败和任务恢复率

**性能工具** ---- 使用 Chromium 性能面板、内存快照、主进程日志、系统监控、Electron 性能指标和实际设备对照，不用跑分替用户完成任务

**性能验收** ---- 在低配机器、多窗口、大文件、长时间运行、睡眠恢复和网络波动场景下测量，优化前后必须有指标和复现条件

## 第十站：测试、调试与跨平台质量

第十站让“能启动”升级成“改完还敢启动”。Electron 测试要同时照顾 Web 页面、IPC、文件系统、窗口、系统能力和真实安装包。

**单元测试** ---- 覆盖领域逻辑、数据转换、配置、权限判断、路径处理、任务状态、错误映射和同步策略

**渲染进程测试** ---- 验证组件、路由、表单、键盘、拖放、加载、错误、离线、权限提示和可访问性

**主进程与预加载测试** ---- 检查窗口管理、IPC、文件、菜单、托盘、通知、更新、系统事件、参数校验和错误处理

**集成测试** ---- 在接近真实的 Electron 环境中验证页面到 IPC、IPC 到系统能力、本地数据库、文件和网络的完整边界

**端到端测试** ---- 使用 Playwright 等工具覆盖启动、登录、创建窗口、打开文件、保存、搜索、导入导出、更新和退出

**设备与系统矩阵** ---- 选择主流 Windows、macOS、Linux 版本、CPU 架构、缩放比例、主题、代理和权限环境

**异常与恢复测试** ---- 注入断网、文件损坏、磁盘满、权限拒绝、窗口关闭、主进程异常、渲染崩溃、更新中断和系统睡眠

**安装与更新测试** ---- 验证全新安装、覆盖安装、卸载、旧版本升级、数据迁移、签名提示、更新失败、回滚和无网络启动

**日志与调试现场** ---- 保留截图、录屏、控制台、主进程日志、IPC 轨迹、版本、系统、路径脱敏信息和任务 ID

**Flaky 治理** ---- 区分等待不当、平台差异、真实竞态、环境波动和产品问题，重试只能减少噪音，不能把证据扫进地毯下面

**测试验收** ---- 能用一套可重复流程发现页面、IPC、系统权限、安装、更新和跨平台差异，并让失败报告足以指导修复

## 第十一站：打包、签名与自动更新

第十一站把应用送出开发机。桌面用户对“下载一个未知来源程序”天然谨慎，安装包、签名、权限、更新和卸载体验就是应用的第一张名片。

**打包工具链** ---- 了解 Electron Builder、Electron Forge、安装资源、应用图标、元数据、资源目录、ASAR、原生模块和多平台产物

**安装包形态** ---- 认识 Windows 安装程序、macOS 磁盘映像与应用包、Linux deb、rpm、AppImage、Snap 或 Flatpak 的差异

**代码签名** ---- 掌握 Windows 签名、macOS Developer ID、强制公证、证书保管、时间戳、签名验证和证书轮换

**安装与卸载** ---- 处理安装路径、权限、快捷方式、开始菜单、Dock、托盘、文件关联、协议注册、卸载清理和用户数据保留

**版本与渠道** ---- 规划稳定、测试、内测、灰度、企业渠道、系统架构、最低版本和升级兼容策略

**更新检查** ---- 设计更新源、版本比较、发布说明、下载、校验、用户确认、后台下载、重启安装和失败重试

**增量与回滚** ---- 了解差分更新、断点续传、旧版本保留、更新失败回退、数据迁移不可逆和紧急停止发布

**CI 发布** ---- 将构建、测试、签名、制品、校验和发布接入流水线，隔离证书与秘密，记录每个安装包对应的提交和环境

**分发渠道** ---- 比较官网下载、应用商店、企业分发、包管理器、官网更新和平台审核，按用户群选择渠道组合

**发布验收** ---- 能在至少一个系统上完成签名安装、覆盖升级、自动更新和失败恢复，并说清用户遇到未知开发者提示时该怎么办

## 第十二站：生产运维与产品化

最后一站解决“用户装上以后怎么办”。桌面应用不像网页那样刷新一下就能换版本，它会在用户电脑里住很久，最好学会礼貌地升级、记录和退出。

**崩溃与无响应** ---- 监控渲染崩溃、主进程崩溃、卡死、启动失败、白屏、内存暴涨和系统资源耗尽

**日志与可观测性** ---- 建立结构化日志、版本、系统、窗口、任务、IPC、网络、更新和错误关联，严格脱敏本地文件与用户数据

**隐私与遥测** ---- 明确收集目的、同意、最小化、保留期限、关闭方式、数据区域和崩溃报告中的敏感字段

**功能开关与降级** ---- 对新功能、实验、系统能力、远程配置和高风险更新设置开关，准备离线默认值与旧功能回退

**兼容性策略** ---- 管理操作系统版本、CPU 架构、Electron 版本、数据库 schema、远程 API 和旧客户端生命周期

**用户支持** ---- 设计诊断信息导出、日志打包、反馈入口、版本识别、隐私提示、恢复指导和可撤销的远程协助

**事故响应** ---- 处理签名失效、更新失败、远程服务不可用、数据迁移错误、恶意依赖、证书过期和大面积崩溃

**发布后验证** ---- 观察安装成功、启动成功、更新成功、崩溃、活跃版本、关键任务完成和卸载原因，发布不是上传完文件就散场

**架构演进** ---- 在单体桌面应用稳定后，再考虑插件体系、多窗口协作、离线同步、模块化、远程配置和原生模块，不为架构图而架构图

**生产验收** ---- 能回答“哪个版本出了问题、影响哪些系统、如何停止更新、如何收集现场、如何回滚以及如何保护用户数据”

## 学习路径与项目主线

**第一阶段：桌面壳** ---- 用前端页面搭出一个窗口，理解主进程、渲染进程、预加载和最小 IPC，完成一次受控的系统能力调用

**第二阶段：桌面工具** ---- 做一个 Markdown 笔记、图片压缩、文件搜索或下载工具，加入打开保存、菜单、快捷键、托盘和本地数据

**第三阶段：产品化** ---- 接入真实后端、登录、离线、任务队列、进度、日志、崩溃监控、跨平台构建、签名和自动更新

**安全专线** ---- 在功能之外专门完成远程内容、导航、IPC、路径、凭据、依赖和更新安全评估，安全不是发布前最后一页 PPT

**性能专线** ---- 以启动、内存、大文件、多窗口、长时间运行和低配机器为样本，形成测量、定位、优化和回归记录

**源码阅读专线** ---- 观察成熟 Electron 应用的进程拆分、窗口管理、更新策略和故障处理，重点学习它们如何做边界，而不是只抄界面

**迁移评估专线** ---- 对照 Tauri 或原生方案评估体积、内存、生态、团队能力和系统集成，先理解取舍，再讨论换不换框架

## 通关标准

**模型通关** ---- 能解释主进程、渲染进程、预加载、沙箱、上下文隔离、窗口生命周期和 IPC 的职责边界

**通信通关** ---- 能设计带类型、校验、错误、超时、取消、进度和权限的 IPC 契约，不暴露任意 Node 能力

**桌面通关** ---- 能交付带窗口管理、菜单、快捷键、托盘、对话框、文件读写、拖放和本地数据的完整工具

**安全通关** ---- 能识别 XSS、远程内容、危险导航、任意文件读写、IPC 注入、秘密泄露、依赖和更新供应链风险

**性能通关** ---- 能定位启动、渲染、内存、IPC、文件、数据库和网络瓶颈，并在真实系统上用指标证明优化结果

**质量通关** ---- 能覆盖页面、主进程、预加载、IPC、文件、权限、安装、更新、崩溃和跨平台关键旅程

**交付通关** ---- 能完成至少一个平台的打包、签名、公证或等价验证、自动更新、失败恢复和版本回滚演练

**Electron 主线毕业** ---- 能把一个 Web 产品变成用户愿意安装、能安全使用、可以持续更新、出了问题也找得到现场的桌面应用

## 结语

Electron 最划算的地方，是让前端团队把熟悉的 Web 技能延伸到桌面；最需要认真对待的地方，是它同时给了页面一把通往操作系统的钥匙。钥匙好用，但不能随手挂在门外。

先吃透三进程与 IPC，再做系统集成；先建立安全边界，再接远程内容；先在真实系统测性能，再谈体积和速度；最后用签名、更新、监控和回滚完成交付。**桌面应用的毕业证不是窗口能打开，而是用户装得上、用得稳、更新不吓人。**
