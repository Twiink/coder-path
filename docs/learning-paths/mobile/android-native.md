# Android 原生开发学习路线

Android 原生开发是在 Kotlin、Android SDK 和一整套 Jetpack 工具上，直接和设备、系统以及厂商生态打交道。它的优势是平台能力最深、设备覆盖最广、职业场景最丰富；它的代价是碎片化也很有职业精神，屏幕、系统、厂商和分发渠道都可能各有一套答案。

这条路线只做 Android 学习地图，不把 Kotlin、Compose 或每个 Jetpack API 写成使用手册。路线会从语言和工具链走到 UI、状态、生命周期、数据、权限、后台、性能、测试、安全和发布；每个知识点都适合作为后续学习笔记的标题。

**路线定位** ---- 适合想深入 Android 平台、硬件、后台任务、车载或企业应用，并愿意在真机和各种系统版本上解决问题的人

**推荐总顺序** ---- Kotlin → Android 工程与组件 → Compose UI → 状态与导航 → 生命周期与架构 → 网络与数据 → 权限与系统能力 → 性能 → 测试与安全 → 签名发布

**先记住一句话** ---- Compose 让界面更现代，但 Android 的难题仍然在生命周期、权限、后台、设备差异和发布；会画界面只是拿到入场券

**本页怎么用** ---- 把粗体条目当作学习索引，把每站的验收当作项目检查点；先建立系统心智，再去背 Jetpack 的“全家桶菜单”

## 第一站：Kotlin 语言与现代并发

第一站先把语言地基打牢。Android 项目里，空值、集合、协程、生命周期和资源释放会长期同桌吃饭；语言基础不稳，后面每个 Bug 都可能长出一张 Kotlin 的脸。

**类型与空安全** ---- 掌握基本类型、可空类型、智能转换、非空断言、类型推断和平台类型，理解空安全如何影响 API 边界与错误路径

**函数与高阶函数** ---- 学习默认参数、命名参数、扩展函数、内联函数、函数类型、闭包和作用域函数，保持表达力但避免把逻辑藏进一串链式调用

**类、对象与接口** ---- 理解数据类、密封类、枚举、对象、伴生对象、继承、组合、接口、委托和可见性，为状态模型与领域建模打底

**集合与不可变性** ---- 掌握 List、Set、Map、序列、只读视图、可变集合、映射、过滤和复杂度，知道数据共享与修改会如何影响 UI

**泛型与类型建模** ---- 了解泛型、方差、类型约束、密封层级和结果模型，用类型表达加载、成功、失败、空数据和权限状态

**异常与错误** ---- 区分异常、业务失败、网络失败、取消和不可恢复错误，建立错误包装、用户提示、日志和重试边界

**协程基础** ---- 掌握挂起、调度器、结构化并发、作用域、上下文、取消、超时、异常传播和并发组合

**Flow 与响应式数据** ---- 理解冷流、热流、StateFlow、SharedFlow、背压、生命周期收集、重复发射和资源关闭

**线程与共享状态** ---- 认识主线程、IO、默认调度器、线程安全、锁、原子性、数据竞争和并发测试，协程不是把并发问题变没

**语言验收** ---- 能用 Kotlin 建模业务状态，用协程完成可取消的异步任务，并解释异常、取消和生命周期之间的关系

## 第二站：Android 工程、组件与资源

第二站熟悉 Android 项目的骨架。Android Studio 会帮你创建很多文件，但不会替你判断哪个配置影响安装包、哪个资源在夜间模式下失效。

**Android Studio 与 SDK** ---- 掌握 SDK、模拟器、设备管理、日志、调试器、布局检查、Profiler、构建同步和真机连接

**Gradle 与构建变体** ---- 理解模块、插件、依赖、版本目录、构建类型、产品风味、签名配置、缓存和构建产物

**应用组件** ---- 认识 Activity、Service、BroadcastReceiver、ContentProvider、Application 和它们的启动、权限与生命周期

**Manifest 与资源** ---- 掌握应用声明、权限、组件导出、资源目录、字符串、颜色、尺寸、主题、图标、密度和本地化

**配置变化** ---- 处理旋转、屏幕尺寸、语言、深色模式、字体、进程重建和系统回收，不把临时界面状态当成永久资产

**模块化** ---- 了解应用模块、功能模块、核心模块、依赖方向、动态特性和构建时间，防止所有业务住进一个巨型模块

**依赖管理** ---- 管理库版本、传递依赖、许可证、漏洞、兼容性、原生库和升级验证

**开发配置** ---- 区分开发、测试、预发布、生产、日志、接口地址、证书、功能开关和敏感配置

**工程验收** ---- 能创建多模块或结构清晰的项目，完成调试、测试构建和生产构建，并说清每个入口与配置的责任

## 第三站：Jetpack Compose 与自适应 UI

第三站开始搭界面。Compose 的声明式心智会让你少写许多样板代码，但“状态变化就重组”也要求你理解状态所有权、重组边界和副作用，否则界面会热情地重复工作。

**Composable 心智** ---- 理解组合、重组、稳定性、记忆、派生状态、快照系统和副作用边界

**布局与约束** ---- 掌握 Row、Column、Box、约束、测量、布局阶段、绘制阶段、对齐和自定义布局

**Material 3 与主题** ---- 了解颜色、排版、形状、动态颜色、暗色模式、组件状态和品牌设计系统

**列表与分页** ---- 使用 LazyColumn、LazyRow、网格、分页、稳定键、分组、吸顶、占位和大数据集渲染

**输入与表单** ---- 处理文本、焦点、键盘、输入法、校验、错误提示、密码、自动填充、无障碍和重复提交

**导航与深链接** ---- 规划导航图、参数、返回栈、嵌套导航、深链接、通知唤起、外部链接和登录拦截

**动画与手势** ---- 学习状态动画、转场、拖拽、嵌套滚动、触摸冲突、触觉反馈和减少动画设置

**响应式与大屏** ---- 适配手机、平板、折叠屏、横竖屏、多窗口、自由窗口、桌面模式和动态字体

**View 互操作** ---- 认识 Compose 与 XML、View、Fragment、RecyclerView 和旧项目并存时的迁移策略

**可访问性与国际化** ---- 关注语义、TalkBack、焦点、对比度、字号、多语言、时区、RTL 和内容描述

**UI 验收** ---- 能做出支持加载、空、错误、权限和不同屏幕的页面，并解释哪些状态会触发重组以及为什么

## 第四站：状态、架构与生命周期

第四站处理 Android 最容易“昨天还好好的”的部分。旋转、后台、进程回收和返回栈会认真考察你是否真的知道状态放在哪里。

**状态所有权** ---- 区分组件状态、屏幕状态、业务状态、持久化状态、服务端状态和派生状态

**ViewModel** ---- 掌握状态持有、生命周期范围、SavedState、事件、单向数据流和配置变化后的恢复

**Repository 与数据层** ---- 组织网络、数据库、缓存、同步和错误映射，让 UI 不直接和数据源握手

**单向数据流** ---- 设计事件输入、状态输出、一次性事件、导航事件、消息和副作用，避免页面自己修改自己又自己猜结果

**依赖注入** ---- 了解 Hilt、构造注入、作用域、组件生命周期、测试替身和模块边界

**Navigation Compose** ---- 处理栈、参数、嵌套图、保存状态、深链接、任务栈和返回行为

**生命周期感知** ---- 使用 Lifecycle、repeatOnLifecycle、前后台、暂停收集、资源释放和重复订阅

**进程死亡与恢复** ---- 设计状态保存、数据库恢复、未完成任务、通知入口和重新登录

**架构取舍** ---- 比较 MVVM、MVI、Clean Architecture、模块化和简单分层，避免为了画架构图而增加三层转发

**架构验收** ---- 能让 UI、ViewModel、数据源和平台能力独立测试，并在旋转、返回、回收和恢复后保持行为一致

## 第五站：网络、本地数据与离线同步

第五站让应用和服务端正式合作。网络会超时，数据库会升级，用户会离线，接口也会偶尔决定换一种错误；可靠的数据层要比页面更有耐心。

**HTTP 与 Retrofit** ---- 理解请求、响应、Header、状态码、序列化、拦截器、连接、超时和错误映射

**OkHttp 网络层** ---- 关注缓存、连接池、日志、重试、证书、代理、请求 ID、网络状态和安全配置

**序列化与契约** ---- 使用 Kotlin Serialization、Moshi 或 Gson，处理兼容字段、未知字段、日期、枚举、错误和版本

**协程请求状态** ---- 管理加载、成功、空、失败、取消、超时、重试、部分成功和并发请求

**Room 数据库** ---- 掌握实体、关系、DAO、查询、事务、迁移、索引、Flow、分页、并发和数据库线程

**DataStore 与配置** ---- 区分偏好数据、协议数据、敏感凭据、迁移、损坏和默认值

**缓存与离线** ---- 设计内存、磁盘、数据库和服务端缓存的层次、过期、刷新、脏数据和回滚

**同步与冲突** ---- 处理本地操作队列、版本号、幂等、冲突、网络恢复、最终一致性和用户解决

**文件与媒体** ---- 关注 URI、MediaStore、权限、临时文件、上传下载、断点、进度、缩略图和磁盘空间

**安全存储** ---- 了解 Keystore、令牌、加密、备份、设备迁移、退出清理和密钥轮换

**数据验收** ---- 在慢网、断网、恢复、数据库升级、令牌过期和重复提交下保持数据可解释

## 第六站：权限、后台与 Android 系统能力

第六站面对 Android 的平台深度。设备能做很多事，但系统会先问你有没有权限、是否在前台、用户是否真的想让你继续工作。

**运行时权限** ---- 处理首次申请、拒绝、永久拒绝、设置页、权限用途、分组变化和能力降级

**相机与媒体** ---- 学习 CameraX、相册、视频、音频、编码、预览、后台限制和隐私提示

**定位与传感器** ---- 关注前台定位、后台定位、精度、电量、权限、地理围栏、蓝牙、NFC、陀螺仪和厂商差异

**通知与推送** ---- 处理通知渠道、权限、前台服务、FCM、厂商推送、点击跳转、冷启动和重复消息

**后台任务** ---- 理解 WorkManager、JobScheduler、前台服务、约束、重试、持久任务、任务唯一性和系统回收

**Alarm 与定时** ---- 认识精确闹钟、时区、夏令时、待机、重复任务和电量影响

**分享与外部唤起** ---- 处理 Intent、深链接、App Links、文件打开、分享、默认应用和参数校验

**桌面小组件与扩展** ---- 了解 Widget、快捷方式、通知入口、锁屏与车载、Wear OS、Android TV 的延伸边界

**厂商与渠道** ---- 关注 ROM 限制、后台保活、推送通道、应用商店、隐私要求和设备兼容

**系统能力验收** ---- 完成至少一项相机、定位、推送、后台或分享功能，并为拒绝、不可用、系统回收和低电量设计回退

## 第七站：性能、内存与稳定性

第七站回答“为什么在模拟器飞起，在旧手机上像在回忆人生”。Android 性能要同时看主线程、绘制、内存、启动、数据库、网络和电量。

**启动性能** ---- 分析冷启动、热启动、Application 初始化、首屏、依赖初始化、内容预取和首个可交互时间

**Compose 重组** ---- 关注稳定性、状态读取、跳过重组、派生状态、列表键、布局测量和副作用

**渲染与帧率** ---- 了解 Choreographer、帧预算、布局、绘制、动画、GPU、过度绘制和掉帧

**列表与图片** ---- 优化分页、懒加载、图片尺寸、解码、缓存、占位、预取和内存峰值

**内存与泄漏** ---- 排查 Activity、Context、View、协程、监听器、Bitmap、数据库、服务和静态引用

**ANR 与线程** ---- 理解主线程阻塞、锁等待、IO、Binder、死锁、StrictMode 和无响应诊断

**数据库与网络** ---- 关注查询、索引、事务、连接、序列化、缓存、请求合并和重试风暴

**电量与温度** ---- 控制定位、传感器、后台任务、唤醒、网络轮询、动画和高频计算

**性能工具** ---- 使用 Profiler、Perfetto、Macrobenchmark、Baseline Profile、Layout Inspector、LeakCanary 和崩溃平台

**性能验收** ---- 在低端机、慢网、冷启动、长列表、低电量、后台恢复和多窗口场景下用指标对照优化

## 第八站：测试、调试与安全

第八站让“真机能跑”变成“升级后也敢跑”。Android 的测试要覆盖 Kotlin 逻辑、Compose、生命周期、数据库、权限、设备和发布产物。

**单元测试** ---- 覆盖纯逻辑、状态机、ViewModel、序列化、错误、时间、重试和权限决策

**协程与 Flow 测试** ---- 验证调度、取消、超时、异常、热流、重复订阅和生命周期收集

**Compose UI 测试** ---- 检查语义、状态、点击、输入、滚动、导航、无障碍和截图回归

**集成测试** ---- 使用真实或隔离数据库、网络、文件、权限和系统服务验证边界

**设备测试** ---- 覆盖系统版本、厂商、屏幕、架构、字体、语言、深色模式、网络和低内存

**故障测试** ---- 注入断网、权限拒绝、进程回收、旋转、睡眠、推送重复、数据库升级和安装失败

**应用安全** ---- 关注组件导出、Intent、深链接、WebView、备份、日志、凭据、文件 Provider 和证书校验

**依赖与供应链** ---- 检查库漏洞、许可证、原生库、构建脚本、密钥、签名和产物来源

**日志与崩溃** ---- 关联版本、设备、页面、请求、线程、错误和用户动作，同时脱敏个人数据

**质量验收** ---- 能让失败带着设备、版本和现场证据回家，而不是只留下一个“偶现，无法复现”

## 第九站：构建、签名与分发

第九站是 Android 的交付课。源码能编译只是开始，真正的产品还要面对应用签名、不同渠道、隐私合规、灰度和旧版本。

**构建类型与渠道** ---- 区分 debug、release、测试、生产、国内渠道、海外渠道、架构和环境

**APK 与 AAB** ---- 理解安装包、应用包、资源拆分、动态特性、版本号和设备交付

**签名与密钥** ---- 掌握 keystore、签名轮换、密钥保管、构建机器权限、丢失风险和 Play App Signing

**R8 与资源缩减** ---- 了解混淆、压缩、反射、序列化、保留规则、资源裁剪和崩溃可读性

**Google Play 发布** ---- 处理应用资料、数据安全、内容分级、测试轨道、审核、分阶段发布和回滚

**国内渠道发布** ---- 关注华为、小米、应用宝等商店的资料、软著、隐私、权限和渠道包差异

**更新与兼容** ---- 设计最低版本、强制更新、数据库迁移、接口兼容、灰度、远程开关和旧客户端退出

**CI/CD** ---- 自动完成检查、测试、构建、签名、产物、版本、发布说明和审批

**运维指标** ---- 观察安装、启动、崩溃、ANR、更新、活跃版本、支付和关键业务失败

**发布验收** ---- 能完成至少一个渠道的签名、测试、发布、灰度、监控、暂停和回滚演练

## 学习路径与项目主线

**第一阶段：Compose 小应用** ---- 先用 Kotlin 与 Compose 做列表、表单、导航、状态和主题，熟悉 Android Studio 与真机

**第二阶段：离线应用** ---- 加入 ViewModel、Room、DataStore、图片、登录、缓存、数据库迁移和网络失败

**第三阶段：系统能力** ---- 接入权限、相机、定位、推送、分享、后台任务或文件，并记录平台差异

**第四阶段：生产交付** ---- 完成性能分析、测试矩阵、签名、渠道发布、崩溃监控、灰度、更新和回滚

**进阶分支** ---- 深入多模块、Compose 底层、Kotlin Multiplatform、Compose Multiplatform、车载、Wear、TV、媒体、图形和系统服务

## 通关标准

**语言通关** ---- 能用 Kotlin 表达业务状态，正确处理空值、协程、Flow、取消、异常和资源关闭

**UI 通关** ---- 能用 Compose 做出自适应、可访问、支持状态与导航的完整界面

**架构通关** ---- 能建立 UI、ViewModel、Repository、数据库、网络和平台能力的清晰边界

**系统通关** ---- 能处理权限、相机或定位、通知、后台、分享、进程回收和设备差异

**性能通关** ---- 能用 Profiler 或 Perfetto 定位一次启动、掉帧、ANR、内存或电量问题

**质量通关** ---- 能建立单元、UI、集成、设备和故障测试，并让失败可诊断

**交付通关** ---- 能完成签名、混淆、商店发布、灰度、监控、更新和回滚演练

**Android 主线毕业** ---- 能把一个真实应用从 Kotlin 代码送到多种 Android 设备，并在系统不配合时仍有备用方案

## 结语

Android 原生的魅力，是你能直接触摸平台、硬件和系统；它的训练方式也很诚实：每一个生命周期、权限和厂商差异，都会要求你把“应该没事”改写成真实证据。

先用 Compose 打通 UI、状态和数据，再深入后台、系统能力、性能和发布。**原生开发不是拒绝跨平台，而是当抽象层到达边界时，你知道下一扇门该怎么打开。**
