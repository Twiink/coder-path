# uni-app 学习路线

uni-app(DCloud 出品)是**国内最流行的多端框架**:一套 Vue 代码,编译到 **iOS/Android App、H5、微信/支付宝/百度/字节等小程序**——"一次编写,多端发布";基于 Vue 语法(Vue 3 为主),中文文档完善、插件市场丰富,是**国内同时要 App + 小程序 + H5 的产品的高频选择**(招聘需求大)。**定位**:对比 RN/Flutter(专注 App 双端),uni-app 的杀手锏是"**小程序端也一并覆盖**";对比原生小程序,它省去多端重复开发。**代价**:多端一致性的抽象层——**平台差异要条件编译处理**,复杂原生/极致性能场景仍建议原生(uni-app x 正在向原生靠拢)。

## 为什么选 uni-app

**①覆盖广**:一份代码 = App(iOS/Android)+ 小程序全家 + H5——**国内产品的现实组合(App+小程序)一条代码库搞定**;**②Vue 零门槛**:会 [Vue](/learning-paths/frontend/vue) 几乎直接上手(模板/组件/生命周期同款),前端团队迁移成本极低;**③国内生态**:中文文档、HBuilderX 开发工具、插件市场(现成组件/模板多)、云打包(不用自己配原生环境就能出 App 安装包);**④招聘需求**:国内中小公司多端产品普遍用它。**代价**:框架抽象层(部分 API 与性能受限于多端兼容);**小程序端体验上限 = 小程序本身的上限**;平台特有能力要靠条件编译与原生插件。

## 基础篇:环境与语法

**环境**:HBuilderX(官方 IDE:创建/运行/打包一体,App 云打包不用装 Android Studio)或 CLI + VS Code 模式(Vue 开发者更熟);**项目结构**:`pages/`(页面,类似路由表在 pages.json 配置)、`components/`、`static/`(静态资源)、`App.vue`/`main.js`、`manifest.json`(多端应用配置:App 图标/小程序 appid)。**模板语法(与 Vue 相同 + 少量差异)**:数据绑定/列表渲染(v-for)/条件渲染;样式:用 **rpx(响应式像素:小程序与 App 的适配单位,750rpx = 屏宽)** 替代 px——**多端适配的第一课**;页面导航用内置 `uni.navigateTo`/`navigateBack`(非 Vue Router——**多端没有 Web 的 URL 概念,导航是 API 式**)。

## 进阶篇:页面、组件与 API

**页面生命周期**:onLoad(带参进入)/onShow/onReady/onPullDownRefresh(下拉刷新)/onReachBottom(上拉加载——**列表分页的标配**);**基础组件**:view/text/image/input/scroll-view(滚动容器)/swiper(轮播)/form 系列;**API(uni 前缀统一封装——多端差异被抹平的核心)**:`uni.request`(网络,封装 Promise 用)、`uni.setStorage`(本地存储,同步版有 StorageSync)、`uni.chooseImage`(相册相机)、`uni.getLocation`、`uni.showToast`(交互反馈)、`uni.login`(微信登录);**注意**:小程序 API 与 Web 差异大(无 DOM/Cookie——**登录态靠 token 自己管**),但 uni 把主流都统一了——查 uni 文档的 API 列表即可。**自定义组件**:Vue 组件语法 + props/事件(与 Web 组件一致)。

## 实战篇:状态、多端适配与发布

**状态管理**:Vuex/Pinia(与 Vue 生态一致,见 [Vue](/learning-paths/frontend/vue));**条件编译(多端差异的唯一正确姿势)**:`// #ifdef MP-WEIXIN` 与 `// #ifndef H5` 注释包裹差异代码——**同一文件里按平台编译不同片段**(支付/登录等平台能力全靠它);**UI 组件库**:uni-ui(官方)/uView(人气高)——按需引入;**性能**:长列表(虚拟列表/分页)、图片优化(压缩/懒加载/域名白名单)、**减少 setData 体积(小程序更新数据的开销与数据量成正比——别一次塞大对象)**、分包加载(主包限制 2MB,大应用拆分包——**小程序上架硬门槛**);**发布三端(走三套流程)**:App(云打包出安装包 → 上架应用商店)、小程序(开发者工具上传 → 微信审核)、H5(静态部署)——**"一套代码三处发布"是 uni-app 的完整交付**;后端:常规自建接口对接,或 **uniCloud(云开发:云函数/云数据库免后端——小团队快速落地)**。

## 学习路径与进阶

**路径**:HBuilderX 建项目跑通 Hello → Vue 语法复习 + 页面与导航 → 组件与 API(列表/表单/请求/存储)→ 登录态与条件编译 → 组件库与样式打磨 → 真机预览(微信开发者工具/HBuilderX 运行到手机)→ 发布微信小程序(最顺的发布路径)。**进阶**:uniCloud 云开发、nvue(原生渲染,复杂页面性能)、分包与性能优化、**对照原生小程序学习平台细节**、Taro(React 语法的同类多端框架——React 团队选它)。

## 通关标准

能独立做到:用 uni-app 做出一个带登录、列表分页、表单、本地存储的页面并在**微信开发者工具与手机 App 两端跑通**;用条件编译处理至少一处平台差异;说清 rpx 单位与 uni API 的多端设计思想;完成微信小程序提审并发布(或完整演练);合理使用分包与列表优化——uni-app 主线通关。

uni-app 的价值一句话:"**国内多端(尤其 App+小程序)的最短交付路径**"——Vue 语法 + 一套代码 + 云打包,让一个小团队能同时占住微信流量与 App 商店。它的代价是抽象层的"够用但非极致"——**记住选型边界:要最快覆盖多端 → uni-app;要单端极致 → 原生/RN/Flutter**;学会条件编译与性能优化,你就能在多端一致与平台体验之间找到平衡。下一步:原生小程序细节看 [微信小程序](/learning-paths/mobile/wechat-miniprogram),或先学 [Vue](/learning-paths/frontend/vue)。
