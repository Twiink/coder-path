# uni-app 学习路线

uni-app 的卖点很朴素：用 Vue 的开发方式，把一套业务代码送往 App、H5 和多个小程序平台。它像一位熟悉各种方言的翻译，能让团队少写几遍重复页面；但翻译不是魔法，平台差异、性能边界和发布规则仍然会来收取“现实税”。

这条路线只负责导航和索引，不把 Vue、JavaScript 或各平台 API 重新写成百科。你会看到从多端选型、项目结构、页面生命周期、跨端 UI，到网络、状态、原生能力、性能、测试和发布的完整地图；每个知识点都应该在后续学习笔记里继续下钻。

**路线定位** ---- 适合已经接触 JavaScript 与 Vue，想用一套代码覆盖 App、H5 和小程序，并愿意认真处理平台差异的人

**推荐总顺序** ---- 多端边界 → Vue 与项目骨架 → 页面和生命周期 → UI 适配 → 网络与数据 → 状态管理 → 条件编译与原生能力 → 性能 → 测试 → 打包发布 → 项目演练

**先记住一句话** ---- uni-app 解决的是“少写几份业务代码”，不承诺“所有平台从此性格完全相同”；越靠近系统能力，越要准备平台分支和原生知识

**本页怎么用** ---- 把每站的粗体条目当作学习清单，把链接当作下一篇笔记的入口；先理解边界，再背 API，否则很容易成为“会调用按钮但不会交付应用”的 API 收藏家

## 第一站：多端世界与选型边界

第一站先别急着创建项目。uni-app 的核心不是“把页面编译到很多地方”，而是理解编译目标、运行容器和平台能力之间的三角关系。选型选错时，后面的每一次兼容性修补都会像给拖鞋焊轮胎。

**目标平台地图** ---- 认识 H5、微信小程序、支付宝小程序、抖音小程序、百度小程序、App 端以及不同厂商扩展的能力范围、审核约束和运行环境

**编译目标与运行容器** ---- 区分浏览器、各家小程序运行时、App WebView、原生渲染方案和 uni-app x 的路线，理解“一套源码”不等于“一套运行时”

**跨端抽象的收益** ---- 了解组件、样式、路由、网络、存储和常用设备能力如何被统一封装，判断哪些业务代码适合复用，哪些内容必须留出平台接口

**平台差异清单** ---- 对照 DOM、Cookie、文件系统、权限、支付、登录、分享、推送、后台任务、包体积、域名白名单和审核规则，建立自己的能力矩阵

**方案横向比较** ---- 了解原生小程序、Taro、React Native、Flutter、原生 App 与 uni-app 的边界，知道何时优先覆盖面，何时优先性能、原生体验或生态深度

**不适合的场景** ---- 识别高性能游戏、重度音视频、复杂 3D、极深原生集成和对单平台体验极端敏感的项目，避免让抽象层背负它不擅长的行李

**选型产出** ---- 写出目标平台、复用比例、平台特有能力、性能预算、团队技能和发布渠道的矩阵，先让项目做选择题，不要上线后做判断题

## 第二站：Vue 3 与 uni-app 项目骨架

第二站把 Vue 的肌肉记忆搬到多端项目里。会写模板只是入场券，还要理解页面、组件、配置和编译工具分别负责什么，否则项目很快会长成一锅“哪里都能改、谁都不敢改”的粥。

**Vue 3 基础** ---- 复习响应式、组合式 API、组件、属性、事件、插槽、生命周期、计算状态、监听和组合函数，重点关注它们在不同端的兼容边界

**JavaScript 与 TypeScript 地基** ---- 补齐模块、异步、Promise、错误处理、对象与数组、类型建模、接口契约和运行时校验；类型提示是护栏，不是对用户输入的免检通行证

**项目目录职责** ---- 认识页面、组件、静态资源、公共工具、组合函数、状态仓库、平台分支、原生扩展和测试目录的边界，让文件各自有户口本

**应用与入口配置** ---- 掌握 App 入口、全局样式、全局生命周期、页面配置、应用清单、图标、启动页、权限声明、应用标识和环境配置

**HBuilderX 与 CLI 工作流** ---- 了解官方 IDE、命令行、编辑器插件、模拟器、真机运行、各平台开发者工具和构建工具之间的分工，选择适合团队的工作流

**依赖与工程规范** ---- 学习包管理、锁定版本、路径别名、环境变量、代码格式化、静态检查、提交检查、资源命名和目录约定，别让“能运行”成为唯一工程标准

**开发、测试与生产配置** ---- 区分本地、测试、预发布和生产环境，理解接口地址、公开配置、敏感配置、构建变量和运行时配置各自应该出现在哪里

**项目骨架验收** ---- 能创建一个可运行的多端项目，明确页面、组件、公共逻辑、配置和平台分支的放置位置，并能在至少两个目标端启动和调试

## 第三站：页面、路由与生命周期

第三站开始接触“应用为什么会突然重新出现、为什么返回后数据变旧”。移动端和小程序不是浏览器标签页的复制品，页面栈、前后台切换和平台回收会不断提醒你：设备才是老板。

**页面注册与导航** ---- 掌握页面清单、页面栈、普通跳转、返回、重定向、重新启动、切换 Tab、页面参数和返回数据，理解不同导航动作对生命周期的影响

**页面生命周期** ---- 梳理加载、显示、初次渲染、隐藏、卸载、下拉刷新、触底、分享和滚动等钩子，区分“页面创建一次”和“页面每次出现都可能执行”

**应用生命周期** ---- 关注启动、进入前台、退到后台、被系统挂起、从通知或分享恢复、冷启动与热启动，设计恢复状态和重复初始化的边界

**组件生命周期** ---- 理解组件创建、挂载、更新、卸载、属性变化和插槽渲染，避免在组件内部偷偷承担页面级请求、导航和全局状态

**页面间通信** ---- 选择参数、事件、返回值、全局状态、持久化存储和消息通知的使用边界，防止页面之间靠互相猜测字段维持友谊

**状态恢复** ---- 处理返回页面、切换 Tab、进程回收、网络恢复、横竖屏变化和系统内存不足后的重新进入，区分恢复界面状态与重新拉取服务端状态

**启动参数与场景** ---- 关注扫码、分享、通知、外部链接、桌面图标和小程序场景值带来的入口差异，让应用从不同入口进来时不至于迷路

**路由验收** ---- 做出列表、详情、编辑、登录和返回刷新闭环，能解释每次导航触发了哪些生命周期，并处理重复点击、失效参数和未登录跳转

## 第四站：跨端 UI、布局与交互

第四站面对多端最常见的误会：页面看起来一样，不代表交互、输入法、屏幕和无障碍行为也一样。跨端 UI 的目标不是复制像素，而是在不同设备上保持清楚、可用和不添堵。

**响应式单位与尺寸** ---- 掌握 rpx、px、百分比、视口单位、最小最大尺寸、屏幕密度和安全区域，建立从手机小屏到平板大屏的适配策略

**布局与组件兼容** ---- 了解 Flex、定位、滚动容器、列表、轮播、表单、媒体和原生组件的支持差异，知道 CSS 能力不一致时如何保留可用降级

**导航与手势** ---- 处理顶部导航、底部 Tab、返回手势、侧滑、长按、拖拽、双指缩放和系统返回键，避免把 Web 鼠标思维硬塞进触摸屏

**输入与键盘** ---- 关注焦点、软键盘顶起、遮挡、提交、输入法、数字与密码键盘、光标、复制粘贴、表单校验和重复提交

**列表与滚动体验** ---- 设计空状态、加载状态、错误状态、下拉刷新、上拉加载、分页、虚拟化、吸顶、滚动位置恢复和长列表回收

**图片、字体与媒体** ---- 规划尺寸、格式、压缩、裁剪、懒加载、缓存、占位、失败重试、字体兼容、视频播放和音频焦点，别让一张原图把用户流量吃成早餐

**主题与设备适配** ---- 处理暗色模式、动态字体、刘海与圆角屏、横竖屏、平板、折叠屏、低端设备、系统字号和高对比度

**可访问性与国际化** ---- 学习语义、读屏标签、焦点顺序、触控目标、颜色对比、多语言、复数、日期金额格式、时区和从左到右或从右到左布局

**样式边界** ---- 理解页面样式隔离、全局样式、选择器支持、平台默认样式、原生组件穿透和条件样式，避免“在 H5 好好的”成为验收结论

**UI 验收** ---- 至少用不同尺寸、不同系统、低速网络和系统字号跑一遍列表、表单、弹窗与键盘场景，视觉一致只是及格线，不是终点

## 第五站：网络、接口与登录态

第五站让应用开始与外部世界交换数据。移动网络会断，小程序会限制域名，H5 会遇到跨域，用户还可能在请求发出后立刻坐上电梯；网络层要为这些坏消息预留座位。

**HTTP 与 HTTPS 基础** ---- 理解请求方法、状态码、Header、缓存、压缩、超时、TLS、证书、域名和代理，为跨端网络差异建立共同语言

**请求层封装** ---- 统一请求入口、基础地址、公共 Header、序列化、响应解析、错误映射、请求 ID、取消、超时、重试和日志，避免页面里散落几十套请求脾气

**平台网络限制** ---- 掌握 H5 跨域、小程序合法域名、App 网络权限、证书校验、HTTP 明文限制、代理配置和不同端的上传下载能力

**失败与重试策略** ---- 区分网络断开、超时、服务端错误、认证失效、业务拒绝和用户取消，按错误类型决定重试、提示、降级或交给人工处理

**幂等与重复请求** ---- 处理按钮重复点击、系统重试、页面重进、网络重放和支付回调，给创建、提交、上传和支付等副作用操作设计幂等方案

**登录与令牌** ---- 理解账号密码、短信、第三方登录、小程序登录、App 授权、短期令牌、刷新令牌、退出、撤销、多设备和登录态恢复

**Cookie 与 Token 差异** ---- 对照浏览器 Cookie、小程序限制、App 本地凭据和安全存储，明确哪些信息能放客户端，哪些信息必须留在服务端

**文件上传下载** ---- 关注选择文件、相册和相机、类型与大小校验、进度、断点、分片、临时路径、权限、预览、缓存和失败恢复

**实时通信** ---- 了解 WebSocket、轮询、推送和平台消息的连接、心跳、断线、重连、鉴权、顺序、重复、离线消息与多端同步

**接口契约与数据校验** ---- 使用 OpenAPI、共享类型、Schema、版本和运行时校验，防止接口字段在服务端换了衣服，页面却还拿着旧尺子

**网络验收** ---- 能在正常、慢网、断网、恢复、过期登录、重复点击、服务端 500 和部分成功场景下稳定展示状态

## 第六站：本地数据与状态管理

第六站解决“数据放哪里、谁能改、什么时候失效”。状态管理工具不是百宝箱；把所有东西都塞进全局仓库，通常只会得到一个更难追踪的全局惊喜。

**状态分类** ---- 区分组件临时状态、页面状态、跨页面客户端状态、服务端状态、缓存状态、持久化状态和派生状态

**Pinia 与 Vuex 路线** ---- 了解仓库、状态、计算值、动作、模块拆分、插件、持久化和调试工具，按项目版本与团队习惯选择，不为迁移而迁移

**组合函数与业务模块** ---- 把请求、分页、表单、权限、缓存和设备能力封装成可复用逻辑，保持组件负责展示，不让页面变成一座没有出口的业务仓库

**缓存与失效** ---- 设计内存缓存、本地缓存、服务端缓存、过期、主动刷新、乐观更新、回滚、版本迁移和脏数据处理

**本地存储分层** ---- 对照键值存储、文件、SQLite、加密存储和平台安全容器，分别规划设置、草稿、离线数据、敏感凭据和大文件

**离线优先与同步** ---- 学习本地队列、重试、冲突、最后写入、版本号、操作日志、网络恢复、部分同步和最终一致性，离线不是“请求失败后弹一句请重试”

**数据生命周期** ---- 处理登录切换、账号退出、应用升级、卸载重装、缓存清理、用户删除、过期数据和跨设备同步

**权限与状态边界** ---- 区分“页面不展示”与“服务端不允许”，所有敏感操作都以服务端授权为最终依据，前端隐藏按钮只能算礼貌

**状态验收** ---- 完成登录、列表缓存、详情更新、离线草稿、退出清理和重新启动恢复，能说清每份数据的所有者与失效条件

## 第七站：条件编译与平台能力

第七站是 uni-app 的分水岭。真正的多端开发不是把所有差异藏起来，而是知道什么时候统一、什么时候分叉、什么时候干脆调用原生能力。

**条件编译** ---- 掌握按 H5、App、微信小程序及其他平台拆分脚本、模板、样式和配置的策略，控制分支数量，避免条件编译长成藤蔓

**平台能力矩阵** ---- 逐项比较相册、相机、定位、地图、蓝牙、NFC、陀螺仪、通讯录、剪贴板、扫码、分享、通知、推送和支付

**权限与隐私** ---- 处理首次申请、拒绝、永久拒绝、再次引导、权限变更、使用时机、隐私说明、最小权限和不同平台的隐私清单

**App 原生扩展** ---- 了解原生插件、模块、原生 SDK、应用权限、Activity 或 iOS 生命周期、回调、线程、构建配置和版本兼容

**原生渲染路线** ---- 认识 nvue、原生组件、uts、uni-app x 和平台原生页面的定位，理解它们解决的性能或能力问题，以及随之增加的维护成本

**小程序平台 API** ---- 关注登录、支付、订阅消息、分享、客服、分包、插件和平台审核，知道统一 API 覆盖不到的地方该怎样设计回退

**Web 能力降级** ---- 处理浏览器权限、文件选择、定位、通知、支付、分享和 WebView 限制，为 H5 准备替代流程，不让它成为被遗忘的表亲

**原生桥与数据边界** ---- 设计参数、返回值、错误、线程、序列化、回调、生命周期和资源释放，减少频繁跨桥调用以及大对象搬运

**uniCloud 与自建后端** ---- 比较云函数、云数据库、云存储、权限、环境、成本、迁移和供应商绑定，知道“免后端”只是少写服务器，不是少做架构

**平台能力验收** ---- 至少完成一项需要权限或原生能力的功能，并为能力不可用、用户拒绝、版本不支持和平台审核失败准备替代路径

## 第八站：性能、包体与电量

第八站专门处理“开发工具里很流畅，真机上像在用远古计算器”的情况。移动端的性能不是一个分数，而是首屏、帧率、内存、电量、网络和包体的联合成绩单。

**启动性能** ---- 分析冷启动、热启动、首屏、首个可交互时刻、初始化任务、字体、图片、请求和分包加载，区分用户等待与后台预热

**渲染与帧率** ---- 关注主线程、重排、重绘、响应式更新、动画、滚动和交互反馈，理解一帧预算与低端设备为什么更容易把问题放大

**长列表优化** ---- 使用分页、虚拟列表、分段渲染、稳定键、图片尺寸、骨架屏和增量加载，避免一次把几千条数据端上来再问设备吃不吃得消

**小程序数据传输** ---- 理解逻辑层与视图层之间的数据更新、序列化和传输成本，减少大对象、频繁更新和无关字段同步

**包体与分包** ---- 学习主包、分包、预下载、懒加载、资源裁剪、依赖去重、代码分割、压缩和平台包体限制，提前规划而不是临近审核才拆家

**图片与媒体性能** ---- 优化格式、尺寸、质量、缓存、解码、预加载、视频清晰度和播放策略，内存峰值比图片文件大小更会制造事故

**网络与电量** ---- 处理请求合并、缓存、后台任务、轮询、定位频率、上传下载、弱网和省电策略，减少“为了刷新一个角标叫醒全家”的行为

**内存与资源生命周期** ---- 排查监听器、定时器、页面缓存、图片、WebSocket、原生对象和临时文件没有释放的问题

**跨端性能差异** ---- 分别在 H5、App WebView、小程序和原生渲染方案上测量，不能拿浏览器开发机的成绩单替真机签字

**性能工具与预算** ---- 使用开发者工具、真机调试、性能面板、网络面板、崩溃平台和自定义指标，建立启动、首屏、滚动、包体和内存预算

**性能验收** ---- 在低端机、慢网、长列表、冷启动、后台恢复和连续使用场景下测量，优化必须有前后对照，不能只凭“感觉顺滑”

## 第九站：测试、调试与质量保障

第九站把“在我手机上没问题”送进历史博物馆。多端项目的测试不是把所有设备买回家，而是建立风险优先的设备矩阵与可重复的验证流程。

**测试分层** ---- 规划 JavaScript 逻辑、组合函数、组件、页面、接口、原生桥、端到端和视觉回归测试的边界与成本

**平台矩阵** ---- 覆盖主流系统版本、屏幕尺寸、厂商 WebView、低端设备、平板、模拟器、真机和不同网络，按用户占比与风险取舍

**交互与生命周期测试** ---- 验证启动、返回、切 Tab、前后台、旋转、键盘、权限、系统中断、分享入口、通知恢复和页面回收

**接口与数据测试** ---- 覆盖空数据、脏数据、慢响应、超时、失效令牌、重复提交、分页边界、上传失败和数据迁移

**原生能力测试** ---- 验证相机、定位、蓝牙、推送、支付、文件、地图和分享在授权、拒绝、系统限制和版本差异下的表现

**自动化与手工组合** ---- 快速逻辑测试交给自动化，关键旅程交给端到端，系统能力和审核流程保留真机与人工验收

**日志与崩溃** ---- 统一日志级别、用户动作、页面、版本、平台、设备、请求 ID、崩溃堆栈和脱敏策略，线上问题要有现场，而不是靠回忆录

**可访问性与视觉回归** ---- 检查读屏、键盘或辅助操作、字体放大、颜色对比、暗色模式和多尺寸截图，保证“能用”不只属于视力和网速都满格的人

**持续集成** ---- 接入格式检查、类型检查、单测、构建、平台工具、产物归档、版本校验和最小冒烟，减少“只有某位同事电脑能发布”的仪式感

**质量验收** ---- 能定位是页面、平台 API、网络、权限、构建产物还是服务端的问题，并保留可重现步骤、设备信息和版本证据

## 第十站：构建、签名与多端发布

第十站是移动开发的成人礼：代码能跑不算交付，能在目标平台安装、审核、更新、回滚，用户还愿意打开，才算完整闭环。

**构建模式** ---- 区分开发、测试、预发布、生产、调试包、正式包、渠道包和不同环境变量，确保日志、接口和权限不会串台

**App 打包方式** ---- 了解云打包、本地原生工程、Android 与 iOS 构建链、应用标识、图标、启动页、权限、架构和原生插件依赖

**签名与证书** ---- 掌握 Android 签名、iOS 证书、描述文件、密钥保管、证书轮换、构建机器权限和签名失败后的恢复方案

**小程序发布** ---- 处理开发者工具、体验版、审核版、正式版、域名、隐私协议、类目、权限、分包、版本回退和平台审核反馈

**H5 发布** ---- 规划静态托管、域名、HTTPS、CDN、缓存、资源路径、历史路由回退、公开配置和跨域，保证页面不是只在本地地址上存在

**版本与数据迁移** ---- 设计本地存储迁移、接口兼容、灰度、强制更新、最低版本、资源更新和旧客户端退出策略

**自动化发布** ---- 使用 CI 管理构建、签名、产物、版本号、变更记录、测试、审核提交和发布审批，减少手工复制粘贴造成的玄学

**监控与回滚** ---- 关注崩溃率、启动失败、接口错误、支付失败、审核状态、活跃版本和更新成功率，准备热修复、降级、回滚和人工兜底

**合规与供应链** ---- 检查隐私政策、权限用途、第三方 SDK、数据收集、开源许可、支付合规和不同商店的分发规则

**发布验收** ---- 至少完整走通一次 App、一个小程序或 H5 的构建与发布流程，能回答“坏版本如何停、旧数据如何迁、用户如何恢复”

## 第十一站：项目主线与进阶分支

最后一站不是继续收集 API，而是用一个真实项目把前面的知识点串起来。建议项目有登录、列表、详情、表单、文件、权限和发布，这样平台差异不会只在课本里礼貌地存在。

**第一阶段：最小闭环** ---- 完成登录、列表、详情、表单、请求、错误、空状态、加载状态和本地存储，并在 H5 与一个小程序端跑通

**第二阶段：多端适配** ---- 增加条件编译、平台登录、文件上传、相册或定位、分享、分页、分包和不同屏幕适配，记录每个平台的差异决策

**第三阶段：产品化交付** ---- 接入权限、离线草稿、实时消息、崩溃监控、自动构建、签名、审核、灰度、更新和回滚，把 Demo 送进现实世界

**进阶分支：原生深度** ---- 深入原生插件、原生渲染、uts、uni-app x、性能剖析、蓝牙、地图、音视频和复杂权限，适合需要突破抽象层边界的项目

**进阶分支：云开发** ---- 研究 uniCloud 的云函数、云数据库、云存储、权限、触发器、定时任务、成本和迁移，适合快速验证但仍要保留供应商边界意识

**进阶分支：多框架迁移** ---- 对照原生小程序、Taro、React Native 和 Flutter，理解组件、导航、状态、原生桥和发布流程如何迁移，培养选型能力而不是框架信仰

**项目复盘** ---- 记录复用代码、平台分支、性能数据、失败场景、发布问题和后续债务；路线的终点不是“都学过”，而是“知道哪里不能偷懒”

## 通关标准

**基础通关** ---- 能解释 uni-app 的编译目标、运行容器、页面注册、生命周期、组件边界和条件编译，而不是只会点运行按钮

**应用通关** ---- 能独立做出带登录、列表分页、详情、表单、错误状态、文件能力和本地数据的多端应用

**跨端通关** ---- 能让同一业务在 H5、小程序或 App 中运行，并明确记录哪些部分复用、哪些部分分支、哪些能力需要原生

**数据通关** ---- 能处理令牌、缓存、离线、同步、重试、幂等、过期、退出清理和服务端最终授权

**性能通关** ---- 能在真机和低速网络下测量启动、首屏、列表、包体、内存与电量，并用证据完成至少一次优化

**质量通关** ---- 能建立设备矩阵，验证权限、前后台、系统中断、弱网、失败恢复和关键用户旅程，并让问题带着日志回家

**交付通关** ---- 能完成至少一个目标端的构建、签名、审核、发布、监控、更新和回滚演练

**uni-app 主线毕业** ---- 能把一个真实需求从页面、接口、数据和平台能力一路送到用户手里，并说清每个妥协是为什么

## 结语

uni-app 的正确打开方式不是迷信“一套代码到处飞”，而是把共性的业务流程、数据模型和 UI 经验复用起来，把平台差异集中管理，把原生能力按需下沉。这样它才是生产力，不是兼容性盲盒。

先用最小闭环验证目标平台，再补网络、状态、权限、性能和发布；遇到差异时先建立矩阵，再决定统一、降级还是分支。**多端开发的高手不是让所有平台长得一模一样，而是让用户在每个平台都觉得这应用挺懂事。**
