# 微信小程序学习路线

微信小程序不是“缩小版网页”，而是运行在微信生态里的平台应用。它用自己的视图、逻辑、网络、登录、支付、分享和审核规则，把用户从扫码或搜索一路带到业务闭环。

这条路线从平台模型和开发工具开始，进入 WXML、WXSS、页面生命周期、组件、setData、网络、登录、支付、云开发、性能、隐私、测试和发布。它是学习导航，不把每个微信 API 重新写成字典。

**路线定位** ---- 适合想快速触达微信用户、做工具、电商、内容、本地生活或小程序商业闭环的人

**推荐总顺序** ---- 平台模型 → 开发工具与三件套 → 页面和组件 → 数据通信 → 登录与平台能力 → 云开发或自建后端 → 性能 → 隐私安全 → 测试发布

**先记住一句话** ---- 小程序是平台大于框架；技术语法只是入场券，域名、包体、审核、登录、支付和隐私才是完整比赛

**本页怎么用** ---- 把粗体条目当作学习笔记索引，把每站验收当作项目关卡；先做工具类闭环，再挑战电商、支付和复杂业务

## 第一站：小程序平台与产品边界

第一站先了解微信为什么愿意让应用住在它里面。它带来流量、分享和支付，也带来包体、权限、审核和平台绑定；好处和约束是同一枚硬币的两面。

**小程序形态** ---- 区分工具、内容、电商、服务预约、社交、营销、小游戏和企业应用

**入口与场景** ---- 了解扫码、搜索、分享、群聊、公众号、服务通知、桌面、历史记录和场景值

**平台能力** ---- 认识登录、支付、分享、订阅消息、客服、地图、位置、相机、蓝牙、文件和订阅能力

**平台约束** ---- 关注主包、分包、域名、请求、上传、下载、审核、类目、隐私和用户授权

**与 H5 的差异** ---- 对照 DOM、Cookie、URL、缓存、线程、渲染、权限、登录态和发布机制

**与 uni-app 的差异** ---- 理解原生小程序的平台深度与 uni-app 的多端复用取舍

**产品验收** ---- 能为一个功能画出入口、页面、接口、权限、平台能力和审核材料清单

## 第二站：开发工具与项目三件套

第二站熟悉微信开发者工具和项目骨架。工具会帮你模拟手机，但真机、网络、权限与审核不会被模拟器永久代打。

**开发者工具** ---- 掌握项目创建、AppID、模拟器、真机预览、调试、上传、版本管理和体验版

**应用配置** ---- 理解全局页面注册、窗口、导航、TabBar、网络超时、权限、分包和插件配置

**页面目录** ---- 认识页面的 WXML、WXSS、逻辑文件与页面配置，建立页面、组件、公共工具的边界

**全局入口** ---- 学习应用启动、前后台、错误、分享、场景参数和全局数据的责任

**环境管理** ---- 区分开发、测试、预发布、生产、接口地址、测试账号、域名和公开配置

**工程规范** ---- 使用 TypeScript、模块、格式化、静态检查、依赖锁定、资源命名和提交规范

**多端工具协作** ---- 了解开发者工具、HBuilderX、CLI、CI 和后端联调工具如何分工

**骨架验收** ---- 能创建项目、注册页面、连接真机、查看日志、调用测试接口并完成体验版上传

## 第三站：WXML、WXSS 与页面组件

第三站学习小程序自己的 UI 语言。WXML 像 HTML 的亲戚，WXSS 像 CSS 的远房表亲，名字相近不代表可以直接交换身份证。

**WXML 模板** ---- 掌握数据绑定、条件、列表、模板、插槽、事件、事件对象和事件冒泡

**WXSS 样式** ---- 了解 rpx、选择器、样式隔离、继承、页面样式、组件样式和平台限制

**基础组件** ---- 认识 view、text、image、scroll-view、swiper、button、input、form、video 和 media

**表单交互** ---- 处理输入、焦点、键盘、校验、提交、密码、选择器、日期和重复点击

**组件化** ---- 掌握属性、数据、事件、插槽、外部样式、组件生命周期和组件通信

**列表与状态** ---- 设计加载、空、错误、分页、刷新、触底、骨架和重试

**响应式适配** ---- 适配不同屏幕、字体、暗色、横竖屏、安全区域和平板

**可访问性与体验** ---- 关注读屏、触控目标、颜色对比、反馈、动画和网络提示

**UI 验收** ---- 能做出列表、详情和表单，在真机、不同屏幕、字体与网络下保持可用

## 第四站：页面栈、生命周期与 setData

第四站理解小程序最有特色的运行模型。页面会进出栈，逻辑层和视图层要传数据，系统还可能在后台把你请出去；setData 不是普通赋值，它是一次跨层沟通。

**页面栈** ---- 掌握跳转、返回、重定向、重新启动、Tab 切换、页面参数和返回数据

**页面生命周期** ---- 关注加载、显示、初次渲染、隐藏、卸载、下拉刷新、触底和分享

**应用生命周期** ---- 处理启动、前后台、场景、冷启动、热启动和被系统回收后的重新进入

**setData 模型** ---- 理解逻辑层到视图层的数据更新、序列化、更新范围、频率和数据量成本

**数据更新策略** ---- 设计字段级更新、列表增量、不可变数据、批量更新和无关字段隔离

**页面通信** ---- 选择参数、事件、全局数据、缓存、页面返回和订阅消息的边界

**状态恢复** ---- 处理返回、Tab、分享、通知、进程回收、网络恢复和临时数据

**重复执行** ---- 防止 onShow 重复请求、重复监听、重复提交和重复初始化

**生命周期验收** ---- 完成列表、详情、编辑、返回刷新和前后台恢复，并能解释每次更新的成本

## 第五站：网络、本地存储与登录态

第五站把小程序接上服务端。微信不会给你一块万能 Cookie，也不会替你判断请求是否应该重试；登录、缓存和错误都要自己设计。

**wx.request 网络层** ---- 统一基础地址、Header、序列化、状态码、错误、请求 ID、超时和日志

**合法域名与 HTTPS** ---- 掌握 request、upload、download、socket 域名配置、证书、开发代理和生产限制

**请求状态** ---- 处理加载、成功、空、失败、超时、取消、重试、部分成功和离线

**登录流程** ---- 理解 wx.login、code、服务端换取身份、业务 Token、刷新、退出和多端绑定

**Cookie 与 Token** ---- 对照小程序限制、Storage、安全存储、过期、撤销和登录态恢复

**本地存储** ---- 区分缓存、设置、草稿、敏感数据、文件、数据库、清理和版本迁移

**上传下载** ---- 关注文件选择、大小、类型、临时路径、进度、后台、断点和失败恢复

**实时通信** ---- 了解 WebSocket、心跳、重连、顺序、重复、后台、订阅和离线消息

**接口契约** ---- 使用类型、Schema、错误码、分页、时间、金额和版本兼容

**网络验收** ---- 在慢网、断网、恢复、Token 过期、重复点击和服务端失败下保持界面可解释

## 第六站：微信生态能力

第六站进入小程序的“平台红利区”。登录、支付、分享和订阅消息很强，但每项能力都伴随资质、隐私、签名、回调和审核流程。

**用户登录** ---- 处理 code 换身份、匿名态、绑定手机号、用户资料、会话、退出和多端登录

**微信支付** ---- 理解服务端下单、签名、前端拉起、支付结果、回调验签、订单幂等、退款和沙箱

**分享与转发** ---- 设计卡片标题、路径、参数、群分享、朋友圈、内容安全和来源追踪

**订阅消息** ---- 了解模板、订阅时机、发送条件、次数、用户拒绝和合规触达

**客服与服务通知** ---- 规划客服入口、消息、通知、用户反馈和运营边界

**位置与地图** ---- 处理权限、用途声明、精度、地图组件、地理编码和隐私

**相机、相册与文件** ---- 关注授权、选择、压缩、临时文件、预览、上传和清理

**蓝牙与设备** ---- 了解蓝牙、扫码、NFC、传感器、设备连接、断开、重试和平台限制

**插件与第三方能力** ---- 管理插件、版本、权限、数据、依赖、审核和替代方案

**生态能力验收** ---- 至少完成登录或支付以外的一项平台能力，并处理拒绝、失败、重复回调和审核问题

## 第七站：云开发、自建后端与数据安全

第七站决定后端怎么落地。云开发可以加快小团队起步，但“免服务器”不等于“免架构”；权限、数据、成本和迁移仍会准时出现。

**云函数** ---- 理解触发、鉴权、超时、冷启动、依赖、日志、重试和成本

**云数据库** ---- 关注集合、索引、权限、事务、查询、分页、数据规模和迁移

**云存储** ---- 处理上传、下载、临时链接、访问控制、生命周期、清理和费用

**云调用与服务端** ---- 规划平台 API、身份、密钥、签名、回调和错误边界

**自建后端** ---- 了解 REST、GraphQL、认证、订单、支付、文件、队列和部署

**权限模型** ---- 区分用户、角色、组织、对象归属、服务身份和服务端最终校验

**数据安全** ---- 保护 Token、个人信息、支付信息、文件、日志和备份

**成本与供应商边界** ---- 估算调用、存储、流量、函数、数据库、迁移和平台绑定成本

**数据验收** ---- 能从小程序请求追到服务端、数据库、回调和日志，并能定位权限或数据一致性问题

## 第八站：性能、包体与弱网体验

第八站专门应对“开发工具里丝滑，真机里沉思”。小程序的包体、setData、首屏、图片和网络边界都很明确，最好提前认识。

**setData 性能** ---- 减少数据量、频率、层级和无关字段，使用增量更新与字段级更新

**主包与分包** ---- 规划主包、分包、独立分包、预下载、分包依赖和包体限制

**首屏加载** ---- 优化启动脚本、首屏请求、关键资源、骨架、缓存和延迟加载

**长列表** ---- 使用分页、虚拟化、回收、稳定键、分段渲染和滚动位置

**图片与媒体** ---- 处理尺寸、格式、压缩、CDN、懒加载、缓存、解码、视频和内存

**网络性能** ---- 合并请求、压缩响应、缓存、超时、重试、并发和断点

**渲染与交互** ---- 关注逻辑层、视图层、动画、滚动、输入、主线程和低端设备

**内存与资源** ---- 清理页面、监听器、定时器、WebSocket、临时文件和媒体资源

**性能工具** ---- 使用开发者工具性能面板、网络面板、真机调试、数据埋点和线上监控

**性能验收** ---- 在低端机、慢网、冷启动、长列表、分包和前后台恢复下对照测量

## 第九站：测试、隐私与安全

第九站把“平台能跑”升级成“用户敢用”。小程序的数据、权限、页面和发布流程都处于平台与用户的双重审视下。

**逻辑与组件测试** ---- 覆盖数据转换、状态、组件、表单、分页、错误和权限提示

**接口测试** ---- 验证登录、认证、分页、支付、回调、幂等、错误和契约

**真机测试** ---- 覆盖机型、系统、屏幕、字体、网络、权限、前后台和系统中断

**平台能力测试** ---- 验证分享、支付、订阅、地图、相机、文件、蓝牙和推送

**安全测试** ---- 关注越权、Token、敏感数据、URL、文件、输入、开放接口和第三方内容

**隐私合规** ---- 准备隐私政策、权限用途、个人信息清单、第三方 SDK、数据删除和用户同意

**测试数据** ---- 使用脱敏账号、测试订单、隔离环境、可重复种子和清理策略

**日志与监控** ---- 关联用户、页面、版本、场景、请求、错误和平台，同时避免记录敏感内容

**故障演练** ---- 注入断网、服务端失败、支付超时、重复回调、权限拒绝和分包加载失败

**质量验收** ---- 能复现问题、定位页面或后端边界，并给出设备、版本和请求证据

## 第十站：审核、发布与持续运营

最后一站把小程序送进微信生态。体验版、审核版和线上版各有职责，发布后还要看数据、处理审核、灰度和紧急回退。

**版本流程** ---- 理解开发、体验、审核、线上、灰度、回退和版本留存

**审核材料** ---- 准备类目、资质、隐私政策、测试账号、功能说明、支付和内容合规

**域名与配置** ---- 管理 request、上传、下载、WebSocket 域名、环境、密钥和公开配置

**分包与资源** ---- 在发布前检查主包、分包、图片、字体、插件和平台限制

**灰度与回滚** ---- 设计小范围发布、版本监控、停发、回退、接口兼容和数据修复

**运营能力** ---- 关注访问、转化、留存、分享、支付、订阅、崩溃、接口错误和审核反馈

**CI/CD** ---- 自动完成检查、构建、上传、版本、审核材料和发布记录

**平台政策** ---- 持续关注隐私、支付、内容、广告、登录、数据和插件政策变化

**发布验收** ---- 能完整走一遍提审、发布、监控、问题回退和用户反馈处理

## 学习路径与项目主线

**第一阶段：工具小程序** ---- 做一个查询、记账、清单或内容工具，跑通页面、网络、存储和真机

**第二阶段：业务闭环** ---- 加入登录、分页、表单、文件、分享、订阅消息或云开发

**第三阶段：商业能力** ---- 接入支付、订单、回调、幂等、权限、客服和运营数据

**第四阶段：产品化** ---- 完成分包、性能、隐私、测试、审核、灰度、监控和回滚

**多端分支** ---- 进入 [uni-app](/learning-paths/mobile/uniapp)，对照原生小程序与多端编译的边界

**进阶分支** ---- 深入插件、蓝牙、WebSocket、Worker、地图、音视频、云开发和平台开放能力

## 通关标准

**平台通关** ---- 能解释 WXML、WXSS、页面栈、生命周期、逻辑层、视图层和 setData

**应用通关** ---- 能完成登录、列表、详情、表单、请求、本地存储、分页和错误处理

**生态通关** ---- 能处理分享、登录、支付、订阅、文件或地图中的至少一组平台能力

**性能通关** ---- 能优化 setData、首屏、长列表、图片、分包、弱网和包体

**安全通关** ---- 能处理权限、隐私、Token、越权、文件、输入和第三方能力风险

**交付通关** ---- 能完成真机验证、体验版、审核、线上发布、监控、灰度和回滚

**微信小程序主线毕业** ---- 能把一个微信内产品从入口做到发布，让平台约束变成产品边界而不是临时事故

## 结语

微信小程序的核心价值，是把开发、传播、登录、支付和服务放进同一套生态入口；它的学习重点，则是把平台约束提前变成设计的一部分。

先做一个能真机运行、能处理弱网、能完成发布的工具，再挑战支付和复杂业务。**小程序不是少做一层工程，而是把工程规则换成了微信的方言。**
