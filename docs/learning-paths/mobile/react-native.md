# React Native 学习路线

React Native 用 JavaScript 和 React 描述界面，再把组件交给 iOS 与 Android 的原生侧渲染。它不是把网页套进手机壳里，而是让前端团队通过一套 React 心智进入移动应用；代价是 JavaScript、原生 UI、通信边界和两个系统的差异都要同时照顾。

这条路线从 React 和 JavaScript 地基出发，依次进入 RN 组件、布局、导航、状态、网络、本地数据、原生模块、性能、测试、Expo 与发布。它是知识索引，不把 Hooks、组件属性和每个库的 API 再抄一遍。

**路线定位** ---- 适合已有 React 或前端背景，想快速交付 iOS 与 Android 应用，并愿意在必要时补原生能力的人

**推荐总顺序** ---- React 与 TypeScript → RN 运行模型 → 核心组件与布局 → 导航与状态 → 网络与本地数据 → 原生能力 → 新架构与性能 → 测试 → 构建发布

**先记住一句话** ---- RN 的优势是复用和生态，不是“从此不需要原生”；遇到权限、推送、支付、性能和系统生命周期，原生知识会准时敲门

**本页怎么用** ---- 把粗体条目当作后续学习笔记标题，把每站验收当作项目关卡；先用 Expo 建立闭环，再决定是否深入原生工程

## 第一站：React、JavaScript 与 TypeScript 地基

第一站先确认自己会 React，而不是只会把组件复制到页面里。RN 会把 Web 中被浏览器照顾的许多细节交回给你，类型和状态边界越清楚，跨平台生活越少惊喜。

**JavaScript 语言** ---- 掌握模块、异步、Promise、闭包、对象、数组、错误、事件循环和资源生命周期

**TypeScript** ---- 学习接口、联合、泛型、类型守卫、事件类型、API 模型和运行时校验，类型系统不能替代服务端验证

**React 心智** ---- 理解组件、Props、State、Hooks、Context、组合、渲染、重建和副作用边界

**单向数据流** ---- 设计事件输入、状态输出、派生状态和异步副作用，避免组件互相修改内部秘密

**不可变性与引用** ---- 关注对象身份、浅比较、记忆化、列表键和状态更新对重渲染的影响

**错误与边界** ---- 处理异常、错误边界、加载、空、失败、重试、取消和用户反馈

**工程工具** ---- 了解 Node.js、包管理、依赖锁定、ESLint、格式化、测试、Git 和环境变量

**React 地基验收** ---- 能独立解释状态、Effect、组件身份和异步更新，并用 TypeScript 建立一套可维护的页面模块

## 第二站：RN 运行模型与开发工具链

第二站认识 RN 与 Web 的分界线。没有 DOM、HTML 和完整 CSS，界面会经过 JavaScript、RN 运行时和原生平台的接力；知道接力棒在哪，排障才不会靠猜。

**Expo 工作流** ---- 掌握项目创建、开发服务器、真机预览、模拟器、开发构建、配置插件和云构建的定位

**裸 React Native 工程** ---- 了解 iOS、Android 原生目录、Xcode、Gradle、原生依赖和何时需要直接修改原生工程

**JavaScript 与原生** ---- 理解 JS 运行时、原生渲染、通信、序列化、线程和模块加载

**新架构** ---- 认识 JSI、Fabric、Turbo Modules、Codegen、同步或异步边界与旧桥接模型的差异

**项目结构** ---- 规划页面、组件、导航、状态、网络、存储、平台实现、原生模块、资源和测试目录

**平台配置** ---- 管理应用标识、图标、启动页、权限、深链接、环境、构建变体和原生配置

**调试工具** ---- 使用 Metro、日志、断点、React DevTools、Flipper 或平台原生调试器定位问题

**工程验收** ---- 能在模拟器和真机运行项目，知道问题属于 JavaScript、RN 运行时、iOS、Android 还是第三方库

## 第三站：核心组件、布局与无障碍

第三站开始搭 UI。RN 的组件像一套移动端积木，积木不多但每块都有平台脾气；尤其要记住，RN 的 Flexbox 默认方向和 Web 不同。

**核心组件** ---- 掌握 View、Text、Image、TextInput、Pressable、SafeArea、Modal、Activity Indicator 和原生平台组件

**布局系统** ---- 理解 Flexbox、尺寸、边距、定位、逻辑像素、像素比、测量、最小最大尺寸和安全区域

**样式系统** ---- 了解 StyleSheet、平台样式、动态样式、主题、暗色、字体、阴影、圆角和样式复用

**长列表** ---- 使用 FlatList、SectionList、虚拟化、稳定键、分页、分组、吸顶、空状态、下拉刷新和触底加载

**图片与媒体** ---- 处理尺寸、格式、缓存、解码、占位、失败、视频、音频焦点和内存峰值

**表单与键盘** ---- 关注输入法、焦点、键盘顶起、校验、提交、密码、自动填充和重复提交

**触摸与手势** ---- 学习 Pressable、Gesture Handler、手势冲突、拖拽、滑动、缩放、长按和触觉反馈

**响应式布局** ---- 适配不同尺寸、横竖屏、平板、折叠设备、动态字体和低端设备

**可访问性** ---- 关注 VoiceOver、TalkBack、语义、标签、焦点、对比度、触控目标和减少动画

**UI 验收** ---- 能在不同尺寸、字号、方向、主题和系统辅助功能下完成核心页面操作

## 第四站：导航、状态与应用生命周期

第四站处理页面流转和状态归属。移动端用户会从通知、分享、深链接和系统恢复进入应用，导航不能只为“从首页点到详情”服务。

**React Navigation** ---- 理解 Stack、Tab、Drawer、嵌套导航、返回栈、参数、返回值和导航生命周期

**深链接与外部入口** ---- 处理 Universal Links、App Links、URL Scheme、通知、分享和冷启动参数

**状态分类** ---- 区分组件、页面、全局客户端、服务端缓存、持久化、临时任务和派生状态

**Context 与状态库** ---- 了解 Context、Zustand、Redux Toolkit、Jotai、服务端状态库和按规模选型

**数据流设计** ---- 组织事件、状态、请求、缓存、乐观更新、回滚、错误和一次性消息

**应用生命周期** ---- 关注冷启动、热启动、前台、后台、挂起、进程终止、通知恢复和重复初始化

**页面恢复** ---- 处理返回、Tab 切换、系统回收、旋转、网络恢复和未完成任务

**资源释放** ---- 管理订阅、定时器、WebSocket、定位、相机、动画和原生对象

**架构边界** ---- 让 UI、领域、数据、平台和基础设施可以分别替换与测试

**导航验收** ---- 完成登录、列表、详情、编辑、通知唤起和返回刷新，并处理失效参数和未登录跳转

## 第五站：网络、本地数据与离线

第五站让 RN 应用和服务端合作。移动网络会断，应用会进后台，用户会重复点击；网络层要比按钮更有耐心。

**网络客户端** ---- 规划 fetch 或 Axios、基础地址、Header、序列化、请求 ID、日志、拦截器和错误映射

**请求状态** ---- 处理加载、成功、空、失败、超时、取消、重试、部分成功和离线

**认证与令牌** ---- 设计登录、刷新、退出、多设备、第三方登录、安全存储、撤销和过期

**本地存储** ---- 比较 AsyncStorage、MMKV、SecureStore、Keychain、Keystore、SQLite、Realm 和文件

**数据库与迁移** ---- 关注模型、索引、事务、版本、迁移、并发、损坏和清理

**缓存策略** ---- 处理内存、磁盘、服务端缓存、过期、刷新、脏数据和回滚

**离线优先** ---- 设计离线查看、草稿、操作队列、同步、冲突、版本、幂等和网络恢复

**上传下载** ---- 关注文件权限、进度、后台、断点、分片、临时路径和磁盘空间

**实时能力** ---- 了解 WebSocket、心跳、断线、重连、顺序、重复、离线消息和多端同步

**数据验收** ---- 在慢网、断网、恢复、令牌过期和重复提交下保持状态可信

## 第六站：原生组件、权限与平台扩展

第六站面对 RN 的边界。现成库能省时间，但版本、权限、原生配置和两端差异不会因为包管理器点了安装就自动消失。

**Expo Modules** ---- 了解 Expo 的相机、相册、定位、通知、文件、设备、更新和构建模块

**原生模块** ---- 理解 Swift、Objective-C、Kotlin、Java 模块的接口、参数、返回、线程、错误和生命周期

**Turbo Modules 与 Codegen** ---- 认识类型化原生接口、代码生成、同步调用边界和新架构迁移

**权限流程** ---- 处理相机、相册、定位、蓝牙、通知、麦克风、生物识别的申请、拒绝、永久拒绝和降级

**系统能力** ---- 覆盖推送、分享、支付、地图、蓝牙、NFC、传感器、后台任务、Widget 和文件关联

**平台差异** ---- 记录 Android 与 iOS 在权限、生命周期、文件、推送、通知、返回和后台上的差异

**第三方 SDK** ---- 管理登录、支付、地图、统计、崩溃、广告和媒体 SDK 的版本、隐私与构建配置

**安全边界** ---- 保护令牌、深链接、WebView、原生日志、IPC、用户文件和远程配置

**原生验收** ---- 至少完成一项权限型能力，并验证拒绝、不可用、版本不支持、系统回收和重复回调

## 第七站：性能、Hermes 与动画

第七站回答“为什么列表滑起来像在读幻灯片”。RN 性能要同时看 JS 线程、UI 线程、渲染、通信、图片、内存和原生模块。

**Hermes 运行时** ---- 了解字节码、启动、内存、垃圾回收、调试和不同运行时的取舍

**JS 线程与 UI 线程** ---- 区分业务计算、布局、动画、触摸、原生渲染和跨线程通信

**重渲染优化** ---- 关注组件拆分、稳定引用、React.memo、派生数据、列表键和状态范围

**列表性能** ---- 优化 FlatList 的窗口、批量、预取、图片、分页、回收和大数据集

**动画性能** ---- 学习 Reanimated、工作线程、手势、布局动画、帧预算和复杂动画降级

**图片与内存** ---- 处理大图解码、缓存、缩略图、预加载、页面销毁和内存警告

**通信性能** ---- 减少高频小消息、大对象序列化、桥接往返和原生模块重复调用

**启动与包体** ---- 优化初始化、依赖、代码分割、资源、字体、应用更新和首屏

**性能工具** ---- 使用 RN 性能监视器、Hermes 分析、Android Profiler、Instruments、Flipper 和真实设备

**性能验收** ---- 在低端机、长列表、弱网、冷启动、后台恢复和长时间运行下用指标证明优化

## 第八站：测试、调试与发布

第八站让 RN 应用从“我手机上能跑”升级成“别人手机上也有证据”。测试要覆盖 JavaScript、组件、导航、原生能力、安装包和更新。

**单元测试** ---- 覆盖纯逻辑、状态机、解析、权限决策、重试、同步和错误

**组件测试** ---- 验证渲染、点击、输入、滚动、键盘、加载、空、失败和可访问性

**导航测试** ---- 检查参数、深链接、登录拦截、返回、通知入口和状态恢复

**原生集成测试** ---- 验证相机、定位、推送、文件、支付、分享和权限状态

**端到端测试** ---- 覆盖注册、登录、列表、编辑、上传、离线、恢复和退出

**设备矩阵** ---- 按系统版本、厂商、屏幕、架构、语言、主题、网络和低端设备选择覆盖

**构建与更新测试** ---- 验证开发包、生产包、签名、覆盖安装、数据迁移、热更新和失败回退

**崩溃与日志** ---- 关联版本、设备、页面、请求、原生堆栈和用户动作，严格脱敏

**Expo EAS** ---- 了解云构建、凭据、内测、商店提交、更新渠道和构建产物

**发布验收** ---- 至少完成一个平台的构建、签名、内测、监控、更新和回滚演练

## 学习路径与项目主线

**第一阶段：RN 页面** ---- 用 Expo 做静态页面、表单、列表和导航，先适应没有 DOM 的移动 UI

**第二阶段：完整应用** ---- 加入 TypeScript、状态、网络、登录、本地数据、分页、错误和离线

**第三阶段：原生能力** ---- 接入相机、定位、通知、文件或支付，记录两端配置与权限差异

**第四阶段：生产交付** ---- 做性能分析、自动化测试、EAS 构建、内测、商店发布和更新监控

**进阶分支** ---- 深入新架构、Fabric、Turbo Modules、Codegen、原生模块、Reanimated、React Native for Web 和桌面延伸

## 通关标准

**基础通关** ---- 能解释 RN 与 Web React 的组件、样式、运行时、线程和通信差异

**应用通关** ---- 能用 Expo、RN 和 TypeScript 完成登录、列表、详情、表单、网络和本地数据

**原生通关** ---- 能处理至少一项权限型系统能力，并能在必要时定位到原生配置或模块

**性能通关** ---- 能分析 JS 线程、UI 线程、列表、图片、动画、启动和内存问题

**质量通关** ---- 能建立组件、集成、端到端、真机、权限、离线和更新测试

**交付通关** ---- 能用 EAS 或原生工具完成构建、签名、内测、发布、监控和回滚

**React Native 主线毕业** ---- 能用前端效率交付移动产品，也知道什么时候该请原生代码出场

## 结语

React Native 的爽点，是 React 团队可以少学一套 UI 语言就进入移动端；它的功课，是别把“跨平台”误读成“平台差异不存在”。

先用 Expo 跑通闭环，再深入导航、数据、权限、原生模块和性能；**效率让你更快出发，原生边界意识让你最终到达。**
