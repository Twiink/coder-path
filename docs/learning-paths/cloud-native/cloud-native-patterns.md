# 云原生模式学习路线

**云原生(Cloud Native)不是"把应用塞进容器"**,CNCF 的定义是:**容器化 + 微服务 + 动态编排 + 自动化**——它是一整套"应用如何设计、开发、部署、运维才能长在云上"的方法论。前面各页给了技术组件(容器/K8s/可观测/CI),本页把它们**收敛成设计模式**:12-Factor 应用、健康检查、配置外部化、优雅启停、弹性(重试/熔断/限流/隔离)、可观测、安全纵深、成本治理——**这些模式是"生产就绪云原生应用"的检查清单**。学完它,你写应用时会自带"云原生视角":这不是部署方式,是设计起点。

这条线按 **12-Factor 应用 → 健康检查 → 配置与密钥管理 → 优雅启动与关闭 → 弹性模式 → 可观测性 → 安全模式 → 成本与多租户 → 组织实践** 推进。

## 第一站:12-Factor 应用——云原生应用的"十诫"

12-Factor(Heroku 提出的 SaaS 应用方法论)是云原生的思想源头,**逐条消化(建议对照自己项目逐条打勾)**:①**基准代码**:一个应用一个代码库、多环境共享;**发布 = 不可变制品(镜像),不是"代码+手工步骤"**;②**依赖**:显式声明(package.json/go.mod)+ **锁定版本(lock 文件)**——不隐式依赖系统包;③**配置外部化**:配置(数据库地址/密钥/开关)进**环境变量或配置中心**,不进代码不进镜像——**同一镜像跑遍 dev/prod 全靠它**(呼应 [Docker](/learning-paths/devops/docker) 与 K8s ConfigMap);④**后端服务可替换**:数据库/缓存/消息队列都是"附加资源",**通过配置切换、不通过改代码**(本地 MySQL → 生产 RDS 只换连接串);⑤**构建-发布-运行严格分离**:构建(出不可变镜像)→ 发布(镜像+配置=带版本号的发布)→ 运行(实例;运行期不改任何东西——**要改就重新发布,这是可回滚的前提**);⑥**无状态进程**:进程不存会话与文件——**状态外置**(Session 进 Redis、上传直连对象存储);无状态才能随意水平伸缩与替换(呼应 K8s 的"Pod 是牲口");⑦**端口绑定**:应用自包含(自带 Web 服务器),通过 PORT 环境变量监听——不依赖外部容器;⑧**并发**:用**进程模型**扩展(web/worker/定时任务分离),水平扩展 = 加实例;⑨**易处理**:快速启动 + 优雅关闭 + 崩溃可承受(见第三站);⑩**开发生产等价**:尽量缩小环境差异(容器统一、后端服务同款、CI 即部署通道)——"在我机器上能跑"的终结;⑪**日志即事件流**:应用只往 **stdout 写结构化日志**,存储/检索是采集层的事(呼应 [Docker](/learning-paths/devops/docker) logs 与 [监控](/learning-paths/devops/monitoring) 日志章);⑫**管理进程**:数据库迁移/一次性脚本与主代码**同库同环境**运行(K8s Job/CronJob 的天然场景)。**心智:12-Factor 不是教条,是"为什么云上应用长这样"的答案**——每条背后都是可伸缩/可替换/可回滚的工程诉求。

## 第二站:健康检查——生产就绪的第一关

**三探针(与 [K8s](/learning-paths/devops/kubernetes) 页对应,这里讲"端点怎么设计")**:liveness(我活着吗——**只查进程自身健康,别查依赖**:数据库挂了重启我也没用,还会放大故障)/readiness(我能接流量吗——**查关键依赖+初始化完成**:DB/缓存连通、连接池预热、缓存加载完;失败=从负载均衡摘除,不重启)/startup(慢启动保护:Java/重型应用启动要 1 分钟,先让 startup 兜住,别让 liveness 误杀)。**端点设计规范**:`/healthz`(liveness:轻量自检,毫秒级)、`/readyz`(readiness:ping 依赖)、`/info` 或 `/version`(返回版本/commit——**排障第一问"线上跑的是哪个版本"**);**反模式**:健康检查里递归调用下游健康检查(级联放大)、检查耗时超时(健康检查自己变成压力源——**加超时与结果缓存**)、不检查就报 200(形同虚设)。**心智:健康检查是编排器的眼睛**——探针写对,滚动更新/自愈/流量摘除才不出妖蛾子。

## 第三站:配置与密钥管理

**配置分层与优先级**:代码默认值 < 配置文件 < 环境变量 < **配置中心(Apollo/Nacos/Spring Cloud Config/自研)**;配置中心的附加价值:**热更新(推送后进程优雅重载,不重启)、版本与回滚、灰度配置(先刷部分实例观察)、审计**——**"配置即代码"与"配置可运行时变更"并存**。**特性开关(Feature Flags,容易被忽略的十二因素+1)**:把"功能"也变成可运行时配置——**发布代码 ≠ 发布功能**:新功能默认关,按用户/百分比灰度开启,出问题一键关(紧急开关)——平台:Unleash/LaunchDarkly/自研(**原理极简:配置查开关,别过度设计**)。**密钥管理与普通配置分离(红线)**:K8s Secret(静态,base64 非加密——配 etcd 加密)、**Vault/云 Secrets Manager(动态密钥/自动轮换/审计)**——密钥不进代码、不进镜像、不进日志;**设计**:应用启动时从密钥服务拉取,内存使用。

## 第四站:优雅启动与优雅关闭——对用户的尊重

**优雅启动**:等依赖就绪(重试而非启动即崩——数据库在滚动更新中可能还没起好)、预热(连接池/缓存)、**readiness 通过后才接流量**(K8s 滚动更新的节奏靠它)。**优雅关闭(线上事故高发区,重点背流程)**:K8s 要删 Pod 时 → ①发 SIGTERM;**应用收到后**:停止接收新请求(在途的继续)②**等待在途请求完成(设上限:超过宽限期的请求会被掐)**,消息消费者:处理完当前消息再停(别丢消息)③关闭连接池/释放资源 ④进程退出;**宽限期默认 30 秒**,超时未退 SIGKILL 强杀——**语言侧**:process.on('SIGTERM')/signal.Notify/Spring 的优雅关闭配置;**配合 K8s**:preStop hook(延迟几秒,等 Service 端点摘除)+ readiness——**零停机部署 = 滚动更新 + 就绪探针 + 优雅关闭三者咬合**;信号处理陷阱:容器里 PID1 的信号转发(shell 启动的进程收不到 SIGTERM——**用 exec 形式直接跑应用**)。**心智:不优雅关闭的账单**——用户请求被掐(报错)、消息丢失(数据不一致)、连接未释放(雪崩)——"优雅"是云原生对每个进程的最低要求。

## 第五站:弹性模式——防止级联失败

**微服务越多,故障概率越高——弹性的目标是"一个挂不拖垮一片"**:**①超时(第一道防线,处处必须有)**:连接/读/总超时三件套;原则:**下游超时 < 上游超时**(A 调 B 的超时要比用户等 A 的超时短,否则用户等死);传递 deadline(Go context/Java 的 timeout 传播)——**没有超时的调用是雪崩的引信**。**②重试(治"抖动")**:只重试**幂等操作与可重试错误**(网络超时/5xx;4xx 永不重试);指数退避 + 抖动(同时重试=惊群);**上限(3-5 次)——无上限重试 + 下游故障 = 自我雪崩**。**③熔断(治"故障中")**:状态机 closed → open(错误率/慢调用超阈值)→ half-open(冷却后放少量试探流量)→ 恢复或再断开——**熔断让重试不再火上浇油:下游挂了,快速失败而不是反复试探**;库:Resilience4j/Sentinel(Java)、go-resiliency;实现:自己写一个也不难(三个状态+计数器),但生产用成熟库(统计/线程安全)。**④限流(治"过载")**:令牌桶(允许突发)/漏桶(匀速)/窗口计数;分布式限流 Redis/网关(见 [Nginx](/learning-paths/middleware/nginx) 与 [Redis](/learning-paths/database/redis));**位置:入口网关限外部,关键服务自保限内部**(防上游 bug 打爆你)。**⑤降级(治"部分不可用")**:依赖挂了给**默认值/缓存/降级文案**,别整个功能 500——"优雅降级优于硬失败"是互联网产品的共识;熔断触发时顺手降级(缓存兜底)。**⑥隔离/Bulkhead(治"慢邻居")**:线程池/信号量**按依赖分组**(支付慢不占光商品查询的线程)、连接池隔离、资源配额(呼应 K8s requests/limits)——**"舱壁"思想:船的一个舱进水,不沉整艘**。**组合拳心智**:超时兜底 → 重试扛抖动 → 熔断停试探 → 限流防过载 → 降级保体验 → 隔离防蔓延——**这六件套是"微服务韧性"的完整答案**(实现可参考 [微服务模式](/learning-paths/microservices/microservices-patterns) 的可靠性章与 [服务网格](/learning-paths/cloud-native/service-mesh) 的平台化)。

## 第六站:可观测性——设计出来,不是后补

**云原生可观测三支柱(回顾 [监控](/learning-paths/devops/monitoring) 页,这里讲"应用侧义务")**:①**结构化日志**:JSON + 标准字段(时间/级别/服务/**traceId**/userId)——**日志要能被机器检索,裸文本是给后补挖的坑**;②**指标**:暴露 /metrics(RED:QPS/错误/延迟直方图 + 业务指标),Prometheus 抓——**应用埋点是黄金信号的唯一来源(网格只能给网络视角)**;③**追踪**:接入 **OpenTelemetry**(统一 SDK:自动/手动埋点产出 trace),traceId 贯穿日志与追踪——**排障 = 从告警 → 指标 → traceId → 日志 一条线走到底**。**告警设计**:分级(P0 页面级/P1 邮件/P2 工单)、聚合防风暴、可行动(每条告警写明"看哪里")、On-call 轮换与事后复盘——**可观测的终点是"快速定位",不是"更多面板"**。

## 第七站:安全模式——纵深防御

**云原生攻击面比传统更大(镜像/编排/网络/密钥),按层防御**:①**镜像层**:最小基础镜像、多阶段、漏洞扫描(CI 里 trivy)、**非 root 运行**、镜像签名;②**运行时**:只读根文件系统、cap 最小化、Pod 安全限制(见 [K8s](/learning-paths/devops/kubernetes) 安全章);③**网络层**:**NetworkPolicy 默认拒绝 + 白名单**(服务间最小连通)、入口 TLS;**服务间加密与身份:网格 mTLS 或框架级(见 [服务网格](/learning-paths/cloud-native/service-mesh))**;④**密钥层**:Vault/云 Secrets Manager(见第三站);⑤**身份与权限**:云 IAM/K8s RBAC/应用内授权三处最小权限——**默认拒绝、显式授权**是云原生安全的统一姿势(零信任)。**安全左移**:扫描与策略进 CI(见 [GitHub Actions](/learning-paths/devops/github-actions) 与 GitLab CI 的安全模板),而不是上线后补。

## 第八站:成本与多租户(FinOps)

**成本是云原生的"第四可观测性"**:资源配准(requests/limits 靠压测不靠猜——见 [K8s](/learning-paths/devops/kubernetes) 资源章)、**自动伸缩(HPA/VPA/Cluster Autoscaler/KEDA(事件驱动伸缩))按需付费**、**Spot 实例(60-90% 折扣:无状态/批处理用,必须优雅处理中断通知)**、标签与成本分摊(云账单按团队分)、预算告警、**"按量计费思维":Serverless 与托管服务按需选**(见 [Serverless](/learning-paths/cloud-native/serverless))。**多租户共享集群**(省钱但要有纪律):命名空间隔离 + ResourceQuota/LimitRange + NetworkPolicy + 成本标签——**共享的是资源,隔离的是故障与账单**。

## 第九站:组织与实践——云原生的第三层

**技术(容器/K8s/CI)是最好学的一层;真正的分水岭在流程与文化**:①**小步发布**(CI 门禁 + 滚动/金丝雀 + 快速回滚——发布频率是团队信心的标尺);②**DevOps 一体化**(开发对自己代码的线上行为负责——on-call 轮换逼出"可观测与优雅"的自觉);③**平台工程**(服务多了,把"环境/CI/可观测"沉淀成内部开发者平台(IDP)——团队自助,平台团队维护);④**不可变基础设施**(镜像与 IaC 是唯一变更途径,服务器不手工改——见 Terraform/Ansible 方向);⑤**混沌工程**(定期故障演练验证弹性设计——Chaos Mesh,进阶)。**一句话:云原生 = 技术容器化 × 流程自动化 × 文化共担责任**——三者缺一,上云只是"搬进虚拟机"。

## 通关标准

能独立做到:拿自己项目对照 12-Factor 逐条打分并说出改哪几条收益最大;写出规范的 /healthz、/readyz、/info 端点并说清 liveness 为什么不查数据库;实现一次完整的优雅关闭(信号处理+在途请求+资源清理+宽限期)并在 K8s 里验证零停机滚动;给服务配上"超时→重试(退避+上限)→熔断→降级"四件套并能讲清每层防什么;日志带上 traceId、指标暴露 RED 并通过 OTel 接上追踪;说出"默认拒绝"在镜像/网络/权限三个层面的落地——云原生模式主线通关。

云原生模式的本质是**把"可靠性"从英雄主义变成工程默认值**:健康检查、优雅关闭、熔断降级、可观测——每一条都是"为故障而设计"。学它的最佳方式不是背模式名,而是**让每个模式对应一次你经历过的线上事故**(发布中断请求?→优雅关闭;一个慢接口拖垮全站?→超时与隔离)——模式是事故的疫苗。把本页和 [K8s](/learning-paths/devops/kubernetes)、[监控](/learning-paths/devops/monitoring)、[微服务](/learning-paths/microservices/microservices-patterns) 三页连起来读,你就拥有了完整的云原生世界观。下一步:补 [微服务模式](/learning-paths/microservices/microservices-patterns) 或 [IaC(Terraform)] 把基础设施也代码化。
