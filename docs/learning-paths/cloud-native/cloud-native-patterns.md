# 云原生模式学习路线

云原生不仅仅是容器和 Kubernetes，更是一套设计理念和最佳实践。从 12-Factor 到健康检查，从配置外部化到优雅关闭，这些模式帮助我们构建弹性、可扩展、易维护的云原生应用。这条路线会带你了解云原生的核心模式、设计原则、实践方法，以及如何构建真正的云原生应用。

## 基础篇：12-Factor App

### 1. 基准代码（Codebase）
- 一个应用一个代码库：版本控制
- 多环境部署：开发、测试、生产共享代码库
- 分支策略：主干开发、特性分支、发布分支
- 单体仓库 vs 多仓库：根据团队和规模选择

### 2. 依赖（Dependencies）
- 显式声明：package.json、pom.xml、go.mod、requirements.txt
- 依赖隔离：不依赖系统级软件包
- 锁定版本：lock 文件、精确版本号
- 私有依赖：私有仓库、企业 Nexus/Artifactory

### 3. 配置（Config）
- 环境变量：DATABASE_URL、API_KEY、REDIS_HOST
- 配置外部化：不写在代码里、不提交到版本控制
- 敏感信息：Secrets Manager、Vault、Kubernetes Secret
- 多环境：开发、测试、生产使用不同配置

### 4. 后端服务（Backing Services）
- 视为附加资源：数据库、缓存、消息队列、对象存储
- 可替换性：通过配置切换、不修改代码
- 服务绑定：URL/连接字符串配置化
- 本地与远程：开发本地 MySQL、生产 RDS

### 5. 构建、发布、运行（Build, Release, Run）
- 严格分离：构建镜像 → 注入配置 → 运行容器
- 构建阶段：编译、打包、生成不可变制品
- 发布阶段：制品 + 配置 = 发布版本
- 运行阶段：启动进程、不可修改
- 版本管理：每个发布版本唯一 ID

### 6. 进程（Processes）
- 无状态：不依赖内存或磁盘状态
- 进程无记忆：重启后状态丢失
- Session 外部化：Redis Session Store
- 文件上传：直接到对象存储、不经过应用
- 水平扩展：无状态进程可随意增减

### 7. 端口绑定（Port Binding）
- 自包含：应用内嵌 Web 服务器
- 导出服务：通过端口对外提供服务
- 不依赖外部服务器：不需要 Apache、Nginx 启动
- 环境变量：PORT=8080、监听指定端口
- 容器化：每个容器暴露自己的端口

### 8. 并发（Concurrency）
- 进程模型：通过进程扩展
- 水平扩展：增加实例数量
- 进程类型：Web 进程、Worker 进程、定时任务进程
- 负载均衡：多实例分担流量
- 单一职责：每个进程做一件事

### 9. 易处理（Disposability）
- 快速启动：最小化启动时间
- 优雅关闭：SIGTERM 信号、完成当前请求、断开连接
- 健壮性：进程突然终止不影响系统
- 无状态优势：进程可随时创建和销毁
- 弹性伸缩：快速响应负载变化

### 10. 开发环境与生产环境等价（Dev/Prod Parity）
- 时间差距：持续部署、缩短发布周期
- 人员差距：开发者参与运维、DevOps
- 工具差距：开发和生产使用相同的后端服务
- 容器化：Docker 保证环境一致性
- 基础设施即代码：Terraform、CloudFormation

### 11. 日志（Logs）
- 事件流：日志视为事件流
- 无日志路由：应用不管日志存储和路由
- 输出到 stdout/stderr：容器捕获标准输出
- 日志聚合：ELK、Loki、CloudWatch
- 结构化日志：JSON 格式、方便查询

### 12. 管理进程（Admin Processes）
- 一次性任务：数据库迁移、脚本执行
- 与应用代码同步：同一代码库、同一环境
- REPL：交互式 shell、调试
- 定时任务：Cron Job、Kubernetes CronJob
- 幂等性：可重复执行、结果一致

## 进阶篇：健康检查与探针

### 存活探针（Liveness Probe）
- 作用：检测应用是否存活
- 失败处理：重启容器
- 检查方式：HTTP GET、TCP Socket、Exec 命令
- 配置：初始延迟、间隔、超时、失败阈值
- 示例：GET /healthz 返回 200

### 就绪探针（Readiness Probe）
- 作用：检测应用是否准备好接收流量
- 失败处理：从负载均衡中移除
- 启动时：等待依赖服务、数据库连接、缓存预热
- 运行时：检查依赖服务、数据库、队列连接
- 示例：GET /ready 返回 200

### 启动探针（Startup Probe）
- 作用：检测应用是否启动完成
- 慢启动应用：允许更长的启动时间
- 失败处理：重启容器
- 与存活探针配合：启动完成后交给存活探针
- Kubernetes 1.16+

### 健康检查最佳实践
- 轻量级：检查不应消耗大量资源
- 快速响应：避免超时
- 依赖检查：检查关键依赖（数据库、缓存）
- 避免级联失败：不要递归检查下游服务
- 版本信息：/version 端点返回版本信息

## 进阶篇：配置管理

### 配置层级
- 默认配置：代码中的合理默认值
- 环境变量：运行时配置
- 配置文件：本地开发、测试
- 配置中心：Apollo、Nacos、Spring Cloud Config
- 优先级：环境变量 > 配置文件 > 默认值

### 敏感信息管理
- Kubernetes Secret：Base64 编码、etcd 加密
- HashiCorp Vault：动态密钥、密钥轮换
- AWS Secrets Manager：自动轮换、审计日志
- Azure Key Vault：托管密钥管理
- 环境变量注入：不写入磁盘、内存读取

### 配置热更新
- 配置监听：文件变化、配置中心推送
- 动态刷新：无需重启、实时生效
- 优雅更新：平滑切换、不中断服务
- 配置版本：回滚、审计
- 灰度配置：部分实例先更新

### 特性开关（Feature Flags）
- 功能开关：运行时启用/禁用功能
- 灰度发布：部分用户先体验
- A/B 测试：不同用户不同功能
- 紧急开关：快速关闭问题功能
- 平台：LaunchDarkly、Unleash、自研

## 进阶篇：优雅启动与关闭

### 优雅启动
- 依赖检查：启动时检查数据库、缓存连接
- 资源预热：连接池、缓存预加载
- 延迟注册：启动完成后才注册到服务发现
- 就绪探针：告知 Kubernetes 准备就绪
- 启动超时：防止启动卡死

### 优雅关闭
- SIGTERM 信号：Kubernetes 发送终止信号
- 停止接收新请求：从负载均衡移除
- 完成当前请求：等待请求处理完成
- 关闭连接：数据库、缓存、消息队列
- 清理资源：释放文件句柄、临时文件
- 超时强制退出：SIGKILL 前的宽限期（默认 30 秒）

### 零停机部署
- 滚动更新：逐个替换 Pod
- 蓝绿部署：新旧版本并存、一键切换
- 金丝雀发布：小流量验证、逐步放量
- 就绪探针：确保新 Pod 就绪才接收流量
- PreStop Hook：关闭前等待、确保流量切走

### 信号处理
- SIGTERM：优雅关闭、默认 15 秒后 SIGKILL
- SIGKILL：强制终止、无法捕获
- SIGINT：Ctrl+C、本地开发
- 信号捕获：注册信号处理器、执行清理逻辑
- 语言支持：process.on('SIGTERM')、signal.Notify

## 实战篇：弹性与韧性

### 重试机制
- 幂等性：重试不影响结果
- 指数退避：1s、2s、4s、8s
- 最大重试次数：避免无限重试
- 可重试错误：网络超时、5xx 错误
- 不可重试错误：4xx 客户端错误

### 超时控制
- 连接超时：建立连接的最长时间
- 读超时：等待响应的最长时间
- 总超时：整个请求的最长时间
- 级联超时：下游超时短于上游
- 超时传播：Context、Deadline

### 熔断器（Circuit Breaker）
- 状态：关闭（正常）、打开（熔断）、半开（尝试恢复）
- 打开条件：错误率阈值、慢调用阈值
- 熔断时间：冷却期、避免雪崩
- 半开尝试：放行少量请求测试
- 库：Hystrix（已停止）、Resilience4j、Sentinel

### 限流（Rate Limiting）
- 令牌桶：固定速率产生令牌、消费令牌
- 漏桶：固定速率处理请求、削峰填谷
- 固定窗口：时间窗口内请求数限制
- 滑动窗口：更精确的限流
- 分布式限流：Redis 计数器、Sentinel

### 降级策略
- 功能降级：关闭非核心功能
- 返回默认值：缓存数据、静态内容
- 快速失败：避免资源浪费
- 熔断降级：依赖服务不可用时降级
- 人工降级：紧急情况手动关闭

### 隔离（Bulkhead）
- 线程池隔离：不同服务使用不同线程池
- 信号量隔离：限制并发数
- 连接池隔离：数据库连接池隔离
- 资源隔离：CPU、内存配额
- 故障隔离：一个服务故障不影响其他

## 实战篇：可观测性

### 日志（Logging）
- 结构化日志：JSON 格式、字段标准化
- 日志级别：DEBUG、INFO、WARN、ERROR
- 关键字段：时间戳、TraceID、UserID、请求路径
- 日志聚合：ELK、Loki、Splunk
- 日志采样：高流量下减少日志量

### 指标（Metrics）
- 四大黄金信号：流量、延迟、错误、饱和度
- RED 指标：Rate、Errors、Duration
- USE 指标：Utilization、Saturation、Errors
- 业务指标：订单量、支付成功率
- Prometheus：时序数据库、PromQL 查询

### 追踪（Tracing）
- 分布式追踪：跨服务请求链路
- Span：单个操作、带时间戳和元数据
- Trace：多个 Span 组成完整链路
- TraceID：全局唯一、串联所有 Span
- OpenTelemetry：统一标准、多后端支持

### 告警（Alerting）
- 告警规则：阈值、趋势、异常检测
- 告警级别：P0/P1/P2/P3
- 告警渠道：邮件、短信、电话、Slack
- 告警聚合：避免告警风暴
- On-Call：值班轮换、事件响应

## 实战篇：安全最佳实践

### 最小权限原则
- RBAC：基于角色的访问控制
- Pod Security Policy：Pod 安全策略
- Service Account：服务账号、权限最小化
- Network Policy：网络隔离、白名单
- 只读文件系统：readOnlyRootFilesystem

### 镜像安全
- 基础镜像：官方镜像、Alpine Linux
- 漏洞扫描：Trivy、Clair、Anchore
- 最小化：多阶段构建、删除无用文件
- 非 root 运行：USER 指令、runAsNonRoot
- 镜像签名：Notary、Cosign

### 密钥管理
- 不写在代码里：配置外部化
- 不写在镜像里：通过 Secret 注入
- 加密存储：etcd 加密、Secret 加密
- 轮换：定期更换密钥
- 审计：密钥访问日志

### 网络安全
- TLS 加密：服务间通信加密
- mTLS：双向 TLS、身份验证
- 服务网格：Istio、Linkerd
- Ingress 证书：Let's Encrypt、自动续期
- DDoS 防护：CDN、WAF

## 实战篇：成本优化

### 资源配额
- Requests：最小资源保证
- Limits：最大资源限制
- QoS 等级：Guaranteed、Burstable、BestEffort
- 合理配置：避免浪费、避免 OOM
- 压测：找到合适的资源配置

### 自动伸缩
- HPA（水平自动伸缩）：CPU、内存、自定义指标
- VPA（垂直自动伸缩）：调整 Pod 资源
- Cluster Autoscaler：节点自动伸缩
- KEDA：基于事件的自动伸缩
- 成本优化：按需扩展、夜间缩容

### Spot 实例
- 低成本：60%-90% 折扣
- 可中断：随时可能被回收
- 适合场景：无状态应用、批处理任务
- 优雅处理：监听终止通知、优雅关闭
- 混合使用：关键应用按需实例 + 非关键 Spot

### 多租户
- 命名空间隔离：不同团队、不同环境
- 资源配额：ResourceQuota、LimitRange
- 网络隔离：Network Policy
- 成本分摊：标签标记、成本分析
- 共享集群：降低基础设施成本

## 下一步学习

掌握云原生模式后，可以继续深入：

- **Kubernetes** - 容器编排、CRD、Operator
- **服务网格** - Istio、Linkerd、流量管理
- **DevOps** - CI/CD、GitOps、自动化
- **可观测性** - Prometheus、Grafana、Jaeger
- **混沌工程** - Chaos Mesh、韧性测试
- **FinOps** - 云成本优化、资源管理

云原生不是技术的简单堆叠，而是一套完整的方法论。它要求我们重新思考应用的设计、开发、部署、运维。12-Factor 是基础原则，健康检查是生产就绪的必要条件，优雅关闭是对用户的尊重，弹性模式是系统韧性的保障。这些模式不是教条，而是经过无数生产环境验证的最佳实践。理解它们背后的原理，根据实际情况灵活应用,才能构建真正云原生的应用。
