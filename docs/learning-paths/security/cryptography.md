# 密码学学习路线

密码学是信息安全的数学基础。从古老的凯撒密码到现代的 RSA、AES，从对称加密到非对称加密，从哈希函数到数字签名，密码学保护着我们的通信、交易、隐私。这条路线会带你了解密码学的核心概念、常用算法、实际应用，以及如何正确使用密码学。记住：不要自己发明加密算法。

## 基础篇：密码学核心概念

### 加密解密基础
- 明文（Plaintext）与密文（Ciphertext）
- 加密（Encryption）与解密（Decryption）
- 密钥（Key）：对称密钥、公钥、私钥
- 算法（Algorithm）：加密算法、解密算法
- 安全性：计算安全、信息论安全
- Kerckhoffs 原则：算法公开、密钥保密

### 对称加密
- 核心特点：加密和解密使用相同密钥
- 优点：速度快、效率高、适合大量数据
- 缺点：密钥分发困难、密钥管理复杂
- 密钥长度：128 位、192 位、256 位
- 应用场景：数据加密、通信加密、磁盘加密

### 非对称加密
- 核心特点：公钥加密、私钥解密（或相反）
- 密钥对：公钥（公开）、私钥（保密）
- 优点：密钥分发简单、适合密钥交换、支持数字签名
- 缺点：速度慢、计算开销大
- 应用场景：密钥交换、数字签名、身份认证

### 哈希函数
- 核心特点：单向函数、固定长度输出
- 性质：确定性、雪崩效应、抗碰撞性、不可逆性
- 输出：摘要（Digest）、指纹（Fingerprint）
- 应用场景：完整性校验、密码存储、数字签名、区块链

### 加密模式
- 分组加密：将数据分成固定大小的块
- 流加密：逐字节加密
- 填充方式：PKCS#5、PKCS#7、Zero Padding
- 初始化向量（IV）：随机性、唯一性

## 进阶篇：对称加密算法

### DES（数据加密标准）
- 分组长度：64 位
- 密钥长度：56 位（实际）、64 位（含校验位）
- 历史地位：最早的标准加密算法
- 现状：已被破解、不再安全、仅供学习
- 3DES：三重 DES、密钥长度 168 位、逐渐淘汰

### AES（高级加密标准）
- 分组长度：128 位
- 密钥长度：128 位、192 位、256 位
- 轮数：10 轮、12 轮、14 轮
- 现状：当前最广泛使用的对称加密算法
- 性能：硬件加速（AES-NI）、速度快
- 安全性：无已知实用攻击、军事级加密

### ChaCha20
- 流密码：不需要分组和填充
- 性能：软件实现快、适合移动设备
- Poly1305：配套的消息认证码
- 应用：TLS 1.3、WireGuard VPN
- 优势：抗时序攻击、简单高效

### 加密模式详解
- ECB（电子密码本）：不安全、明文块相同则密文相同、不推荐
- CBC（密码块链接）：需要 IV、常用、顺序加密
- CTR（计数器）：并行加密、流式、需要 nonce
- GCM（伽罗瓦计数器）：认证加密、完整性保护、TLS 常用
- CCM（CTR + CBC-MAC）：认证加密、802.11i 使用

## 进阶篇：非对称加密算法

### RSA
- 数学基础：大数分解难题
- 密钥长度：1024 位（已弱）、2048 位（当前标准）、4096 位（高安全）
- 用途：加密、签名、密钥交换
- 填充方案：PKCS#1 v1.5、OAEP（最优非对称加密填充）
- 性能：慢、适合小数据
- 安全性：密钥长度足够时安全

### ECC（椭圆曲线密码学）
- 数学基础：椭圆曲线离散对数问题
- 优势：相同安全级别下密钥更短、性能更好
- 常用曲线：P-256、P-384、Curve25519、secp256k1（比特币）
- 应用：TLS、SSH、比特币、以太坊
- ECDH：椭圆曲线 Diffie-Hellman 密钥交换
- ECDSA：椭圆曲线数字签名算法

### Diffie-Hellman
- 密钥交换协议：在不安全信道上协商密钥
- 数学基础：离散对数问题
- DHE：临时 DH、前向安全性
- ECDHE：椭圆曲线 DH、更高效
- 应用：TLS、SSH、VPN

### EdDSA（Edwards-curve Digital Signature Algorithm）
- 签名算法：基于扭曲爱德华曲线
- Ed25519：常用实现、高性能、高安全
- 优势：速度快、签名短、确定性签名
- 应用：SSH、Git commit 签名、区块链

## 进阶篇：哈希函数

### MD5
- 输出长度：128 位（32 字符十六进制）
- 历史：曾经广泛使用
- 现状：已被破解、碰撞攻击、不再安全
- 应用：仅用于非安全场景（校验和、去重）

### SHA-1
- 输出长度：160 位（40 字符十六进制）
- 现状：已被破解（SHAttered 攻击）、不再安全
- 淘汰：Git 正在迁移到 SHA-256

### SHA-2 家族
- SHA-224、SHA-256、SHA-384、SHA-512、SHA-512/256
- SHA-256：最常用、256 位输出、安全
- SHA-512：512 位输出、64 位系统更快
- 应用：数字签名、证书、区块链

### SHA-3（Keccak）
- 新标准：2015 年发布、不是 SHA-2 的升级
- 设计：海绵构造、不同于 SHA-2
- 安全：抗长度扩展攻击
- 应用：以太坊、新系统

### BLAKE2/BLAKE3
- 高性能：比 SHA-2 快、比 MD5 安全
- BLAKE2b：适合 64 位系统
- BLAKE2s：适合 32 位系统
- BLAKE3：更快、并行化
- 应用：Zcash、文件完整性

## 实战篇：密码存储

### 密码哈希
- 原则：不可逆、慢哈希、加盐
- 错误方式：明文、MD5、SHA-256（太快）
- 盐（Salt）：随机值、每个密码不同、防彩虹表
- 成本因子：增加计算时间、对抗暴力破解

### bcrypt
- Blowfish 算法：慢哈希、可配置成本
- 成本因子：10-12（推荐）、每增加 1 倍时间翻倍
- 输出：包含算法、成本、盐、哈希
- 优点：经过时间考验、抗 GPU 破解
- 缺点：最大密码长度 72 字节

### scrypt
- 内存硬函数：大量内存需求、抗 ASIC
- 参数：N（CPU/内存成本）、r（块大小）、p（并行度）
- 优点：抗硬件加速
- 缺点：内存开销大

### Argon2
- 新标准：2015 年密码哈希竞赛冠军
- 版本：Argon2i（抗侧信道）、Argon2d（抗 GPU）、Argon2id（推荐）
- 参数：内存成本、时间成本、并行度
- 优点：现代、灵活、最安全
- 应用：新系统首选

### PBKDF2
- 基于 HMAC：使用 SHA-256 等哈希函数
- 迭代次数：100,000+（NIST 推荐）
- 优点：标准化、广泛支持
- 缺点：不抗 GPU、性能较弱
- 应用：WPA2、老系统

## 实战篇：数字签名

### 签名原理
- 私钥签名、公钥验证
- 签名过程：哈希 → 私钥加密 → 签名
- 验证过程：公钥解密 → 哈希对比
- 作用：认证、完整性、不可否认

### RSA 签名
- PKCS#1 v1.5：老标准、仍在使用
- PSS（概率签名方案）：更安全、推荐
- 应用：JWT、代码签名、文档签名

### ECDSA 签名
- 优势：签名更短、速度更快
- 应用：TLS、比特币、以太坊
- 问题：k 值必须随机（PlayStation 3 破解事件）

### EdDSA 签名
- Ed25519：最常用实现
- 优势：确定性签名、无随机数风险、速度快
- 应用：SSH 密钥、Git 提交签名、Signal

### HMAC（消息认证码）
- 对称签名：共享密钥
- 构造：HMAC = Hash(Key || Hash(Key || Message))
- 算法：HMAC-SHA256、HMAC-SHA512
- 应用：JWT、API 签名、Cookie 签名
- 与哈希区别：带密钥、双方验证

## 实战篇：TLS/SSL

### TLS 握手
- 协商版本：TLS 1.2、TLS 1.3
- 密码套件：加密算法组合
- 密钥交换：ECDHE、RSA（不推荐）
- 证书验证：服务器证书、客户端证书（可选）
- 会话密钥：对称加密实际通信

### 证书与 PKI
- X.509 证书：公钥 + 身份信息 + CA 签名
- CA（证书颁发机构）：根 CA、中间 CA
- 证书链：服务器证书 → 中间 CA → 根 CA
- 证书验证：签名验证、有效期、吊销列表（CRL/OCSP）
- 自签名证书：测试环境、内网

### TLS 1.3 改进
- 简化握手：1-RTT、0-RTT（重放风险）
- 移除不安全：RSA 密钥交换、CBC 模式、SHA-1、MD5
- 强制前向安全：必须使用 ECDHE
- 性能提升：更快连接、更少延迟

### 证书透明度（CT）
- 公开日志：所有证书公开记录
- 防止伪造：CA 错误签发可被发现
- SCT（签名证书时间戳）：证书包含 CT 日志证明

### 证书钉扎（Certificate Pinning）
- 移动应用安全：硬编码证书或公钥
- 防止中间人：即使 CA 被攻破也无法伪造
- 风险：证书更新困难、回滚复杂

## 实战篇：安全随机数

### 随机数重要性
- 密钥生成：AES 密钥、RSA 密钥对
- IV/Nonce：加密模式、签名
- 盐值：密码哈希
- Token：会话 Token、CSRF Token

### CSPRNG（密码学安全伪随机数生成器）
- /dev/urandom（Linux）
- CryptGenRandom（Windows）
- SecureRandom（Java）
- crypto.getRandomValues（JavaScript）
- secrets 模块（Python 3.6+）

### 常见错误
- 使用 Math.random()：不安全、可预测
- 使用时间戳：熵不足、可预测
- 种子固定：每次生成相同序列
- 不刷新熵池：虚拟机克隆问题

## 实战篇：密码学最佳实践

### 算法选择
- 对称加密：AES-256-GCM（首选）、ChaCha20-Poly1305
- 非对称加密：RSA-2048/4096、ECC P-256/P-384、Ed25519
- 哈希：SHA-256、SHA-512、BLAKE2/BLAKE3
- 密码哈希：Argon2id（首选）、bcrypt、scrypt
- 签名：Ed25519（首选）、ECDSA、RSA-PSS

### 密钥管理
- 密钥生成：CSPRNG、足够长度
- 密钥存储：硬件安全模块（HSM）、密钥管理服务（KMS）、加密存储
- 密钥轮换：定期更换、版本管理
- 密钥分发：安全信道、非对称加密
- 密钥销毁：安全擦除、覆盖写入

### 常见陷阱
- ECB 模式：不要用
- 固定 IV：每次加密必须使用新的随机 IV
- 无认证加密：GCM/CCM 防止篡改
- 密钥派生：使用 KDF（HKDF、PBKDF2）而非直接哈希
- 时序攻击：密码对比使用常数时间算法
- 填充预言攻击：使用认证加密

### 合规与标准
- FIPS 140-2/140-3：美国联邦标准
- PCI DSS：支付卡行业标准
- GDPR：欧盟数据保护
- 国密算法：SM2、SM3、SM4（中国）

## 下一步学习

掌握密码学后，可以继续深入：

- **区块链** - 比特币、以太坊、共识算法
- **零知识证明** - zk-SNARKs、zk-STARKs
- **同态加密** - 加密数据上计算
- **量子密码学** - 后量子密码、抗量子算法
- **安全协议** - TLS、SSH、IPsec、WireGuard
- **硬件安全** - TPM、HSM、Secure Enclave

密码学是复杂而精密的学科。不要尝试自己实现加密算法，不要自己设计协议，不要觉得"简单加个密"就安全了。使用成熟的库、遵循最佳实践、关注安全公告、保持学习。密码学的敌人不是黑客，而是错误的使用方式。
