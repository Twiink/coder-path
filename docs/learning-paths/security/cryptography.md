# 密码学学习路线

密码学是信息安全的数学地基,也是开发者最容易"半懂不懂就出事"的领域。**本页最重要的三句话(先记住)**:①**不要自己发明/实现加密算法与协议**(数学正确 ≠ 实现安全,用成熟库);②**加密 ≠ 编码**(Base64 只是编码,可逆且无密钥——"我 Base64 加密了密码"是常见事故发言);③密码学的敌人不是黑客,是**错误的使用方式**(算法选错/模式用错/随机数不随机/密钥硬编码)。本页目标:**让你看懂 HTTPS、JWT、密码存储、签名背后在干什么,并能在工程里选对用对**。配套:[Web 安全](/learning-paths/security/web-security)(攻击面)与 [认证授权](/learning-paths/security/auth)(应用层)。

这条线按 **核心概念与随机数 → 对称加密 → 非对称加密与密钥交换 → 哈希与 MAC → 密码存储 → 数字签名与 PKI → TLS → 常见陷阱与纪律** 推进。

## 第一站:核心概念——加密要解决的三件事

**密码学的三个目标(所有算法对号入座)**:①**机密性(别人看不懂)→ 加密算法**;②**完整性(没被篡改)→ 哈希/MAC**;③**认证与不可否认(确实是对方发的)→ 数字签名**。**基础概念**:明文 ↔ 密文;密钥(对称一把/非对称一对);**Kerckhoffs 原则(设计哲学):算法公开、密钥保密**——"安全不靠隐藏算法"(别迷信"保密算法更安全");**IV/Nonce(初始化向量/一次性数)**:分组加密的"盐",**每次加密必须随机且不重复**(固定 IV = 相同明文出相同密文,机密性归零);**CSPRNG(密码学安全随机数)——所有安全操作的前提**:密钥、IV、盐、Token 的生成**必须用它**(各语言:`secrets`(Python)/`crypto.getRandomValues`(JS)/`SecureRandom`(Java)/`/dev/urandom`;用 `Math.random`/`Date.now()` 生成安全参数 = 灾难(可预测=可破解)。

## 第二站:对称加密——快,用于大数据

**原理**:加密解密同一把密钥(如 AES-256 的 256 位密钥);**特点:快,适合加密实际数据(数据库字段/通信内容/文件)**;代价:密钥分发难(怎么安全地把密钥给对方——交给非对称解决)。**算法**:**AES(当代标准:128/256 位;硬件加速 AES-NI)**;ChaCha20(流式,软件实现快——移动端/TLS1.3 备选)。**模式(选错=白加密,重点)**:`ECB`(电子密码本:**相同明文块→相同密文块,会泄露模式——永远别用**);`CBC`(链式:经典但要 IV,只加密不防篡改);**`GCM`(认证加密 AEAD:加密+完整性校验一体——现代首选)**。**工程铁律:用 AEAD(如 AES-256-GCM),别自己"先 CBC 加密再拼 MAC"**(自己拼的认证方案几乎必有缝——填充预言攻击等)。

## 第三站:非对称加密——慢,用于小数据与身份

**原理**:公钥/私钥一对——公钥加密、私钥解密(机密性:任何人能用你公钥加密,只有你能解);私钥签名、公钥验签(见签名站)。**特点:慢,不适合大数据——实际只用于密钥交换与签名**。**算法**:RSA(大数分解难题;**2048 位起步**,4096 高安全);**ECC(椭圆曲线:同安全性密钥短得多(256 位 ECC ≈ 3072 位 RSA)——现代首选**,常用 Curve25519/P-256);**Diffie-Hellman/ECDHE(密钥交换协议:双方在不安全信道协商出共享密钥——TLS 握手用它)**;**前向安全(必懂概念)**:用**临时密钥(ECDHE 的 E)** 协商——即使服务器长期私钥日后泄露,**历史通信记录仍解不开**——现代 TLS 强制要求。**混合加密(真实世界的形态)**:非对称(ECDHE)安全协商出**会话密钥** → 用对称(AES-GCM)加密实际数据——**性能与安全的组合,HTTPS 就是这么干的**。

## 第四站:哈希与 MAC——完整性的工具

**哈希(Hash)**:任意长度输入 → 固定长度摘要;**性质:单向(不可逆)、确定性、雪崩效应(改一个字符摘要全变)、抗碰撞**。用途:完整性校验(下载文件 SHA-256)、密码存储(见下站)、数据指纹。**算法现状(重要,别用过时的)**:MD5 与 SHA-1 **已被碰撞攻击攻破**(能构造出相同哈希的不同内容——完整性场景不可用);用 **SHA-256/SHA-512(SHA-2 家族)** 或 BLAKE2/3。**MAC(消息认证码,带密钥的哈希)**:HMAC-SHA256 = 用**共享密钥**参与计算——**没有密钥就算不出合法 MAC**;用途:API 签名(请求防篡改+防伪)、Cookie 签名、**JWT 的 HS256 就是 HMAC**。**关键区分(面试/事故常客)**:**哈希不防篡改**(攻击者改了内容可以重算哈希——公开算法谁都能算),**MAC/签名才防篡改**(需要密钥);"完整性校验"要 MAC 或签名,不是裸哈希(除非校验方信任来源的公开摘要)。

## 第五站:密码存储——开发者最该会的密码学

**目标**:数据库泄露时,攻击者拿不到明文密码。**错误示范史(全是教训)**:明文存储(最糟)→ MD5/SHA 直接哈希(**太快:GPU 每秒几十亿次,弱密码秒破**)→ 加盐哈希(盐=每用户随机串,防**彩虹表**(预计算哈希表)→ 还是不够:**普通哈希依然太快,可暴力**)→ **慢哈希(正确答案:故意让每次计算花 0.1~0.5 秒——攻击者暴力成本暴涨)**。**现代算法**:`Argon2id`(2015 年竞赛冠军,**内存硬(抗 GPU/ASIC),新系统首选**)/bcrypt(普及最广,注意 72 字节密码上限)/scrypt(内存硬)/PBKDF2(老标准,迭代数要 10 万+)。**工程姿势:用库,别 DIY**——各语言/框架的 `password_hash`(PHP)/`bcrypt`(Go/Node)/`Argon2` 直接调;**验证用库的"常数时间比较"**(防时序攻击——普通 `==` 比较不同长度耗时不同,可被侧信道探测)。完整登录体系见 [认证授权](/learning-paths/security/auth)。

## 第六站:数字签名与 PKI——身份的数学证明

**数字签名**:私钥签名、公钥验证——提供**认证(确实是私钥持有者发的)+ 完整性(内容没改)+ 不可否认**。过程:对内容哈希 → 用私钥"签名"哈希 → 验证方用公钥验签。**算法选型**:Ed25519(现代首选:**确定性签名(无随机数依赖——ECDSA 的 k 必须真随机,出过 PS3 被完全破解的著名事故)**、快、签名短——SSH 密钥/Git 签名/TLS 都在用)/ECDSA/RSA-PSS。**HMAC 是对称世界的"签名"**(见第四站:共享密钥双方用)。**PKI(公钥基础设施)与证书——HTTPS 信任的根基**:**X.509 证书 = 公钥 + 身份信息(域名/组织)+ CA 的签名**;**信任链:服务器证书 ← 中间 CA ← 根 CA(浏览器内置的信任锚)**——你验证的不是"公钥数学上对不对",而是"**这张证书确实由可信 CA 签发给这个域名**";验证项:链上签名、有效期、吊销状态(CRL/OCSP)。**为什么 HTTPS 能防中间人**:攻击者可以伪造证书,但**没有 CA 的合法签名,浏览器不认**;自签名证书(测试/内网)浏览器会警告——需要手动信任。**Let's Encrypt**:免费自动签发(见 [Nginx](/learning-paths/middleware/nginx) HTTPS 章)——别手动抠证书。

## 第七站:TLS——把上面全串起来

**TLS 握手(密码学视角,网络细节见 [计算机网络](/learning-paths/cs-basics/computer-networks))**:①客户端问候(支持的版本/套件)→ ②服务器回证书 → ③**客户端验证证书链**(信任问题,第六站)→ ④**ECDHE 密钥交换**(双方协商出会话密钥,前向安全)→ ⑤之后用 **AES-GCM/ChaCha20 对称加密** 通信——**一次握手 = 证书(认证)+ 非对称(协商)+ 对称(传输)的完整混合加密**。**TLS 1.3 的进步**:握手从 2-RTT 降到 1-RTT、**只保留安全算法(强制 ECDHE 前向安全、移除 RSA 密钥交换/CBC/SHA-1)**——"版本越新越安全"在 TLS 上成立;配置见 [Nginx](/learning-paths/middleware/nginx) 页(禁 TLS1.0/1.1)。**工程相关**:证书透明度 CT(公开日志防 CA 乱发证书)、移动端证书钉扎(硬编码公钥防中间人——**强但证书更新麻烦,权衡用**)。

## 第八站:常见陷阱与使用纪律

**陷阱清单(扫一眼,能避 90% 的坑)**:①用 **ECB 模式**;②**IV 固定或重复**(每次新随机);③只加密不认证(用 GCM/CCM 类 AEAD);④自己拼"加密+MAC"组合;⑤**用 MD5/SHA-1** 做安全用途;⑥用普通哈希存密码;⑦**用 Math.random 生成密钥/Token**;⑧**把密钥硬编码进代码/仓库**(用环境变量/配置/KMS/Secret 管理,见 [云原生](/learning-paths/cloud-native/cloud-native-patterns) 密钥章);⑨用 `==` 比较哈希/MAC(常数时间比较);⑩把 Base64/编码当加密;⑪自己设计协议("我这样加密够安全了吧"——**协议设计比算法更难,用现成 TLS/标准**)。
**算法选型速查(直接抄)**:数据加密 **AES-256-GCM**(或 ChaCha20-Poly1305);哈希 SHA-256+;密码存储 **Argon2id**/bcrypt;签名 **Ed25519**;密钥交换 ECDHE;JWT 签名 HS256(单服务)或 RS256/EdDSA(多服务)。
**使用纪律**:用**成熟库**(OpenSSL/libsodium/Tink/各语言标准 crypto 模块),**别自己实现 AES/RSA**(实现漏洞比数学漏洞常见得多);读库的"安全默认值"(很多库有高等级封装,如 libsodium 的 secretbox——直接用);关注安全公告与弃用(算法有寿命:DES→3DES→AES;MD5→SHA-1→SHA-2);合规场景了解国密 SM2/SM3/SM4。

## 通关标准

能独立做到:说出加密三目标与对应工具、对称/非对称/哈希/MAC 各自解决什么;给"加密存储字段"场景给出完整方案(AES-256-GCM + 密钥管理 + 为什么不用 ECB/CBC);讲清"哈希为什么不防篡改、MAC 为什么防"与 HMAC 在 JWT 里的角色;解释 HTTPS 信任链(证书→CA→根)与中间人攻击为什么被挡住;写出密码存储的正确姿势(Argon2id/加盐/常数时间)并指出 MD5 直存错在哪;说出五个以上常见密码学陷阱与正确替代——密码学主线通关。

对开发者而言,密码学的价值不在"会算",而在"**会用与会避坑**":知道选什么算法、为什么不能自己拼、密钥该放哪——这些判断力保护的是用户数据与公司信誉。**记住那句行业箴言:不要自己发明加密,不要自己实现加密,不要自己设计协议——你的工作是在正确的位置调用经过检验的工具**。把本页的"选型速查"与"陷阱清单"存进心里,再配合 [TLS/网络](/learning-paths/cs-basics/computer-networks)、[认证授权](/learning-paths/security/auth) 与 [Web 安全](/learning-paths/security/web-security),你的安全知识就成体系了。下一步:用 [Burp/靶场] 看看这些机制被攻击时什么样,或深入 [区块链/零知识] 等密码学前沿。
