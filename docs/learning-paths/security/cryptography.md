# 密码学学习路线

密码学是安全世界的数学地基，也是“差不多懂了”最容易变成事故的领域。它像一位严肃的锁匠：不关心你的产品多漂亮，只关心随机数够不够随机、密钥有没有被保护、消息有没有被篡改、验证对象是不是正确。开发者最重要的密码学能力，通常不是发明算法，而是**识别目标、选择成熟原语、正确组合、管理密钥并知道何时请专家审查**。

这是一条独立的密码学学习地图，从机密性、完整性和随机数走到对称加密、哈希、密码存储、非对称密码、签名、PKI、TLS、密钥管理与工程陷阱。每一站覆盖常用能力、少见边界和值得深挖的机制；路线少放公式和代码，把注意力留给安全目标、威胁模型和使用纪律。

路线按 **安全目标 → 随机数 → 对称加密 → 哈希与 KDF → 密码存储 → 非对称与签名 → PKI/TLS → 密钥管理 → 协议陷阱 → 工程治理** 推进。

## 第一站：安全目标与密码学心智

欢迎来到密码学的锁匠铺。加密保护秘密，哈希留下指纹，签名证明来源；把三种工具混着用，就像拿门牌号去锁保险箱。

**机密性** ---- 理解未经授权者不能读懂数据的目标，区分传输中、存储中和使用中的保护边界

**完整性** ---- 认识篡改检测、认证标签、消息认证码和签名，知道“看不懂”不等于“没被改过”

**认证与不可否认** ---- 理解身份确认、消息来源和签名责任，避免把加密结果误当作发送者证明

**编码与加密** ---- 区分 Base64、URL 编码、压缩、混淆、哈希和加密；编码不会凭空召唤密钥

**Kerckhoffs 原则** ---- 接受算法公开、密钥保密的设计纪律，不依赖隐藏算法或自创格式获得安全感

**威胁模型** ---- 明确攻击者能读、改、重放、伪造、观察或控制什么，再选择需要的安全性质

**不要自创密码学** ---- 使用成熟库、标准协议和经过审查的组合，自己发明算法只适合写进反面教材

**重点在这** ---- 能把一个需求翻译成机密性、完整性、认证、抗重放和可用性目标，知道密码学不是一瓶万能喷雾

## 第二站：随机数、Nonce 与密钥材料

第二站是随机数的抽签室。安全系统里很多秘密的第一口气来自随机数；如果抽签机能被预测，后面的锁再高级也只是装饰。

**随机性层次** ---- 区分普通伪随机、密码学安全伪随机和硬件熵源，知道模拟、测试和安全生产不能共用同一把随机勺

**CSPRNG** ---- 用操作系统或成熟库提供的安全随机源生成密钥、Token、盐、Nonce 和验证码

**熵与种子** ---- 理解种子、熵不足、启动早期、虚拟机和容器环境的随机性边界

**Nonce 与 IV** ---- 区分随机、唯一、公开和秘密的要求，知道不同算法对 Nonce 重用的惩罚可能是灾难级

**盐与 Pepper** ---- 理解密码哈希中的独立盐、服务端额外秘密和存储位置，避免把盐当作万能加密钥匙

**随机 ID** ---- 设计不可预测、无序泄露和可审计的标识，防止数据库自增编号直接暴露资源数量与访问路径

**测试随机性** ---- 在测试中固定随机源，在生产中使用安全随机源，明确可重复性和不可预测性的边界

**重点在这** ---- 生成安全材料时能回答随机从哪来、是否可预测、是否需要唯一、是否会重复以及如何轮换

## 第三站：对称加密与 AEAD

第三站是对称锁具车间。一把共享密钥开关两边，速度很快，适合大量数据；但钥匙怎么交给对方、消息有没有被改，是它必须和别的工具配合解决的问题。

**对称密码** ---- 理解共享密钥、分组密码、流密码、明文、密文和密钥长度，知道密钥长度不等于整体安全等级

**AES 与 ChaCha20** ---- 了解主流算法、硬件加速、软件性能、平台差异和标准库支持，优先使用成熟实现

**AEAD** ---- 掌握认证加密同时提供机密性和完整性的模型，理解密文、认证标签、Nonce 和附加认证数据

**GCM 与 ChaCha20-Poly1305** ---- 认识常用 AEAD 的使用边界、Nonce 唯一性、标签验证和失败处理

**附加认证数据** ---- 用 AAD 保护协议版本、用户 ID、资源标识和元数据，理解它被认证但不被加密

**密文格式** ---- 设计版本、算法标识、Nonce、标签和密文的可迁移格式，避免把解析信息藏在猜测里

**失败处理** ---- 认证失败时统一拒绝，不泄露是密钥错、数据被改还是格式错，避免错误信息帮助攻击者

**重点在这** ---- 现代应用优先使用成熟 AEAD，不自己拼“加密 + 哈希 + 字符串截取”的私人协议

## 第四站：哈希、MAC 与 KDF

第四站是指纹与钥匙加工厂。哈希适合留下固定长度指纹，MAC 需要共享秘密，KDF 负责把一把钥匙加工成多把有用途的钥匙；三者职责不同，不能轮流冒充。

**密码学哈希** ---- 理解单向性、抗碰撞、抗第二原像、雪崩效应和固定长度输出，知道哈希不是加密

**SHA-2 与 SHA-3** ---- 了解主流哈希家族、输出长度、库支持和使用场景，避免为密码存储直接选择快速哈希

**HMAC** ---- 使用共享密钥保护消息完整性与来源，理解密钥、消息、标签和比较方式

**HKDF** ---- 从高熵输入派生用途隔离的子密钥，规划盐、上下文、信息标签和派生层级

**密码哈希** ---- 使用专门的内存困难或成本可调算法处理人类密码，区分密码验证与普通数据完整性校验

**密钥分离** ---- 为加密、签名、会话、数据库和 Token 使用不同用途的密钥，避免一把钥匙打开整栋楼

**恒定时间比较** ---- 对认证标签、摘要和 Token 等敏感值使用抗时序泄露的比较方式

**重点在这** ---- 能根据目标选择 Hash、HMAC、KDF 或密码哈希，并说明密钥从哪里来、用途如何隔离

## 第五站：密码存储与凭据保护

第五站是密码保管所。用户密码不是要“加密后放数据库”，而是要让服务能验证却尽量无法还原；数据库泄露时，保管所要尽量不给攻击者现成钥匙。

**密码哈希算法** ---- 了解 Argon2id、scrypt、bcrypt 和 PBKDF2 的成本参数、内存需求、兼容性与升级策略

**盐值管理** ---- 为每个密码生成独立盐并随摘要存储，理解盐公开并不可怕，重复盐才会让攻击者获得规模化优势

**成本调节** ---- 根据服务器容量、登录峰值和攻击预算设置时间、内存、并行参数，定期重新评估

**密码升级** ---- 登录成功后透明升级旧成本或旧算法，处理无法登录、批量迁移和账户恢复的边界

**泄露响应** ---- 设计强制改密、会话失效、Token 撤销、风险通知和取证，密码摘要泄露不是“数据库修好就算了”

**恢复流程** ---- 保护重置令牌、邮箱/短信、备份码和人工恢复，恢复渠道不能比主登录门槛更矮

**秘密存储** ---- 使用密钥管理系统、秘密管理器和最小权限访问，避免密码、盐、密钥和 Token 出现在日志与源码

**重点在这** ---- 能证明密码不可逆、成本可升级、恢复可控、会话可撤销，而不是只说“我们用了加密”

## 第六站：非对称密码、签名与密钥交换

第六站是公钥信使馆。公钥可以广泛分发，私钥必须严密保管；它让陌生双方能协商秘密，也让消息可以带上可验证的签名。

**公钥与私钥** ---- 区分加密/解密与签名/验签两类方向，理解谁持有哪把钥匙、谁能验证什么

**RSA** ---- 了解密钥尺寸、填充、签名与加密模式的差异，禁止把裸 RSA 或错误填充直接带进应用

**椭圆曲线** ---- 认识现代曲线的安全等级、密钥长度、库支持和实现边界，理解曲线名字不是装饰品

**Diffie-Hellman** ---- 理解双方如何在公开信道协商共享秘密，区分静态密钥、临时密钥和中间人风险

**前向安全** ---- 通过临时密钥交换降低长期私钥泄露对历史通信的影响，知道它需要协议与密钥生命周期共同配合

**数字签名** ---- 设计消息规范化、摘要、签名、验签、密钥标识和重放保护，避免签了一个含义不明确的字符串

**密钥格式与互操作** ---- 处理编码、曲线、算法标识、证书、公钥指纹和跨语言库差异

**重点在这** ---- 能解释密钥交换解决什么、签名解决什么、私钥泄露意味着什么，以及如何验证完整的消息上下文

## 第七站：PKI、证书与 TLS

第七站是网络的身份证办公室。证书把公钥和身份绑定，CA 负责签发信任，TLS 把协商、认证和加密串成一条通道；浏览器报错时，它其实是在认真保护你。

**证书结构** ---- 认识主体、SAN、颁发者、有效期、公钥、用途、扩展和签名，避免只看 Common Name

**信任链** ---- 理解根 CA、中间 CA、服务器证书、信任库和链验证，知道“证书存在”不等于“证书可信”

**域名验证** ---- 处理 SAN、通配符、国际化域名、私有域名和证书轮换，避免扩大证书覆盖范围

**TLS 握手** ---- 建立协商版本、密码套件、密钥交换、证书验证、会话密钥和应用数据的整体模型

**TLS 1.2 与 1.3** ---- 了解现代版本的握手差异、前向安全、0-RTT 重放边界和兼容性策略

**证书生命周期** ---- 管理申请、签发、部署、续期、吊销、密钥轮换和过期告警，证书到期不是惊喜活动

**客户端认证** ---- 理解 mTLS、客户端证书、服务身份和吊销边界，区分网络身份与业务权限

**重点在这** ---- 能从一次 HTTPS 连接解释身份如何验证、密钥如何协商、数据如何保护、证书如何轮换

## 第八站：密钥管理与数据保护

第八站是钥匙保险库。算法选得再漂亮，密钥若写在仓库、截图或日志里，密码学也只能礼貌地宣布退休。

**密钥生命周期** ---- 规划生成、激活、使用、轮换、停用、归档、销毁和恢复，每个状态都要有责任人

**KMS 与 HSM** ---- 理解软件密钥管理、硬件安全模块、云 KMS、访问策略和审计的取舍

**信封加密** ---- 用数据密钥加密内容、用密钥加密密钥，处理数据密钥、主密钥、版本和解密授权

**用途隔离** ---- 为环境、租户、服务、数据类型和协议分离密钥，避免一处泄露扩大成全网失守

**轮换与兼容** ---- 支持新旧密钥并行、历史数据解密、重加密、缓存失效和回滚

**备份与恢复** ---- 保护密钥备份、恢复审批、双人控制和灾难演练，丢密钥可能比丢数据更难恢复

**访问审计** ---- 记录谁在何时为哪个用途使用密钥，限制批量解密和异常访问

**重点在这** ---- 设计密钥系统时能说清密钥在哪里、谁能用、如何换、怎么撤、丢了怎么恢复

## 第九站：协议组合、Token 与常见陷阱

第九站是反面案例博物馆。密码学原语单独看都很可靠，组合和上下文一错就会互相拆台；真正的漏洞经常住在格式、重放、验证对象和错误处理里。

**加密格式** ---- 为版本、算法、Nonce、标签、密文、密钥 ID 和上下文设计明确格式，避免解析歧义

**签名上下文** ---- 对域名、用途、版本、受众、时间、请求方法和资源绑定签名，防止同一签名被搬到另一个场景

**重放防护** ---- 使用 Nonce、时间窗、序列号、状态和一次性令牌，结合服务端记录判断请求是否已经使用

**JWT 边界** ---- 区分编码、签名、加密、受众、算法允许列表、密钥 ID 和撤销能力，避免 Payload 放秘密

**长度与侧信道** ---- 关注错误时长、响应长度、压缩、填充和比较时间，理解信息可能从“看不见的地方”漏出

**降级与算法混淆** ---- 固定允许算法、拒绝弱版本和不兼容回退，不让攻击者替你选择更舒服的锁

**错误与密文验证** ---- 先验证认证标签和签名，再使用明文；失败统一处理，不在日志中打印敏感中间值

**量子与长期数据** ---- 了解量子计算对公钥算法的长期影响、后量子迁移和加密敏捷性，按数据保密年限做准备

**重点在这** ---- 能审查一个自定义协议的目标、格式、验证顺序、重放边界、密钥轮换和失败行为

## 第十站：密码学工程治理与审查

最后一站是安全评审室。这里不再问“算法名字听起来高级吗”，而是问“目标、实现、密钥、协议、监控和恢复是否形成闭环”。

**标准与库选择** ---- 使用成熟标准、官方库和经过维护的封装，审查版本、实现语言、平台支持和漏洞记录

**密码学敏捷性** ---- 把算法、密钥 ID、参数和格式做成可升级配置，但不允许运行时被不可信输入任意选择

**测试策略** ---- 覆盖正确性、互操作、篡改、截断、重放、错误密钥、过期、轮换和恢复，不只测一次成功解密

**安全审查** ---- 让密码学专家、威胁建模和协议评审进入高风险功能，代码审查不能独自证明数学与组合正确

**观测与告警** ---- 监控验证失败、密钥使用、证书到期、随机源、算法迁移和异常解密，同时避免泄露秘密

**合规与隐私** ---- 根据数据类别、地区、保留期、访问权和审计要求设计加密、删除与密钥销毁

**事故与恢复** ---- 准备密钥泄露、证书误签、算法退役、数据重加密、批量撤销和回滚方案

**重点在这** ---- 生产密码学的完成标准是可验证、可轮换、可观测、可恢复、可审查，而不是项目里出现了一个 AES 单词

## 通关标准

**密码学新手能分清工具** ---- 能区分编码、哈希、加密、MAC、签名、密钥交换和密码哈希。

**初级工程师能正确调用** ---- 能使用安全随机数、AEAD、专用密码哈希和成熟 TLS/库，并保护密钥与失败边界。

**中级工程师能设计协议** ---- 能处理 Token、签名上下文、重放、PKI、密钥轮换、信封加密和数据保护。

**高级工程师能做治理** ---- 能完成威胁建模、密码学审查、迁移、审计、事故响应和长期加密敏捷性规划。

## 结语

密码学最值得培养的习惯，是在动手前先问：我要保护什么，攻击者能做什么，密钥由谁保管，失败如何处理，未来如何轮换。不要自己造锁，不要把编码叫加密，不要把算法名当安全证明。等你能让一套保护机制在协议、密钥、实现、监控和恢复上彼此对得上，密码学这位严肃锁匠才会把工具箱交给你。
