# 认证授权学习路线

认证和授权是安全系统里的双人门卫：认证回答“你是谁”，授权回答“你能做什么”。一个只会登录不会授权的系统，像门口查了身份证却把整栋楼的钥匙一起发出去；一个只会写角色不会管理会话的系统，则会让已经离职的人继续在门里散步。

这是一条独立的认证授权学习地图，从身份、会话和密码登录走到 Token、JWT、OAuth 2.0、OIDC、SSO、RBAC/ABAC、多租户、服务间认证和工程治理。每一站兼顾常用方案、容易漏掉的边界和值得深挖的协议机制；路线少放代码，重点放在威胁模型、信任边界和方案取舍。

路线按 **身份基础 → 会话 → Token → OAuth → OIDC → 授权模型 → 服务间身份 → 浏览器/移动端 → 生命周期 → 工程治理** 推进。

## 第一站：身份、主体与信任边界

欢迎来到身份登记处。用户、设备、服务、租户和管理员都是主体，声明是它们带来的证件，资源服务器则是那个不接受“我和他很熟”的保安。

**认证与授权** ---- 区分身份确认、权限判断、会话管理和审计记录，避免把登录成功当成所有安全问题都结束了

**主体与资源** ---- 建模用户、服务账号、设备、组织、租户、资源和动作，明确谁对什么资源发起什么操作

**身份提供方与资源服务器** ---- 理解 IdP、客户端、授权服务器、资源服务器和用户代理的角色，知道每个令牌应该给谁看

**信任边界** ---- 标记浏览器、移动端、前端、网关、服务、数据库和第三方之间的信任差异，客户端输入永远不能只因为“来自自家页面”就被信任

**身份声明** ---- 区分用户 ID、用户名、邮箱、角色、权限、租户和设备属性，避免把可变展示字段当作稳定主键

**攻击者模型** ---- 设想凭据泄露、Token 被窃、重放、会话固定、权限提升、钓鱼和内部滥用，按影响与可行性排序

**重点在这** ---- 能画出身份流、令牌流、资源流和信任边界，知道每一步由谁验证、验证什么、失败如何记录

## 第二站：密码登录与 Session-Cookie

第二站是传统登录大厅。服务端发 Session，浏览器带 Cookie，流程朴素却不老土；只要 Cookie 属性、会话轮换和失效策略没偷懒，它依然是许多 Web 应用的稳妥住址。

**密码收集** ---- 处理登录、注册、改密、忘记密码和验证邮箱，限制尝试频率并避免在响应中泄露用户存在性

**密码存储** ---- 使用专用密码哈希、独立盐和可升级成本参数，绝不保存明文或可逆加密后的密码

**Session 生命周期** ---- 管理创建、续期、空闲超时、绝对过期、主动撤销、登出和改密后的全量失效

**Cookie 属性** ---- 理解 Secure、HttpOnly、SameSite、Domain、Path 和过期策略，按会话风险设置而不是复制默认值

**会话固定与轮换** ---- 登录成功、权限变化和敏感操作后轮换会话标识，防止攻击者预先种下的标识被继续使用

**分布式会话** ---- 选择内存、共享缓存、数据库或无状态方案，处理一致性、失效传播、容量和故障恢复

**重点在这** ---- 能从一次登录追踪凭据、会话、Cookie、请求和登出，知道浏览器自动携带凭据带来了哪些 CSRF 风险

## 第三站：Token、JWT 与刷新机制

第三站是令牌印刷厂。Token 让服务可以携带身份声明跨系统流动，但“看起来像一串乱码”不等于安全；JWT 的 Payload 通常只是编码，不是加密。

**访问令牌** ---- 理解 Access Token 的受众、作用域、过期、传输和资源服务器验证，不把它当成永不过期的万能门票

**JWT 结构** ---- 认识 Header、Payload、Signature、Base64URL 和声明字段，明确签名防篡改不等于隐藏内容

**算法与密钥** ---- 区分对称签名、非对称签名、算法允许列表、密钥 ID 和轮换，拒绝从 Token 自己的声明决定信任算法

**声明校验** ---- 验证签发者、受众、过期、未生效时间、主题、作用域和必要业务声明，避免只验签名不验语义

**刷新令牌** ---- 设计短命 Access Token、可撤销 Refresh Token、轮换、重放检测和设备会话管理

**撤销与版本** ---- 处理登出、改密、封禁、权限变化和密钥轮换，理解无状态便利与主动失效能力之间的交易

**Token 存储** ---- 比较内存、HttpOnly Cookie、安全存储和浏览器存储的 XSS、CSRF、体验与跨端风险

**重点在这** ---- 能解释 Token 被盗后暴露多久、谁能撤销、资源服务器如何拒绝错 audience，以及刷新重放如何被发现

## 第四站：OAuth 2.0——授权，不是登录

第四站来到授权协议大厅。OAuth 解决的是“允许某客户端访问某资源”，不是“凭一个字符串证明用户是谁”；把两者混在一起，协议就会开始替你编事故剧本。

**OAuth 角色** ---- 区分资源所有者、客户端、授权服务器和资源服务器，理解授权码、访问令牌与资源请求的流向

**授权码流程** ---- 掌握浏览器跳转、回调、授权码交换和客户端认证，理解为什么授权码不应直接当访问令牌

**PKCE** ---- 认识 code verifier、challenge 和回调拦截风险，为公共客户端与移动端建立抗截获能力

**重定向 URI** ---- 使用精确注册、状态校验和安全回调，避免开放重定向、授权码窃取和登录 CSRF

**Scope 与同意** ---- 设计最小作用域、用户同意、增量授权和资源边界，别让一个“全家桶 scope”把授权变成签字仪式

**客户端类型** ---- 区分机密客户端、公共客户端、单页应用、移动端、设备流和服务账号，选择与无法保密的现实相匹配的流程

**令牌端点安全** ---- 处理客户端认证、限流、错误响应、回调、TLS、重放和日志脱敏

**重点在这** ---- 能画出 OAuth 授权码 + PKCE 的全流程，并说清它解决的风险、没解决的风险和仍需 OIDC 的地方

## 第五站：OpenID Connect 与单点登录

第五站是身份联盟大厅。OIDC 在 OAuth 之上补了身份层，让客户端能知道“这位用户是谁”；SSO 则让用户少输几次密码，但少输不等于少做验证。

**ID Token** ---- 理解 ID Token 面向客户端、Access Token 面向资源服务器的职责差异，校验签发者、受众、nonce 和时间声明

**UserInfo** ---- 认识 UserInfo 端点、访问令牌、声明来源和隐私最小化，避免把展示资料当作永久身份事实

**发现与密钥** ---- 了解 discovery 元数据、JWKS、密钥 ID、轮换与缓存失效，处理身份提供方更新密钥时的过渡窗口

**Nonce 与状态** ---- 使用 state、nonce、PKCE 和精确回调抵御请求伪造、重放和授权响应串线

**SSO 会话** ---- 区分本地应用会话、IdP 会话、单点登录和单点登出，设计过期、撤销和多标签行为

**账号关联** ---- 处理同邮箱、不同 IdP、账号合并、首次登录和已验证邮箱边界，避免自动关联给攻击者送礼物

**企业联邦** ---- 了解 SAML、OIDC、目录同步、群组映射和租户配置，识别外部声明不能直接等于内部权限

**重点在这** ---- 能解释一次 SSO 中谁验证用户、谁签发什么、客户端信任哪些声明，以及退出后哪些会话仍然存在

## 第六站：授权模型与权限工程

第六站是权限规划室。角色是快捷标签，策略才是规则；把所有权限都塞进“管理员/普通用户”两个抽屉，迟早会有一张资源从抽屉里掉出来。

**RBAC** ---- 设计用户、角色、权限和继承，控制角色爆炸、职责冲突和临时授权

**ABAC** ---- 根据主体、资源、动作、环境和上下文做策略判断，适合细粒度条件，但需要可解释与可测试

**ReBAC** ---- 用资源关系、成员关系和组织图表达共享、协作与继承，识别关系图查询和缓存一致性成本

**多租户权限** ---- 将租户边界、资源归属、管理员范围和跨租户操作写进策略，不能只依赖 URL 中的一段 ID

**最小权限** ---- 默认拒绝、按需授权、短期提升和职责分离，避免“为了方便先给全权限”变成永久遗产

**资源级校验** ---- 每个敏感操作都在服务端验证资源所有权、动作和上下文，防止 IDOR 与水平/垂直越权

**权限缓存** ---- 处理策略缓存、权限变更传播、撤销延迟和多服务一致性，明确安全容忍的过期窗口

**策略测试** ---- 用表格、性质、负向用例和审计样例验证允许与拒绝，权限系统最怕只测“管理员能成功”

**重点在这** ---- 能把一句业务权限要求翻译成主体、资源、动作、条件、决策点和审计事件

## 第七站：服务间身份与 API 访问

第七站是后端门禁区。服务之间没有用户坐在屏幕前替它们刷脸，身份、受众、证书和权限都要自己说明白；“内网所以可信”是这里最贵的童话。

**服务账号** ---- 管理服务身份、用途、所有者、范围、轮换和撤销，避免共享万能 API Key

**客户端凭据** ---- 使用客户端认证、短期令牌和最小 scope，区分服务代表自己行动与代表用户行动

**用户委托** ---- 传播用户身份、授权范围和审计上下文，避免服务用自己的高权限覆盖用户原本的限制

**mTLS 与证书** ---- 理解双向 TLS、证书身份、信任链、轮换和吊销，明确网络加密与业务授权不是同一层

**网关与内部服务** ---- 设计边缘验证、服务内复核、Token 受众和请求上下文，不能只在网关验一次然后一路放行

**消息与异步任务** ---- 为消息生产者、消费者、任务所有者和重放建立身份与授权，处理消息复制和延迟权限变更

**密钥托管** ---- 通过密钥管理系统、工作负载身份和短期凭据减少静态秘密，记录访问与轮换

**重点在这** ---- 每个服务请求都能回答“谁在代表谁、访问哪个资源、权限从哪来、过期如何撤销”

## 第八站：浏览器、移动端与设备流

第八站是多端候机厅。浏览器会自动带 Cookie，移动端会丢失网络，设备可能没有键盘；统一身份体验不等于所有端都用同一把钥匙。

**浏览器应用** ---- 处理 Cookie、CSRF、XSS、回调、SameSite 和会话固定，优先保护浏览器无法保守保存的秘密

**单页应用** ---- 理解公共客户端、授权码 + PKCE、内存令牌、静默续期与刷新策略，避免把长期令牌裸奔在可读存储中

**移动端** ---- 使用系统浏览器、深链/应用链接、安全存储、设备绑定和注销，防止回调被恶意应用拦截

**设备授权** ---- 了解无浏览器设备的用户码、验证 URI、轮询、过期和钓鱼提示，限制轮询与授权窗口

**多设备会话** ---- 展示设备列表、远程登出、最近活动和异常登录，平衡安全与用户可理解性

**恢复与换机** ---- 设计备份码、二次验证、设备迁移和人工恢复，恢复流程通常比登录流程更容易成为后门

**重点在这** ---- 每种客户端都要诚实面对“秘密能否保存、回调能否保护、网络是否可靠、用户如何撤销”

## 第九站：身份生命周期、风控与审计

第九站是身份档案馆。账户从注册到删除会经历很多状态，权限也会变化；安全系统不能只在登录那一刻认真五分钟。

**账户生命周期** ---- 管理注册、验证、激活、冻结、删除、恢复和匿名化，明确每个状态能做什么

**入职与离职** ---- 处理组织目录、群组同步、权限开通、回收、转岗和紧急撤销，避免离职账号继续拥有旧世界的钥匙

**自适应认证** ---- 根据设备、地点、行为、风险和操作敏感度触发二次验证或重新认证

**多因素认证** ---- 区分密码、OTP、推送、硬件密钥、生物识别与恢复因子，理解抗钓鱼能力和恢复风险

**异常检测** ---- 观察暴力尝试、Token 重放、异地、设备变化、权限突增和大量资源读取，避免风控只盯登录成功率

**审计日志** ---- 记录主体、动作、资源、结果、来源、关联请求、策略版本和时间，敏感信息要脱敏且不可随意篡改

**隐私与留存** ---- 只收集必要身份属性，规划访问、导出、删除、保留期限和区域合规边界

**重点在这** ---- 认证系统的完成标准不是“能登录”，而是身份可管理、风险可发现、权限可撤销、行为可审计

## 第十站：工程落地与安全验证

最后一站是安全发布室。协议写得正确只是起点，配置、密钥、日志、错误、回滚和测试才决定系统上线后是否会闹脾气。

**失败响应** ---- 统一处理未登录、无权限、过期、撤销、范围不足和策略错误，避免用 500 掩盖权限问题或泄露内部信息

**速率与锁定** ---- 对登录、验证码、Token、刷新、密码重置和授权端点限流，防止暴力攻击又不把正常用户锁在门外

**密钥轮换** ---- 规划密钥生成、分发、双钥并行、JWKS 缓存、旧钥过渡和紧急撤销

**集成测试** ---- 覆盖登录、登出、过期、重放、权限变更、多租户、回调、CSRF、Token 误用和恢复流程

**配置审计** ---- 检查回调 URI、Cookie、CORS、算法、受众、scope、日志和开发开关，生产不能靠“默认应该安全”

**渗透与演练** ---- 用攻击路径验证会话劫持、授权码拦截、越权、Token 重放和账户恢复，记录修复与复测

**事故响应** ---- 预先准备批量撤销、密钥轮换、账户冻结、通知、取证和回滚流程，别等密钥泄露后再召开创意会议

**重点在这** ---- 生产身份系统要安全、可观察、可撤销、可恢复；协议名背得再熟，也不能替代配置审查和攻击验证

## 通关标准

**认证新手能做安全登录** ---- 能区分认证与授权，正确处理密码、Session、Cookie、超时和登出。

**初级工程师能接入 Token** ---- 能校验 JWT 声明、设计刷新与撤销，并处理浏览器和移动端存储边界。

**中级工程师能建权限系统** ---- 能设计 OAuth/OIDC、SSO、RBAC/ABAC、多租户和服务间身份。

**高级工程师能治理身份平台** ---- 能完成生命周期、风控、密钥轮换、审计、演练、事故撤销与合规边界。

## 结语

认证授权像一座不断换班的门禁系统：登录只是第一次验票，真正的工程还包括谁能看什么、什么时候失效、如何撤销、出了事怎么查。先把主体、资源和信任边界画清，再选 Session、Token、OAuth 或 OIDC；先让权限默认收紧，再让体验变顺滑。等你能解释一条身份声明从哪里来、在哪被验证、如何影响决策、怎样被撤销，门卫就不再只是“登录功能”，而是系统安全的骨架。
