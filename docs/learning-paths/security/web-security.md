# Web 安全学习路线

Web 安全像给一座热闹的城市做治安规划：浏览器是居民区，API 是交通枢纽，数据库是金库，第三方服务是隔壁城市。攻击者不一定先撞正门，可能从一张图片、一个跳转、一个对象 ID 或一条日志绕到后院；所以安全不是记漏洞名，而是理解输入、信任边界、身份、权限、输出和恢复。

这是一条独立的 Web 安全学习地图，从威胁建模走到 XSS、CSRF、注入、SSRF、文件上传、越权、浏览器机制、供应链、安全开发、测试与响应。每一站兼顾常见攻击、少见边界和深层原理；路线少放攻击代码，重点放在漏洞为什么发生、防御在哪里生效、失败如何被发现。

路线按 **威胁模型 → 输入输出 → XSS → CSRF → 注入 → 服务器利用 → 越权 → 浏览器防线 → 工程治理 → 验证响应** 推进。

## 第一站：威胁模型与信任边界

欢迎来到 Web 城市的规划局。用户输入是访客，浏览器是半可信居民，第三方回调是外来车辆；先画清谁能影响什么，安全检查才不会只盯着一扇门。

**资产识别** ---- 盘点账户、个人数据、支付、业务状态、密钥、内部服务和可用性，按价值与影响排序

**攻击者能力** ---- 设想匿名用户、已登录用户、低权限用户、恶意租户、被盗 Token、供应商和内部人员能做什么

**信任边界** ---- 标记浏览器、CDN、网关、应用、队列、数据库、对象存储和第三方之间的输入与验证责任

**攻击面** ---- 关注 URL、Header、Cookie、表单、JSON、文件、WebSocket、GraphQL、Webhook、管理入口和调试接口

**安全性质** ---- 分清机密性、完整性、认证、授权、不可否认、可用性和隐私，避免只把安全理解成“不能被黑”

**风险排序** ---- 结合可利用性、影响、暴露范围、检测能力和修复成本决定优先级

**重点在这** ---- 能把一个功能画成数据流和信任边界，指出输入在哪里被验证、输出在哪里被编码、权限在哪里被决定

## 第二站：输入、输出与数据边界

第二站是城市的海关。输入校验负责判断数据形状，输出编码负责防止数据变成代码，参数化负责阻止字符串冒充指令；三位同事各有岗位，不能互相代班。

**输入校验** ---- 使用类型、长度、格式、范围、白名单和业务约束限制数据，理解校验是质量控制而非唯一安全防线

**规范化** ---- 处理编码、Unicode、大小写、路径、URL、空字节和重复参数，避免验证对象与实际使用对象不一致

**输出编码** ---- 根据 HTML、属性、JavaScript、CSS、URL、JSON 和 Header 上下文选择编码，不能拿一种转义包打天下

**参数化接口** ---- 对 SQL、命令、模板、路径和表达式使用结构化参数，避免把数据拼成代码

**解析器差异** ---- 关注代理、网关、框架、浏览器和后端对重复参数、Header、Content-Type 和路径的不同解释

**错误与日志** ---- 向用户返回最小必要信息，向日志记录可诊断上下文并脱敏，避免错误页面变成攻击者的地图

**重点在这** ---- 能说清数据从进入系统到离开的每次转换、验证、编码和解析，不把“前端校验通过”当安全通行证

## 第三站：XSS——让浏览器误把数据当代码

第三站是浏览器剧场。XSS 的危险在于攻击者的内容穿上了脚本戏服，浏览器还热情地替它登台；输出上下文、模板逃生舱和 CSP 是主要防线。

**反射型 XSS** ---- 识别恶意输入经过请求进入响应、再在受害者浏览器执行的路径，防止错误页、搜索和跳转参数成为回声筒

**存储型 XSS** ---- 关注评论、昵称、富文本、工单和画像等持久数据，理解一次存储为何可能影响大量访问者

**DOM 型 XSS** ---- 排查前端把 URL、存储、消息或接口数据送入危险 DOM API 的路径，服务端没参与也不代表安全

**上下文编码** ---- 分别处理 HTML、属性、脚本、样式、URL 和 JSON 输出，理解编码必须发生在正确的输出点

**安全模板与逃生舱** ---- 使用框架默认转义，审查 `innerHTML`、富文本、动态模板、HTML 注入和自定义渲染边界

**CSP** ---- 通过脚本来源、Nonce、Hash、对象、连接和报告策略降低注入后的执行能力，理解 CSP 是纵深防御而不是修复 XSS 的借口

**Cookie 与隔离** ---- 使用 HttpOnly、SameSite、Secure、沙箱和权限最小化降低会话被利用的影响

**重点在这** ---- 能按“输入来源 → 输出上下文 → 浏览器解析 → 影响 → 防御层”分析一条 XSS 链路

## 第四站：CSRF——借浏览器的刀

第四站是跨站请求的交通局。浏览器很热心，会自动带上 Cookie；攻击者只需诱导它发起请求，服务器就可能把恶意动作当成用户本人。

**攻击条件** ---- 理解 Cookie 自动携带、可预测操作、缺少请求来源校验和状态改变接口共同构成 CSRF 风险

**同步 Token** ---- 为表单或请求绑定不可预测令牌，并在服务端校验会话关联、过期和重放边界

**SameSite Cookie** ---- 了解 Strict、Lax、None、Secure 和跨站导航差异，知道它降低风险但不能替代所有校验

**Origin 与 Referer** ---- 校验来源 Header，处理缺失、代理、隐私策略和合法跨域客户端

**无 Cookie API** ---- 理解纯 Bearer Token 请求与 Cookie 会话的风险差异，仍要防止 Token 窃取、重放和 CORS 误配

**敏感操作** ---- 对改密、支付、授权、绑定和删除增加重新认证、二次确认和幂等保护

**跨站状态** ---- 审查 GET 是否改变状态、表单自动提交、图片请求、预取和第三方集成

**重点在这** ---- 能判断一个操作是否具备 CSRF 条件，选择 Token、SameSite、来源校验和重新认证的组合

## 第五站：注入——数据不该变成指令

第五站是指令边界的审计室。SQL、命令、模板、表达式、NoSQL 和 LDAP 都有自己的语言；只要把不可信字符串直接塞进去，攻击者就可能替你补上标点。

**SQL 注入** ---- 理解字符串拼接如何改变查询结构，使用参数化查询、预编译和最小数据库权限

**盲注与二阶注入** ---- 认识错误不可见、时间差、布尔差异和“先存储后触发”的路径，防御不能只依赖页面是否显示错误

**NoSQL 注入** ---- 校验对象结构与操作符，避免客户端可控 JSON 直接进入查询条件

**命令注入** ---- 避免拼接 Shell，优先使用参数数组、固定命令和最小权限；下载、图像处理与压缩工具都可能成为入口

**模板与表达式注入** ---- 区分模板数据与模板语法，限制表达式能力，避免让用户输入获得服务端执行上下文

**LDAP、XPath 与日志注入** ---- 对不同解析器使用对应参数化和编码，防止查询篡改与日志伪造

**ORM 边界** ---- 理解 ORM 不是自动免疫，原生查询、排序字段、过滤表达式和动态表名仍需结构化控制

**重点在这** ---- 每类注入都要回答使用了哪种语言、攻击者能控制哪部分语法、结构化 API 如何切断拼接

## 第六站：文件上传、SSRF 与服务器利用

第六站是服务器后门检查站。文件上传像收快递，SSRF 像让服务器替你打电话；攻击者一旦借到服务器的网络位置、权限或解析能力，内网就不再是安全结界。

**文件类型验证** ---- 同时检查扩展名、MIME、文件签名、大小、数量和内容，不能只相信客户端报来的名字

**文件存储** ---- 将不可信文件放在不可执行、隔离、限权和可扫描的位置，使用不可预测名称与访问控制

**图片与文档处理** ---- 审查解析器、宏、压缩炸弹、路径穿越、元数据和资源耗尽，第三方库也在攻击面里

**路径穿越** ---- 规范化并限制路径根目录，防止 `..`、编码差异、符号链接和归档解压逃逸

**SSRF** ---- 限制 URL scheme、目标网络、DNS 解析、重定向、IP 表示和端口，防止访问云元数据与内部管理面

**DNS Rebinding** ---- 处理解析时与连接时地址变化，避免只在第一次解析时做网络范围判断

**反序列化与解析器** ---- 限制类型、禁用危险功能、验证结构和资源上限，识别“输入看起来只是数据”的执行风险

**重点在这** ---- 能从上传或 URL 输入追踪文件系统、网络、解析器、凭据和权限影响，不把内网当成天然可信

## 第七站：认证、越权与业务逻辑

第七站是权限法院。系统可能没有明显的代码漏洞，却把订单、租户、审批和退款的规则判错；这类漏洞最会穿着“功能正常”的外套。

**身份认证** ---- 保护密码、会话、Token、刷新、恢复和多因素流程，区分已登录与可信身份

**水平越权** ---- 防止用户通过修改 ID、路径、过滤条件或导出参数访问同级他人的资源

**垂直越权** ---- 防止普通用户调用管理员接口、隐藏功能或更高风险动作，服务端必须重做权限判断

**对象级授权** ---- 将主体、资源、动作、租户和上下文一起纳入每次敏感操作决策

**业务逻辑漏洞** ---- 检查价格、库存、优惠、审批、状态转换、重复提交、顺序绕过和时间窗口

**批量与导出** ---- 限制分页、搜索、导出和聚合的范围与速率，防止合法接口被组合成数据搬运机

**竞态条件** ---- 通过幂等键、事务、锁、版本和状态机保护余额、库存、权限和一次性操作

**重点在这** ---- 权限验证必须发生在服务端、资源附近和每次操作中；隐藏按钮不是授权系统

## 第八站：浏览器防线与安全策略

第八站是浏览器的城墙。CORS、CSP、Cookie、点击劫持防护和权限策略各自挡不同方向的箭；城墙再高，应用自己把门敞开也没用。

**同源策略** ---- 理解协议、域名、端口、源、站点和浏览器隔离，知道跨源读取与跨源发送不是同一件事

**CORS** ---- 精确配置允许源、凭据、方法、Header、预检和缓存，避免通配符与凭据组合造成数据外泄

**CSP** ---- 限制脚本、样式、图片、连接、Frame 和对象来源，采用报告、Nonce/Hash 与逐步收紧策略

**安全 Cookie** ---- 使用 Secure、HttpOnly、SameSite、合理 Domain/Path 和过期策略，配合会话轮换

**点击劫持** ---- 配置 frame-ancestors 或相关响应头，识别嵌入、支付和管理界面的覆盖风险

**安全响应头** ---- 了解 HSTS、X-Content-Type-Options、Referrer-Policy、Permissions-Policy 和跨源资源策略

**浏览器存储** ---- 评估 Local Storage、Session Storage、IndexedDB、Cache 与 Cookie 的泄露、持久化和隔离风险

**重点在这** ---- 能根据攻击面选择浏览器策略，并验证策略在真实响应、重定向、子资源和第三方集成中确实生效

## 第九站：安全开发、供应链与秘密

第九站是工程治理办公室。安全不是上线前临时贴的封条，而是需求、设计、编码、依赖、构建、部署和运营都要交作业。

**安全设计** ---- 在需求阶段定义资产、滥用场景、权限、数据分类、失败行为和审计需求

**依赖供应链** ---- 管理依赖版本、漏洞、许可证、来源、锁文件、构建脚本和发布构件

**秘密管理** ---- 使用秘密管理器、短期凭据、最小权限和轮换，避免秘密进入源码、镜像、日志、截图和缓存

**安全默认值** ---- 生产默认启用 HTTPS、身份验证、授权、限流、日志脱敏和安全头，开发开关不能悄悄活到生产

**错误与观测** ---- 记录攻击信号、拒绝原因、关联请求和策略版本，保护日志完整性与个人隐私

**安全编码规则** ---- 将参数化、输出编码、资源限制、路径约束、权限校验和加密封装成可复用模式

**配置与部署** ---- 审查反向代理、CDN、容器、服务账号、网络策略、域名、证书和环境变量边界

**重点在这** ---- 让安全控制进入开发反馈与发布门禁，而不是等扫描器在发布前给团队发一封惊悚邮件

## 第十站：测试、监控与事故响应

最后一站是安全应急中心。防御要可验证，告警要能行动，事故要能止血；“我们应该有日志”不是响应方案，只是一句愿望。

**安全测试** ---- 使用静态分析、依赖扫描、动态扫描、模糊测试、渗透测试和手工审查，理解每种方法能证明什么

**负向用例** ---- 覆盖未登录、错误角色、越界 ID、恶意输入、超大文件、重放、超时和异常状态

**回归保护** ---- 将已修复漏洞转成最小回归测试，验证修复没有只堵住一个 URL 而留下同类入口

**监控信号** ---- 观察认证失败、权限拒绝、注入探针、异常上传、SSRF 尝试、速率异常和数据导出

**告警与分级** ---- 按置信度、影响、范围和响应时间分级，避免告警过多让真正的火灾被背景音乐淹没

**事故止血** ---- 准备禁用账号、撤销 Token、轮换密钥、隔离服务、阻断网络、回滚版本和保留证据的流程

**复盘与改进** ---- 找到根因、逃逸的控制、检测缺口和组织问题，把行动项纳入系统而不是只写在会议纪要里

**重点在这** ---- 安全能力的完成标准是预防、发现、响应、恢复和学习都能闭环

## 通关标准

**Web 安全新手能守住输入** ---- 能理解信任边界，处理输出编码、参数化、Cookie、基本安全头和错误信息。

**初级开发者能修常见漏洞** ---- 能识别 XSS、CSRF、SQL 注入、文件上传、SSRF 和基础越权，并在正确边界防御。

**中级工程师能做安全设计** ---- 能建模身份、权限、租户、业务状态、供应链、秘密和浏览器策略。

**高级工程师能治理风险** ---- 能推动安全测试、监控、响应演练、漏洞回归、密钥轮换和持续改进。

## 结语

Web 安全不是把漏洞清单背成绕口令，而是让数据、身份、权限、浏览器、服务和运维彼此知道边界。先建威胁模型，再选控制；先验证服务端，再优化体验；先准备失败与恢复，再谈“绝对安全”。等你能解释一条输入如何变成代码、一个 ID 如何越权、一枚 Cookie 如何被滥用，以及事故后怎样止血，Web 安全就从吓人的警报声变成了可以治理的工程能力。
