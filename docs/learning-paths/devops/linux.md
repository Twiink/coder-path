# Linux 系统管理学习路线

Linux 是基础设施界那位穿灰色工装的老管家：平时不抢镜，却把进程、文件、网络、磁盘和权限全安排得明明白白。容器、数据库、CI/CD、云主机看起来各有一套魔法，落到底层，往往还是一组 Linux 进程在读写文件、等待 I/O、监听端口。

这条路线不要求把命令背成咒语，而是建立一套“看到症状就能定位层次”的心智模型：先认识系统，再管理运行时；先学会观察，再动手修改；先在可恢复的实验机上折腾，再把经验带到生产。命令只选最常用和最能迁移的一组，偏门能力会告诉你它解决什么问题、什么时候值得掏出来。

**推荐顺序** ---- Shell 与文件系统 → 文本处理与查找 → 用户、权限与安全边界 → 进程与服务运行时 → 网络与 SSH → 磁盘、文件系统与软件包 → 日志与调度 → Shell 自动化 → 资源与性能排障 → 发布、可靠性与演进

## 第一站：终端、文件系统与命令骨架

第一站先和 Linux 的门卫打招呼。它不在乎你是新手还是架构师，只认当前目录、环境变量和退出码；路径写错时，它会用一脸冷漠的“找不到文件”提醒你保持谦逊。

**目录层次** ---- 认识 `/etc` 配置、`/var` 运行数据与日志、`/usr` 程序、`/home` 用户目录、`/tmp` 临时文件、`/proc` 进程视图、`/sys` 内核与设备视图；知道 FHS 是约定，不同发行版会有少量差异

**路径与文件操作** ---- 熟悉绝对路径、相对路径、隐藏文件、符号链接与硬链接，以及 `pwd`、`ls`、`cd`、`cp`、`mv`、`mkdir`、`touch`、`rm` 的边界；删除前确认路径，递归删除永远当作高风险操作

**查看大文件与二进制** ---- 小文件用 `cat`，大文件用 `less`，日志用 `tail`，类型用 `file`，需要字节级判断时认识 `od`、`xxd`；不要把二进制文件当成乱码日志强行阅读

**Shell 的展开顺序** ---- 理解别名、变量、命令替换、通配符、引号、重定向和管道的大致顺序；知道带空格、通配符或用户输入的路径为什么必须正确引用

**标准输入输出与退出码** ---- 认识 stdin、stdout、stderr、文件描述符、`>` 覆盖、`>>` 追加、`2>` 错误输出和管道；命令退出码为 0 代表成功只是惯例，脚本要主动检查它

**终端效率** ---- 掌握 Tab 补全、历史搜索、前台中断、挂起、退出、后台任务和 `tmux`；SSH 断开时，tmux 能让长任务继续活着，不必每次都和网络一起心跳停止

**编辑与求助** ---- 至少会用 `vi` 或 `nano` 修改配置，能读 `man`、`--help` 和发行版文档；先看命令作用、参数和示例，再把危险选项交给生产环境

## 第二站：文本处理、查找与数据搬运

第二站的 Linux 像一位会做侦探笔录的编辑：给它一堆日志和配置，它能用正则、列和计数把线索捞出来。真正高效的运维不是敲一条神秘巨命令，而是把小工具接成一条可解释的流水线。

**grep 与正则** ---- 用 `grep` 搜索文本，理解固定字符串、扩展正则、反选、忽略大小写、行号、计数和递归搜索；复杂正则要写得可读，避免为了省一行把同事送进迷宫

**sed 的流式编辑** ---- 认识替换、打印区间、删除匹配行和原地修改；原地改配置前先不落盘预览，保留备份并确认匹配范围，避免一条宽泛规则把整份配置改成抽象画

**awk 的列式分析** ---- 掌握记录、字段、分隔符、行号、列数、条件和聚合；它适合从访问日志、表格输出、监控快照中计算频次和总量，但不应被当成完整数据库

**排序、去重与计数** ---- 熟悉 `sort`、`uniq`、`wc`、`cut`、`tr`、`paste` 和 `join` 的组合关系；去重计数通常先排序再聚合，数字排序与字典序排序不要混淆

**find、xargs 与文件安全** ---- 按名称、类型、大小、时间、属主查找文件，理解 `-print0` 与空格文件名；批量删除或执行前先把结果输出检查一遍，再考虑 `xargs` 或 `-exec`

**结构化文本工具** ---- 认识 `jq` 处理 JSON、`column` 整理表格、`diff` 比对配置、`file` 判断格式；日志格式越结构化，后续统计、告警和审计越省力

**管道的可维护性** ---- 每段管道只承担一个清晰动作，给关键中间结果留临时文件或注释；排障命令要能复现、能解释、能被别人接手，而不是只在你的终端里神奇地成功

## 第三站：用户、权限与安全边界

第三站由 Linux 的保安队长值班。它的口头禅是“能不能访问”和“为什么能访问”必须分开回答；权限设得太松会给入侵者开门，设得太紧又会让应用自己锁在门外。

**用户与组** ---- 理解 UID、GID、主组、附加组、系统用户、登录 Shell 和用户家目录；为服务创建专属账号，避免所有进程都用同一个高权限身份

**传统权限模型** ---- 掌握文件和目录的属主、属组、读写执行位、八进制表示、目录执行权限与默认权限；文件的可读不等于目录可遍历，权限判断要沿路径逐级看

**umask 与默认权限** ---- 理解创建文件时权限如何被 `umask` 收紧；密钥、令牌、配置和临时文件要有明确的默认权限，不能依赖“大家应该不会去看”

**sudo 与提权边界** ---- 使用最小化的 sudoers 规则、记录提权行为并避免把整套 Shell 交给应用；`sudo` 是临时授权工具，不是把 root 当成万能胶带

**ACL、能力与特殊位** ---- 了解 POSIX ACL 处理精细授权，认识 setuid、setgid、sticky bit 的用途与风险；Linux capabilities 可以拆分部分 root 能力，但也要审计是否给得过宽

**强制访问控制** ---- 知道 SELinux、AppArmor 与传统 rwx 的区别，遇到拒绝时查看审计日志和安全上下文；临时关闭安全模块只能用于隔离实验，不能当作正式修复

**凭据与敏感信息** ---- 区分密码、SSH 私钥、API Token、证书和配置文件的保护方式；不把秘密写进 Shell 历史、公共日志、镜像层或世界可读目录

## 第四站：进程、线程与 systemd 运行时

第四站进入 Linux 的后台：进程像一群各自忙碌的员工，线程在共享地址空间里搬货，systemd 像严厉的值班经理，负责启动、重启、记账和追问“你为什么又崩了”。

**进程与线程** ---- 理解 PID、PPID、进程组、会话、线程、僵尸进程和孤儿进程；知道 `/proc/<pid>` 能看到命令行、环境、文件描述符和资源信息

**查看与控制进程** ---- 用 `ps`、`top` 或 `htop` 看 CPU、内存、线程和状态；优先发送 TERM 让程序收尾，再使用 KILL 处理失控进程，并理解信号不等于“强制执行某个业务动作”

**文件描述符与限制** ---- 认识进程打开的文件、Socket、管道都占用文件描述符；遇到“too many open files”时同时检查应用泄漏、进程级限制、用户级限制和系统上限

**环境与启动上下文** ---- 比较交互式 Shell、cron、systemd 和容器中的环境差异；服务无法启动时先确认工作目录、PATH、用户、环境变量和权限，不要只盯着业务代码

**systemd 单元** ---- 掌握 service、socket、timer、target 的职责，理解启动、停止、重载、开机启用、依赖关系和重启策略；服务定义要写清 User、WorkingDirectory、Environment、ExecStart 与 Restart

**journalctl 与服务现场** ---- 按服务、时间、优先级查看 journald 日志，结合状态、退出码和最近一次重启判断故障；“服务没了”通常只是最后一幕，日志才是前情提要

**cgroup 与 namespace** ---- 理解 cgroup 做资源计量与限制，namespace 提供进程、网络、挂载、用户等隔离；这两组内核能力是容器运行时的地基，不要把容器误认为轻量虚拟机

## 第五站：网络、Socket 与 SSH

第五站请网络管理员出场。它对“网站打不开”的回答永远是“哪一层打不开”：接口、端口、路由、DNS、TLS、认证还是应用，每一层都有自己的证据。

**网卡、地址与路由** ---- 使用 `ip addr`、`ip link`、`ip route` 观察接口状态、IPv4/IPv6 地址、默认路由和策略路由；虚拟网卡、桥、隧道和云安全组都可能改变真实路径

**Socket 与监听端口** ---- 用 `ss` 查看 TCP/UDP 状态、监听地址、连接队列和所属进程；区分只监听 localhost、监听内网地址和监听所有地址带来的暴露面

**TCP、UDP 与连接生命周期** ---- 理解握手、端口、连接状态、超时、重传、拥塞和半连接队列；服务端“端口开着”不代表应用一定能处理请求，还要看 backlog、线程和下游依赖

**DNS 排障** ---- 掌握解析器、缓存、TTL、权威服务器、A/AAAA/CNAME/TXT 等记录的基本作用，使用 `dig` 分别查询递归解析与权威回答；DNS 错误常常伪装成网络或应用故障

**HTTP、TLS 与 curl** ---- 用 `curl` 观察请求方法、状态码、重定向、响应头、代理、证书和超时；区分连接成功、TLS 成功、HTTP 成功和业务成功这四个层次

**防火墙与云网络** ---- 认识 nftables、iptables、ufw、firewalld、云安全组、子网和负载均衡的职责边界；排查连通性要从客户端、路由、策略、服务端监听到应用逐层验证

**SSH 与安全通道** ---- 使用密钥、Host 别名、跳板机、端口转发和 agent forwarding；私钥权限收紧，禁用不必要的密码登录与 root 直登，并审计谁能进入哪台主机

## 第六站：磁盘、文件系统、软件包与资源

第六站是 Linux 的仓库管理员。它会提醒你：磁盘空间用完只是其中一种“写不进去”，inode、挂载、只读文件系统、配额和 I/O 延迟也能让服务当场摆烂。

**块设备、分区与挂载** ---- 认识块设备、分区、文件系统、挂载点、UUID 和 `/etc/fstab`；用 `lsblk`、`findmnt`、`mount` 判断“设备存在”“已经挂载”“路径可写”并不是同一件事

**文件系统与 inode** ---- 理解 ext4、XFS 等文件系统的基本差异、inode、目录项、链接、保留空间和只读挂载；小文件海啸可能先耗尽 inode，日志删除后空间不回收则可能是进程仍持有文件描述符

**空间与 I/O 诊断** ---- 用 `df` 看分区、`du` 找目录、`iostat` 看设备、`iotop` 看进程；空间问题、吞吐问题、延迟问题和 I/O 等待要分别测量

**LVM、快照与云盘** ---- 了解物理卷、卷组、逻辑卷、在线扩容和快照的用途；快照不是备份，云盘扩容后还要分别扩分区、文件系统和应用数据目录

**软件包与供应链** ---- 区分 apt、dnf、rpm、dpkg、仓库、签名、依赖和锁文件；优先使用发行版或组织维护的软件包，记录版本与来源，避免“手工编译后没人知道怎么升级”

**内核参数与资源限制** ---- 认识 `sysctl`、`ulimit`、进程优先级、nice、CPU 亲和性和内存 overcommit 的适用边界；参数调整必须有指标、回滚方案和版本记录，不能照抄一张万能调优表

**内存与交换** ---- 看 `free` 时关注 available、回收、swap、缓存和 OOM，而不是只盯 free 数字；swap 能缓冲尖峰但不能替代内存，数据库与低延迟服务要按工作负载决定策略

## 第七站：日志、审计与定时调度

第七站的日志管理员像一位记性过分好的会计：什么时间、哪个服务、哪个用户、做了什么，它都想记；但日志没有保留策略就会把磁盘吃成自己的年夜饭。

**日志来源与级别** ---- 区分应用 stdout/stderr、journald、syslog、内核日志、审计日志和云平台日志；统一时间、主机、服务、请求标识和严重级别，才能跨组件拼出事件链

**日志检索与保留** ---- 用 `journalctl` 按服务、时间、优先级筛选，理解持久化 journald、转发和采集代理；为日志轮转、压缩、保留期、脱敏和访问权限制定规则

**logrotate 与文件句柄** ---- 了解复制截断、重命名轮转、应用 reopen 和压缩时机；轮转后应用仍写旧文件会造成“日志不再增长但磁盘仍在涨”，需要结合进程打开文件检查

**cron 与 systemd timer** ---- 掌握定时任务的时间表达、用户上下文、环境变量、锁与超时；systemd timer 可与 service、日志、依赖和失败重试配合，复杂任务不要只留在某台机器的个人 crontab 里

**审计与变更记录** ---- 认识 auditd、sudo 记录、登录记录、包变更和配置版本；安全审计与业务日志要分层保存，既能追责又不把敏感数据到处复制

**时间同步** ---- 了解 NTP、chrony、时钟漂移和时区展示；分布式日志、证书、缓存过期、数据库事务与追踪都依赖可信时间，服务器时区不统一时排障会像看错字幕

## 第八站：Shell 自动化与配置管理

第八站让 Shell 从“临时小抄”升级成“可重复工具”。它很勤快，也很容易闯祸：少一个引号就能把文件名拆开，少一个失败检查就能让错误一路滚到生产。

**脚本结构与参数** ---- 掌握 shebang、位置参数、标准输入、函数、退出码、临时目录和帮助信息；脚本应明确输入、输出、副作用与失败状态

**安全脚本习惯** ---- 理解 `set -euo pipefail` 的价值与例外，给变量加引号，使用安全临时文件，避免把用户输入拼接进命令；严格模式是安全带，不是自动驾驶

**条件、循环与并发** ---- 会做文件、进程、端口、数字和字符串判断，理解循环中的空格与换行边界；批量操作要有并发上限、超时、重试、幂等和失败清单

**锁、陷阱与清理** ---- 使用 lockfile 或 flock 防止定时任务重入，用 trap 清理临时资源并捕获退出；脚本被中断后仍能恢复，是自动化从玩具变工具的分水岭

**备份与健康检查脚本** ---- 能检查磁盘、内存、端口、服务、证书到期和备份新鲜度；备份脚本必须验证恢复，而不是只统计“文件成功生成”

**Ansible 与声明式配置** ---- 理解 Inventory、Playbook、模块、角色、变量、Vault 和幂等；主机数量增加后，把手工 SSH 命令变成可审查、可重复、可回滚的配置

**基础设施即代码** ---- 认识 Terraform 等工具的状态、计划、漂移、模块和审批边界；资源创建、系统配置、应用发布要分层，避免一个脚本既改云网络又改业务文件

## 第九站：资源、性能与分层排障

第九站是性能医生。它不接受“感觉很慢”这种病历，而是要求你拿出负载、CPU、内存、I/O、网络、进程和日志的证据，先定位瓶颈，再讨论药方。

**USE 与 RED 思路** ---- 对基础设施看利用率、饱和度、错误；对服务看请求速率、错误率、延迟；不要把单一 CPU 百分比当成整台机器的健康证明

**负载与 CPU** ---- 理解 load average 是等待运行或不可中断睡眠的任务数量，要结合 CPU 核数、运行队列、上下文切换和 I/O wait 判断；负载高不一定是 CPU 高

**内存与 OOM** ---- 使用 `free`、`vmstat`、`smem`、`dmesg` 观察回收、swap、RSS、页错误和 OOM killer；容器或服务被杀时，同时检查宿主机与 cgroup 内存限制

**磁盘与网络瓶颈** ---- 用 `vmstat`、`iostat`、`sar`、`ss` 和应用指标定位队列、延迟、重传、连接耗尽与带宽；同一个“请求超时”可能是磁盘卡住，也可能是连接池排队

**系统调用与内核现场** ---- 了解 `strace` 看系统调用，`lsof` 看文件和 Socket，`perf` 看 CPU 热点，eBPF 工具看调度、网络和 I/O；进阶工具要在采样边界和生产开销可控时使用

**核心转储与故障现场** ---- 配置 core dump、保留崩溃时间线和二进制符号，区分应用崩溃、被信号终止、被 OOM 杀死和服务管理器重启；现场证据比“重启后好了”更有价值

**十分钟体检路径** ---- 先确认时间与主机，再看服务状态、端口、日志、负载、内存、磁盘、连接和依赖；每一步都记录结论，避免在多个猜测之间来回跳舞

## 第十站：发布、加固、可靠性与演进

最后一站把单机能力接到工程系统。Linux 管家终于要退休了吗？没有，它只是把钥匙交给自动化、镜像和平台；底层心智仍然决定你能不能解释发布失败、节点失联和容量账单。

**服务器上线基线** ---- 完成补丁、时钟、主机名、专属用户、SSH 密钥、防火墙、最小权限、SELinux/AppArmor、日志和备份配置；云安全组与主机防火墙要一起检查

**发布与回滚** ---- 认识停止替换、滚动、蓝绿、金丝雀和不可变镜像的区别；发布前准备健康检查、迁移兼容性、回滚版本、配置回滚和数据恢复路径

**可靠性基本功** ---- 为服务设置启动超时、优雅停止、自动重启上限、依赖重试、熔断和磁盘水位；自动重启只能恢复进程，不能修复数据损坏或错误配置

**备份、恢复与灾难演练** ---- 备份应用配置、数据库、密钥材料和基础设施状态，保留异地副本并定期做恢复演练；明确 RPO、RTO、负责人和恢复顺序

**容量与成本** ---- 记录 CPU、内存、磁盘、带宽、日志和备份增长，设置水位与预算；小规格实例未必便宜，人工维护、过度预留和无效日志都可能是更大的账单

**从单机到容器与集群** ---- 当发布、隔离、伸缩和多机调度超过 Shell 的舒适区，再进入 Docker、Kubernetes、CI/CD 和云平台；知道何时升级抽象层，比盲目上平台更重要

## 通关标准

能在一台陌生 Linux 主机上完成一次安全体检：说清服务、端口、进程、负载、内存、磁盘、日志和权限的现状；能用文本工具从日志中统计异常；能写一个带参数、退出码、锁、日志和清理逻辑的健康检查或备份脚本；能创建 systemd 服务并解释其运行上下文；能从 DNS、路由、Socket、TLS 到应用逐层排查网络故障；能完成最小权限的 SSH 与防火墙加固；能说明一次发布的健康检查、回滚和恢复证据。

## 下一站去哪

先去 Docker，把 Linux 的进程、namespace、cgroup、文件系统和网络能力装进可交付的镜像；如果更关心内核原理，则补操作系统、计算机网络和文件系统，再回到容器与 Kubernetes。

## 结语

Linux 的真正通关不是记住一串命令，而是面对“慢、挂、满、拒绝访问、连不上”时，能把问题拆成可验证的层次。你越会观察，就越少需要靠重启碰运气；你越能自动化，就越少需要在凌晨手工敲命令。把实验机折腾坏几次，系统反而会变成可靠的老师。
