# Vue 学习路线

Vue 是一套“先让你做出东西，再慢慢揭开魔法”的渐进式框架。它把模板、响应式、组件、路由和状态管理串起来，适合从一个小组件一路长成完整应用。亲民不等于浅：响应式追踪、编译器优化、渲染器调度和服务端水合，背后都有一整套精密机械。

这条路线是**索引和指引**。它不把每个指令写成 API 字典，也不让页面被大段代码占领；每一站告诉你要建立什么心智模型、要覆盖哪些常用与冷门知识、往深处应该去学习笔记查哪条线。

## 第一站：模板语法与单文件组件

欢迎来到 Vue 的模板剧场：插值负责念台词，指令负责调度，key 是每个演员的身份证，单文件组件则把舞台、剧本和灯光放进同一个文件。先学会和模板沟通，别一上来就把所有业务逻辑塞进双花括号。

**插值与表达式** ---- 认识文本插值、表达式边界、自动转义和模板中不该出现的语句；模板负责描述视图，复杂业务逻辑请移到脚本层，不要把模板养成意大利面

**属性绑定** ---- 掌握普通属性、动态属性、对象批量绑定和布尔属性；理解绑定值的类型、空值行为以及属性与 DOM property 的区别

**事件绑定** ---- 覆盖内联处理器、方法处理器、事件参数、动态事件名和修饰符；理解阻止冒泡、默认行为、按键和系统修饰键背后的浏览器事件模型

**双向绑定** ---- 认识输入框、复选框、单选框、选择器、文本域和组件的模型绑定；理解它是语法糖，不是数据流方向消失了

**条件渲染** ---- 区分真正创建和销毁节点的条件渲染、只切换显示状态的方案，以及条件分支中的状态保留和生命周期差异

**列表渲染** ---- 掌握数组、对象和数字列表，理解 key 的唯一性、稳定性、状态复用和列表更新成本；不要拿 index 给动态列表当身份证

**指令体系** ---- 熟悉文本、HTML、显示、一次性渲染、跳过编译、缓存子树等内置指令；知道每个指令改变的是渲染、编译还是更新策略

**模板引用** ---- 了解对 DOM、组件实例和循环节点的引用方式；关注引用何时可用、更新时机和为什么不能把它当成 React 式状态

**插槽初识** ---- 建立默认插槽、具名插槽和作用域插槽的概念；插槽是内容分发协议，不是“子组件随便把父组件的 DOM 拿走”

**单文件组件结构** ---- 理解模板、脚本、样式三块如何被编译，认识 scoped 样式、CSS Modules、深度选择器和样式变量的边界

**编译宏与开发体验** ---- 了解 script setup、Props、Emits、Expose、Model、Options、Slots 等宏的职责；宏是编译期能力，不是运行时全局函数

**重点在这** ---- 模板要声明“页面应该长什么样”，脚本要处理“数据如何变化”；把两者职责混在一起，Vue 也只能替你叹气

## 第二站：组件模型与通信

第二站来到组件装配厂：Props 是进料单，Emits 是出货单，Slots 是可替换的内饰，attrs 则是那些差点漏填的快递信息。组件边界画得好，后面状态管理和测试就不会天天上演“到底是谁改了它”。

**组件注册与解析** ---- 理解局部注册、全局注册、自动导入和组件命名；关注 tree-shaking、命名冲突和组件来源可追踪性

**Props 输入契约** ---- 学习声明类型、必需性、默认值、校验和单向数据流；父组件给的是输入，不是子组件可以随手涂改的共享草稿

**Emits 输出事件** ---- 设计事件命名、载荷校验和父子协作；事件表达“发生了什么”，不要把它伪装成远程操控父组件内部变量

**属性透传** ---- 理解未声明属性如何落到根节点、多根节点组件的透传策略和手动绑定；组件根节点变化时，透传行为可能跟着变

**事件与属性继承** ---- 区分监听器、原生属性、组件声明属性和 fallthrough attrs；这是封装输入组件时最容易“看起来能用、细节很刺”的地方

**插槽协议** ---- 深入默认、具名、作用域、动态和后备插槽；关注插槽作用域、渲染权归属、可测试性和组件 API 的长期稳定性

**组件 `v-model`** ---- 理解单模型、多模型、修饰符和自定义组件双向绑定；本质仍是受控输入与更新事件的约定，不是状态瞬移

**依赖注入** ---- 使用 provide 与 inject 解决跨层级依赖；理解注入键、响应式值、默认值和隐式依赖的可维护性风险

**组件实例暴露** ---- 了解 expose 的边界，知道什么时候父组件需要调用子组件能力；如果暴露了半个内部世界，封装就开始漏风

**动态与异步组件** ---- 认识组件切换、缓存、异步加载、加载状态、错误状态和 Suspense；把“延迟加载”与“暂时没写完”分清

**递归与高阶组件** ---- 了解树形组件、包装组件、渲染代理和组合式封装；组件抽象要围绕稳定变化点，不要为了复用三行模板造一座城

**重点在这** ---- 组件通信的主线是输入、输出、内容分发和跨层依赖；边界越清楚，组件越像零件，越不像一锅粥

## 第三站：响应式系统

第三站进入响应式侦探所：ref 和 reactive 是线人，computed 会记账，watch 负责盯梢，track 与 trigger 则在后台画依赖关系。数据改了页面会变只是表面，真正的剧情是“谁读了它，谁该被通知”。

**响应式容器** ---- 区分 ref、reactive、readonly、shallowRef、shallowReactive 和标记原始值等模型；理解容器层级、深浅代理和解包规则

**依赖追踪** ---- 建立 track、trigger、依赖集合和副作用函数的概念；知道读取会建立关系，写入才会触发更新，没读过的数据不会凭空订阅

**Proxy 与反射** ---- 理解 Vue 3 为什么采用 Proxy、它能拦截哪些操作、数组和 Map 等集合为何需要特殊处理；也要知道代理不是没有边界的魔法

**计算属性** ---- 学习惰性求值、缓存、脏标记、可写计算属性和依赖传播；计算属性适合派生值，不是把所有副作用塞进一个 getter

**侦听器** ---- 掌握 watch、watchEffect、同步与异步依赖、深度监听、立即执行、一次执行和清理回调；监听是副作用工具，不是计算属性的替身

**调度器与刷新时机** ---- 理解批量更新、微任务队列、pre、post、sync 等刷新阶段；知道为什么修改数据后 DOM 还没立即改变

**响应式解构** ---- 认识解构、展开、toRef、toRefs、unref 和响应式丢失的关系；“看起来只是换了个写法”有时会把订阅线剪断

**副作用作用域** ---- 学习 effect scope、组件卸载时的自动清理和组合式函数中的资源管理；定时器、监听器和请求不能靠祈祷自动消失

**数组与集合响应式** ---- 关注索引、长度、迭代、Map、Set、键和值变化的追踪差异；这些是深入源码和排查性能问题的重要入口

**调试响应式** ---- 了解渲染追踪、触发调试钩子和开发工具；排查更新问题时先问“依赖有没有被读到”，不要马上给页面再套一层 watch

**重点在这** ---- 响应式不是“任何变化都重绘”，而是依赖图和调度器合作的结果；理解它，才知道什么时候该用 ref，什么时候该删掉一个 watch

## 第四站：Composition API 与逻辑复用

第四站是 Composition API 的收纳课：不再把同一功能拆散到 data、methods、computed 三个抽屉，而是按业务把它们整套收好。自由度变高了，乱放东西的责任也一起变高了，清理副作用尤其不能装失忆。

**setup 的执行模型** ---- 理解 setup 运行时机、组件实例可用范围、返回值暴露和异步 setup 的限制；setup 不是“另一个 mounted”

**script setup** ---- 掌握顶层暴露、自动注册、宏、泛型支持和编译期限制；知道哪些东西能直接使用，哪些仍然是普通 JavaScript 运行时行为

**组合式函数** ---- 设计输入、输出、响应式保持、副作用清理和错误状态；好的 composable 像小型服务，坏的 composable 像全局变量穿上了外套

**生命周期** ---- 覆盖挂载、更新、卸载、激活、停用、错误捕获和渲染调试钩子；重点理解生命周期是组件实例的时间线

**模板引用与组合式函数** ---- 处理 DOM、组件实例和异步节点的可用时机；组合式函数应尽量返回能力，而不是把整个组件内部暴露出去

**组合式函数的资源管理** ---- 为事件、定时器、观察器、请求和订阅设计取消与清理；卸载后还在更新状态，是前端版的幽灵来信

**可测试性** ---- 让组合式函数的输入输出清晰，尽量减少隐式全局依赖；复杂逻辑可以脱离组件测试，别让每个测试都先搭一栋房子

**SSR 下的组合式函数** ---- 识别浏览器对象、服务器执行、多实例隔离和水合差异；服务端代码不能偷偷访问 window，然后等生产环境来抓现行

**重点在这** ---- Composition API 的高级感来自逻辑边界，而不是把所有代码都挪进 setup；复用要降低认知成本，不要换一种方式制造迷宫

## 第五站：状态管理与数据流

第五站进入状态管理办公室：局部状态是个人抽屉，Pinia 是共享档案室，服务端数据则是外单位寄来的快递。先搞清谁拥有、谁能改、多久过期，再决定要不要把一个输入框也送进中央仓库。

**局部状态优先** ---- 先判断状态是否只属于当前组件、是否是可派生值、是否能通过 Props 和 Emits 传递；别因为有 Pinia 就把输入框也送进仓库

**Pinia 的核心模型** ---- 认识 store、state、getters、actions、组合式与选项式写法；理解 store 是业务状态边界，不是所有变量的公共储物间

**状态修改与批处理** ---- 关注直接修改、批量 patch、重置、订阅和开发工具；状态变化应能追踪，别让修改路径像密室逃脱

**跨 store 协作** ---- 处理 store 之间的依赖、循环引用和初始化顺序；大型项目需要按业务领域拆分，而不是按“感觉方便”随手建一个巨型 store

**持久化与恢复** ---- 设计本地存储、版本迁移、失效、隐私和跨标签同步；持久化的是用户体验，不是把所有状态永久供奉

**服务端状态** ---- 区分客户端状态、远程缓存、请求状态和派生视图；列表数据、缓存失效和重新验证通常需要专门的数据获取策略

**权限与敏感状态** ---- 认识前端状态只是界面提示，真正的权限必须在服务端验证；不要把“按钮隐藏”误当成“权限完成”

**状态调试** ---- 学习时间旅行、订阅日志、状态快照、开发工具和最小复现；能追踪状态从哪里来，比会写一百个 action 更重要

**重点在这** ---- 状态管理的目标是让数据流可预测；如果所有组件都能改所有状态，那不是灵活，是全村一起拧同一根水管

## 第六站：Vue Router 与应用导航

第六站来到 Vue Router 交通局：URL 是路牌，router-view 是站台，守卫是检票员，懒加载是分时段发车。页面能跳过去只是起点，还要能刷新、返回、分享，并且别把没权限的人送进后门。

**路由表与匹配** ---- 认识静态路径、动态参数、可选参数、通配符、优先级和匹配顺序；路由表本质是一套 URL 解析规则

**Router View 与 Link** ---- 理解渲染出口、导航链接、激活状态和嵌套出口；布局组件与页面组件要分工，不要把整棵应用树塞进一个页面

**编程式导航** ---- 掌握 push、replace、前进后退、重复导航和导航失败；导航是异步流程，不能只把它当成改字符串

**路径参数与查询参数** ---- 区分 params、query、hash 和 history 状态；参数来源不同，缓存、分享、刷新和安全含义也不同

**嵌套路由与布局** ---- 用 children 组织页面层级、共享布局和局部出口；嵌套应该反映界面结构，不要为了少写一个组件硬套层级

**命名路由与命名视图** ---- 让导航和多区域布局不依赖脆弱字符串；多视图适合复杂工作台，但也会增加状态同步成本

**导航守卫** ---- 区分全局、路由级、组件级守卫和异步流程；权限、未保存提醒、登录跳转和数据预检要各司其职

**路由元信息** ---- 用元信息表达权限、标题、面包屑、布局和过渡策略；元信息应是声明，不要把业务逻辑藏成一串 if

**懒加载与错误处理** ---- 按路由拆分代码，处理加载失败、网络断开、404 和导航取消；用户看到的不是“chunk error”，而是可恢复的体验

**滚动行为** ---- 设计回到顶部、锚点、前进后退恢复和异步内容后的滚动策略；滚动位置也是状态，只是经常被忘记的那种

**重点在这** ---- 路由是应用的骨架和入口协议；URL 要能表达位置、状态和权限边界，不能只追求“点击能跳过去”

## 第七站：渲染器、编译器与性能

第七站下潜到 Vue 的发动机舱：响应式负责发通知，编译器负责提前找重点，渲染器负责搬 DOM，浏览器负责最后验收。虚拟 DOM 不是速度护身符，真正的性能要看谁在更新、更新了多少、用户等了多久。

**虚拟 DOM 与渲染器** ---- 了解 vnode、组件更新、元素创建、属性更新、卸载和补丁流程；先理解更新发生在哪里，再谈优化

**Diff 与 key** ---- 认识同层比较、节点复用、移动、插入和删除；key 不只是消除警告，它决定列表状态是否被正确复用

**编译器优化** ---- 了解静态提升、事件缓存、Patch Flag、Block Tree 和编译时常量；编译器会帮忙，但不会替你修复错误的组件边界

**更新批处理** ---- 理解响应式触发、队列去重和 DOM 提交时机；减少无意义更新比盲目给每个地方加 memo 更有效

**v-once 与 v-memo** ---- 认识一次性渲染与按依赖跳过子树的场景；优化指令是手术刀，不是全站撒胡椒粉

**KeepAlive** ---- 了解缓存组件、激活停用、include、exclude 和缓存淘汰；缓存状态很方便，也可能把过期数据养成常驻居民

**异步组件与 Suspense** ---- 处理按需加载、加载占位、错误回退和异步依赖；性能优化最终要落到用户等待时看到了什么

**大列表与高频更新** ---- 学习虚拟列表、分页、窗口化、节流、批处理和可见性策略；一万条数据全塞进 DOM，浏览器也会有情绪

**水合与 SSR 性能** ---- 理解服务端 HTML、客户端接管、结构不一致、延迟水合和浏览器专属逻辑；SSR 不是免费午餐，服务端与客户端要演同一出戏

**性能诊断** ---- 结合 DevTools、性能时间线、组件更新追踪、网络瀑布和 Web Vitals 定位瓶颈；先测再优化，避免对着感觉做体操

**重点在这** ---- 性能来自正确的更新边界、稳定的数据流和合理的加载策略；“加一个缓存”不等于性能工程结束

## 第八站：服务端渲染与 Nuxt 入口

第八站办理 Vue 的跨平台通行证：CSR 坐浏览器班车，SSR 让服务器先端菜，SSG 提前把餐盒打包，ISR 则定时回来换新。先弄清内容在哪生成、何时更新，再去 Nuxt 站点继续深挖。

**CSR、SSR 与 SSG** ---- 区分浏览器渲染、请求时渲染和构建时生成；它们在首屏、SEO、服务器成本、数据新鲜度和交互接管上各有账单

**水合** ---- 理解客户端如何接管服务端 HTML、为什么结构和数据必须一致，以及浏览器专属 API 应该放在哪个边界

**服务端数据与客户端状态** ---- 区分首屏数据、客户端缓存、用户会话和交互状态；不要让同一份数据在两个世界各自长成两只脾气不同的猫

**异步组件与流式输出** ---- 认识 Suspense、流式 HTML、异步依赖和加载边界；性能体验要考虑用户什么时候看到内容，而非只看构建时间

**SEO 与元信息** ---- 页面标题、描述、结构化数据、社交分享和可爬取内容都应与路由和业务一致

**安全边界** ---- 关注服务端渲染注入、用户内容、序列化、Cookie、CSRF 和敏感数据泄漏；服务端出现后，风险也会一起上线

**重点在这** ---- SSR 是渲染位置的选择，不是“把 Vue 放到服务器就赢了”；先明确产品目标，再选渲染策略

## 第九站：测试、工具与工程实践

第九站进入 Vue 的质检车间：组件测试检查零件，端到端测试跑整条流水线，DevTools 负责还原案发现场，构建与监控则守着出厂门。只会让页面跑起来，项目一长就会变成“改一个按钮，五个页面皱眉”。

**组件测试** ---- 覆盖渲染结果、用户交互、Props、Emits、插槽和异步状态；测试用户能观察到的行为，不要把实现细节供起来

**组合式函数测试** ---- 独立验证响应式变化、计时器、请求、清理和错误；让逻辑可以脱离完整页面测试

**端到端测试** ---- 覆盖登录、导航、表单提交、权限和关键业务链路；端到端测试数量不必最多，但要守住最贵的失败

**类型与静态检查** ---- 使用 TypeScript、Vue 类型工具、ESLint、格式化和提交检查建立反馈闭环；工具越早报错，生产越少加班

**开发工具** ---- 熟悉 Vue DevTools、网络面板、性能面板、组件更新追踪和源码映射；会观察比会猜更高级

**组件库与设计系统** ---- 评估 Element Plus、Naive UI、Vuetify、Vant 等生态，理解主题、无障碍、按需加载和二次封装成本

**目录与依赖边界** ---- 按功能、领域或层次组织组件与组合式函数；避免 utils 文件长成“所有没人知道放哪的东西都放这里”

**发布与监控** ---- 关注构建产物、错误上报、性能指标、Source Map、缓存和回滚；上线不是打包成功的那一刻，而是用户开始使用之后

**重点在这** ---- 工程化的目标是稳定交付和快速定位，不是把配置文件写得像古籍

## 通关标准

**Vue 新手村能拼出组件** ---- 会用模板、Props、Emits、插槽和响应式做出 Todo 或表单组件，知道按钮为什么会亮、输入为什么能回显。状态还可能住错房间，但至少不会把所有逻辑塞进一个文件。

**初级前端能做出应用** ---- 能组织路由、Pinia、表单、请求、权限和错误页，知道局部状态不必全局化。面试问 v-if 和 v-show，你不再靠硬币决定。

**中级前端能解释魔法** ---- 能说清 track、trigger、computed、watch、批量更新、key、编译器优化和水合的大致关系，能定位重复请求、状态丢失与性能抖动。页面出问题时先查依赖，不会只会重启开发服务器。

**高级前端能治理生态** ---- 能按项目规模选择 Router、Pinia、Nuxt、组件库、测试与数据方案，能设计可复用组件和清晰的 SSR 边界。Vue 负责顺手，你负责让项目长期不乱。

## 结语

Vue 的好处是让你容易入门，Vue 的深处是提醒你：简单的 API 背后仍然有复杂的工程。先用它把页面做出来，再去理解响应式和编译器为什么这么顺手；这条路走稳了，框架就不是魔法，而是工具箱。
