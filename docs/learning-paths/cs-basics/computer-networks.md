# 计算机网络学习路线

你每天写的 HTTP 接口、调的 API、连的数据库,全都跑在网络上。但"会用"和"真懂"之间,隔着三次握手、四次挥手、DNS 解析和 TLS 握手——这些才是面试官眼里的分水岭,也是线上问题排查时的救命稻草。

互联网的本质是一句大实话:**一群不可靠的信道,拼出了可靠的服务**。理解这句话,你就理解了一半的网络。

## 第一站:分层——网络的建筑学

网络太复杂,所以被拆成**层**,每层只干自己的活,只和上下层打交道。两套模型要知道:**OSI 七层**(应用、表示、会话、传输、网络、链路、物理)是教科书标准,**TCP/IP 五层**(应用、传输、网络、链路、物理)是现实标准——面试写 OSI,日常聊 TCP/IP,心里有数就行。

数据从上层往下走叫**封装**:每层给数据包"套一个信封"(加头部);到达对端再一层层拆开(**解封装**)。分层的好处是各层可以独立演进:应用层从 HTTP/1.0 升级到 HTTP/3,底下的网线一根不用换。

## 第二站:应用层——你最熟的一层

**HTTP** 是你天天打交道的协议。要掌握:请求方法(GET/POST/PUT/DELETE 等,以及 GET 和 POST 的语义区别)、**状态码家族**(2xx 成功、3xx 重定向、4xx 客户端错、5xx 服务端错——`404` 是找不到资源,`403` 是没权限,`502` 是网关上游挂了,`504` 是网关超时,排查线上问题全靠它们)、常见请求头与响应头、`Cookie` 与 `Session` 的配合(以及后来居上的 Token,JWT 的细节见 [认证授权学习路线](/learning-paths/security/auth))。

**HTTPS** 不是新协议,是 HTTP 套了一层 **TLS** 加密。握手的精髓:先用**非对称加密**(RSA/ECC)安全地协商出一个对称密钥,之后数据全用**对称加密**(AES,快得多);而"怎么确认对面是真的服务器"靠**证书**——CA 签发的证书链,浏览器只信任证书链能追溯到根 CA 的站点。所以"证书过期""证书不受信任"的报错,本质是这条信任链断了。

现代 HTTP 进化史也值得一条线理清:HTTP/1.1(一个连接一次请求,有队头阻塞)→ HTTP/2(多路复用,一个连接并发多个请求,但 TCP 层仍有队头阻塞)→ HTTP/3(换用基于 UDP 的 QUIC,彻底解决队头阻塞,连接迁移不断线)。

**DNS** 是"电话簿":把域名翻译成 IP。解析过程是递归 + 迭代:先问根域名服务器,再问顶级域,再问权威服务器,每一级都有**缓存**(所以改 DNS 要等生效)。**WebSocket** 则是 HTTP 的升级版:一次握手后变成全双工长连接,服务端能主动推送——聊天、实时通知、在线协作全靠它。

## 第三站:传输层——可靠与效率的取舍

传输层两大将:**TCP** 和 **UDP**。

**UDP** 简单粗暴:发出去就不管,可能丢、可能乱序,但快、延迟低——视频通话、游戏、DNS 查询都用它(丢一帧画面无所谓,卡顿才致命)。

**TCP** 是"可靠传输"的模范生,可靠靠一整套机制堆出来:**序号与确认(ACK)**(丢了能发现)、**超时重传**(丢了就重发)、**滑动窗口**(流量控制,防止把慢的接收方压垮)、**拥塞控制**(慢启动 + 拥塞避免,防止把整个网络压垮——TCP 会主动"试探"网络容量,这就是为什么大文件传输开头总是慢慢加速)。

三个面试名场面:

- **三次握手**:客户端 SYN → 服务端 SYN+ACK → 客户端 ACK。为什么不是两次?因为要确认双方的"发送和接收"都正常,还要防止"过期的连接请求"突然到达造成误会。
- **四次挥手**:主动方 FIN → 被动方 ACK → 被动方 FIN → 主动方 ACK。为什么比握手多一次?因为 TCP 支持**半关闭**——被动方收到 FIN 后可能还有数据要发,先 ACK 表示"我知道了",发完再 FIN。
- **TIME_WAIT**:主动关闭方最后要等 2MSL(两倍报文最大生存时间)才彻底关闭,为了让迟到的报文在网络里自然消亡、防止污染新连接。高并发短连接的服务器 TIME_WAIT 堆积,是经典的调优场景。

还有一个开发必踩的坑:**粘包与半包**。TCP 是"字节流",没有消息边界——你 send 两次,对端可能一次 recv 全收到(粘包),也可能只收到一半(半包)。所以应用层协议必须自己定界:固定长度、分隔符,或最常用的"长度前缀"。你用过的每个 RPC 框架、消息队列,内部都在做这件事。

## 第四站:网络层——寻址与路由

**IP 地址**是每台设备的"门牌号"。IPv4 只有 32 位,早就不够用了,于是有了 **NAT**:家庭路由器只占一个公网 IP,内部设备用私有地址(192.168.x.x),出门时路由器做地址转换——所以"我的电脑 IP 是多少"和"我对外显示的 IP 是多少"是两回事。IPv6 是终极方案,地址多到给地球每粒沙子都够分。

**子网掩码与 CIDR**:`192.168.1.0/24` 表示前 24 位是网络号,后面是主机号——划分网段、判断"两个 IP 是否同网段"全靠它。

**路由**是"逐跳转发":每个路由器只查路由表决定"下一跳给谁",像传话游戏一样一站站送到目的地。**ICMP** 是网络层的"体检工具":`ping` 靠它测通不通、`traceroute` 靠它看路径(顺便认识 TTL——每经一跳减一,减到零就丢弃,防止数据包在环路里永远转圈)。

## 第五站:链路层——最后一公里

这一层解决"同一根网线/同一个局域网里怎么传"。**以太网帧**按 **MAC 地址**(设备的物理身份证)寻址,**ARP** 协议负责问"这个 IP 的 MAC 是谁"。**交换机**是二层设备(按 MAC 转发),**路由器**是三层设备(按 IP 转发)——这就是"交换机组局域网、路由器连互联网"的分工。Wi-Fi 的原理也在这层:无线电波上的以太网。这一站了解即可,排查问题很少需要下探到这里,但"为什么 ping 不通先看是不是同一网段"的直觉要有。

## 第六站:排错工具箱

理论学完,实战排错才是真功夫。按层从下往上排查:

- `ping`:通不通、延迟多少(网络层)。
- `nslookup`/`dig`:DNS 解析对不对(应用层)。
- `telnet host port`/`nc`:端口通不通(传输层)。
- `curl -v`:看完整的 HTTP 请求响应、TLS 握手过程(应用层)。
- `netstat`/`ss`:本机端口监听与连接状态——大量 TIME_WAIT、SYN_SENT 都是线索。
- 浏览器 Network 面板:瀑布图能告诉你哪一步慢(DNS?连接?等待响应?)。
- `traceroute`:数据包卡在哪个路由器。
- **Wireshark**:终极武器,直接看报文——亲手抓一次三次握手,胜过背十遍。

"网页打不开"是经典排查题:先 ping 域名(DNS 挂了?)、再 ping IP(网络不通?)、再 telnet 端口(服务没起?防火墙?)、再 curl 看状态码(应用层 4xx/5xx?)——一层层缩小范围,这就是分层思想的最大价值。

## 第七站:压轴题——输入 URL 到页面展示

这是面试必考的综合题,也是检验你整条线学没学通的试金石,完整旅程是:

1. 浏览器解析 URL,向 **DNS** 查域名对应的 IP(先查本地缓存,逐级向上)。
2. 浏览器与服务器建立 **TCP 连接**(三次握手)。
3. 如果是 HTTPS,进行 **TLS 握手**(协商密钥、验证证书)。
4. 浏览器发送 **HTTP 请求**(携带 Cookie、必要的 Header),请求经过可能存在的 **CDN** 和**负载均衡器**,到达后端服务器。
5. 服务器处理请求(查数据库、跑业务逻辑),返回 HTTP 响应(状态码、响应体、Set-Cookie)。
6. 浏览器接收响应,解析 HTML、加载 CSS/JS/图片(又是若干次请求),构建 DOM 树、渲染页面。

能流畅讲出这六步,并能在每一步展开细节,计算机网络就算真正入门了。往里加一层 CDN 缓存命中、加一层负载均衡策略,就是 [云原生](/learning-paths/cloud-native/cloud-native-patterns) 和 [Nginx 学习路线](/learning-paths/middleware/nginx) 的地盘。

## 通关标准

能独立做到:画出并讲清 TCP 三次握手与四次挥手(含为什么);说清 HTTPS 加密流程与证书的作用;完整讲述"输入 URL 到页面展示"的旅程;用 curl/telnet/ping 定位"网页打不开"是哪一层的问题;知道粘包是什么、怎么解。做到这些,网络主线通关。
