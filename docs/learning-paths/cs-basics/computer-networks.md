# 计算机网络学习路线

网络是计算机之间共同签署的一份“即使路上很乱，也要尽量把话送到”的协议。数据包可能丢、延迟、乱序，连接可能断，域名可能绕路；DNS、TCP、TLS、HTTP 和路由器们却会轮流站出来，把混乱包装成一个看起来还挺可靠的互联网。

这份路线是 **通用基础 → 计算机科学基础 → 计算机网络** 的独立学习地图。它从分层和数据包出发，走过链路、IP、TCP/UDP、DNS、TLS、HTTP、代理、实时通信、安全和故障排查，重点建立“请求到底经过了谁”的全链路视角。

**适合谁** ---- 写 Web、后端、客户端、网关、云服务、实时系统，或遇到接口超时、连接失败、跨域、丢包和证书问题时不想靠重启碰运气的开发者

**先记住一件事** ---- 网络从来没有承诺“马上送达”，它只是在一层层协议的帮助下努力让结果可接受；延迟、丢包、拥塞和故障都不是意外，是设计输入

**推荐总顺序** ---- 分层与封装 → 链路与局域网 → IP 与路由 → TCP/UDP/QUIC → DNS → TLS → HTTP → 代理与负载均衡 → 实时通信 → 网络安全 → 抓包与性能

**本页怎么用** ---- 每学一个协议，都追问五件事：数据长什么样、谁来发送、如何确认、哪里会失败、如何观测。协议名字会变，失败方式总会来上班。

## 第一站：分层、封装与数据包

网络太复杂，于是协议们决定分层办公：上层提需求，下层搬货；每层都有自己的信封、规则和脾气，谁也别越俎代庖。

**OSI 与 TCP/IP 模型** ---- 理解 OSI 七层、TCP/IP 分层、现实协议归属和分层模型的抽象价值，知道模型是地图，不是每根网线都必须照着画

**封装与解封装** ---- 掌握应用数据、报文段、数据报、帧和比特的层层包装，理解头部、载荷、尾部和 MTU 的位置

**地址与标识** ---- 区分域名、应用标识、端口、IP 地址、MAC 地址和接口，知道“找到哪台机器”和“找到哪个服务”是两件事

**协议状态与边界** ---- 认识连接状态、会话、超时、重试、幂等和层间错误如何向上反馈

**重点解释** ---- 这一站通关是能画出一次请求的封装路径，解释每层增加了什么、负责什么、不能负责什么

## 第二站：链路、以太网与局域网

链路层住在同一片局部街区，负责把帧交给附近邻居。它不负责认识全世界，但会认真处理地址、碰撞、广播和校验。

**物理介质与信号** ---- 了解双绞线、光纤、无线、电信号、调制、带宽、噪声、衰减和链路速率的基本关系

**帧与 MAC 地址** ---- 掌握帧结构、源/目的 MAC、类型、长度、校验和、单播、广播与组播

**以太网与交换机** ---- 理解交换表、学习、转发、泛洪、环路和全双工，知道交换机不是“更快的路由器”

**ARP 与邻居发现** ---- 学习 IP 到链路地址的解析、缓存、过期、欺骗风险和 IPv6 邻居发现

**VLAN 与广播域** ---- 认识标签、端口模式、广播域、Trunk、隔离和跨 VLAN 路由

**无线局域网** ---- 了解接入、信道、竞争、漫游、认证、隐藏节点和无线环境对延迟的影响

**重点解释** ---- 这一站要能说明同一局域网内一帧如何找到邻居、交换机如何转发、广播为何会扩散，以及链路问题该看哪里

## 第三站：IP、路由与网络边界

IP 层像一位负责长途运输的邮差：它只承诺尽力投递，不承诺每封信都平安抵达。路由器们会根据地址和路由表决定下一跳，然后把不确定性继续交给上层。

**IPv4 与 IPv6** ---- 掌握地址结构、前缀、子网、掩码、CIDR、回环、私有地址、链路本地地址和 IPv6 的基本设计

**路由与下一跳** ---- 理解路由表、最长前缀匹配、默认路由、静态路由、动态路由和策略路由

**ICMP 与诊断** ---- 认识错误反馈、回显、TTL、路径探测和为什么 ping 通不代表应用一定能通

**分片与 MTU** ---- 学习链路 MTU、分片、重组、路径 MTU 发现、黑洞和大包失败

**NAT 与地址转换** ---- 理解源/目的地址转换、端口映射、连接状态、穿透限制和 NAT 不等于防火墙

**路由协议概览** ---- 了解自治系统、BGP、OSPF、收敛、路由策略和互联网规模的组织方式

**重点解释** ---- 这一站通关是能从源地址、目的地址、路由表、下一跳、MTU 和 NAT 解释数据报的旅程与失踪原因

## 第四站：TCP、UDP 与可靠传输

TCP 像一位认真负责的快递主管：给包编号、收回执、发现缺件就重寄，还要在路堵时主动减速。UDP 则更像轻装快递员：我负责发，收件人自己决定怎么处理。

**UDP 模型** ---- 理解无连接、报文边界、无可靠性、无序、低开销、广播/组播和应用自建可靠性的场景

**TCP 连接状态机** ---- 掌握监听、建立、传输、半关闭、关闭、TIME_WAIT、RST、SYN 队列和状态转换

**三次握手与四次挥手** ---- 理解序列号同步、确认、半连接、全连接、关闭方向和异常中断

**可靠传输** ---- 覆盖序列号、确认、重传、超时、快速重传、乱序、重复包、累计确认和选择确认

**流量控制** ---- 理解接收窗口、发送窗口、零窗口、窗口更新、缓冲区和背压

**拥塞控制** ---- 学习慢启动、拥塞避免、快速恢复、拥塞窗口、丢包信号、带宽延迟积和公平性

**连接保活与超时** ---- 认识 keepalive、应用心跳、读写超时、空闲连接、半开连接和资源清理

**重点解释** ---- 这一站要能区分可靠性、顺序、流量控制和拥塞控制，解释一次连接为什么建立慢、传输慢或关闭后还留在系统里

## 第五站：DNS 与命名系统

人类喜欢记名字，机器喜欢记地址，于是 DNS 成了两边的翻译官。它平时很安静，缓存失效或权威服务器走神时，全世界突然一起想起它的重要性。

**域名层级** ---- 掌握根、顶级域、权威域、主机名、标签、FQDN 和委派关系

**递归与迭代查询** ---- 理解客户端、递归解析器、根、TLD、权威服务器之间的询问链路

**记录类型** ---- 认识 A、AAAA、CNAME、MX、NS、TXT、SRV、PTR、SOA 等记录及其语义边界

**TTL 与缓存** ---- 学习缓存命中、过期、负缓存、预取、传播延迟和修改记录后的等待

**分流与服务发现** ---- 了解轮询、权重、地理、健康检查、内部域名、服务发现和故障切换

**DNS 安全与加密** ---- 认识 DNSSEC、缓存投毒、DoH、DoT、隐私与可观测性的取舍

**重点解释** ---- 这一站通关是能追踪域名从输入到地址的解析路径，知道缓存、委派、记录类型和 TTL 如何影响请求

## 第六站：TLS 与 HTTPS

TLS 像网络世界的保密信使：先核验身份，再协商暗号，之后把对话装进加密信封。它不是让网络瞬间变快，而是让窃听者看不懂、篡改者露馅。

**密码学角色** ---- 区分对称加密、非对称加密、哈希、消息认证、数字签名、密钥交换和随机数

**证书与信任链** ---- 理解证书主体、SAN、有效期、CA、根证书、中间证书、吊销和域名校验

**握手与会话密钥** ---- 掌握客户端/服务端协商、密钥交换、加密套件、会话恢复、票据和握手耗时

**HTTPS 与应用边界** ---- 认识 TLS 保护到哪一层、代理终止、端到端加密、Header/URL 可见性和证书部署

**版本与配置** ---- 了解协议版本、前向保密、弱算法、密码套件、证书轮换和兼容性

**常见失败** ---- 排查域名不匹配、链不完整、过期、时间错误、SNI、代理和客户端信任库问题

**重点解释** ---- 这一站要能解释 HTTPS 握手、证书信任、会话恢复和终止位置，知道“浏览器显示小锁”背后发生了哪些交换

## 第七站：HTTP、WebSocket 与应用协议

HTTP 是 Web 的公共语言，GET、POST、状态码和 Header 像一套礼貌但很严格的对话礼仪。WebSocket 和 SSE 则把“一问一答”改成“保持通话”，也顺手带来了更多生命周期问题。

**HTTP 消息模型** ---- 掌握请求行/响应行、方法、状态码、Header、Body、内容类型、字符编码和消息边界

**语义与幂等** ---- 理解安全方法、幂等方法、缓存语义、条件请求、范围请求、重定向和重试边界

**HTTP/1.1** ---- 认识持久连接、管线化、队头阻塞、分块传输和连接复用限制

**HTTP/2** ---- 学习二进制帧、流、多路复用、头部压缩、优先级、流控和连接级队头阻塞

**HTTP/3 与 QUIC** ---- 了解 UDP 之上的可靠流、TLS 融合、连接迁移、独立流和丢包影响

**WebSocket 与 SSE** ---- 对比握手、双向/单向、心跳、重连、顺序、背压和代理支持

**缓存与条件验证** ---- 掌握 Cache-Control、ETag、Last-Modified、Age、Vary、代理缓存和失效策略

**重点解释** ---- 这一站通关是能从协议语义、连接、流、缓存和失败重试解释一次 Web 请求，而不是只会把 URL 贴进浏览器

## 第八站：代理、负载均衡与服务网络

真实网络很少只有客户端和服务器两位演员，中间往往站着 CDN、反向代理、网关、负载均衡和服务网格。每多一位中间人，就多一层能力，也多一处“我以为它会处理”的误会。

**正向与反向代理** ---- 区分代表客户端出站和代表服务端接入，理解代理头、连接复用、缓存、认证和审计

**负载均衡** ---- 掌握四层/七层、轮询、最少连接、权重、哈希、健康检查、会话粘滞和故障摘除

**网关与服务发现** ---- 了解路由、名称解析、注册、探活、版本、灰度、限流和跨服务调用

**连接池与超时** ---- 设计连接复用、建立超时、读写超时、总截止时间、空闲回收和连接上限

**重试与退避** ---- 理解瞬时错误、指数退避、抖动、重试预算、幂等键和重试风暴

**可观测上下文** ---- 认识请求 ID、trace ID、代理链、真实客户端地址、TLS 终止和日志关联

**重点解释** ---- 这一站要能画出客户端到服务的中间链路，判断哪个组件负责路由、缓存、TLS、限流、重试和健康检查

## 第九站：网络安全与可靠性

网络上的每个包都像一个想进门的陌生人。防火墙、认证、分段和限流是门卫，但门卫也需要知道自己看的是哪扇门、哪种证件和哪类风险。

**威胁与信任边界** ---- 建立攻击面、身份、权限、机密性、完整性、可用性、重放和中间人攻击的基本模型

**防火墙与网络分段** ---- 理解包过滤、状态防火墙、ACL、安全组、零信任、VPC/子网和最小暴露面

**认证与授权** ---- 区分 TLS 身份、应用登录、Token、Session、服务间身份和资源权限

**常见网络攻击** ---- 认识扫描、欺骗、投毒、DDoS、放大、反射、劫持、端口暴露和协议滥用

**限流与抗过载** ---- 学习连接限制、请求限流、队列、熔断、降级、超时和负载 shedding

**隐私与合规边界** ---- 关注 DNS、Header、日志、IP、Cookie、加密元数据和数据最小化

**重点解释** ---- 这一站通关是能为网络服务画出信任、暴露和过载边界，知道安全措施保护什么、可能牺牲什么

## 第十站：抓包、排障与性能

网络问题最擅长伪装：DNS 慢看起来像接口慢，TLS 慢看起来像服务器忙，客户端超时可能是服务端根本没收到。排障要让每一层都拿出证据。

**分层排障** ---- 建立从进程、端口、DNS、路由、链路、TCP、TLS、HTTP 到业务的逐层排查顺序

**抓包与协议分析** ---- 了解抓包、过滤、时间戳、序号、重传、握手、窗口、TLS 元数据和会话重组

**连接与队列观测** ---- 查看监听、连接状态、半连接、TIME_WAIT、发送/接收队列、丢包和重传

**延迟分解** ---- 拆分 DNS、连接、TLS、排队、服务处理、数据库、响应传输和客户端解析时间

**带宽与吞吐** ---- 理解带宽、RTT、BDP、窗口、压缩、批量、并发和尾延迟的关系

**故障演练** ---- 关注丢包、延迟、断网、DNS 失效、证书过期、连接耗尽、代理重启和区域故障

**重点解释** ---- 这一站通关是能用抓包、指标、日志和分层假设定位网络故障，不会只对着“请求失败”四个字发呆

## 学习路径建议：让一个请求走完全程

**第一阶段：协议地基** ---- 理解分层、链路、IP、地址、路由、TCP/UDP 和 DNS，能说清数据包如何找到服务

**第二阶段：安全与 Web** ---- 学习 TLS、证书、HTTP、缓存、WebSocket 和 SSE，能解释浏览器到 API 的请求生命周期

**第三阶段：服务网络** ---- 进入代理、负载均衡、连接池、超时、重试、服务发现和网络隔离，建立生产链路视角

**第四阶段：观测与演练** ---- 用抓包和指标验证握手、重传、队列、延迟和故障恢复，让网络从“玄学”变成证据题

**每阶段的节奏** ---- 每学一个协议，画一次状态机、看一次报文、故意制造一次失败；网络这位老师不怕你问细，只怕你只记住缩写

## 通关标准

**模型通关** ---- 能解释分层、封装、地址、端口、路由、MTU 和协议边界

**传输通关** ---- 能说明 TCP/UDP/QUIC 的状态、可靠性、流量控制、拥塞、重传和关闭

**Web 通关** ---- 能解释 DNS、TLS、HTTP、缓存、代理、WebSocket 和 SSE 的完整链路

**安全通关** ---- 能画出网络信任边界，识别暴露、认证、加密、限流、DDoS 和重放风险

**诊断通关** ---- 遇到超时、连接失败、慢请求、丢包或证书错误，能按层收集证据并提出恢复动作

## 结语

网络是一群性格不同却必须合作的角色：DNS 负责问路，路由器负责指路，TCP 负责收拾丢件，TLS 负责保密，HTTP 负责礼貌说话。它们谁都不能单独完成互联网，却一起把“远方的服务”变成了一个可调用的地址。

当你能从域名一路追到网卡，再从抓包回到业务语义，网络就不会只在故障时突然现身。它会变成一位平时安静、出事时很愿意提供线索的老同事。
