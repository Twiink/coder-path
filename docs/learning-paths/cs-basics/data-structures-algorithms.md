# 数据结构与算法学习路线

"程序 = 数据结构 + 算法",这句名言你迟早会在某本书的扉页上看到。翻译成人话:数据结构是数据存放的"仓库设计图",算法是处理数据的"操作流程"。面试必考它,不是面试官闲得慌——而是因为它是少数能在一小时内看出"一个人能不能把问题想清楚"的东西。

好消息是:数据结构与算法不靠天赋,靠的是见多识广的肌肉记忆。这条路线的目标不是让你背答案,而是让你拿到任何问题都能先说出思路。

## 第一站:先学会估复杂度

动手写代码之前,先学会"估算"。**时间复杂度**回答"数据量翻倍后,程序会慢多少",**空间复杂度**回答"它吃多少内存"。

大 O 记法不复杂,你只需要建立一张图谱:常数 O(1)(哈希查找)、对数 O(log n)(二分查找)、线性 O(n)(遍历)、O(n log n)(优秀排序)、平方 O(n²)(双层循环)、指数 O(2ⁿ)(别让代码走到这)。分析时还要分**最好、最坏、平均**三种情况——数组里找元素,最好第一个就中,最坏要翻到底,面试和优化看的是最坏与平均。

练习方法:每写完一段代码,先问自己"这段的复杂度是多少,能不能更低"。这个习惯比多刷一百道题都值钱。

## 第二站:线性结构三件套

**数组**是连续内存里的一排格子:按下标随机访问是 O(1),但中间插入要挪动后面所有元素。**链表**反过来:每个节点装着数据和指向下一个节点的指针,插入删除只要改指针,O(1) 搞定,但想找第 n 个节点只能从头走。经典考题是反转链表、判断是否有环——环的检测用快慢指针,一个走两步一个走一步,会相遇就有环。

**栈**是"后进先出":函数调用栈、编辑器撤销、括号匹配都是它。**队列**是"先进先出":任务排队、消息缓冲都用它,环形队列能避免反复搬运。栈和队列的实现本身不难,难的是识别"这题该用栈"——看到"最近匹配""嵌套结构"想栈,看到"排队""按序处理"想队列。

进阶玩法:**双端队列**两头都能进出,滑动窗口最大值这类题就是它的主场。

## 第三站:哈希表——用空间换时间的典范

**哈希表**(字典/映射)能实现平均 O(1) 的查找,秘诀是把 key 通过**散列函数**算出一个下标直接定位。代价是:它不保证顺序、要处理**哈希冲突**(两个 key 算出同一个位置)——主流方案是**链地址法**(同一个桶挂链表)或**开放寻址**(往后找空位),还要在**负载因子**过高时扩容重散列。

工程里到处都是它:Java 的 HashMap、JavaScript 的 Map/Set、Python 的 dict,底层思路一致。看清语言自带容器,是学好数据结构的第一步——能说出"什么时候用 Set 而不是数组去重",你已经赢过一半人了。

了解级选手可以认识一下**布隆过滤器**:用多个哈希位判断"一定不存在/可能存在",是缓存穿透防护和去重的利器,面试加分项。

## 第四站:树——一维装不下的数据

**二叉树**是树的入门:每个节点最多俩孩子。三种深度遍历(前序、中序、后序)和**层序遍历**要能手写递归版,再挑战迭代版(栈模拟递归,层序用队列)。中序遍历有序——这是**二叉搜索树(BST)** 的性质:左小右大,查找平均 O(log n)。但 BST 有个致命弱点:按顺序插入会退化成链表,于是有了**自平衡树**:AVL 严格平衡但旋转频繁,红黑树"松平衡"更实用——Java 的 TreeMap、C++ 的 map 底层都是红黑树,知道"它通过染色和旋转保持大致平衡"就够用了。

**堆**是另一种重要树:完全二叉树 + 父节点优先(大顶堆/小顶堆),用来实现**优先队列**。经典场景:TopK 问题(海量数据里找最大的 K 个,用一个 K 大小的小顶堆)、堆排序。**Trie(前缀树)** 适合字符串前缀匹配,输入法的联想、路由的公共前缀匹配是它的主场。

## 第五站:图——关系网的数学化

**图**由顶点和边组成,社交网络的好友关系、地图的路径规划、微服务的调用链,都是图。两种存储:**邻接矩阵**(二维数组,稠密图友好)和**邻接表**(每个顶点挂邻居链表,稀疏图省内存)。

两种遍历是万法之源:**DFS(深度优先)** 一条道走到黑再回头,适合找路径、判断连通; **BFS(广度优先)** 层层推进,天然适合求最短路径(无权图)。在此基础上:**
Dijkstra** 求带权最短路径(贪心 + 优先队列),**拓扑排序**处理依赖关系(先修课程、构建顺序——还记得构建工具里的依赖图吗),最小生成树了解概念即可。

## 第六站:排序与检索——算法的基本功

排序是算法的"九九乘法表"。重点掌握四件套及它们的复杂度与稳定性:**归并排序**(O(n log n) 稳定,分治思想)、**快速排序**(平均 O(n log n),最坏 O(n²) 当输入已有序且选第一个做基准时——所以有随机化基准)、**堆排序**(O(n log n) 原地)、插入排序(小数组反而快,工程里常作快排的收尾)。冒泡和选择了解即可。能默写快排、能画出归并过程、能说出"工程排序为什么混合多种策略",这关就过了。

**二分查找**是另一个必须形成肌肉记忆的算法:有序数组里找目标,每次砍一半。真正的难点全在边界条件:循环用 `left <= right` 还是 `left < right`、mid 取中间还是偏左、找不到返回什么——建议认准一套写法练到底,别今天一套明天一套。配套技巧:**双指针**(有序数组两数之和、原地去重)和**滑动窗口**(子串、子数组的最优解),这两招能解决一大票中等题。

## 第七站:经典算法思想——从"会写"到"会想"

- **递归**:函数调用自己。核心是"基线条件 + 递推关系",但别真去人肉跟踪每一层——相信它"能搞定子问题"。递归深度过大会**爆栈**(还记得调用栈吗),所以有尾递归优化和"递归改迭代"。
- **回溯**:递归 + 撤销选择,穷举所有可能。全排列、N 皇后、组合总和是三大样板题。套路固定:选择→递归→撤销。
- **贪心**:每步取当前最优。区间调度、跳跃游戏,但贪心需要证明局部最优能推出全局最优,别见到"最大/最小"就无脑贪。
- **动态规划**:最难也最常考。特征是**重叠子问题**(同一个子问题反复算)和**最优子结构**(大问题的最优由子问题最优组成)。套路:定义状态 → 写状态转移方程 → 确定边界 → 按顺序填表。从斐波那契(记忆化)到爬楼梯,再到背包问题、最长递增子序列——先学会"暴力递归 → 加缓存 → 改递推"这条进化链,动态规划就没那么可怕了。
- **分治**:把大问题拆成互不重叠的子问题,归并排序和快速排序都是分治的活例子。

## 第八站:刷题方法论

理论再好,不刷题等于没学。几个经验之谈:

1. **先易后难**:先把简单题刷出手感,再碰中等,困难题前期别碰,容易打击信心。
2. **按专题刷**:链表一周、二叉树两周、动态规划三周……同类型集中突破比东一榔头西一棒子有效得多。
3. **卡住有节奏**:一道题独立思考 30 分钟想不出,直接看题解,看懂后**合上答案自己重写一遍**,隔天再写一遍。题解不是用来背的,是用来"偷思路"的。
4. **先讲后写**:面试时先大声说出思路和复杂度,再动手——面试官想看的就是你的思考过程。

## 通关标准

能独立做到这几件事,数据结构与算法主线就算通关:给任意数据结构说出增删查的复杂度;默写快排、二分、二叉树三种遍历、BFS/DFS;独立 AC 中等难度的链表、树、动态规划各若干题;看到新题能先说出暴力解,再给出优化方向和复杂度分析。
