# 计算机组成原理学习路线

你写的每一行代码,最终都会变成 0 和 1 的电信号,在一块硅片上跑完它的一生。学计算机组成原理,不是为了让你去造 CPU,而是为了让你写代码时心里有一张"硬件地图":知道 `0.1 + 0.2` 为什么不等于 `0.3`,知道为什么遍历数组比遍历链表快,知道为什么 32 位系统内存上限是 4G。

这条线从"数据怎么表示"讲到"一条指令怎么变成电信号",建议按顺序走,前面是后面的地基。

## 第一站:数据是怎么表示的

计算机里只有 0 和 1,所以一切从进制开始:二进制(0b1010)、八进制(0o12,3 位二进制一组)、十六进制(0xA,4 位二进制一组,所以内存地址、颜色值 #FF5733、网络包抓包都用它)。进制转换要熟练:十进制 13 = 二进制 1101 = 十六进制 0xD。

整数用补码存储,这是计算机最优雅的设计之一:原码(符号位+绝对值,简单但 +0 和 -0 两个表示,加减法要分情况)→ 反码(负数按位取反,过渡产物)→ 补码(负数反码 +1)。补码的天才之处:加法和减法共用一套电路(1 - 1 = 1 + (-1),补码加法溢出的进位自然丢弃,结果正确)、没有 -0(表示范围 -128~127 for int8)、模运算天然成立。代价是整型溢出:有符号 32 位最大 2^31 - 1(0x7FFFFFFF,2147483647),再加 1 变成 0x80000000(最小负数 -2147483648)——这就是为什么 Java int 加法可能突然变负、为什么 C 的 UB(未定义行为)、为什么 JavaScript 有 Number.MAX_SAFE_INTEGER(2^53 - 1,因为 double 尾数 53 位)和 BigInt。无符号整数(unsigned)没有负数,范围 0~255(int8),溢出回绕(255+1=0)。

位运算(补码基础上的操作,性能优化利器):AND(&,掩码取位)、OR(|,置位)、XOR(^,翻转、无临时变量交换 a^=b^=a^=b)、NOT(~,按位取反)、左移(<<,乘 2^n)、右移(>>,除 2^n,逻辑右移补 0、算术右移补符号位)——哈希函数、加密、底层驱动全是位运算的天下。

小数更精彩。IEEE 754 浮点数(float 32 位,double 64 位)用"符号位(1 位)+ 指数(8/11 位,指数偏移 127/1023)+ 尾数(23/52 位,隐含首位 1)"三段表示——能表示的数是离散的,两个可表示数之间有"缝隙"(机器精silon)。0.1 在二进制是无限循环小数(0.0001100110011...),截断后存储,所以 0.1 + 0.2 = 0.30000000000000004(不是 0.3)——这不是 JavaScript 的 bug,是任何二进制浮点(C/Java/Python 都一样)绕不开的宿命。特殊值:±0(符号位不同)、±∞(指数全 1、尾数全 0)、NaN(指数全 1、尾数非 0,0/0、sqrt(-1) 产生,NaN != NaN 是唯一不等于自己的值)。为什么金融计算不能用浮点:0.1 元存不准,累加几万次误差放大——用整数分(1 元 = 100 分)或十进制定点数库(Java BigDecimal、Python Decimal)。

字符编码:ASCII 7 位 128 个字符(0-127,控制字符+英文+数字+符号,扩展 ASCII 8 位 256 个)→ 码点太少装不下中文——GB2312/GBK(中文双字节,国标)、Unicode(统一码点,给地球上所有字符编号,U+0041 是 A、U+4E2D 是中,17 个平面 110 万码位)→ UTF-8/UTF-16/UTF-32(Unicode 的存储编码)。UTF-8(变长 1-4 字节,ASCII 兼容,英文 1 字节、中文 3 字节,网络传输主流)、UTF-16(2 或 4 字节,BMP 基本平面 2 字节,JavaScript/Java 内部用它)、UTF-32(固定 4 字节,浪费但定长)。乱码的本质:用 GBK 写、UTF-8 读,或 UTF-8 文件没 BOM 被误识别——记住"编码与解码必须一致"。

## 第二站:从逻辑门到加法器

再往下一层,是**逻辑门**:与、或、非——初中物理的开关电路就能搭出来。把门电路组合起来,能做出**半加器、全加器**,再做出一整块能做算术和逻辑运算的电路。这一站不需要你会设计电路,只需要建立一个信念:计算机里一切"智能",都是亿万次"开关"的组合。CPU 就是一块超级复杂的门电路集合。

## 第三站:CPU 是怎么干活的

CPU 执行的是指令(机器码),每条指令由指令集架构(ISA)定义——x86(PC/服务器主流,CISC 复杂指令集)、ARM(手机/笔记本,RISC 精简指令集,功耗低)、RISC-V(开源新贵,学术界与嵌入式热门)是三大门派。指令集不同,软件不能直接通用,这就是为什么 macOS 从 Intel 换到 Apple Silicon 后老软件要重编译或转译(Rosetta 2 动态翻译 x86 到 ARM)。CISC vs RISC 的哲学:CISC 指令复杂功能强(一条指令能做很多事,但译码复杂、长度不定)、RISC 指令简单(固定长度、统一格式,流水线友好,靠编译器优化)。

一条指令的旅程是指令周期:取指(Fetch,从内存按 PC 程序计数器取指令到指令寄存器)→ 译码(Decode,控制单元解析操作码与操作数)→ 执行(Execute,ALU 算术逻辑单元计算)→ 访存(Memory,读写内存,非必需)→ 回写(Write Back,结果写回寄存器)。单周期 CPU(每条指令一个时钟周期,简单但主频拉不高)→ 多周期(不同指令分多个周期,复杂)→ 流水线(现代标配)。

流水线是现代 CPU 的核心:把指令周期的 5 个阶段拆成 5 个"车间",5 条指令重叠执行(第 1 条在回写时第 2 条在访存、第 3 条在执行……),理想情况下吞吐量提升 5 倍(但单条指令延迟不变)。流水线的敌人:冒险(Hazard):

结构冒险:硬件资源冲突(如取指和访存都要用内存)——解法:哈佛结构(指令内存与数据内存分离)或停顿(Stall)。

数据冒险:后一条指令依赖前一条结果,但结果还没算完——解法:转发(Forwarding,提前把 ALU 结果直接送给下一条)、停顿(插入气泡 Bubble)、编译器调度(重排指令填充空隙)。

控制冒险:分支指令(if/跳转)导致下一条指令不确定——解法:分支预测(静态:向后跳预测跳、向前不跳;动态:BTB 分支目标缓冲+历史统计,现代 CPU 准确率 95%+)、延迟槽(MIPS 的做法:分支后一条指令总是执行,编译器填充有用指令)、推测执行(猜错了丢弃,Spectre 漏洞就是推测执行的侧信道攻击)。

超标量(Superscalar):单周期同时发射多条指令到多个执行单元(多个 ALU、FPU 浮点单元),靠乱序执行(Out-of-Order)与寄存器重命名消除伪数据依赖——现代高端 CPU 都是超标量乱序。你的 CPU 可能同时跑 4-6 条指令,比简单流水线又快一个量级。

两个常见误区提前排雷:主频(3GHz)不等于性能,还要看 IPC(每周期指令数)——3GHz 的新架构可能比 5GHz 的老架构快,因为 IPC 高、流水线效率好;核心数也不是越多越好,程序得能并行才有用——单线程任务 8 核和 4 核没区别,多线程/多进程才吃满(还记得并发和并行的区别吗,那是 [操作系统学习路线](/learning-paths/cs-basics/operating-systems) 的主场)。功耗墙(Power Wall):主频提升带来的功耗与发热呈指数增长,所以现代 CPU 不再无限堆主频,而是堆核心数与改进架构(大小核设计:ARM 的 big.LITTLE、Intel 的 P-core/E-core)。

## 第四站:存储层次——快与便宜的博弈

没有一种存储既快又便宜又大,所以计算机搞了存储层次:寄存器(< 1ns,几十个,直接在 CPU 内)→ L1 缓存(~1ns,32KB)→ L2 缓存(~3ns,256KB)→ L3 缓存(~10ns,几 MB,所有核共享)→ 内存 DRAM(~100ns,几 GB)→ SSD(~0.1ms,几百 GB)→ 机械硬盘(~10ms,TB 级)。每往下一层,容量大 10-100 倍,速度慢 10-100 倍,价格便宜 10-100 倍。这条链的设计理念:用小而快的存储保存热数据,大而慢的存储保存全量数据,靠局部性让程序大部分时间访问上层。

局部性原理(缓存生效的前提,也是所有性能优化的哲学):

时间局部性:刚用过的数据很快再用——循环变量、函数栈帧、热点代码。

空间局部性:用了一个字节,附近字节很快也会用——数组遍历、结构体字段、代码的顺序执行。

CPU 缓存按缓存行(Cache Line,通常 64 字节)加载——读一个字节会把整行 64 字节都搬进缓存。所以:

顺序遍历数组极快:一次加载 64 字节,后续 15 个 int(4 字节)全命中,miss 率低。

跳着访问链表节点极慢:每个节点可能在不同缓存行,每次访问都可能 miss,还要追指针(指针追逐,Pointer Chasing,无法预取)。

这就是数据结构那课"数组 vs 链表"在硬件层面的答案——[数据结构与算法学习路线](/learning-paths/cs-basics/data-structures-algorithms) 里的"数组快"不是抽象结论,是缓存行的物理事实。

缓存映射方式(Cache 怎么找数据):

直接映射:每个内存块只能放在一个固定缓存行——简单但冲突多(两个常用地址映射到同一行,互相踢出)。

全相联:内存块可以放任意缓存行——灵活但查找慢(要遍历或用贵的硬件)。

组相联(现代 CPU 标配):折中,缓存分组,块先映射到组再在组内全相联(如 8 路组相联,每组 8 个候选位置)。

缓存替换策略:LRU(最近最少使用,理论最优)、近似 LRU(硬件便宜的实现)、随机(简单够用)。

缓存一致性(多核心共享内存的核心问题):多个核各有 L1/L2,但共享 L3 和内存——如何保证核 A 改了数据、核 B 能看到最新值?MESI 协议(Modified/Exclusive/Shared/Invalid,缓存行的四种状态):一个核修改数据会通过总线通知其他核"这行失效了",其他核下次访问时重新读——缓存一致性协议是多核正确性的基石,也是性能杀手(写操作要等总线通知完成,伪共享的根源)。

多线程性能杀手:伪共享(False Sharing)。两个线程改不同的变量,但它们恰好挤在同一个缓存行里(如 struct {int a; int b;} 在一行)——线程 1 改 a 会让包含 b 的缓存行失效,线程 2 改 b 又让 a 失效,虽然逻辑无冲突但硬件层互相踢缓存,性能雪崩。解法:缓存行填充(Padding,让 a 和 b 分居不同缓存行:struct {int a; char pad[60]; int b;})或编译器对齐属性。Java 的 @Contended、C++ 的 alignas(64)、Go 的手动 padding——高性能库的标配技巧。知道这个概念,你以后排查多线程性能问题时就不会一脸懵(为什么加了锁还是慢?可能根本不是锁,是伪共享)。

预取(Prefetching):硬件检测访问模式(如顺序访问)自动提前加载下一块数据——数组遍历快的另一个原因;软件预取:编译器插入预取指令(如 x86 的 PREFETCH)。

## 第五站:内存与地址

内存是字节编址的一长条,CPU 按**地址**访问。这里有个细节叫**字节序**:一个多字节整数(比如 `0x12345678`),内存里是"高位在前"还是"低位在前"?x86 是小端,网络协议规定大端。所以二进制协议都要显式规定字节序,而 JSON 这种文本格式压根没这个问题——这也是为什么跨语言通信用文本格式更省心。

另一个概念是**内存对齐**:CPU 按字(4/8 字节)读内存,数据没对齐可能要读两次,所以编译器会在结构体里"偷偷塞填充字节"。结构体字段顺序影响内存占用,这是 C/C++ 工程师的日常,其他语言大多帮你处理好了。

## 第六站:输入输出——CPU 怎么和外界打交道

键盘、硬盘、网卡都是外设,CPU 跟它们通信靠**总线**。三种方式层层进化:**轮询**(CPU 不停问"好了没",浪费)、**中断**(设备好了主动喊 CPU,像有人按门铃)、**DMA**(数据搬运直接由 DMA 控制器完成,不占用 CPU,大文件传输全靠它)。你每次读写文件、收发网络包,背后都是这套机制在跑——操作系统把这一切封装成了"文件"和"套接字",这就是下一站衔接操作系统的地方。

## 第七站:汇编语言初体验

别被吓到,这一站不求会写,只求"不怕看"。汇编是机器码的助记符版本:`mov`(搬数据)、`add`/`sub`(加减)、`cmp`(比较)、`jmp`(跳转)、`call`/`ret`(调用函数和返回)。函数调用的硬件真相在这里揭开:**调用栈**——`call` 把返回地址压栈,函数局部变量在栈上分配,返回时弹栈,所以递归太深会**栈溢出**(栈空间有限),所以栈上变量函数结束就自动"释放"。

进阶玩家可以用 `objdump` 反汇编看看自己写的代码长什么样,或者用调试器单步看寄存器变化——你会第一次直观感受到"高级语言的一行,是底下的几十条指令"。

## 第八站:从源代码到电信号

把整条线串起来看一次:**高级语言**(if、for、函数)→ 编译器翻译成**汇编** → 汇编器变成**机器码** → CPU 取指执行 → 电信号在门电路里流转。解释型语言(JavaScript、Python)不提前编译,而是运行时由**解释器/JIT** 边翻译边执行——JIT 会把热点代码编译成机器码,所以"解释型语言慢"早已不是铁律。

再往上,操作系统接管了硬件:进程调度、虚拟内存、文件系统——CPU 和内存怎么被"分时复用",请看下一站 [操作系统学习路线](/learning-paths/cs-basics/operating-systems)。

## 通关标准

能向别人解释清楚这几件事,计算机组成原理就算入门了:`0.1 + 0.2` 为什么不等于 `0.3`、负数为什么要用补码、为什么遍历数组比链表快(结合缓存行)、32 位系统为什么最多 4G 内存、一条 `if` 语句在硬件层面大致发生了什么、函数调用为什么用栈。
