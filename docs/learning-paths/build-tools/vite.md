# Vite 学习路线

Vite 的卖点是开发时快、配置相对轻、和现代 ESM 生态配合得好。但“启动很快”只是第一印象，真正要掌握的是开发服务器、依赖预构建、插件钩子、生产构建、资源处理和部署边界。

这条路线是**索引和指引**，不是把配置项抄成八百页字典。它从开发体验讲到构建产物，再连接 SSR、库模式、Monorepo 和迁移排障，让你知道 Vite 在整条前端流水线中负责什么。

## 第一站：为什么 Vite 开发快

欢迎来到 Vite 高速公路：开发时 ESM 负责按需放行，依赖预构建负责提前整理，HMR 负责让改动少绕路。它快不是浏览器学会瞬移，而是工具终于不再每次改一个字都把整座城重修一遍。

**原生 ESM** ---- 理解浏览器按模块请求开发源码、按需编译和模块边界；开发时不必先把整个应用打成一团

**esbuild 与开发转换** ---- 了解依赖预构建、源码转换与类型检查的分工；快速转译不等于自动完成类型检查

**Rollup 与生产构建** ---- 认识生产阶段的模块图、优化、压缩和输出；开发服务器的速度与生产包的质量是两场比赛

**按需编译** ---- 关注页面访问路径、模块请求、缓存和首次访问延迟；按需不代表所有延迟都消失，只是把等待放到了更合理的位置

**依赖与源码的区别** ---- 依赖通常需要预构建和兼容处理，业务源码需要快速 HMR；两者处理方式不同

**开发与生产差异** ---- 认识环境变量、路径、资源、代理、压缩和动态导入在两种模式中的差异；本地看起来正常不代表 dist 也同意

**重点在这** ---- Vite 的快来自开发阶段的策略选择；理解它为什么快，比记住一句“Vite 很快”更有用

## 第二站：项目、配置与命令生命周期

第二站是 Vite 项目登记处：根目录是地址，mode 是通行证，开发、构建和预览是三种不同服务。配置少是优点，不理解配置就会在目录、端口和环境变量之间玩迷宫。

**项目根目录** ---- 理解 index、public、src、配置文件和构建输出的职责；根目录决定很多相对路径的起点

**开发、构建与预览** ---- 区分开发服务器、生产构建、静态预览和真实部署；预览接近产物，但不等于生产平台

**配置文件** ---- 了解配置函数、异步配置、环境读取、共享配置和条件配置；配置应描述项目需求，不要把它写成个人收藏夹

**命令行覆盖** ---- 认识模式、根目录、主机、端口、调试和构建参数；命令行适合临时覆盖，长期规则应进入配置

**模式与环境** ---- 区分 development、production、自定义模式以及 mode 与 NODE_ENV 的关系；名称相似不代表职责相同

**缓存目录** ---- 了解依赖预构建缓存、强制重新优化和缓存失效；遇到幽灵问题时，清缓存是工具，不是第一反应

**类型检查分工** ---- Vite 负责转译与打包，TypeScript 检查通常由独立命令、插件或 CI 完成；把转译成功当成类型正确，是常见误会

**Monorepo 根目录** ---- 处理工作区、包目录、依赖解析和多个应用共享配置；根目录一变，路径与缓存就可能一起变

**重点在这** ---- 先知道每个命令负责什么，再修改配置；配置不是越长越专业，能解释、能复现才专业

## 第三站：依赖预构建与模块解析

第三站进入依赖海关：npm 包要检查入口，CJS 和 ESM 要翻译，预构建缓存要登记。理解依赖从哪来、被解析到哪、为什么要重新准备，才能知道清缓存究竟是在治病还是撒盐。

**依赖预构建** ---- 认识 CommonJS 兼容、模块合并、浏览器请求数量和缓存；预构建是开发优化，不是业务打包的全部

**依赖发现** ---- 了解入口扫描、动态导入、可选依赖和包导出；工具看不见的依赖就无法正确准备

**模块解析** ---- 关注 package exports、入口字段、条件导出、别名和扩展名；同一个包在不同环境可能被解析到不同入口

**别名** ---- 设计源码别名、共享包别名和测试环境同步；别名能消除相对路径，也能制造“本地能跑、工具不认识”的分裂

**依赖排除与包含** ---- 处理特殊依赖、原生模块、浏览器不兼容包和需要强制预构建的包；每次排除都要理解原因

**优化缓存** ---- 关注锁文件、Node 版本、依赖版本和缓存目录；依赖升级后缓存仍恋旧，清理才有意义

**CJS 与 ESM** ---- 理解默认导出、命名导出、动态导入和互操作；模块格式冲突时，错误信息常常像一封不太友好的情书

**依赖体积** ---- 使用构建分析、导入路径和包导出控制客户端体积；能加载不代表值得加载

**重点在这** ---- 模块解析是工具链的交通规则；解析不清，开发服务器、测试和生产构建会各走各的车道

## 第四站：资源处理与模块图

第四站来到资源物流中心：JavaScript 只是乘客，图片是大件货，字体是易碎品，Worker 还要走另一条通道。每种资源都要有明确的引用、输出、缓存和部署地址，不能统一丢进后备箱。

**源码资源导入** ---- 理解资源被纳入模块图、生成指纹、返回 URL 或内联的规则；导入方式会影响缓存和构建结果

**public 静态目录** ---- 认识不经过模块处理的公共资源、根路径引用和缓存责任；public 是直达车，不是所有文件的默认停车场

**资源内联** ---- 了解小资源内联、base64、构建阈值和首屏权衡；内联减少请求，也会增加 HTML 或 JS 体积

**图片与字体** ---- 规划格式、尺寸、懒加载、字体加载和 CDN；构建器能处理 URL，不能替你选择合适资源

**CSS 处理** ---- 认识 PostCSS、预处理器、模块化、自动前缀和 CSS 分割；CSS 也是构建图的一部分

**JSON 与其他资产** ---- 处理 JSON、文本、WebAssembly、Worker 和自定义资源；资源类型要和运行时需求匹配

**路径与 base** ---- 了解根路径、子路径、相对资源、部署在 CDN 或子目录时的地址策略；路径错一个斜杠，页面就能变成空白展览馆

**资源缓存** ---- 关注内容指纹、长期缓存、HTML 入口和版本失配；缓存有效期越长，发布更新越要谨慎

**重点在这** ---- 资源引用方式决定输出形态；先理解模块图，再决定资源放 src 还是 public

## 第五站：开发服务器、HMR 与代理

第五站是本地开发服务台：HMR 负责热更新，代理负责转发，HTTPS 负责安全上下文，WebSocket 负责保持联系。启动快只是见面礼，改动能及时反馈、错误能看懂才是真正的开发体验。

**开发服务器** ---- 认识根目录、主机、端口、监听地址、历史回退和静态服务；本机能访问不代表局域网一定能访问

**HMR** ---- 理解模块更新、状态保留、边界、全量刷新和失效条件；热更新不是魔法，模块边界不合适就会要求重启

**HMR 与状态** ---- 设计组件状态、全局状态和模块副作用的恢复；开发时不丢状态，生产时才更容易发现真正的问题

**代理** ---- 处理 API 转发、跨域、路径重写、WebSocket、Cookie 和 HTTPS；开发代理只解决开发环境，不能代替生产网关

**开发 HTTPS** ---- 认识证书、信任、Secure Cookie、服务工作者和安全上下文；HTTPS 配错时，浏览器会很诚实地拒绝配合

**自定义中间件** ---- 将日志、模拟数据、访问控制和特殊响应接入服务器；中间件应简单、可移除、可测试

**错误与调试** ---- 使用调试日志、源码映射、浏览器模块请求和服务器输出；先确认请求走到了哪一步

**局域网与容器** ---- 关注监听地址、端口暴露、容器网络和文件监听；“localhost”在容器里不一定是你以为的那台机器

**重点在这** ---- 开发服务器解决反馈速度与本地协作；代理、HMR 和 HTTPS 的边界要和生产架构分开

## 第六站：环境变量与运行时配置

第六站来到环境变量保险柜：公开变量可以上浏览器，密钥只能留服务器，构建时变量和运行时配置也不是同一把钥匙。前缀写错可能拿不到配置，前缀写对也可能把秘密送上街。

**模式文件** ---- 认识默认、开发、生产和自定义模式对应的环境文件；加载顺序和覆盖规则需要写进团队约定

**公开变量** ---- 理解只有明确前缀的变量会进入客户端；一旦进入浏览器，就不再是秘密

**构建时替换** ---- 了解变量通常在构建时注入，运行中的静态文件不会自动读取服务器新变量；部署方式不同，策略也不同

**类型与校验** ---- 为环境变量建立类型、必填校验、默认值和启动失败信息；拼写错的环境变量不应该默默变成 undefined

**服务端变量** ---- 区分 Vite 客户端变量与服务器运行时配置；密钥、数据库地址和内部令牌必须留在服务器边界

**多环境部署** ---- 处理预览、测试、生产、分支环境和动态配置；环境越多，变量来源越要可追踪

**敏感信息防护** ---- 检查日志、Source Map、构建产物和公开仓库；秘密泄露后，删掉变量并不等于没有发生

**重点在这** ---- 环境变量的第一原则是“公开与私有分开”；配置能让应用适配环境，也能让密钥坐上直达浏览器的高铁

## 第七站：插件系统与构建钩子

第七站进入插件游乐园：插件能改文件、造虚拟模块、接入框架、扩展服务器，还能把钩子排成一条没人敢碰的迷宫。能力越大，越要知道顺序、边界和退出方式。

**插件职责** ---- 理解文件解析、转换、解析、加载、生成和服务器钩子；每个插件应该有清晰的输入、输出和顺序

**插件顺序** ---- 关注前置、后置、框架插件和 Rollup 插件顺序；顺序不清时，两个插件可能像两位同时修改同一份作业的同学

**虚拟模块** ---- 用虚拟入口提供生成配置、路由、环境和元数据；虚拟模块要有稳定命名与调试路径

**文件转换** ---- 处理 Markdown、Vue、React、SVG、GraphQL 和自定义 DSL；转换越早发生，Source Map 越要准确

**开发服务器钩子** ---- 扩展中间件、WebSocket、热更新和模拟接口；开发能力不要偷偷改变生产行为

**构建钩子** ---- 参与输出、资源生成、清理和分析；钩子适合基础设施，不适合把业务逻辑埋进构建过程

**插件配置** ---- 管理选项、环境、类型、文档和错误提示；插件的默认行为要可解释

**自研插件治理** ---- 控制数量、版本、测试、兼容矩阵和弃用；插件不是越多越高级，依赖链太长会反噬反馈速度

**重点在这** ---- 插件是工具链的扩展边界；每增加一个插件，都要问它改变了什么、在哪运行、坏了怎么退出

## 第八站：生产构建与 Rollup 优化

第八站来到生产阅卷处：开发服务器可以飞，生产包却可能胖、慢、缓存不稳。代码分割、Tree Shaking、压缩和资源指纹会逐项打分，构建成功只是拿到准考证，不是考满分。

**构建流程** ---- 认识入口、模块图、转换、摇树、分割、压缩、资源输出和清理；构建是流水线，不是一个黑色按钮

**代码分割** ---- 按动态导入、路由、功能和依赖拆包；拆得太碎会增加请求，拆得太粗会拖慢首屏

**手动分包** ---- 了解 manual chunks 的收益与风险；分包应反映稳定的依赖边界，不要为了让文件名看起来整齐而硬切

**Tree Shaking** ---- 依赖 ESM 静态结构、sideEffects 声明和无副作用模块；导入一个函数不一定只带来一个函数

**压缩与 Source Map** ---- 处理 JavaScript、CSS、资源压缩和生产调试映射；Source Map 要保护敏感源码，同时保证定位能力

**产物分析** ---- 观察入口、共享块、重复依赖、动态块和大模块；分析报告是诊断工具，不是排行榜

**库模式** ---- 了解库入口、格式、外部依赖、类型声明和样式输出；库构建与应用构建的目标不同

**缓存策略** ---- 使用内容指纹、稳定入口、长期缓存和 HTML 更新；缓存和发布必须组成一套策略

**构建警告** ---- 区分真实风险、可接受的大资源和配置噪音；解决警告要修问题或明确阈值，不要习惯性静音

**重点在这** ---- 生产优化是体积、请求、缓存、调试和部署的平衡；看到一个大文件，先问它为什么大、谁需要它

## 第九站：SSR、SSG 与库开发

第九站打开 Vite 的多功能航站楼：SPA 走浏览器航线，SSR 走服务器航线，预渲染提前发货，库模式还要服务别人的项目。入口和运行时不同，行李规则也不同。

**SSR 基础** ---- 区分服务端入口、客户端入口、HTML 生成与水合；SSR 需要两套运行环境共同遵守同一份组件契约

**预渲染** ---- 了解构建时生成页面、动态路径、数据来源和部署；预渲染适合内容稳定但不代表所有页面都适合

**多入口应用** ---- 处理多个页面、管理后台、嵌入式小应用和共享资源；入口越多，公共块与缓存越重要

**库模式** ---- 规划模块格式、外部依赖、CSS、类型文件、Source Map 和发布字段；库的消费者环境可能比你的项目复杂得多

**Worker 与特殊运行时** ---- 处理 Web Worker、Service Worker、WebAssembly 和边缘限制；环境能力要明确，不要把 Node API 带进浏览器

**静态站部署** ---- 关注 base、路由回退、资源路径、CDN 和缓存；部署在子路径是路径策略的压力测试

**平台适配** ---- 比较 Node、容器、Serverless、边缘和静态平台；构建产物的运行方式会反过来限制代码写法

**重点在这** ---- Vite 是构建基础设施，不替你决定应用架构；理解入口与运行时，才能把它用在 SPA 之外

## 第十站：迁移、Monorepo 与排障

第十站是 Vite 故障维修铺：先查源码，再查解析、缓存、插件和产物，最后才考虑重装依赖。连续删除 node_modules 有时能带来心理安慰，但证据链才是真正的扳手。

**从 Webpack 迁移** ---- 对比入口、Loader、Plugin、别名、环境、代码分割和开发服务器；迁移是模型转换，不是配置文件逐行翻译

**从旧脚手架迁移** ---- 识别隐式 polyfill、环境变量、CSS 处理、代理和测试配置；先列出依赖的默认行为，再搬家

**Monorepo** ---- 处理工作区、包边界、依赖链接、共享配置和缓存；共享越多，边界和版本越需要纪律

**插件冲突** ---- 通过最小复现、顺序调整、日志和钩子范围定位问题；先确认谁改了模块，再决定改哪份配置

**缓存问题** ---- 区分浏览器缓存、预构建缓存、构建缓存、CDN 缓存和服务端缓存；每层都清一遍不是排障策略

**路径问题** ---- 检查 base、alias、根目录、子路径、容器和平台 URL；路径错误通常会在部署后才大声说话

**构建性能** ---- 观察依赖预构建、文件扫描、插件转换、类型检查和压缩时间；优化反馈速度也要有数据

**版本升级** ---- 关注 Vite、Rollup、插件、Node、浏览器和框架兼容；升级先读变更，再用最小范围验证

**重点在这** ---- 排障的核心是保留证据、缩小范围、确认运行阶段；盲目重装只能让问题暂时换个藏身处

## 通关标准

**Vite 新手村能启动项目** ---- 能解释开发、构建、预览、模式、根目录和环境变量。终端里出现一个本地地址只是开场动画，别把“能访问”误认成“已毕业”。

**初级前端能处理资源** ---- 能规划模块、图片、字体、CSS、Worker、路径和缓存。图片不会因为换了个文件夹就离家出走，字体也不会只在你的电脑上正常工作。

**中级前端能写插件** ---- 能理解常用钩子、虚拟模块、开发服务器和生产构建扩展，知道什么时候该扩展工具、什么时候该修自己的代码。插件不再是配置文件里的召唤术。

**高级前端能优化构建** ---- 能定位大包、重复依赖、分包、摇树、Source Map 和缓存问题。构建速度变快了，产物也没有悄悄塞进一整套不需要的家具。

**Vite 老兵能解决生产问题** ---- 能处理子路径、SSR、部署平台、环境变量、插件冲突和版本迁移。上线后不靠“本地没问题”护身，而是能把问题定位到具体边界。

## 结语

Vite 的快不是魔术，是把开发与生产的问题拆开处理。学会它之后，启动速度只是彩蛋；真正的能力是能看懂一条模块从源码到浏览器的旅程，并在它迷路时把它领回来。
