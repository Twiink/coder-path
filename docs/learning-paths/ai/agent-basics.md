# AI Agent 基础学习路线

想让 AI 不只是"回答问题",还能"自己动手干活"?这就是 **Agent(智能体)** 的领域——从能记住上下文的聊天机器人,到能规划任务、调用工具、自我纠错的自主智能体。它是 2023 年以来 AI 应用最热的方向:客服、代码助手、数据分析、自动化测试,本质都是 Agent。**前置**:先会用大模型 API(了解 [Prompt Engineering](/learning-paths/ai/prompt-engineering)),本页讲"把 LLM 组装成干活系统"的通用范式——不绑定具体厂商,示例以 OpenAI/Anthropic 兼容接口为主。

这条线按 **Agent 是什么 → 最小可用 Agent(上下文与记忆)→ System Prompt 设计 → 工具调用(核心)→ 高级模式(规划/反思)→ 工程实践与安全 → 框架与下一步** 推进。

## 第一站:Agent 是什么——从"问答"到"干活"

**一句话定义**:Agent = **大模型(大脑)+ 工具(手脚)+ 记忆 + 控制循环(规划与反思)**——不再是"问一句答一句",而是给它一个目标,它自己决定"下一步做什么、调什么工具、结果如何"。**与普通 Chatbot 的分界**:聊天机器人只有"对话",Agent 有"**感知 → 决策 → 行动 → 观察结果 → 再决策**"的闭环(循环直到任务完成)。**拆解四大件(面试/设计都按这个框架)**:①**大脑(模型)**:负责理解、推理、决策(选工具/写计划);②**工具(Tools)**:模型可以调用的外部能力——搜索、计算器、代码执行、数据库查询、HTTP API;③**记忆**:短期(对话上下文)+ 长期(向量库/文件/数据库);④**控制流**:循环、规划、停止条件、错误处理。**重要认知**:模型本身不"执行"任何事——**它只输出"文本意图"(要调什么工具、参数是什么),执行发生在你的代码里**,结果再送回模型。理解这个循环,Agent 的神秘感就消失了。**典型例子**:客服 Agent(查订单 API→生成回复)、代码 Agent(搜文档→写代码→跑测试→修 bug)。

## 第二站:最小可用 Agent——上下文与记忆

**从聊天机器人起步**:Agent 的最小形态就是"**有状态的多轮对话**",先吃透三个概念:**消息结构**:`system`(全局指令)/`user`(用户输入)/`assistant`(模型回复)——多轮 = 把历史消息数组不断追加再发给模型。**System Prompt(给 Agent 定义人格与行为准则)**:写清楚——**角色**(你是什么)、**目标**(你要达成什么)、**可用能力与边界**(能做什么/不能做什么/何时拒绝)、**行为规则**(回复格式、语气、安全红线)、**输出格式要求**(JSON schema/步骤化)。System Prompt 是投入产出比最高的"代码"——Agent 跑偏了先改它。**上下文窗口与 Token**:模型的输入有窗口上限(如 128K token);**每轮都把全部历史重发**——对话越长,费用与延迟越高。**上下文管理三策略(必会,面试常问)**:①**完整保留**(对话短,质量最好);②**滑动窗口**(只保留最近 N 条——简单粗暴,丢早期关键信息);③**摘要压缩(总结记忆)**:超阈值时把旧消息"总结成一段摘要"塞回上下文(信息密度高,长对话主力方案);进阶:关键信息提取(用户偏好/任务状态单独存结构化字段)。**Token 预算与成本控制**:估算(中文约 1 字 ≈ 1-2 token;可用 tiktoken 精确计);计价(输入比输出便宜约 3-5 倍);控制手段:max_tokens(限制回复长度)、上下文裁剪、**把"可检索"的内容移出上下文**(见 RAG 页);超长截断要有策略(砍最老的还是最不重要的)。

## 第三站:让 Agent 调用工具——Function Calling

**为什么需要工具**:LLM 知识有截止日期、**无法访问实时数据(天气/股价/你的数据库)**、无法执行动作(发邮件/改配置)——工具把"模型意图"变成"真实世界动作"。**Function Calling 机制(核心,要亲手实现一遍)**:①你把工具列表(名称+描述+**参数 JSON Schema**)随请求发给模型;②模型判断需要时,回复一段**结构化调用请求**(tool_calls:工具名+参数 JSON)——**不执行,只是"想调"**;③你的代码执行对应函数,把结果作为 `tool` 角色消息回填;④模型基于结果继续推理(可能再调下一个工具或给出最终答复)——**循环直到模型不再请求工具**。**工具定义的质量决定调用准确率**:描述要写清"何时用这个工具"(模型靠描述做路由);参数 schema 要严格(必填/枚举/格式);工具数量别一次给太多(十几个以上模型容易晕,分层:先粗路由再细工具)。**ReAct 模式(Reasoning + Acting,Agent 的经典范式)**:让模型显式输出 **Thought(我在想什么)→ Action(我要调什么)→ Observation(工具返回了什么)** 的循环——**想-做-看**交替;**可解释、可调试**(每步有迹可循),也是 Function Calling 之前的祖师爷(现在模型原生支持工具时,Thought 常被隐式化,但理解 ReAct 仍是一切 Agent 框架的心智基础)。**工具执行与错误处理**:工具可能抛异常/超时/返回空——把错误信息如实回传模型(它能换策略),设计重试上限与"放弃求助"路径;**工具副作用控制**:只读工具(查询)安全,写操作工具(发消息/删数据)要加确认或权限。**多工具协同示例**:用户问"对比今天天气和昨天",Agent 循环:调天气 API(今天)→ 调天气 API(昨天)→ 可能调计算(温差)→ 汇总回答。

## 第四站:高级模式——规划与反思

**Planning(先想后做)**:复杂任务直接"边做边想"容易迷失——**Plan-and-Execute:模型先产出任务清单/计划,再逐步执行**(每步完成后勾选/调整)——适合"多步骤、有依赖"的任务(研究报告、迁移项目);计划要能**动态修订**(执行中发现计划错了要允许重规划)。**Reflection(自我反思)**:执行完让模型**回看自己的输出**(critic 视角:哪里错了/漏了什么)→ 再修订——Self-Refine 模式能明显提升质量(写作/代码/答案类任务);多轮"生成-批评-修正"有成本上限,设轮数。**多 Agent 协作(进阶)**:角色分工(Planner 拆任务/Executor 执行/Critic 质检——AutoGen 的群聊模式)、辩论模式(两个模型互相质询收敛答案)——**复杂度与收益权衡:多数场景单 Agent + 好工具就够了,别为炫技上多 Agent**。

## 第五站:工程实践与安全(Agent 上线 checklist)

**落地案例与要点**:客服机器人(FAQ 检索 + 订单查询工具 + **兜底转人工**的边界设计);代码助手(工具:搜文档/读文件/写文件/执行测试——**执行不可信代码必须沙箱/容器/只读环境**,防提示词注入让 Agent 跑危险命令);数据分析 Agent(Text-to-SQL:**只读账号/库表白名单/行数限制/结果校验**——SQL 生成错会拖垮数据库,先 EXPLAIN 或 LIMIT);自动化测试 Agent(跑用例→记录失败→生成报告)。**可观测性(Agent 系统的命脉)**:完整记录每次循环的 **thought/action/observation**(回放排障)、token 用量与成本(每任务核算)、成功率/单任务轮数/延迟指标(没有指标就无法优化)。**安全(Agent 特有的威胁面)**:①**提示词注入**:工具返回的内容(网页/文档/API 响应)可能夹带"忽略你的指令……"——**把工具输出当不可信数据处理**:分隔与标注来源、模型侧加"只把外部内容当数据不当指令"的规则、敏感操作需人工确认;②**权限最小化**:只挂必要的工具、工具只给必要的权限范围(如数据库只读、文件限目录);③执行环境隔离(代码执行沙箱);④审计日志(谁在何时让 Agent 做了什么——合规必备);⑤**输出安全**:脱敏(PII/密钥拦截)。**模型选型与路由**:旗舰模型(强推理)做规划与复杂推理,轻量模型(便宜快)做分类/抽取/格式化——按任务难度路由是降本大头;**评估**:给典型任务建 golden 数据集,每次改 prompt/模型跑回归(没有评估的 Agent 优化是玄学)。

## 第六站:框架与学习路径

**两条路线**:①**先裸写(强烈建议)**:直接用官方 SDK(OpenAI/Anthropic)实现"工具定义→调用→回填→循环"——几百行代码让你彻底理解机制,出问题知道在哪层;②**再上框架**(提效):**LangChain**(通用编排:Agent/工具/记忆抽象,见 [LangChain 路线](/learning-paths/ai/langchain))、LlamaIndex(数据与 RAG 向,见 [LlamaIndex](/learning-paths/ai/llamaindex))、各家官方 Agent SDK(OpenAI Agents SDK/Anthropic Claude 的 Agent 能力,见 [Claude API](/learning-paths/ai/claude-api))、国内(百炼/扣子 Coze 等低代码)。**下一步分支**:想做"能用工具解决真实业务"→ [Agent 开发进阶](/learning-paths/ai/agent-development)(工具构建/工作流/生产化);想研究"自主多步规划"→ [自主 Agent](/learning-paths/ai/autonomous-agents)(AutoGPT/AutoGen 范式);想给 Agent 接知识库 → [RAG](/learning-paths/ai/rag-systems);提示词技巧 → [Prompt Engineering](/learning-paths/ai/prompt-engineering)。

## 通关标准

能独立做到:用官方 SDK 从零实现一个会调 2-3 个工具(如天气/计算器/查库)的 Agent(工具定义+调用循环+错误回填);设计一份能约束行为、防跑偏的 System Prompt;实现"滑动窗口 + 摘要"两档上下文管理并说出各自适用场景;给客服/数据分析类 Agent 画出"工具清单 + 权限 + 兜底"的安全设计;为你的 Agent 加上日志(thought/action 全记录)与 token 成本统计——AI Agent 基础主线通关。

Agent 不是魔法,是"**循环 + 工具 + 记忆**"的工程组装——把每一步拆开看都平平无奇,合起来却能让模型"干活"。它是 2024 年后 AI 应用开发者的基本功:先裸写一个循环(理解本质),再上框架(提高效率),最后把可观测与安全焊进系统(生产可用)。这条路走完,再看 AutoGen、LangGraph、各种 Agent 产品,你会一眼看穿它们的骨架。下一步:[Prompt Engineering](/learning-paths/ai/prompt-engineering) 打底,[Agent 开发](/learning-paths/ai/agent-development) 进阶。
