# AI 开发路线总览

AI 开发不是单独学习几个模型 SDK，而是从大模型基础出发，逐步完成“模型调用 → 知识增强 → Agent 编排 → 生产交付”的完整能力闭环。

## 这条路线怎么走

侧边栏按能力边界组织，而不是按厂商或框架平铺：

1. **基础与大模型**：先理解 LLM、推理和提示词，再掌握模型 API 的基本调用方式。
2. **Agent 系统**：理解 Agent 的循环、工具、记忆、规划和自主执行，再进入生产级开发。
3. **知识库与 RAG**：掌握 Embedding、向量检索、重排和知识库更新，让 Agent 能使用可靠的领域知识。
4. **框架与协议**：在理解原理后再学习 LangChain、LlamaIndex、MCP 和多 Agent 框架，避免被框架 API 牵着走。
5. **生产工程**：补齐安全、测试、部署、监控和成本控制，把 Demo 变成可交付的 AI 应用。

## 能力地图

| 阶段 | 重点问题 | 建议产出 |
| --- | --- | --- |
| 基础与大模型 | 模型能做什么，如何稳定调用 | 一个具备结构化输出的 LLM 应用 |
| Agent 系统 | 模型如何决定下一步并调用工具 | 一个能完成多步任务的 Agent |
| 知识库与 RAG | 如何让回答基于私有知识 | 一个带引用和评估的知识库问答 |
| 框架与协议 | 如何复用生态能力并连接外部系统 | 一个可编排、可扩展的 Agent |
| 生产工程 | 如何保证安全、质量、稳定与成本 | 一个可部署、可监控的 AI 服务 |

## 学习边界

Python、Git、数据库、网络、测试、部署和安全等通用能力仍然归入项目侧边栏的公共路线。AI 开发只保留 AI 特有的知识，避免同一项基础能力在多个方向重复维护。

模型微调、多模态、端侧推理、评估体系和 AI 产品设计属于后续扩展方向；它们应在现有主线稳定后继续拆成独立模块，而不是和 Agent、RAG、SDK 混在一层。
