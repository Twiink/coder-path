# 生成式 AI 应用开发路线总览

AI 开发不是背一串模型名称，也不是把“智能”两个字贴在普通 CRUD 上。完整能力链是：**理解模型 → 稳定调用 → 接入知识 → 组织工具 → 控制 Agent → 评估与上线**。每一步都能单独做成项目，连起来才是一条能交付的 AI 应用路线。

这页是地图，不是教程。它负责告诉你每个模块解决什么问题、应该先学什么、什么时候换路线；具体概念和工程细节放在各专题页。建议先读本页，再按自己的项目选择一条主线，别把侧边栏当自助餐厅每道都夹一勺，最后只记得自己吃撑了。

这条路线聚焦于把现有模型接入真实产品：模型调用、检索、工具、Agent、评估和上线。若目标是训练、微调、服务或运维模型，应转向[机器学习与模型工程](/learning-paths/machine-learning/overview)；若目标是分析数据、实验和洞察，应转向[数据科学](/learning-paths/data-science/overview)。三条路线会在数据、评估和部署上交汇，但不把彼此的基础任务混成一页清单。

## 第一站：先建立 AI 应用的全景图

欢迎来到 AI 应用的新手村。村口站着六位性格迥异的 NPC：模型负责动脑，适配层负责翻译，RAG 负责找资料，Agent 负责跑腿，编排层负责排班，治理层负责在大家闯祸前把门锁上。先认清谁负责什么，后面才不会让模型去替数据库签合同。

**模型层** ---- 负责理解、生成、分类、抽取、推理和多模态处理；模型能力有差异，但都不能直接替你访问数据库或改变业务状态

**适配层** ---- 统一消息、流式事件、结构化结果、工具调用、错误、用量和追踪信息；把供应商差异关在边界内，避免业务代码被某家 SDK 绑架

**知识层** ---- 负责文档解析、切分、Embedding、检索、重排、引用和数据更新；RAG 的难点是数据质量与评估，不是把向量塞进一个库

**行动层** ---- 负责工具、权限、确认、沙箱、幂等和副作用；模型只能提出行动意图，真正执行必须经过应用控制

**编排层** ---- 负责工作流、状态、循环、分支、并发、暂停、恢复和人工接管；简单流程用确定性代码，复杂流程再引入 Agent 或图编排

**治理层** ---- 负责安全、可观测性、评估、成本、版本、审计和上线策略；没有治理的 Demo 只是一个很会说话的事故预告

**重点在这** ---- 任何新概念都先问“它属于哪一层、解决哪个边界、失败时谁负责”；这三个问题比记住一百个类名更能迁移

## 第二站：主线学习顺序

主线像一条有补给站的长途路线：先学会开车，再换不同品牌的车，接着拉货，最后处理爆胎、堵车和账单。每一站都要留下一个可运行、可观测、可评估的阶段产物，不然很容易只收集到一堆“以后再看”的收藏夹。

**第一阶段：模型与提示** ---- 先掌握消息角色、上下文窗口、Token、提示词、结构化输出与基础评估；产出一个能稳定完成分类、抽取或摘要的模型应用

**第二阶段：通用 API** ---- 学会适配层、流式输出、错误重试、工具调用、成本记账与模型路由；产出一个能切换两家模型平台的内部接口

**第三阶段：知识增强** ---- 学会文档处理、Embedding、向量检索、混合检索、重排、引用和 RAG 评估；产出一个基于私有资料回答且能说清证据来源的知识库

**第四阶段：Agent 基础** ---- 理解工具循环、短期与长期记忆、停止条件、规划、反思和权限护栏；产出一个会调用两三个受控工具的任务助手

**第五阶段：生产 Agent** ---- 学会工作流编排、状态持久化、人工确认、并发、队列、故障恢复、观测和回归测试；产出一个可暂停、可恢复、可追责的业务流程

**第六阶段：框架与协议** ---- 在原理稳定后学习 LangChain、LlamaIndex、MCP 以及 Codex 等平台；产出应该证明框架带来了复用或控制力，而不是只证明你会安装依赖

**第七阶段：模型与基础设施分支** ---- 按数据边界、延迟、成本和多模态需求进入 Claude、OpenAI、Gemini 或本地开源模型；平台页是对照表，不是品牌收集册

## 第三站：按目标选择分支

每位冒险者的任务都不一样：有人要造知识库，有人要养 Agent，有人只想让本地显卡别闲着。先看任务公告，再选路线；从最热门的库出发，通常会在第三个教程里迷路并开始怀疑人生。

**想做知识库问答** ---- 模型 API → [RAG 系统](/learning-paths/ai/rag-systems) → [向量数据库](/learning-paths/database/vector-databases) → [LlamaIndex](/learning-paths/ai/llamaindex) 或 [LangChain](/learning-paths/ai/langchain)

**想做工具型助手** ---- [Prompt Engineering](/learning-paths/ai/prompt-engineering) → [Agent 基础](/learning-paths/ai/agent-basics) → [Agent 开发](/learning-paths/ai/agent-development) → MCP 与工作流编排

**想做复杂自主任务** ---- Agent 基础 → Agent 开发 → [自主 Agent](/learning-paths/ai/autonomous-agents)；先掌握停止、预算和人工接管，再研究“全自动”

**想接入某家模型** ---- [模型 API 通用原理](/learning-paths/ai/model-api-overview) → [OpenAI / Responses API](/learning-paths/ai/openai-responses)、[Claude API](/learning-paths/ai/claude-api) 或 [Gemini API](/learning-paths/ai/gemini-api)

**想在本地运行模型** ---- 通用 API → [开源模型与本地推理](/learning-paths/ai/open-source-local) → RAG/Agent 评估；先证明质量与运维成本，再决定是否为了“本地”承担完整基础设施

**想做编码 Agent** ---- Agent 基础 → [Codex SDK / App Server](/learning-paths/ai/codex-platform) → [MCP 协议](/learning-paths/ai/mcp) → [Codex MCP 兼容集成](/learning-paths/ai/codex-mcp)

## 第四站：阶段产物与验收方式

每阶段都有一位严肃的验收官。它不接受“截图看起来挺聪明”，只认固定样例、失败记录、运行指标和边界说明；AI 项目的毕业证，不能靠模型自己给自己盖章。

**模型应用** ---- 有一组固定输入、schema 校验、失败重试和 token/延迟记录；换模型后能比较质量、成本与响应时间

**RAG 应用** ---- 有来源、页码或文档版本等引用；能分别报告召回、上下文相关性、答案忠实度和无答案时的拒答质量

**工具 Agent** ---- 有工具清单、参数 schema、权限矩阵、最大步数、超时和审计记录；写操作默认需要确认，模型不能绕过服务端校验

**生产工作流** ---- 有状态持久化、取消、恢复、幂等、人工接管与降级路径；服务出错时能说明任务停在哪里，而不是只返回一句“请重试”

**平台适配** ---- 有统一内部契约与两套后端对照测试；平台特性可以暴露，但不能让供应商对象渗透到业务领域模型

**本地推理** ---- 有硬件、模型版本、量化方案、上下文长度、吞吐、首 Token 延迟和质量数据；可复现、可回滚，才算部署成功

**重点在这** ---- 先建小而真的评估集，再扩功能；AI 系统最怕功能越做越多，没人知道它到底有没有变好

## 第五站：暂时不要混在主线里的主题

村外还有微调、多模态、复杂评估、端侧推理和 AI 产品设计几片高级地图。它们都值得探索，但别刚学会点火就去挑战火箭发射；先把主线跑通，再决定要不要给显卡和自己增加支线任务。

**微调** ---- 适合稳定改变风格、格式或领域行为；如果问题是知识更新、权限或检索失败，先修 RAG 和数据管道

**多模态** ---- 先从图片、文档、图表输入开始，补齐脱敏、分辨率、上下文、成本与结果校验，再进入音视频和实时交互

**评估与观测** ---- 小项目也要有日志和样例，大项目再引入完整数据集、轨迹评估、在线采样和告警体系

**本地与端侧** ---- 数据合规、离线、延迟或成本确实需要时再投入；“能在电脑上跑”不等于“能为用户稳定服务”

## 通关标准

你不需要把所有平台学完才算入门。能从一个真实问题出发，选择合适模型，构造上下文，接入知识或工具，处理失败和权限，最后用评估数据证明结果，就已经进入 AI 应用开发的正循环。

完整通关应能交付一个小型 AI 服务：支持结构化输出或工具调用，有最小 RAG 或业务数据接入，有日志、成本和延迟统计，有提示词/模型版本记录，并能说明哪些事情应该交给代码而不是交给模型。

## 结语

AI 开发的主线其实很朴素：先让模型看懂，再让它找到证据，再让它调用工具，最后让系统在出错时知道怎么停。框架、平台和模型会轮换上场，但“边界、证据、权限、评估”这四位老员工不会退休。

别急着把所有按钮点亮。先交付一个小而真的闭环，能解释它为什么成功、为什么失败、花了多少钱、下一步该找谁；当你能做到这些，才算从“会和 AI 聊天”升级成“会做 AI 应用”。
