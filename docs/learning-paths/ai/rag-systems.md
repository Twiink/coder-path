# RAG 系统构建学习路线

**RAG(Retrieval-Augmented Generation,检索增强生成)** 是当下 AI 应用最重要的架构:让 LLM **先检索你的知识库,再基于检索到的内容生成答案**——一举解决大模型的三大痛点:**知识过时**(训练数据有截止)、**幻觉**(不懂装懂)、**没有私有数据**(你的文档/数据库它没见过)。从 2023 年起,"RAG 应用"几乎等于"知识库问答"的代名词:客服、文档助手、企业搜索、合规审查全是它。**与微调的分工(先想清楚)**:RAG 负责"知识与事实"(可更新、可溯源);微调负责"风格与格式"(让模型像你说话)——**多数场景先 RAG,微调是后话**。框架用法见 [LlamaIndex](/learning-paths/ai/llamaindex) 与 [LangChain](/learning-paths/ai/langchain) 页;本页讲**原理与调优方法论**。

这条线按 **基本流程与最简实现 → 切分 → Embedding 与向量库 → 检索优化 → 生成优化 → 评估体系 → 生产工程 → 高级形态** 推进。

## 第一站:基本流程——五段管线

**RAG 的标准管线(背下来,所有变体都是它的改装)**:①**加载**:把文档(Word/PDF/网页/数据库)读进来;②**切分**:长文档切成检索单元(chunk,下一站细讲);③**向量化**:每个 chunk 用 **Embedding 模型**转成向量(文本→高维向量,语义相近的文本向量也相近);④**检索**:把用户问题也向量化,在**向量库**里找最相似的 top-k 个 chunk(余弦相似度);⑤**生成**:把"问题 + 检索到的 chunks"拼进 prompt 交给 LLM,要求"只基于提供的资料回答"。
**为什么语义检索**:关键词检索匹配字面("苹果"找不到"iPhone 公司");向量检索匹配**语义**(近义词/同义表达都能命中)——这是 RAG 能"听懂人话"的根基。**最简实现(建议亲手写,约百行)**:选个 embedding API + 向量库(起步用内存列表都行)+ LLM API——五步各十几行;跑通后你就能看懂所有框架的 RAG 代码。
**经典失败模式(先有预期)**:检索不到(切分/embedding 问题)、检索到不相关(排序问题)、检索到但模型没用上(prompt 问题)——**后面每一站都在治这三种病**。

## 第二站:切分——质量的第一环

**chunk 大小是检索质量的第一旋钮**:太小(几百 token 以下)→ 语义碎、上下文不完整("这个方案"指代落空);太大 → 噪声多、检索命中率降、费 token。**经验值**:chunk_size 300-800 token(中文可偏小)、**overlap(重叠)10-15%**(避免关键句被拦腰切断)。**切分方式演进(由基础到高级)**:①固定长度(最糙);②**按结构切**(标题/段落/代码块——Markdown/HTML 结构化文档用结构切,保语义完整);③**语义切分**(按句子向量相似度找边界——更自然,计算贵);④**父子切分(生产常见)**:小块建索引(检索准)+ 关联大块(回答上下文全)——"检索到子块,生成用父块"。**切分评估**:同一问题在不同切分下的检索命中与答案质量对比——**切分没有银弹,按文档类型试**(代码/合同/小说策略不同)。

## 第三站:Embedding 与向量库

**Embedding 模型选型**:闭源(OpenAI text-embedding-3/Cohere)vs **开源(BGE/M3E/E5——中文场景国产开源模型常明显更好,可本地部署零成本)**;关注点:质量(自己数据集实测)、维度(越高越贵)、最大输入长度、多语言;**铁律:换 embedding 模型必须全量重建索引**(向量空间不同,旧向量不可比)。
**向量库选型(详见 [向量数据库](/learning-paths/ai/vector-databases) 页)**:原型 Chroma/FAISS(内存级,零运维)、**生产:pgvector(已有 PostgreSQL 直接加,事务与向量同库)/Milvus(大规模专用)/Qdrant(云托管友好)/Elasticsearch 的 dense_vector(已有 ES 生态)**——选型看:数据量、是否已有该库、运维成本。
**混合检索(强烈建议生产上)**:**向量(语义)+ 关键词 BM25(字面)互补**——专有名词、代码标识符、型号 ID 这类"语义检索的盲区"恰恰是关键词的强项;实现:两路检索后**分数融合(RRF 倒数排名融合或加权)**;Elasticsearch 的 hybrid、Qdrant/Weaviate 原生支持;**实测常见结论:混合 + 重排是"免费"的精度提升**。

## 第四站:检索优化——让"找到"更准

**按性价比排序的手段**:①**Rerank 重排(性价比之王,生产标配)**:第一阶段用便宜的向量检索取 top-20~50,再用**交叉编码器(Cross-Encoder,如 BGE-reranker)对"问题×候选"逐对精排**取 top-3~5——精度大幅提升、第二阶段只排几十条成本可控;②**Query 转换**:改写问题(口语→书面)、**多查询**(一个问题拆多个角度分别检索再合并——覆盖更全,费一点 token)、HyDE(先让模型写一段"假设答案"再用它检索——查询与文档用词差异大时有效);③**元数据过滤**:chunk 带元数据(日期/来源/部门/文档类型),检索时按条件圈范围——**多租户隔离与"只看某类文档"全靠它**;④**时间感知**:新闻/公告类场景按时间加权或过滤(最新优先);⑤Self-Query:让 LLM 把自然语言问题解析成"结构化过滤条件+查询词"("去年 Q3 的销售报告"→ &#123;date_range, doc_type&#125;)——复杂筛选的正确姿势。
**调试检索**:把"问题→召回的 top-k"打出来看(检索日志)——**检索不对,生成一定不对,先查检索**。

## 第五站:生成优化——让"用到"更充分

检索对了,生成侧还能再抠:**①上下文组装与指令**:检索块按相关度排序、块前标引用编号;prompt 明确"**只基于提供的资料回答;资料没有就明说不知道;不要编造**"(幻觉的最后防线,见 [Prompt](/learning-paths/ai/prompt-engineering) 页);②**引用溯源(信任与排障的基石)**:要求答案里标 `[1][2]` 并在末尾列出对应来源——**用户能点开验证,开发能定位"哪块导致答错"**;③**上下文压缩**:检索块里只有一句相关,整块塞入浪费 token 还可能引入噪声——用"相关性重写/裁剪"只留相关句子(LangChain 的 ContextualCompression/LlamaIndex 后处理);④**对话式 RAG(多轮)**:难点是"追问"("那它多少钱"没有主语)——先做**追问重写**(结合历史把问题补全)再检索;历史本身不进检索(太长),只用于改写;⑤**模型路由**:复杂回答用强模型,简单抽取用小模型。

## 第六站:评估体系——RAG 的体检报告

**没有评估的 RAG 优化是玄学**,两个层面分开测:**①检索质量**(召回有没有命中该命中的):指标 recall@k、命中率、排序质量;②**生成质量**(答案好不好):**忠实度 Faithfulness(回答是否忠于检索内容——防幻觉的核心指标)**、相关性(答没答到点上)、有用性;**实践工具**:**RAGAS(开源主流指标库:忠实度/答案相关性/上下文精度一键算)**、LlamaIndex 内置评估器、**LLM-as-judge**(让强模型打分——快,注意偏差,见 [Agent 开发](/learning-paths/ai/agent-development) 评估章);**数据集**:从你的文档自动生成 20-100 条问答对(golden set);**调优闭环**:跑分 → 看失败样本(**检索漏了?检索对但答案错?**)→ 针对性改(切分/检索/重排/提示)→ 回归重测——**每改一处都能量化涨跌,这才是工程**。

## 第七站:生产工程——从 demo 到服务

**①数据更新(知识库是活的)**:文档增删改的索引同步——删除旧块、重切、upsert(向量库按 doc_id 覆盖);定时管道 + 手动触发;②**索引版本管理**:embedding 模型升级/切分策略调整 = 索引重建(离线重建双写切换);③**多租户隔离**:向量库 partition/命名空间或强制元数据过滤——**检索层不过滤,数据就串了**;④**监控**:检索延迟、top-k 相关度分布、无结果率、生成延迟、token 成本、错误率;缓存(问题级语义缓存——相同问题直接回);⑤**防注入**:知识库文档也可能是恶意内容("忽略指令"藏在 PDF 里)——**检索内容一律当不可信数据处理**(见 [Prompt](/learning-paths/ai/prompt-engineering) 注入章);⑥**大文档/海量文档**:先分层(文档级检索→命中文档内再检索)或摘要树(先全局摘要再定位);⑦**RAG vs 长上下文**:单文档 ≤ 窗口且要全局理解 → 直接整读(更准);知识库大/要省钱 → RAG;**混合:长文档整读 + 检索 并存**(见 [Claude API](/learning-paths/ai/claude-api) 长文节)。

## 第八站:高级形态(按需点亮)

**Router(路由)**:一个问题先判"属于哪个知识库/哪条管道"再分派(客服:售前库/售后库/订单系统);**Agentic RAG(让 RAG 活起来)**:把检索做成 Agent 的工具——Agent 自主决定"要不要查、查什么、一次不够再查"(多跳问题:先查公司再查其产品);见 [Agent 基础](/learning-paths/ai/agent-basics);**GraphRAG(知识图谱增强)**:文档抽实体关系建图——"全局性问题"(整个语料有哪些主题/实体间什么关系)比纯向量强(微软开源方案,社区热度高);**多模态 RAG**:PDF 里的表格/图片 → OCR/视觉模型提取文本再入管道;**结构化数据 RAG**:问数据库走 Text-to-SQL(见 Agent 数据分析场景),别硬塞向量。

## 通关标准

能独立做到:自建或复用框架搭出五段式 RAG,并能逐环节解释"坏在哪怎么治";给文档选过切分策略(结构/父子)并说出理由;上过"向量+BM25 混合 + rerank"并量化精度变化;用 RAGAS 或 LlamaIndex 跑出检索与生成两类指标,能定位失败样本属于检索还是生成;生产清单(增量更新/多租户过滤/防注入/监控)逐项能落地——RAG 主线通关。

RAG 的价值在"**让 AI 说你有依据的话**":它把幻觉从"模型属性问题"变成"可检索可溯源的工程问题"。它的学习曲线不在概念(五步就懂),而在**调优手感**——切分、混合检索、重排、压缩、评估,每个环节都有 10% 的精度可挖,而评估体系让你每挖一步都看得见。把它和 [Agent](/learning-paths/ai/agent-basics) 结合(Agentic RAG)、和 [向量数据库](/learning-paths/ai/vector-databases) 结合、和 [微调] 结合,你会拥有 2025 年 AI 应用最值钱的一整套手艺。
