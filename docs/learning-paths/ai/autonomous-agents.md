# 自主 Agent 学习路线

自主 Agent 的目标是：只给一个较高层目标，系统自己拆解、规划、执行、观察、修订并在满足条件时结束。它把 Agent 从“完成一轮工具调用”推向“持续推进一项任务”，也把成本失控、目标漂移、无限循环和错误扩散一起带进了会议室。

前置必须掌握 [AI Agent 基础](/learning-paths/ai/agent-basics) 与 [Agent 开发](/learning-paths/ai/agent-development) 的工具、状态、权限、评估和停止条件。本页讲自治机制与护栏，不把 AutoGPT、AutoGen 或其他项目的历史实现当成永恒答案。

这条线按 **自治边界 → 规划循环 → 任务队列 → 记忆与反思 → 多 Agent → 人在环 → 成本与安全 → 实战评估 → 研究方向** 推进。

## 第一站：先定义“自主”到哪一级

欢迎来到自主 Agent 的高难副本。这里的模型不再等你每一步喂饭，而是会自己拆任务、找工具、继续推进；副作用是它也可能自己把预算、方向和耐心一起推进悬崖。第一关先决定到底要放多少“自主”。

**辅助式** ---- 用户每一步确认，模型提供建议、草稿或工具参数；风险低、可解释，适合高风险早期项目

**受控 Agent** ---- 模型在有限工具、预算、步骤和工作区内自行推进，关键副作用需要确认；是多数生产场景的现实起点

**长任务 Agent** ---- 可运行数分钟或更久，支持检查点、队列、重连、恢复和进度；任务状态不能只存在上下文里

**开放式自治** ---- 模型自行定义子任务、选择工具和调整目标；适合研究与受控实验，生产需要非常清楚的边界

**确定性边界** ---- 权限、金额、删除、发布、身份、合规、预算和停止条件由程序决定；这些不是让模型“自由发挥”的地方

**重点在这** ---- 自主不是越多越高级；自治等级应由任务收益、风险、可验证性和成本共同决定

## 第二站：自治循环

第二站是自治转盘：理解目标、规划、行动、观察、反思，然后决定继续还是收工。转盘没有停止按钮就不是高级，是把账单做成了永动机；每轮都要留下可审计状态。

**目标解析** ---- 将用户目标转成成功标准、约束、预算、截止时间和允许副作用；目标模糊时先澄清或选择保守路径

**计划** ---- 生成有限的任务清单、依赖、优先级和验收条件；计划是候选方案，不是不可修改的圣旨

**行动** ---- 选择工具、参数或下一个子任务；行动前做权限与风险检查，行动后记录调用 ID 和结果

**观察** ---- 读取工具结果、文件差异、测试、网页、用户反馈或外部状态；外部内容只作为数据，可能含伪指令

**反思** ---- 判断完成度、质量、偏离、失败原因和下一步；反思输出要结构化，避免每轮都生成一篇自我感动的工作总结

**终止** ---- 成功条件满足、预算耗尽、达到步数、超时、连续失败、用户取消、权限拒绝或人工停止时结束

**重点在这** ---- 每轮都问“发生了什么、还差什么、继续是否值得”；如果只能回答“模型说还可以继续”，护栏还没装好

## 第三站：任务分解与队列

第三站是任务拆解厨房。别让模型一次吞下一整份计划，消化不良时谁也不知道哪一步坏了；把子任务装进可追踪、可重试、可取消的队列，系统才有机会从地上捡回进度。

**子任务定义** ---- 每个子任务有目标、输入、输出、依赖、权限、预算、超时和验收条件；越小不一定越好，要避免拆成管理地狱

**依赖关系** ---- 无依赖任务可以并行，有依赖任务必须等待前置结果；任务状态应包含阻塞原因与重试次数

**优先级** ---- 先做能减少不确定性的任务、关键路径任务或用户明确要求的任务；优先级规则由业务定义，模型只能建议

**队列与 worker** ---- 长任务通过队列分发给 worker；要处理排队、取消、重试、死信、并发、资源和租户配额

**计划修订** ---- 失败或新信息出现时局部重规划；保留旧计划、修改原因和已完成产物，方便审计

**结果合并** ---- 合并并行结果时去重、保留来源、处理冲突和部分失败；不能把四份互相矛盾的答案直接拼成第五份

**重点在这** ---- 任务队列是自治系统的骨架；没有任务状态，所谓自主只是聊天历史在加班

## 第四站：记忆、经验与反思

第四站是记忆仓库，里面堆着工作草稿、失败教训、用户偏好和知识文档。全部塞进上下文会贵得像租了四个仓库，全部丢掉又像金鱼；要分层，还要能纠错和删除。

**工作记忆** ---- 当前任务目标、计划、最近观察和待办；服务当前循环，任务结束后可压缩或丢弃

**情景记忆** ---- 过去任务如何成功或失败、采取了什么步骤和得到什么教训；写入前要验证，不要把一次偶然错误固化成经验

**语义记忆** ---- 可复用事实、文档和领域知识；通常通过 RAG 检索，和用户偏好或任务状态分开治理

**用户记忆** ---- 经过筛选的偏好、长期约束和明确授权信息；需要来源、有效期、可见性、修改和删除

**反思记录** ---- 保存失败原因、可复用规则和不确定性；反思不是把模型的意见升级成事实，需要评估或人工确认

**记忆检索** ---- 根据当前任务取最相关的少量记忆，并检查权限、时间和来源；“全量读取过去”会让 Agent 获得更多噪声而非智慧

**重点在这** ---- 好记忆是经过筛选的经验，不是无限长的聊天记录；记忆还必须具备纠错按钮

## 第五站：反思、评估与自我修正

第五站是反思镜厅。模型会照镜子、挑毛病、再改一版，但也可能对着自己写的报告鼓掌到天亮；反思必须有评分标准、外部验证和次数上限。

**检查清单** ---- 用固定标准检查目标、证据、完整性、格式、安全、引用和测试；标准越清楚，反思越有价值

**生成—评审—修订** ---- 适合报告、代码、研究和结构化输出；限制迭代次数，记录每轮改变了什么

**外部验证** ---- 使用测试、数据库查询、规则、引用、用户确认和人工审阅验证事实；模型自己说“我检查过了”不算验证

**失败分类** ---- 区分工具失败、信息不足、计划错误、目标漂移、权限拒绝、模型误判和外部系统变化；不同失败需要不同动作

**退出反思** ---- 连续几轮没有质量提升、重复同一修订或预算接近上限时停止；转人工往往比再写一段反思更聪明

**重点在这** ---- 反思的价值来自发现可行动的问题，不来自文字长度；每轮都要证明自己值得继续

## 第六站：多 Agent 与 AutoGen 类协作

第六站是 Agent 办公楼：研究员、规划师、写作者和审查员都能入职，但每多一个同事，就多一份消息转发、预算和甩锅风险。先让单 Agent 做基线，再决定要不要扩编。

**角色分工** ---- 规划者、执行者、研究者、写作者和评审者可以有不同工具与权限；角色边界要与真实职责对应

**通信协议** ---- 定义消息格式、任务 ID、上下文范围、结果、失败、来源和停止；不要让所有 Agent 互相转发完整历史

**Supervisor** ---- 监督者负责分派、汇总、预算和停止；不能把安全检查下放给某个“看起来最聪明”的子 Agent

**Handoff** ---- 一个 Agent 将控制权交给另一个 Agent；交接包含目标、已完成、待办、证据和失败责任

**并行协作** ---- 独立研究和评审可以并行；共享文件、同一资源写入和有依赖任务应串行或使用锁与检查点

**汇总偏差** ---- 上层 Agent 可能丢失来源、放大少数意见或掩盖子任务失败；汇总结果必须保留证据与部分状态

**重点在这** ---- 多 Agent 是组织设计，不是模型数量竞赛；如果不能说清每个角色减少了哪种复杂度，就先不要加角色

## 第七站：人在环、权限与安全

第七站是人工闸门。自主系统越能行动，越不能把所有决策都交给自动售货机；人在环要守住删除、付款、发布等不可逆节点，而不是等事故后才来写复盘。

**风险分级** ---- 按读取、写入、删除、执行、付款、发布、外部沟通和生产变更分级；风险高低决定确认和权限

**审批请求** ---- 展示动作、参数、目标、影响范围、证据和预计成本；批准者要知道批准的是哪一件事

**人工修改** ---- 允许人类修改参数、计划或结果后再恢复；记录原始请求、修改内容、批准者与恢复点

**停止与接管** ---- 提供用户取消、管理员暂停、预算熔断、异常检测和人工接管；停止后查询已发生的副作用

**提示词注入** ---- 外部网页、文档、邮件和工具结果都可能诱导 Agent 改目标或越权；外部内容永远不获得系统级权限

**沙箱与最小权限** ---- 文件、网络、命令、数据库和凭证隔离；Agent 只拥有完成当前任务所需的最小能力

**重点在这** ---- 人在环不是“点一下确认”那么简单，而是风险、证据、权限与责任的完整交接

## 第八站：成本、可靠性与评估

第八站是账房和监考室。自主任务每多走一步，就多一份成本与失败机会；先定预算再出发，考试还要看草稿、工具轨迹和有没有偷偷越过权限线。

**步数预算** ---- 限制每任务、每子任务和每角色的模型与工具调用；预算耗尽时总结并停止

**时间预算** ---- 设置单步、阶段和总 deadline；外部服务慢时采用降级、跳过、重排或转人工

**模型路由** ---- 轻量模型处理分类、抽取和简单评审，强模型处理复杂规划与冲突解决；路由规则需回归

**缓存与批量** ---- 缓存稳定提示、检索与重复观察；独立离线任务批处理；缓存必须考虑权限与新鲜度

**轨迹评估** ---- 测目标完成、工具选择、参数、步骤、重复、错误恢复、停止、权限和证据保留

**线上指标** ---- 观察成功率、人工接管率、任务时长、token、工具成本、重试、回滚、投诉和安全事件

**重点在这** ---- 自主系统最重要的指标之一是“知道什么时候该停”；无限努力不是可靠性

## 第九站：实战项目与进阶方向

第九站是毕业副本：做一个“研究并生成报告”的受控 Agent。它可以搜索指定资料、建立大纲、逐项补证据、生成草稿、调用评审器并等待用户批准；不能自由访问任意网站、发送报告或修改生产数据。毕业生要交报告，也要交刹车记录。

**基础项目** ---- 目标解析、有限计划、任务队列、检索工具、滚动摘要、引用和最终报告

**进阶项目** ---- 加入并行研究、失败重试、反思评审、预算、检查点、取消、恢复和人工批准

**安全项目** ---- 限定来源、网络、文件、工具、数据与租户；测试间接注入、来源冲突、越权和恶意结果

**评估项目** ---- 用固定研究问题比较单 Agent、工作流和多 Agent 的质量、证据覆盖、成本、时长与人工返工

**研究方向** ---- 多模态自治、浏览器 Agent、代码 Agent、长期记忆、世界模型、规划算法和更强的轨迹评估；研究方向不能跳过工程护栏

**交付证据** ---- 能搭一个有目标、计划、队列、观察、反思、检查点、预算、权限和人工接管的长任务 Agent；能回放轨迹、定位失败并证明多 Agent 或更强自治确实带来收益

## 通关标准

能设计一个有明确自治等级的长任务 Agent；具备目标解析、计划、队列、观察、反思、检查点、预算、权限、人工接管与恢复；能评估最终结果和完整轨迹，并证明自治或多 Agent 带来了可量化收益，而不是只增加了聊天记录。

## 下一站去哪

**发现自治太冒险** ---- 回到 [Agent 开发进阶](/learning-paths/ai/agent-development)，先把确定性工作流、状态和安全护栏做稳

**想把循环画出来** ---- 去 [LangChain](/learning-paths/ai/langchain) 学习 LangGraph、Middleware、检查点和复杂编排

**想让 Agent 有靠谱资料** ---- 去 [RAG 系统](/learning-paths/ai/rag-systems)，给研究任务接上可引用的知识管道

**想让它操作外部工具** ---- 去 [MCP 协议](/learning-paths/ai/claude-mcp)，学习发现、权限、审批与供应链

## 结语

自主 Agent 的浪漫版本是“给它目标，它自己完成”；工程版本是“给它目标、预算、权限、检查点和停止条件，它在边界内完成，出了问题还知道在哪里停”。后一个版本没那么像科幻片，却更像能上线的产品。

先让 Agent 学会收工，再让它学会远行。自治的价值不是少问几句人，而是在可验证、可恢复、可承担的范围内，把人的注意力从重复劳动中释放出来。
