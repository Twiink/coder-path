# 自主 Agent(AutoGPT/AutoGen 范式)学习路线

给 AI 一个目标,让它自己搞定——**自主 Agent(autonomous agent)** 是从"问答助手"到"自主同事"的跨越:不再每步等人喂,而是**目标驱动、自主规划、持续执行、自我反思**,直到任务完成。AutoGPT(2023 年的现象级开源项目)点燃了这股热潮,但它也暴露了现实:**全自主还很不可靠**——偏离目标、成本失控、无限循环是常态。所以这条路线既教"自主循环怎么搭",更教"**怎么给自主装上护栏**"(终止、预算、人在环)——**受控的自主才是能上生产的自主**。前置:[AI Agent 基础](/learning-paths/ai/agent-basics)(工具调用循环)与 [Agent 开发](/learning-paths/ai/agent-development)(工程化)。

这条线按 **核心机制与循环 → 自主循环的工程实现 → 记忆与反思 → 多 Agent 协作(AutoGen)→ 安全与人在环 → 实战项目 → 现实定位与研究** 推进。

## 第一站:核心机制——Think-Plan-Act-Observe-Reflect

**自主 Agent 与普通 Agent 的分界**:普通 Agent 是"一问一循环"(用户给任务→调用工具→回答);自主 Agent 是"**给定一个目标,自己拆解出子任务序列,连续多轮推进**"(如"调研并写一份新能源车市场报告"——它自己规划搜索哪些主题、分几轮写、怎么查漏补缺)。**核心循环 TPAOR(Think-Plan-Act-Observe-Reflect,记住这个缩写就能讲清自主 Agent)**:①**Think**:理解当前状态与目标差距;②**Plan**:决定下一步(拆任务/定顺序/选工具);③**Act**:执行(调工具/写内容/发请求);④**Observe**:看结果(工具返回/报错);⑤**Reflect**:评估进展——完成了?偏了?失败了怎么调整?→ 回到 Think——**直到满足终止条件**。**AutoGPT 的核心思想**(都在这循环里):**任务分解**(目标 → 可执行的 task 清单)、**循环执行**(每次只做一步,动态更新清单)、**动态调整**(计划不是一次定死,根据观察持续修订——**计划是活的**)、**自我反思**(每轮自评进度与质量)。**记忆三型(自主 Agent 的"经验系统")**:短期记忆(当前上下文)、长期记忆(向量库存事实/文档,见 [RAG](/learning-paths/ai/rag-systems))、**情景记忆(episodic:存"过去怎么做成的/怎么失败的"——Reflexion 范式的核心:把教训写进记忆,下次规避)**。**终止条件设计(第一课,防失控先于能力)**:显式完成判定(模型输出"任务完成 + 最终交付")、**最大轮数**(如 30 步)、**成本上限**(见下一站)、时间上限;终止条件不足 = 无限空转烧钱——**"什么时候停"与"怎么走"同等重要**。

## 第二站:自主循环的工程实现——从 20 行到 200 行

**最小自主循环(建议亲手写一遍,就 20 行左右)**:给模型 system prompt(角色+目标+可用工具+输出格式(每步输出 JSON:thought/action/action_input))+ 循环:{ 调模型 → 解析 action → 执行工具 → 把 observation 追加进消息 → 判断终止(模型说完成/超轮数/超预算) }——**先跑通裸循环,再加一切**(所有框架都是这个循环的装修)。**工程化要点**:①**任务队列动态管理**(拆出的子任务入队,带依赖的等前置完成——复杂任务别让模型"一次性背完计划",边做边拆);②**错误处理分级**(工具失败:瞬时错(网络)→重试;逻辑错(参数)→让模型换参重来;**连续失败(如 3 次)→降级**:换策略/跳过该子任务/报告人工——**别让模型在同一个坑里重试到天荒地老**);③**上下文管理**(自主任务跑几十轮,历史超窗——**每轮后把"已完成步骤摘要+当前任务状态"压缩回上下文**(滚动摘要),原始细节落日志/向量库备查);④**调试**:每步 thought/action/observation **结构化落盘**(JSON Lines)——自主 Agent 行为随机,**能回放才能 debug**;⑤**可观测面板**(简单版:每步状态+成本+耗时列表)。

## 第三站:成本控制——自主 Agent 的经济学

**成本失控是自主 Agent 的第一生产事故**:一次"写报告"任务可能触发 30-80 次模型调用,且**模型可能重复调用同一工具**(上次失败重试/忘了已查过)——防护体系:**逐轮记账**(每次调用的 token/费用累计)、**总预算硬顶**(超预算触发优雅收尾:输出当前成果+说明+转人工——别硬断在中途)、**轮内去重**(工具调用结果按 key 缓存——同一查询不重复付费)、**模型路由**(规划/反思用旗舰,子任务(摘要/分类/改写)用轻量模型——成本差 10 倍以上)、**prompt 精简**(长 system prompt 每轮都付钱,能短则短;历史用摘要而非全文);**监控告警**(单任务成本异常突增 = 循环失控信号——熔断:连续 N 轮"无进展"(观察没带来状态变化)自动暂停)。

## 第四站:多 Agent 协作(AutoGen 范式)

**为什么要多 Agent**:让"不同视角"对话——写代码的与审查代码的分开,比一个 Agent 自写自审更有效(自己审自己容易自恋)。**AutoGen 的经典组件**:①**角色 Agent**(系统提示定义人格与能力:Assistant(出方案/写代码)/Critic(挑错)/Executor(执行工具));②**UserProxy(关键设计:代表人类的代理)**——它"假装是用户"在对话里插入反馈,并**负责执行代码/工具**,天然形成"**提出→执行→反馈**"的闭环,**也是 human-in-the-loop 的接入点**(关键步骤由真人接管);③**GroupChat(群聊)**:多个 Agent 轮流发言,GroupChatManager 决定下一个谁说——适合头脑风暴/辩论型任务;**必须设 max_round(群聊没有终止条件会聊到预算爆炸)**;④**Sequential Workflow**(流水线:生成→审查→修改→测试,顺序传递——确定性更强,生产更爱);⑤**Nested Chat**(Agent 内部再开子对话解决子问题——递归分解)。**多 Agent 的代价(清醒认知)**:token 消耗成倍(每轮所有 agent 都发言)、**串联错误放大**(一个 agent 的错会污染下游)、调试复杂度陡增——**选择标准:任务需要"不同角色的视角冲突"时(代码审查/方案辩论/内容多轮打磨)才值得**;单 Agent + 好工具 + 反思循环能覆盖 80% 场景。**MetaGPT 变体**(角色化 + SOP 流程:产品经理→架构师→工程师按标准作业流程接力——研究/团队协作向)。

## 第五站:安全与人在环(human-in-the-loop)

**自主 Agent 的风险放大器**:一个目标 → 一串自主执行的工具调用 → 真实副作用(写文件/发请求/花钱)——所以护栏必须更硬:**HITL 设计**:关键决策点插入人工确认——写操作(发邮件/改数据/删除)、花钱(下单/调用付费 API)、高影响输出(对外发布)——实现:工具层确认钩子(遇到写操作暂停,等人工 approve/reject/修改);**AutoGen 的 UserProxy 就是标准 HITL 模式**(人可以在循环里随时插入指令)。**其他护栏**:工具白名单与最小权限、**执行环境沙箱**(自主 Agent 跑的代码/命令必须在容器,见 [Docker](/learning-paths/devops/docker))、**审计日志**(谁/何时/让 Agent 做了什么——全链路留痕)、熔断与降级(连续失败/超预算 → 自动暂停并通知人)、**目标约束强化**(system prompt 定期重申边界:"你只能做 X,不能做 Y;涉及 Z 必须停下问人"——自主 Agent 跑久了会"忘本",定期把约束贴回上下文);**多租户隔离**(一个用户的检索/记忆不能串给另一个用户——自主 Agent 带记忆后尤其危险)。更系统的注入/权限框架见 [Agent 开发](/learning-paths/ai/agent-development) 的安全章。

## 第六站:实战项目(建议复刻 2-3 个)

①**简化版 AutoGPT(必做,理解全局)**:核心循环 + 3-4 个工具(搜索/文件读写/计算) + 预算与轮数硬顶——跑一个"调研并写总结"任务,观察它怎么偏、怎么救;②**代码三 Agent 流水线(体验多 Agent 价值)**:Writer(按需求写)→ Reviewer(挑 bug/风格)→ 修改循环 → Tester(跑测试)——对比单 Agent,质量与可控性差异直观;③**研究助手(Plan-and-Execute)**:先出大纲计划 → 逐节搜索写作 → 汇总——**长任务用"先计划后执行"比自由循环稳得多**;④**Reflective Agent(Reflexion)**:任务失败后生成"反思文本"(为什么失败/下次怎么避免)写入记忆,重跑同任务对比成功率——感受"经验累积"的力量;⑤**Generative Agents 小镇式模拟**(进阶/研究):记忆流+反思+规划的行为模拟——理解"自主"的学术前沿形态。**评估**:自主任务随机性大——golden 任务集 + 成功率/轮数/成本三指标,每次改动跑回归(评估方法见 [Agent 开发](/learning-paths/ai/agent-development))。

## 第七站:现实定位、开源与下一步

**清醒的现实定位**:2024-2025 的自主 Agent **"演示强于生产"**——AutoGPT 式"随便给个目标自己跑"在真实业务里可靠性不足;**生产落地的正确姿势是"受控自主"**:限定任务域(别让它跨领域自由发挥)+ 确定性流程兜底(能编排就编排,见 LangGraph)+ 强护栏(预算/轮数/人在环)+ 明确交付物(自主部分只负责"探索与草稿",人负责"确认与发布")。**研究/前沿方向**:Voyager(游戏探索:技能库累积)、Generative Agents(记忆+社交模拟)、Agent 评估基准(GAIA 等)、浏览器/桌面操作 Agent、**多模态自主 Agent**。**开源地图**:AutoGPT(架构参考:任务队列+循环)、BabyAGI(最简任务循环,几十行)、MetaGPT(角色化流程)、AutoGen/AG2(多 Agent 对话)、CrewAI(角色 Crew 协作)——**看架构思想,别照抄会过期的代码**。**论文必读三篇**:ReAct(推理-行动交替的祖师)、Reflexion(语言强化:反思重试)、Generative Agents(记忆/反思/规划的完整建模)。**下一步**:基础不牢回 [Agent 基础](/learning-paths/ai/agent-basics);要工程化生产回 [Agent 开发](/learning-paths/ai/agent-development)(图编排/评估/成本);给自主 Agent 接知识库 → [RAG](/learning-paths/ai/rag-systems);把"思考得更深"交给 [Prompt Engineering](/learning-paths/ai/prompt-engineering)。

## 通关标准

能独立做到:从零写出带轮数/预算双硬顶的最小自主循环(JSON 化 thought/action 日志可回放);给"写报告"类任务设计 Plan-and-Execute 流程并说清它比自由循环稳在哪;搭一个带 UserProxy 与人工确认点的多 Agent 流水线(生成→审查→测试),并能量化多 Agent 的 token 成本;实现一次 Reflexion 式"失败反思→记忆→重试"并对比成功率;给任何自主 Agent 项目列出完整护栏清单(终止/预算/熔断/沙箱/审计/HITL)——自主 Agent 主线通关。

自主 Agent 是 AI 应用皇冠上的宝石,也是最容易翻车的方向:它把"模型不可靠 + 循环放大 + 成本失控"三个问题叠在了一起。学它的正确姿势:**先敬畏(护栏先行),再赋能(循环与记忆),后放权(有限域自主)**——能把一个"自主写周报的 Agent"稳定跑三个月,比 demo 一个"全自主 CEO Agent"值钱一百倍。框架会过时,但"目标-计划-执行-反思-终止"这套心智与"预算/人在环/审计"这套工程,会陪你很久。下一步:夯实 [Agent 基础](/learning-paths/ai/agent-basics) 或钻研 [LangChain](/learning-paths/ai/langchain)/LangGraph 的实现。
