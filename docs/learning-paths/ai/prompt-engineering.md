# Prompt Engineering

跟 AI 说话是门技术活。同样的问题，换个问法，效果可能天差地别。这条路线会教你如何写出让 AI 又听话又聪明的提示词。

## 基础篇

掌握这些，你的 prompt 质量能提升 80%：

- **清晰具体的原则**：别让 AI 猜你想要什么
- **结构化 Prompt**：给 AI 一个填空的框架
- **角色设定（Role Playing）**：让 AI 扮演专家角色
- **输出格式控制**：要 JSON 就给 JSON，要 Markdown 就给 Markdown
- **Few-Shot Learning**：给几个例子，AI 就懂你要什么
- **零样本 vs 少样本**：什么时候用哪个

## 进阶篇

想让 AI 更聪明？试试这些高级技巧：

- **Chain of Thought（思维链）**：让 AI 展示推理过程
- **Self-Consistency**：生成多个答案，投票选最佳
- **Tree of Thoughts**：探索多条推理路径
- **ReAct 模式**：推理 + 行动循环
- **Prompt Chaining**：把复杂任务拆成多个步骤
- **Negative Prompts**：告诉 AI 别做什么
- **Temperature 和 Top-p 调优**：控制创造性和确定性
- **System Message 设计**：定义 AI 的全局规则

## 实战篇

理论再好，不如动手练：

- **代码生成 Prompt**：让 AI 写出高质量代码
- **代码审查 Prompt**：找 bug、提建议、评估性能
- **文档生成**：API 文档、README、技术方案
- **数据处理**：结构化输出、格式转换、信息提取
- **测试用例生成**：边界情况、异常处理、覆盖率优化
- **Meta Prompts**：用 AI 生成更好的 Prompt
- **Prompt 版本管理**：记录迭代过程，A/B 测试效果

## 下一步学习

Prompt 只是工具，组合起来才强大：

- **AI Agent 基础** → 让 AI 能调用工具执行任务
- **LangChain 框架** → Prompt Template、Few-Shot 管理
- **Claude API 使用** → System Prompt、多轮对话、长文本处理

## Few-Shot Learning：教 AI 举一反三

有时候你说破嘴皮 AI 也不懂，那就给它看例子。这叫 Few-Shot Learning。

做法：准备 2-5 个「输入 → 理想输出」的示例再提问；示例风格要与目标输出一致，数量不必多，贵在典型。

给几个例子，AI 就知道你想要什么风格的输出了。就像给新员工看前辈的工作成果。

## Chain of Thought：让 AI 慢慢想

直接让 AI 给答案，很容易出错。让它把思考过程写出来，准确率会高很多。

做法：在提问末尾加一句「请先逐步推理，再给出最终答案」，复杂数学与多步逻辑题的准确率会明显提升。

结构化版本：要求模型按「理解问题 → 分析 → 解决方案 → 代码实现 → 验证」的固定框架输出，推理更完整、结果可审阅。

这个技巧特别适合复杂问题。就像让学生展示解题步骤，不仅能得到答案，还能看到思路。

## Role Playing：给 AI 一个人设

告诉 AI 它是谁，它就会按照这个角色的方式思考和回答。

做法：开头给 AI 设定身份与视角（如"你是一位有 10 年经验的安全专家"），它会按该角色的知识结构与语气作答；代码审查等任务可让多个角色轮番上阵。

同一段代码，不同角色的人会看到不同的问题。这就是 Role Playing 的威力。

## Temperature 与 Top-p：控制 AI 的创造力

这两个参数控制 AI 的"发散程度"。

调参口诀：代码生成与数据提取要确定性，temperature 调到接近 0；创意写作要发散，0.7-0.9 更合适。Top-p 一般与 temperature 二选一调节即可。

Temperature 像是给 AI 喝酒，喝得越多越放飞自我。Top-p 像是限制它的词汇表范围。

## System Message：设定全局规则

System message 是最强大但也最容易被忽视的工具。它决定了 AI 的"人格"。

System Message 是全局规则手册：定义角色、语气、输出格式、禁忌与边界。稳定不变的约束放 system，每次变化的需求放 user。

System message 就像给 AI 发了一份工作手册。它会按照手册的要求来工作。

## Prompt Chaining：分而治之

复杂任务不要一个 prompt 搞定，拆分成多个步骤，每个步骤一个 prompt。

拆法：复杂任务先列步骤（需求分析 → 方案设计 → 实现 → 审查），每一步一个 prompt、只专注一件事，上一步输出作为下一步输入。

Prompt Chaining 就像流水线作业，每一步都专注做好一件事。最后组装起来就是完整产品。

## Negative Prompts：告诉 AI 别干什么

有时候告诉 AI"不要做什么"比告诉它"要做什么"更有效。

技巧：明确列出「不要」清单（不要解释、不要重复、不要输出 Markdown），能有效压住 AI 的过度发挥。

Negative prompts 就像给小孩立规矩："不许摸火"、"不许玩电"。有些坑，明确说清楚，AI 就不会踩。

## 元提示（Meta Prompts）：让 AI 生成 Prompt

最高级的技巧：让 AI 帮你写 prompt。

玩法：先让 AI 描述"生成高质量 prompt 的规则"，再让它按规则为你的具体任务产出专用 prompt，实现提示词的自我迭代。

这就是所谓的"递归式提示"。用 AI 来优化 AI 的使用方式。

## 实战技巧汇总

模板沉淀：把反复验证有效的 prompt 固化成模板（角色 + 任务 + 约束 + 输出格式），并做版本管理与 A/B 测试，迭代有依据。

格式锚定：明确要求"按以下格式回答"，用编号、表格或填空结构把输出钉死，AI 的排版与结构就会很听话。

## 最后的建议

Prompt Engineering 不是玄学，是实践出来的。几个核心要点：

1. **清晰明确**：别指望 AI 能读懂你的心思
2. **结构化**：给 AI 一个框架，它会表现更好
3. **迭代优化**：第一个 prompt 不满意就改，没人第一次就能写完美
4. **提供示例**：有时候一个例子胜过千言万语
5. **设定约束**：告诉 AI 什么能做什么不能做

记住：好的 prompt 是测试出来的，不是想出来的。多试，多调，多总结。就像调试代码一样，prompt 也需要 debug。
