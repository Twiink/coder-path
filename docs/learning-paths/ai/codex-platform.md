# Codex SDK / App Server 学习路线

Codex 更适合按“编码 Agent 平台”来理解，而不是当作模型 API 旁边又一套聊天接口。它的核心问题是：如何让一个 Agent 在受控工作区里理解代码、使用工具、修改文件、运行验证，并把过程和结果交给用户或更大的业务系统。

前置建议先掌握 [AI Agent 基础](/learning-paths/ai/agent-basics)、[Agent 开发](/learning-paths/ai/agent-development) 与 [MCP 协议](/learning-paths/ai/mcp)。本页讲平台集成的边界和学习顺序，不替代当前 SDK、App Server 或宿主应用的版本文档。

这条线按 **编码 Agent 心智模型 → 任务与工作区 → SDK 会话 → App Server 边界 → 工具与审批 → 事件与恢复 → 评估与治理 → 练习项目** 推进。

## 第一站：编码 Agent 的职责边界

欢迎来到编码 Agent 的工地。模型是会读图的架构师，工具是拿着扳手的施工队，工作区是围挡起来的现场，测试则是验收监理；先把围挡立好，再让它碰生产代码。

**任务输入** ---- 明确目标、仓库范围、约束、验收标准和不可触碰的目录；“把它优化一下”不是任务定义，是把方向盘递给雾

**工作区** ---- 为每次任务指定工作目录、分支或临时副本、可读写范围和清理策略；工作区隔离是防止 Agent 把邻居项目也顺手重构的第一道墙

**工具集合** ---- 代码搜索、文件读取、编辑、测试、版本控制和必要的网络访问分别授权；工具越强，权限与审计越重要

**完成条件** ---- 任务完成应同时满足修改范围、测试、静态检查、用户目标和未解决风险；Agent 的一句“已完成”只能作为待验证报告

**重点在这** ---- 先从只读分析与小范围修复开始，再逐步开放写文件、执行命令和联网；能力按风险分级，不按炫技分级

## 第二站：任务、会话与工作区生命周期

第二站是项目工地办公室。编码 Agent 不是问一句答一句，而是一段会读文件、改代码、跑测试的施工过程；项目经理必须知道它改过什么、卡在哪里、取消后留下了什么。

**任务描述** ---- 将自然语言目标、上下文文件、环境变量、工具策略和验收标准绑定到一次运行；不要让重要限制只存在于用户临时聊天里

**会话状态** ---- 保存消息、工具调用、审批、检查点、修改摘要和最终报告；长期状态与单次任务状态分开管理

**工作树或临时目录** ---- 为并行任务提供隔离路径，避免未提交修改互相覆盖；任务结束后明确保留、合并、丢弃或交给用户审阅

**取消与超时** ---- 用户取消、工具卡住、模型无进展和整体 deadline 都要有终止路径；取消后检查是否有未完成的写操作或后台进程

**恢复** ---- 依赖检查点、文件差异、测试结果和工具状态恢复，而不是把全部聊天记录重新投喂一遍；恢复前验证工作区仍然属于原任务

**重点在这** ---- 会话是运行记录，工作区是副作用载体；两者必须能独立审计与恢复

## 第三站：Codex SDK 与程序化编排

第三站进入调度室。SDK 的任务是启动、观察、控制和结束 Agent，不是把一个终端窗口穿上后端外套；程序化编排要让每个动作都能追踪、暂停和解释。

**启动与配置** ---- 传入任务、工作区、模型策略、工具策略和审批模式；将配置版本化，便于重现一次运行

**输入与追加消息** ---- 区分初始任务、用户追问、系统事件和人工批准；追加消息不应悄悄改变原始权限范围

**事件消费** ---- 关注模型消息、工具调用、文件变化、命令输出、审批请求、警告、错误和完成事件；事件流是 UI、日志与审计的共同输入

**最终结果** ---- 把最终答案、修改摘要、测试证据、未解决问题和任务状态结构化保存；不要只保存 Agent 最后一段自然语言

**取消与并发** ---- 通过任务 ID 管理取消、超时和并发；多个 Agent 不能同时无协调地编辑同一工作区

**错误边界** ---- 区分 SDK 连接错误、Agent 失败、工具失败、测试失败、权限拒绝和用户取消；上层据此决定重试、降级、暂停或转人工

**重点在这** ---- SDK 负责运行控制，不替业务决定哪些代码可以改、哪些测试足够、什么结果能发布

## 第四站：App Server 与宿主应用

第四站是总包与前台分工。App Server 把 UI、会话、审批和执行拆开，让前台不用亲自拿电钻；先画清客户端、服务端、工作区和工具的边界，再研究事件协议。

**客户端职责** ---- 展示任务、差异、日志、审批与进度，发送用户消息和批准；客户端不应自行执行服务端原本需要审计的工具

**服务端职责** ---- 创建与管理任务、持有权限、调度 Agent、执行工具、保存事件和返回结果；服务端是策略执行点

**事件协议** ---- 统一任务创建、消息、工具请求、审批、文件变化、错误、取消与完成事件；事件要可关联、可重放、可扩展

**会话路由** ---- 用用户、项目、任务和会话 ID 做隔离；不可把一个会话里的工作区、凭证或历史误发到另一个任务

**连接断开** ---- 客户端断开后任务是否继续、暂停还是取消要有显式策略；重连时从事件游标或快照恢复，而不是重复执行副作用

**重点在这** ---- App Server 的价值是解耦与可控；如果 UI、权限和执行仍然全部挤在一个进程里，换了名词并没有换架构

## 第五站：工具、审批与安全策略

第五站是工地安全检查。读写文件、跑测试和执行命令都可能造成真实损坏，因此默认只读、逐项开放；能让 Agent 先戴安全帽，就别先发给它拆墙许可证。

**文件权限** ---- 限定允许读取、修改和创建的目录；拒绝路径穿越、符号链接逃逸、隐藏凭证和工作区外访问

**命令白名单** ---- 将命令、参数、网络、环境变量和资源额度分级；不要把“可以运行终端”解释成“可以运行任何终端命令”

**审批节点** ---- 写文件、删除、联网、安装依赖、修改配置、提交代码和访问敏感目录可分别要求批准；审批要显示即将发生的动作与范围

**沙箱与隔离** ---- 对不可信代码使用容器或其他隔离运行时，限制网络、CPU、内存、时间和文件；宿主凭证不应默认挂载

**差异审阅** ---- 修改后向用户展示文件差异、测试命令和结果；不让 Agent 通过“先改后说”绕过审阅

**审计** ---- 记录谁发起任务、Agent 使用了什么工具、读写了什么范围、执行了哪些命令、谁批准了什么和最终状态

**重点在这** ---- 审批是策略的一部分，不是用户界面上的一个漂亮按钮；服务端必须再次执行同样的限制

## 第六站：验证、恢复与协作

第六站是验收流水线。补丁不是终点，理解、修改、运行、观察、修正和报告要闭环；少了测试或差异审阅，最后交付的可能只是“长得像答案”的装修。

**验证分层** ---- 从格式化、类型检查、单元测试、集成测试到人工审阅逐层执行；Agent 应根据项目已有工具选择验证，而不是凭空宣称覆盖充分

**失败修复** ---- 测试失败可让 Agent 分析并有限重试；重复相同修改、持续扩大范围或忽略新错误时必须停止

**差异控制** ---- 设置允许修改的文件、最大差异规模和高风险文件清单；超出范围先暂停请求用户确认

**回滚** ---- 保留原始差异与检查点，确保任务失败或取消时能恢复到安全状态；回滚方案要测试，不要等事故当天发现它只存在于愿望里

**并行协作** ---- 独立任务使用隔离工作区与清晰交付物；共享文件、依赖升级和合并顺序必须有协调者

**报告证据** ---- 最终报告至少包括改动摘要、验证命令与结果、未运行的检查、风险和下一步；“测试通过”要能追溯到具体证据

**重点在这** ---- Agent 的交付物是“差异 + 证据 + 边界说明”，不是一段看起来很自信的总结

## 第七站：评估、成本与平台治理

第七站是工程能力考场。代码能编译只是进场签到，真正要看修改范围、测试证据、回归缺陷、工具轨迹和返工时间；不然 Agent 只是把手写加班换成机器加班。

**任务成功率** ---- 比较目标是否达成、测试是否通过、修改是否在范围内、是否需要人工返工和是否引入回归

**轨迹质量** ---- 观察工具选择、搜索范围、重复调用、命令安全、停止时机和验证完整度；过程错误可能暂时被最终结果掩盖

**代码质量** ---- 评估可读性、类型、测试、依赖变化、性能、安全和维护成本；编译通过只是起跑线

**成本与延迟** ---- 记录模型 token、工具耗时、命令耗时、总时长、失败重试与人工等待；按任务类型看 P50/P95，不要只看平均值

**数据治理** ---- 源代码、密钥、日志、补丁和外部服务响应按敏感等级处理；追踪系统同样需要脱敏、访问控制和保留期限

**版本与回滚** ---- 同时锁定 SDK、App Server、模型、工具、提示词和项目策略；升级前跑固定仓库任务，异常时能切回旧版本

**重点在这** ---- 代码 Agent 的生产标准是可控修改与可验证交付，而不是让 Agent 尽量少问人

## 第八站：练习项目

建议做一个“仓库变更审查器”：Agent 只能读取指定目录、运行白名单测试并生成审查报告，不能直接发布、联网安装依赖或修改生产资源。逐步开放一个小范围修复动作，再加入审批和回滚。

**基础练习** ---- 完成只读代码搜索、问题定位和带文件引用的报告；记录事件与工具轨迹

**进阶练习** ---- 在隔离工作区执行小范围修复、运行测试、展示差异并等待批准；测试超时、错误命令、越权路径和取消

**平台练习** ---- 用 SDK 管理会话，用 App Server 或等价服务层管理事件、审批、断线重连与任务状态

**交付证据** ---- 能启动受控任务；能处理事件、取消、超时、审批和恢复；能限制工作区与命令权限；能用测试、差异和审计记录证明修改可回溯、可验证

## 通关标准

能启动一次受控的 Codex Agent 任务；能处理事件、取消、超时、审批、断连与恢复；能限制工作区、文件、命令和网络权限；能用测试、差异、日志和审计证明 Agent 的修改可回溯、可验证、可回滚。

## 结语

编码 Agent 的真正产物不是一份“看起来能跑”的补丁，而是差异、测试证据、权限记录和没有被偷偷扩大过的修改范围。它可以很能干，但工地的围挡、审批和验收不能省。

先让 Agent 在小工作区里学会读、改、测和报告，再给它更大的项目。能让机器干活，也能让人类随时看懂、叫停和回滚，这才是编码 Agent 的成熟形态。
