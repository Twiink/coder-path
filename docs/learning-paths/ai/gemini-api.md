# Google / Gemini API 学习路线

Gemini 是 Google 的模型平台，学习价值通常集中在多模态输入、长上下文、结构化结果、工具调用以及与 Google 生态的连接。它仍然只是模型适配层的一种实现：模型负责生成或提出动作，应用负责权限、执行、状态和验证。

前置建议先读 [模型 API 通用原理](/learning-paths/ai/model-api-overview)。本页关注 Gemini 平台上需要特别理解的能力边界。模型名称、上下文限制、价格和可用特性会随版本变化，选型时以官方文档和自己的 golden 集为准。

这条线按 **模型与输入 → 多模态 → 上下文与缓存 → 结构化输出 → Function Calling → 安全与可靠性 → 评估与生态** 推进。

## 第一站：模型家族与请求心智模型

欢迎来到 Gemini 的多模态游乐园。这里的模型不只读文字，还会看图、看表、看文档；但游乐园有身高限制、票价和安全员，先看任务能进哪种设施，再别急着背型号。

**任务分类** ---- 区分聊天、摘要、抽取、复杂推理、代码、视觉理解和实时交互；同一个模型不一定在每类任务上都值得默认

**能力矩阵** ---- 记录文本、图片、文件、视频或音频输入，流式、结构化输出、函数调用、长上下文、缓存和批处理支持；接口存在不等于能力完全兼容

**请求与响应** ---- 把输入内容、生成配置、工具声明、候选结果、安全反馈和用量信息分层理解；业务不应直接依赖供应商的响应对象

**上下文状态** ---- 多轮历史、用户资料、检索内容和工具结果通常由应用管理；会话历史要可裁剪、可删除并按用户和租户隔离

**平台配置** ---- 端点、模型、输出上限、采样参数、超时、重试和安全设置都进入配置与版本管理；不要把实验旋钮散落在业务函数里

**重点在这** ---- 先用一个简单任务验证质量与错误路径，再拓展多模态和工具；功能多不等于系统稳

## 第二站：多模态输入

第二站是视觉展馆。图片、文档和图表都能入场，但“把文件丢进去”不是导览：清晰度、页码、来源、脱敏和结果复核一个都不能逃票。

**图像理解** ---- 关注分辨率、裁剪、方向、文字大小、压缩和背景噪声；低清截图先放大或重拍，别让模型替摄像头承担物理学

**文档分析** ---- 保留页码、标题、段落、表格、脚注和版本；让模型指出证据位置，便于人工复核与引用

**图表与表格** ---- 视觉模型可帮助定位趋势和结构，但金额、比例、行列关系要用程序重新计算与校验

**音视频输入** ---- 先了解分段、时间戳、采样、转写、关键帧和成本，再做长媒体处理；实时媒体还需要队列、断点与延迟预算

**输入治理** ---- 检查 MIME、大小、恶意文件、个人信息、版权和用户权限；模型能读取不代表应用有权处理

**结果表达** ---- 对观察、推断、证据和不确定性分栏；多模态答案尤其需要保留“看不清”“资料缺失”和“需人工确认”

**重点在这** ---- 多模态的第一生产力是更丰富的证据，第一风险也是更丰富的误读；输入与输出都要可审计

## 第三站：长上下文与缓存

第三站是超长过山车。整份文档和会议材料可以一起上车，但车厢再长也要算票价和注意力；先分层、留预算，再决定要不要让 RAG 负责分流。

**整读与检索** ---- 文档较小且需要整体理解时整读；资料海量、更新频繁或权限复杂时用 [RAG 系统](/learning-paths/ai/rag-systems)；两者可以组合

**上下文布局** ---- 将系统规则、用户问题、证据、历史和外部资料明确分区；外部文档只是数据，不是可以改写系统规则的临时老板

**长文档定位** ---- 先定位相关章节、列出证据，再生成结论；保存页码、片段、文件版本与来源

**上下文压缩** ---- 通过摘要、滑动窗口、去重、相关片段提取和状态结构化控制输入；压缩必须保留限制条件与不确定性

**缓存能力** ---- 对稳定的长提示、文档或工具定义研究平台缓存；比较命中条件、生命周期、成本、隐私与失效，不要把缓存当数据库

**重点在这** ---- 长上下文解决“看得更多”，不自动解决“看得准确”；证据组织与评估仍是主线

## 第四站：结构化输出与安全反馈

第四站来到质检台。自由文本像一位很会聊天的导游，结构化输出才是能被系统验票的票据；安全反馈也别丢在角落，它是“为什么没发车”的重要状态。

**Schema 设计** ---- 定义字段、类型、枚举、必填关系、空值、不确定和拒答状态；允许模型承认不知道，通常比逼它猜更可靠

**原生结构化能力** ---- 优先使用平台支持的 schema 约束，并记录模型对嵌套对象、数组、枚举和长度的实际表现

**服务端校验** ---- 通过语法解析后继续检查范围、权限、业务不变量、数值和引用；模型输出是外部输入，不能直接写库或触发动作

**安全反馈** ---- 理解内容被拦截、部分返回、空结果和安全分类等状态；为用户准备解释、改写提示或人工处理路径

**失败恢复** ---- 缩小 schema、补充上下文、换模型、重试可恢复错误或转人工；重试次数与预算必须有上限

**重点在这** ---- schema 管形状，程序管可信度，安全策略管可接受范围；三层不能互相代班

## 第五站：Function Calling 与工具 Agent

第五站是工具租赁柜。模型可以提出“请把计算器借我”，但应用要检查谁借、借来做什么、是否归还；Function Calling 是借条，不是无限额度的信用卡。

**工具描述** ---- 说明用途、输入、输出、限制和何时不要使用；工具描述既是模型路由提示，也是安全评审材料

**参数校验** ---- 服务器重新检查类型、范围、用户、租户、资源和业务状态；schema 通过仍不代表参数有权限

**工具结果** ---- 返回最少必要数据、来源、状态和可读错误；外部 API、网页和文档结果标记为不可信内容

**副作用分级** ---- 查询、计算和草稿生成可以自动化；改库、发信、删文件、执行命令和发布动作要确认、幂等、审计或人工审批

**循环控制** ---- 设置最大步数、单步超时、整体 deadline、预算和重复调用检测；任务完成还需要业务条件验收

**MCP 对接** ---- MCP 可作为工具与资源的发现和传输层，但不会替代 Gemini 应用的权限、审批、沙箱和审计

**重点在这** ---- 工具循环的可靠性来自程序的边界，不来自模型“看起来很会计划”

## 第六站：可靠性、成本与数据治理

第六站是运营控制室。图片更大、工具更多，延迟、成本和权限就会一起长高；生产封装要给每个变量装仪表盘和备用出口。

**限流与重试** ---- 区分参数错误、认证失败、限流、过载、网络中断、超时、安全拒绝和业务错误；只对可恢复错误做有限退避

**流式与取消** ---- 流式事件用于界面与进度，最终结果用于入库与计费；客户端断连后仍要处理正在执行的工具副作用

**并发与队列** ---- 短请求可同步，长文档、媒体和 Agent 任务应进入队列；并发受平台配额、文件处理、数据库和下游工具共同限制

**成本控制** ---- 记录文本与媒体输入、输出、缓存、工具、重试和任务总成本；按任务路由模型，先裁剪无关内容再扩大上下文

**隐私与区域** ---- 只发送完成任务所需数据，日志脱敏，明确保留周期、区域、训练使用与删除政策；敏感数据进入平台前要过组织合规流程

**提示词注入** ---- 用户内容、图片文字、文档和工具结果都可能带伪指令；把它们作为资料传递，执行工具前后重新鉴权

**重点在这** ---- 可靠的 Gemini 应用不是“支持所有输入”，而是能说明每种输入的质量、成本、权限和失败边界

## 第七站：评估、生态与练习项目

第七站是毕业展。做一个“技术文档审阅器”：让它看架构图、读文字、查只读规范，再输出固定 schema 的风险清单；低清图片、缺字段、超长材料和安全拒绝，都是故意安排的考官。

**多模态质量** ---- 评估识别准确率、证据位置、结构化字段、遗漏率和不确定性表达；人工抽检与自动规则要结合

**工具质量** ---- 评估工具选择、参数正确率、调用轮数、越权拒绝、错误恢复和最终任务成功率

**运行质量** ---- 记录首 Token、完整延迟、输入输出 token、媒体处理耗时、缓存命中、重试与成本；按场景分组看数据

**平台对照** ---- 与另一模型后端使用同一 golden 集比较；保留差异，不把平台特色强行改造成虚假统一

**生态连接** ---- 了解 Google Cloud、数据分析、多模态处理和现有 Agent/RAG 框架的集成边界；先掌握通用接口，再进入生态专长

**交付证据** ---- 能完成文本与图像输入、结构化输出和工具调用；能解释长上下文与缓存的取舍；能处理安全反馈、限流、超时、隐私和成本；能将 Gemini 接入通用适配层而不改写业务流程

## 通关标准

能完成文本与图像输入、结构化输出和工具调用；能解释长上下文与缓存的取舍；能处理安全反馈、限流、超时、隐私和成本；能将 Gemini 接入通用适配层而不改写业务流程。

## 下一站去哪

**想比较不同模型** ---- 回到 [模型 API 通用原理](/learning-paths/ai/model-api-overview)，用同一适配层和 golden 集做公平对照

**想做图文知识库** ---- 去 [RAG 系统](/learning-paths/ai/rag-systems)，学习文档解析、引用和多模态证据管道

**想让模型使用工具** ---- 去 [Agent 基础](/learning-paths/ai/agent-basics)，把 Function Calling 变成受控循环

**想接入工具生态** ---- 去 [MCP 协议](/learning-paths/ai/mcp)，学习通用工具发现、权限和审计

## 结语

Gemini 的多模态能力像给模型多装了几双眼睛，但眼睛多不代表每张图都看得清，也不代表看见的内容就能直接做决定。清晰输入、结构化输出、权限和评估，才是把“会看”变成“能用”的关键。

先做一个小而可验收的图文任务，再扩大到长媒体、复杂工具和实时流程。让模型看得多，也让系统知道什么时候该说“看不清，请人工确认”。
