# Java 全栈开发学习路线

Java 全栈不是“后端穿西装，前端顺便会点按钮”，而是以 Java 和 Spring Boot 为后端主轴，再接上 Vue 或 React、数据库、缓存、消息与部署的一条工程路线。它的学习曲线确实陡，但爬上去之后，事务、安全、规范和大型系统会给你一张相当结实的地图。

这份路线只负责设计 Java 全栈的学习路径，不展开成 Java 语法百科或 Spring 注解字典。路线会从语言、JVM、Web、Spring、数据、权限、前端协作一路走到测试、性能、微服务和生产；具体 API、源码和代码练习留给后续专题学习。

**适合谁** ---- 想进入企业级后端、金融、电商、政企或大型业务系统，重视长期维护、团队协作、事务一致性和工程规范的人

**典型画像** ---- 后端深度通常强于前端深度，但仍能独立把页面、接口、数据库、权限和部署串起来；全栈不是平均用力，而是有主次的完整交付

**推荐总顺序** ---- Java 语言 → 集合与并发 → JVM → Spring Boot → Web 与 API → 数据访问 → 安全 → Vue 或 React → 消息与缓存 → 测试观测 → 性能部署 → 微服务与架构

**本页怎么用** ---- 先按站点建立知识地图，再按项目逐站验收；看到注解先问容器做了什么，看到 ORM 先问数据库会怎样，看到微服务先问单体为什么不够

## 第一站：Java 语言与面向对象地基

欢迎来到 Java 的施工现场。这里的每个概念都像图纸上的钢筋：类、接口、泛型、异常和集合不一定天天被单独讨论，却会一起决定服务能否长期维护。

**基本类型与对象模型** ---- 掌握基本类型、包装类型、字符串、数组、枚举、记录、不可变对象、装箱拆箱与 null；重点理解值语义、对象身份、内存分配和 API 边界

**流程控制与方法** ---- 学习条件、循环、方法重载、可变参数、递归、作用域、返回值和异常传播；代码应表达业务状态，而不是把嵌套 if 盖成一栋楼

**类、接口与封装** ---- 理解继承、组合、多态、抽象类、接口默认方法、访问控制、内部类、匿名类和对象生命周期；接口不是装饰品，而是边界与替换能力

**泛型与类型擦除** ---- 掌握泛型类、泛型方法、通配符、上下界、类型推断、PECS 思维与类型擦除，知道哪些类型信息运行时还在，哪些已经下班

**注解与反射基础** ---- 认识注解元数据、保留策略、反射、动态代理、方法句柄与模块边界，为 Spring 的扫描、代理和配置理解幕后机制

**异常与资源管理** ---- 区分受检异常、非受检异常、业务异常、系统异常、异常链、try-with-resources、重试与回滚；异常不是返回值的替身，也不是日志垃圾桶

**集合框架** ---- 覆盖 List、Set、Map、队列、双端队列、优先队列、迭代器、比较器、哈希、红黑树、并发集合与不可变集合；选择集合要看访问、更新、顺序、并发和内存

**函数式与 Stream** ---- 学习 Lambda、函数式接口、方法引用、Stream、Optional、并行流和收集器，理解惰性、中间操作、终止操作与副作用边界

**模块与构建** ---- 认识包、模块、classpath、module path、Maven 或 Gradle、依赖范围、插件、仓库、锁定与多模块工程；构建脚本也是生产代码

**重点解释** ---- 这一站通关是能读懂业务 Java，知道对象、类型、集合、异常和资源如何协作，并能解释后续框架代码为什么可以“自动做事”

## 第二站：JVM、内存模型与并发

第二站进入 JVM 机房。Java 代码只是入口，类加载、字节码、堆、栈、垃圾回收、即时编译和 Java 内存模型才是服务真正运行的地形；不了解它们，线上性能问题会像雾里看花。

**字节码与类加载** ---- 理解源码、字节码、类加载器、加载链接初始化、双亲委派、类隔离、热加载和类卸载；依赖冲突时，先问究竟是哪一个类被谁加载

**JVM 运行时区域** ---- 认识程序计数器、虚拟机栈、本地方法栈、堆、方法区或元空间、直接内存与线程栈；内存溢出不是一种病，诊断前要先分型

**JIT 与执行优化** ---- 了解解释执行、热点探测、C1/C2、内联、逃逸分析、标量替换、去优化与 safepoint；优化不是魔法，代码形状和运行数据会影响结果

**垃圾回收** ---- 掌握新生代、老年代、标记清除、复制、整理、分代、并发回收、暂停时间、吞吐与响应延迟，知道不同收集器适合的服务画像

**Java 内存模型** ---- 理解主内存、工作内存、可见性、有序性、原子性、happens-before、volatile、final 与安全发布；“变量改了”不等于“所有线程都看见了”

**锁与并发工具** ---- 覆盖 synchronized、Lock、ReentrantLock、读写锁、StampedLock、条件队列、原子类、CAS、AQS、ThreadLocal 与并发集合

**线程池与任务调度** ---- 设计核心线程、最大线程、队列、拒绝策略、命名、监控、定时任务和线程上下文；线程池不是越大越热闹，过量线程只会争抢 CPU

**CompletableFuture 与异步组合** ---- 理解串行、并行、合并、异常、超时、取消、线程池选择与上下文传递，避免异步链变成另一种回调地狱

**锁竞争与并发故障** ---- 排查死锁、活锁、饥饿、竞态、长事务、线程阻塞、连接池耗尽与队列堆积，使用线程栈、JFR、火焰图和指标寻找证据

**重点解释** ---- 这一站的通关是能把“接口慢”拆到 GC、线程、锁、队列、数据库或外部依赖，而不是把所有性能问题都归咎于 JVM

## 第三站：Spring Boot 与容器思维

第三站来到 Spring 的魔法学院。Spring 让对象创建、装配、代理、配置和生命周期变得自动，但自动化越强，越要知道谁在什么时候做了什么，否则启动日志会像一场没有字幕的魔术。

**IoC 与依赖注入** ---- 理解容器、Bean、组件扫描、构造器注入、生命周期、作用域、懒加载、循环依赖与显式装配；依赖注入的价值是边界可替换，不是少写几个 new

**自动配置与条件装配** ---- 掌握配置类、条件注解、属性绑定、自动配置报告、环境、Profile 和配置优先级，知道“开箱即用”背后有哪些条件

**Bean 生命周期与扩展点** ---- 了解实例化、属性注入、初始化、后置处理器、代理、销毁、事件、监听器与上下文层级；Bean 出问题时，生命周期比猜注解更可靠

**AOP 与代理** ---- 理解切点、通知、代理、JDK 动态代理、CGLIB、方法调用边界、自调用失效与事务代理限制；代理只拦得住经过它的调用

**配置与环境** ---- 管理多环境配置、外部化配置、秘密、配置校验、动态刷新、启动失败与配置优先级；缺配置时尽早失败，别让服务运行两小时后才发现数据库地址写错

**Starter 与模块边界** ---- 认识 Starter、自动装配、公共组件、模块化单体、多模块构建与依赖方向；抽公共包前先确认它是不是只是一个搬家中的 utils 文件夹

**日志与错误基础** ---- 统一日志格式、级别、关联 ID、异常映射、敏感字段过滤与启动诊断，为 Web 层和生产观测打底

**重点解释** ---- 这一站要能解释 Spring 如何创建对象、注入依赖、生成代理、读取配置、管理生命周期，并知道什么时候自动化应该被显式配置接管

## 第四站：Spring Web、HTTP 与 API

第四站进入 Web 服务大厅。Controller 能收到请求只是入场券，真正的后端能力在于 HTTP 语义、参数边界、校验、错误、序列化、幂等和业务分层。

**Spring MVC 请求链** ---- 掌握 DispatcherServlet、HandlerMapping、参数解析、消息转换、拦截器、过滤器、异常解析和响应写出，能沿着请求链定位问题

**REST 与 HTTP 语义** ---- 设计资源、方法、状态码、Header、Cookie、缓存、重定向、幂等、条件请求和版本；URL 不要一会儿像名词，一会儿像命令行

**参数绑定与校验** ---- 处理路径、查询、Header、Cookie、JSON、表单、文件、嵌套对象、未知字段、格式与范围，区分传输模型和领域模型

**统一响应与异常处理** ---- 建立成功、校验失败、未认证、无权限、未找到、冲突、限流和未知错误结构，隐藏堆栈与内部实现细节

**序列化与契约** ---- 理解 Jackson、字段命名、日期、时区、枚举、循环引用、懒加载、BigDecimal、脱敏与版本兼容；JSON 很方便，但没有义务保存所有 Java 对象的尊严

**分层与领域服务** ---- 区分 Controller、Application Service、Domain、Repository、Infrastructure 与 DTO，设计事务边界和依赖方向

**接口文档与 OpenAPI** ---- 维护参数、响应、错误、安全方案、分页和示例，让接口文档成为可验证契约，而不是发布后才想起的纪念册

**异步、流式与文件** ---- 了解异步返回、SSE、WebSocket、响应流、上传、下载、断点、大小限制、临时资源和客户端断开

**重点解释** ---- 这一站的通关是能独立交付一组规范 API，并能说明一次请求如何经过过滤器、拦截器、控制器、服务、事务与响应

## 第五站：数据访问、事务与一致性

第五站是企业应用的数据仓。Spring Data、JPA 和 MyBatis 可以让数据库操作变顺手，但数据库不会因为实体类长得像 POJO 就放弃锁、索引和事务。

**JDBC 与连接池** ---- 理解驱动、连接、事务、预编译、结果集、连接池、超时、泄漏检测与多实例总连接数；连接池配置是容量设计，不是复制一份默认值

**JPA 与 Hibernate** ---- 学习实体、持久化上下文、一级缓存、脏检查、延迟加载、级联、批量、关联、N+1、Flush 与查询边界

**MyBatis 与 SQL 控制** ---- 了解 Mapper、参数绑定、结果映射、动态 SQL、批量、插件、缓存和原生 SQL 的透明度与风险

**领域模型与数据库模型** ---- 区分实体、值对象、聚合、DTO、表、视图与读模型，决定何时使用对象关系映射，何时让查询直接服务于读取场景

**事务与传播** ---- 掌握 ACID、隔离级别、传播行为、只读事务、回滚规则、嵌套调用、自调用失效与跨线程事务边界

**锁、并发更新与死锁** ---- 处理乐观锁、悲观锁、唯一竞争、死锁顺序、长事务、库存或余额不变量与失败重试

**索引与执行计划** ---- 深入 B-tree、复合、覆盖、选择性、排序、范围、分页、慢查询与 EXPLAIN；ORM 生成的 SQL 仍然需要人类审阅

**迁移与数据演进** ---- 管理 Flyway 或 Liquibase、schema 版本、数据修复、大表变更、先发后迁、先迁后发和回滚策略

**缓存与一致性** ---- 设计 Redis 缓存旁路、过期、穿透、击穿、雪崩、双写、失效、预热、分布式锁和最终一致性

**重点解释** ---- 这一站通关是能解释一次业务写入的事务边界、并发风险、SQL 计划、缓存策略和恢复方式，而不是只会调用 save

## 第六站：Spring Security 与权限体系

第六站来到城门。Spring Security 的过滤器链很强，但“配置通过”不等于“权限正确”；登录、身份、授权、对象访问和审计要分开设计。

**认证与过滤器链** ---- 理解 SecurityContext、过滤器顺序、认证管理器、用户详情、密码编码、Session 与无状态请求

**Session、JWT 与刷新** ---- 比较会话、短期访问令牌、刷新令牌、Cookie、撤销、轮换、过期、重放与多设备登录

**OAuth 2.0 与 OpenID Connect** ---- 掌握授权码、PKCE、state、nonce、scope、客户端、资源服务器、身份提供方与回调校验

**授权模型** ---- 区分角色、权限、方法级授权、资源级授权、数据权限、租户、组织层级与服务身份；隐藏按钮只能改善体验，后端拒绝才是安全

**密码与账户安全** ---- 学习哈希、盐、成本、重置、登录限流、账户锁定、多因素认证、会话撤销与敏感操作二次确认

**跨站与输入攻击** ---- 防御 CSRF、XSS、SQL 注入、路径穿越、SSRF、开放重定向、文件上传、反序列化与日志注入

**安全响应与秘密** ---- 配置 HTTPS、HSTS、CSP、Cookie 属性、CORS、密钥、证书、环境变量、审计和泄露响应

**重点解释** ---- 这一站通关是能画出一次登录和一次越权请求的完整流转，并指出每个身份、权限、输入和秘密的信任边界

## 第七站：Vue 或 React 前端协作

第七站让 Java 后端走到用户面前。前端不是后端 API 的展示柜；它有自己的组件、状态、渲染、缓存、可访问性和弱网问题，双方需要契约而不是猜谜。

**前端主线选择** ---- Vue 见 [Vue 学习路线](/learning-paths/frontend/vue)，React 见 [React 学习路线](/learning-paths/frontend/react)；选一个深入组件、路由、表单、状态和调试，另一个了解思想即可

**组件与状态分层** ---- 区分组件状态、表单状态、URL 状态、全局 UI、服务端数据、缓存与持久化；不要因为一个对象被三个页面使用，就立刻给它颁发全局身份

**接口消费与错误映射** ---- 对齐请求、响应、分页、错误码、字段错误、加载、空状态、重试、取消与乐观更新

**类型与契约协作** ---- 使用 OpenAPI、共享 schema、生成客户端或明确 DTO 维护跨端契约，处理字段新增、弃用、类型变化与版本过渡

**认证体验** ---- 设计登录、过期、刷新、退出、多标签页、路由体验、权限按钮与无权限页面；体验层可以提前拦，安全层必须后端兜底

**表单、文件与实时** ---- 处理校验、草稿、上传进度、取消、断点、WebSocket、SSE、重连、通知和弱网反馈

**SSR、SPA 与部署边界** ---- 比较传统前后端分离、SSR、静态生成与同构框架的首屏、SEO、缓存和团队成本

**重点解释** ---- 这一站的通关是前端能稳定消费 Java API，接口失败有反馈，权限体验不越界，前后端改动有契约保护

## 第八站：缓存、消息与分布式协作

第八站开始接触“多台机器一起工作”的世界。Redis、Kafka、RabbitMQ 和定时任务可以让系统更强，也会把重复、乱序、延迟和丢失请进会议室。

**Redis 数据结构与缓存** ---- 学习键值、哈希、集合、有序集合、过期、淘汰、流水线、Lua、发布订阅、锁和持久化

**消息队列模型** ---- 理解生产者、消费者、确认、分区、偏移、顺序、重复、至少一次、死信、延迟和积压

**事务消息与 Outbox** ---- 处理数据库提交与消息发送之间的间隙，设计 Outbox、发布、重试、重放和幂等消费

**事件驱动设计** ---- 区分领域事件、集成事件、命令、通知和进程内事件，管理事件版本、契约和消费者失败

**定时与批处理** ---- 处理时区、重复执行、分布式锁、任务状态、取消、补偿、批量导入导出与资源上限

**实时通信** ---- 设计 WebSocket、SSE、心跳、断线、重连、广播、房间、多实例与背压

**分布式一致性** ---- 了解最终一致性、幂等、重试、Saga、补偿、读写分离、缓存失效与服务边界

**重点解释** ---- 这一站通关是系统在重启、重复消息、消费者变慢、网络抖动和部分失败时仍然能解释并恢复

## 第九站：测试、调试与可观测性

第九站是质检车间。Java 的测试生态很成熟，但工具不会替你决定测试边界；要同时验证业务、HTTP、数据库、权限、消息与前端协作。

**单元测试** ---- 覆盖领域规则、纯函数、校验、权限、状态机、异常和边界，减少对 Spring 容器的依赖以保持速度

**Spring 测试切片** ---- 理解单元、Web 切片、数据切片、完整上下文测试的成本与边界，避免所有问题都用启动完整容器解决

**接口与集成测试** ---- 检查状态码、Header、认证、权限、序列化、数据库事务、迁移与真实依赖，必要时使用容器化测试依赖

**契约与端到端测试** ---- 验证 OpenAPI、DTO、关键浏览器流程、登录、核心 CRUD、上传、消息与失败恢复

**并发与性能测试** ---- 观察线程池、连接池、锁、GC、吞吐、P95/P99、队列积压与资源峰值

**调试与诊断** ---- 掌握日志、线程栈、Heap Dump、JFR、火焰图、SQL、请求追踪和配置诊断；证据比猜测更便宜

**日志、指标与追踪** ---- 关联请求 ID、trace ID、用户或租户、版本、路由、耗时、数据库、缓存和消息，过滤凭证与隐私

**CI 质量门禁** ---- 接入格式化、静态检查、依赖审计、测试、覆盖率、构建、迁移检查与部署前冒烟

**重点解释** ---- 这一站的通关是问题能复现、线上能发现、现场能定位、修复能回归，而不是只看 Maven 输出了一片绿色

## 第十站：性能、部署与生产

第十站是成人礼。JVM 服务的生产性能要同时看堆、GC、线程、连接、SQL、缓存、网络与容器；只把堆内存调大，通常只是把闹钟往后拨。

**性能基线** ---- 建立吞吐、P50/P95/P99、错误率、GC 暂停、线程、CPU、内存、数据库、缓存与队列指标

**查询与连接性能** ---- 排查慢 SQL、N+1、锁等待、连接池、序列化、远程调用与事务时间，优化前后用数据比较

**JVM 调优** ---- 结合堆、元空间、直接内存、收集器、暂停目标、容器限制、启动参数与 JFR 证据调优，拒绝参数考古学

**容器与反向代理** ---- 掌握 Docker、非 root、资源限制、信号、健康检查、Nginx、TLS、代理头、超时与 WebSocket 转发

**配置与秘密** ---- 区分构建、启动、请求配置，使用环境变量或秘密管理，避免把密码和生产地址写进代码库

**数据库迁移与发布** ---- 设计备份、迁移顺序、兼容窗口、灰度、健康检查、数据修复与回滚

**CI/CD 与发布策略** ---- 串起测试、构建、镜像、迁移、部署、审批、滚动、蓝绿、金丝雀和回滚

**监控与恢复** ---- 建立错误、日志、指标、追踪、告警、备份、恢复点、恢复时间和故障演练

**重点解释** ---- 生产通关是能重复构建、可安全发布、可观测运行、可快速回滚，并能解释一次 JVM 服务故障的证据链

## 第十一站：微服务与企业级架构

最后一站不是“学完单体马上拆十个服务”。微服务是组织、部署、数据和故障边界的选择，不是架构图上的奖杯；先把模块化单体做好，往往更接近理性。

**模块化单体** ---- 用领域模块、依赖方向、内部契约、独立测试与清晰数据边界建立可拆分的单体

**服务拆分信号** ---- 根据团队边界、发布节奏、资源差异、故障隔离、数据所有权与扩展需求决定拆分，而不是按表数量拆

**Spring Cloud 与服务治理** ---- 了解服务发现、配置、网关、负载均衡、熔断、限流、重试、链路追踪与版本治理的边界

**同步 RPC 与异步消息** ---- 比较延迟、耦合、一致性、重试、顺序、观测与调试成本，避免所有业务都被塞进同步调用链

**分布式事务与补偿** ---- 掌握本地事务、Outbox、Saga、幂等、状态机、补偿和人工介入，知道哪些一致性值得付出成本

**高可用与容灾** ---- 规划副本、故障转移、限流、降级、隔离、备份、恢复和多区域边界

**架构表达与演进** ---- 用时序、数据流、容量、故障树、决策记录和迁移计划表达设计；框框图不能替你处理失败

**重点解释** ---- 这一站通关是能在业务约束下判断何时保持单体、何时拆服务、何时用消息，并能说明迁移与回滚路线

## 学习路径建议：从企业 CRUD 到可交付系统

**第一阶段：Java 与 JVM** ---- 完成第一、第二站，能解释集合、异常、泛型、字节码、GC、内存模型、线程和线程池

**第二阶段：Spring Web** ---- 进入 Spring Boot，完成依赖注入、配置、Web 请求、校验、统一错误、日志与 API 文档

**第三阶段：真实数据** ---- 使用 PostgreSQL 或 MySQL 学习 SQL、JPA 或 MyBatis、事务、索引、迁移、连接池与缓存

**第四阶段：前后端闭环** ---- 接入 Vue 或 React，完成登录、权限、CRUD、分页、错误映射、文件或实时功能

**第五阶段：质量与安全** ---- 加入 Spring Security、对象权限、契约、单测、接口测试、集成测试、审计与依赖审计

**第六阶段：生产交付** ---- 完成 Docker、CI/CD、HTTPS、监控、压测、灰度、回滚、备份与恢复演练

**第七阶段：架构进阶** ---- 根据真实瓶颈再学习消息、微服务、分库分表、读写分离和云原生，不要为了简历先制造分布式问题

## 结语

Java 全栈的学习曲线像一条认真修过的山路：前面坡陡，后面视野好。Spring 的注解、JVM 的参数、事务的传播和权限的过滤器链，初见都像在和你讨论人生；理解之后，它们其实都在回答同一个问题：边界在哪里，责任由谁承担。

先把单体应用做稳，再谈微服务；先把事务和 SQL 讲清，再谈分布式一致性；先能观察和回滚，再谈高可用。**Java 的优势不是让第一版最快，而是让第十版仍然有人敢接手。**
