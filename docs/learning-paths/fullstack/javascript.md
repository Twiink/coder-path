# JavaScript 全栈开发学习路线

JavaScript 全栈的招牌很诱人：浏览器里写 JavaScript，服务器上还是 JavaScript，接口传的是 JSON，前后端还可以共享 TypeScript 类型。听起来像一张通行五层楼的电梯卡；但电梯按钮很多，按错了还是会把你送到“线上凌晨三点排查 500”的楼层。

这份路线的定位是**指引和索引**，不是把 API 手册重新装订一遍。它会把语言、浏览器、Node.js、HTTP、数据库、鉴权、安全、测试、性能与部署串成一条可执行的学习主线；每个知识点只交代“要学到哪里、为什么重要、继续往哪看”，具体类型、方法、源码和代码练习不在本路线展开。

**适合谁** ---- 想从页面走到接口、想独立完成产品、想用一套语言覆盖前后端，或者已经会前端但不想再把后端当作神秘地下室的人

**先记住一件事** ---- “一门语言走天下”不等于“只学一门语言”；网络、数据库、操作系统、浏览器渲染和部署仍然会来收房租，只是 JavaScript 负责把它们串起来

**推荐总顺序** ---- JavaScript 语言地基 → 浏览器平台 → Node.js 运行时 → HTTP 服务 → 数据库与缓存 → 接口契约 → 认证安全 → Next.js 或 Nuxt → 测试观测 → 性能部署 → 完整项目

**本页怎么用** ---- 按站点顺序建立全栈知识地图，把粗体知识点当作学习清单；先理解每一层要解决的问题，再决定后续深入哪条技术路线

## 第一站：JavaScript 语言地基

欢迎来到全栈村的新手村。前端里那个会改按钮文字的 JavaScript，到了后端依然会因为 `this`、闭包和隐式转换给你发邮件；所以先把语言本体学扎实，框架才不会变成一层会自动报错的魔法袍。

**变量、作用域与提升** ---- 掌握 const、let、var、块级作用域、函数作用域、模块作用域、词法作用域、作用域链、变量提升与暂时性死区；全栈代码跨文件、跨请求、跨运行时，变量边界不清就会开始串台

**原始类型与引用类型** ---- 理解 Number、String、Boolean、Undefined、Null、Symbol、BigInt 与 Object 家族的差异，进一步分清值、引用、可变性、同值判断和序列化边界；这是一切数据流转的地基

**特殊值与类型判断** ---- 认识 NaN、Infinity、负零、真假值、typeof、instanceof、Object 原型方法和 Array.isArray；别把“能进 if”误认为“类型正确”，那是给线上 Bug 发邀请函

**显式转换与隐式转换** ---- 学会数字、字符串、布尔、对象在运算、比较、拼接和序列化时的转换规则，重点理解加法、相等比较、ToPrimitive 与 ToBoolean；前端表单和后端请求体尤其容易把字符串伪装成数字

**运算符与控制流** ---- 覆盖比较、逻辑、位运算、三元、可选链、空值合并、逻辑赋值、解构、循环、异常与提前返回；重点是表达清楚业务分支，而不是参加“最短代码大赛”

**函数与参数模型** ---- 掌握函数声明、表达式、箭头函数、默认参数、剩余参数、arguments、返回值、递归、高阶函数、纯函数、柯里化、组合与管道；函数是前后端共享的最小业务单元

**闭包与函数生命周期** ---- 理解闭包如何保存外部变量、如何实现私有状态、缓存和工厂函数，也要知道它如何意外留住大对象、定时器、请求和 DOM；能解释“谁还引用着它”，才算真正懂闭包

**this 与调用方式** ---- 按 new、显式调用、隐式调用、默认调用和箭头函数的规则理解 this，分清 call、apply、bind 与回调丢失上下文的关系；方法在浏览器事件、类、服务对象里会反复换座位

**数组、字符串与正则** ---- 覆盖遍历、映射、过滤、归并、查找、排序、稀疏数组、不可变操作、Unicode、模板字符串、正则分组、断言、贪婪匹配与灾难性回溯；常用招式要熟，不常用招式要知道什么时候不该拔刀

**对象与内建对象** ---- 了解属性描述符、访问器、枚举、冻结、浅拷贝、深拷贝、structuredClone、Map、Set、WeakMap、WeakSet、Date、Intl、JSON 与序列化限制；数据库记录、接口响应和缓存对象都离不开这些边界

**原型、类与继承** ---- 理解 prototype、原型链、new、instanceof、class、extends、super、私有字段、静态成员、Mixin 与组合优于深继承的取舍；class 是西装，prototype 仍然是里面那位老裁缝

**错误与资源意识** ---- 区分语法错误、运行时错误、业务错误、网络错误和数据错误，建立可捕获、可传播、可记录的错误思维；不要把所有异常都压成一句“系统开小差了”

**重点解释** ---- 这一站的通关不是背完方法名，而是能看懂一段前后端共用的 JavaScript，解释它的作用域、数据形状、调用上下文、异常路径与可变性

## 第二站：执行模型、异步与内存

第二站进入 JavaScript 的交通指挥中心。它表面上“单线程”，实际上浏览器、Node.js、操作系统和线程池一起忙活；真正需要学会的不是把每个函数前面都贴上 async，而是让并发有顺序、有上限、能取消、能收尾。

**执行上下文与调用栈** ---- 理解全局、函数、模块执行上下文，词法环境、变量环境、this 绑定、外部环境引用和调用栈；调试时看到的每一层栈帧，都是程序当时的脚印

**宏任务与微任务** ---- 区分定时器、I/O、事件、渲染、Promise 回调、queueMicrotask 与 Node 的 nextTick，理解“清空微任务后才进入下一轮”的基本节奏；队列排错，日志就会开始讲悬疑故事

**浏览器事件循环** ---- 掌握任务执行、微任务清空、样式计算、布局、绘制、合成、requestAnimationFrame 与空闲任务的关系，理解长任务为什么会让点击像寄出了平信

**Node.js 事件循环** ---- 了解 timers、pending callbacks、poll、check、close callbacks 等阶段，以及 I/O、setImmediate、定时器和 nextTick 的调度差异；浏览器的“异步直觉”不能原封不动搬到服务器

**Promise 状态与链式传播** ---- 掌握 pending、fulfilled、rejected、then 链、错误冒泡、finally、Promise.resolve、Promise.reject、all、allSettled、race、any 与 AggregateError；重点放在失败如何到达真正的处理者

**async/await 的真实模型** ---- 理解 async 总是返回 Promise、await 只暂停当前异步函数、串行 await 与并发组合的差异，以及顶层 await、异步迭代器和异步生成器；语法像同步，不代表执行真的同步

**并发控制与背压** ---- 学习并发上限、任务队列、批处理、流水线、生产者消费者、流式处理和资源池；无限 Promise.all 不是性能方案，是把故障排队买团体票

**取消、超时与截止时间** ---- 掌握 AbortController、AbortSignal、请求取消、任务取消、超时传播和 finally 清理；一个请求结束后，后台还在悄悄干活，通常就是资源管理没毕业

**重试、退避与幂等** ---- 区分瞬时错误与永久错误，理解指数退避、随机抖动、最大次数、重试预算和幂等键；重试不是把同一个请求再扔一次，而是先证明重复不会造成事故

**竞态与顺序一致性** ---- 处理搜索旧结果覆盖新结果、重复提交、缓存重建、并发更新和任务重复消费；需要时引入版本号、取消、锁、状态机或最后写入规则

**V8 执行与优化** ---- 了解解析、AST、字节码、解释执行、JIT、TurboFan、内联缓存、隐藏类、去优化和对象形状；不用背引擎源码，但要知道为什么“看起来一样”的对象也可能走不同的快车道

**内存、垃圾回收与泄漏** ---- 认识栈、堆、新生代、老生代、标记清除、标记整理、增量与并发回收，排查闭包、监听器、缓存、定时器、连接、请求引用和脱离 DOM；GC 是清洁工，不是性能替罪羊

**重点解释** ---- 这一站要建立“时间与资源”的心智模型：任何异步任务都要回答何时开始、何时结束、失败去哪、谁能取消、占多少内存、能否同时跑一百个

## 第三站：模块、TypeScript 与工程化

第三站是全栈项目的交通枢纽。代码从一个文件长成一个仓库后，真正让人迷路的往往不是业务，而是模块边界、依赖解析、构建产物和“本地能跑、CI 不认”的环境差异。

**ES Module 与 CommonJS** ---- 对比静态导入、动态导入、命名导出、默认导出、实时绑定、运行时加载、顶层 await 与 this 行为；同时理解两套模块互操作时的默认导出和循环依赖陷阱

**模块解析与包边界** ---- 学习相对路径、包入口、exports、imports、type、条件导出、扩展名、别名和工作目录；能 import 不代表应该跨层 import，依赖方向才是架构的骨架

**循环依赖与初始化顺序** ---- 认识部分初始化、未定义导出、模块副作用、顶层执行和循环引用的差异；遇到循环依赖，先问边界是否画歪，不要只给它再套一层转发文件

**TypeScript 类型地基** ---- 覆盖类型推断、联合与交叉、字面量、泛型、条件类型、映射类型、类型守卫、模块声明、类型收窄与编译配置；类型是契约护栏，不是运行时保镖

**运行时校验与类型边界** ---- 理解 TypeScript 类型会在运行时消失，外部输入仍需校验；把请求体、环境变量、数据库结果和第三方响应视为不可信数据，建立类型与验证的双层边界

**package.json 与版本策略** ---- 掌握 scripts、dependencies、devDependencies、peerDependencies、optionalDependencies、engines、exports 与 package manager 字段，理解 SemVer、版本范围和弃用策略

**锁文件与可重复安装** ---- 认识 package-lock、pnpm-lock、yarn.lock、依赖树、幽灵依赖、可复现构建和安装脚本；“删掉 node_modules 再装一次”不该是团队唯一的修复哲学

**npm、pnpm、Yarn 与 Workspace** ---- 了解各包管理器的链接、缓存、严格依赖、工作区、Monorepo 与发布边界；全栈项目适合共享类型和工具配置，但不适合把所有应用揉成一锅粥

**Babel、编译与 Polyfill** ---- 分清语法转译、运行时补丁、目标浏览器、Node 版本、源码映射与原生支持；转译能改语法，不能替你凭空制造一个数据库连接

**Vite、Rollup、Webpack 与打包** ---- 理解开发服务器、依赖预构建、入口、插件、loader、代码分割、Tree Shaking、sideEffects 与生产产物；前端包和服务端包的目标不同，配置也不应盲目复制

**ESLint、Prettier 与提交检查** ---- 建立静态检查、格式化、类型检查、提交钩子、lint-staged、commit 规范与 CI 门禁；工具的职责是减少争论，不是让每个人在分号问题上修炼内功

**测试构建与源码映射** ---- 关注测试环境与生产环境差异、source map、覆盖率、构建缓存和失败日志；开发体验快不等于发布产物可信

**依赖供应链** ---- 学习锁版本、审计漏洞、许可证、依赖来源、安装脚本、恶意包、最小权限和升级回滚；全栈工程师也要给依赖做背景调查

**重点解释** ---- 这一站的目标是让项目“换一台机器仍能装、换一个人仍能懂、换一个环境仍能测”；工程化不是把配置文件写成迷宫，而是把不确定性提前暴露

## 第四站：浏览器平台与 Web API

第四站回到浏览器，但这次不是只让按钮变色，而是理解浏览器如何承载应用。DOM、BOM、网络、存储、渲染和后台能力共同组成前端运行时，也是全栈请求链路的另一半。

**BOM 与页面生命周期** ---- 掌握 window、location、history、navigator、screen、DOMContentLoaded、load、beforeunload 与页面可见性；SPA 路由、跳转、刷新和离开确认都建立在这些能力上

**DOM 树与节点操作** ---- 理解 Document、Element、Text、DocumentFragment、查询、创建、插入、删除、属性、dataset、classList、样式、尺寸、位置和滚动；先懂平台原语，再看框架如何替你管理它

**事件监听与传播** ---- 学习捕获、目标、冒泡、target、currentTarget、preventDefault、stopPropagation、passive、once、事件委托与自定义事件；事件委托省内存，但也会让调试现场多一位嫌疑人

**表单、键盘与指针** ---- 覆盖 input、change、focus、blur、submit、reset、键盘修饰键、鼠标、触摸、Pointer Events 与可访问交互；表单不只是输入框，它是用户与后端的第一份合同

**文件、剪贴板与拖放** ---- 了解 File、FileReader、Blob、ArrayBuffer、FormData、Clipboard、拖放事件和上传进度；文件名、大小、类型和内容都不能只信浏览器嘴上说的

**Fetch 与请求生命周期** ---- 掌握 Request、Response、Headers、Body、JSON、文本、Blob、流式响应、credentials、cache、redirect、重定向和 AbortSignal；Fetch 不会因为收到 404 就自动 reject，细节要记牢

**同源策略与 CORS** ---- 理解源、简单请求、预检 OPTIONS、凭证、响应头和开发代理；跨域不是“浏览器坏了”，而是浏览器在替用户看门

**Cookie、Storage 与 IndexedDB** ---- 对比 Cookie、localStorage、sessionStorage、IndexedDB 的作用域、容量、同步性、生命周期与安全边界；不要把 localStorage 当成保险箱，它连门锁都没有

**缓存与 Service Worker** ---- 学习 HTTP 缓存、Cache Storage、Service Worker 安装与激活、请求拦截、离线策略、更新与失效；缓存的难题不是“存进去”，而是“什么时候承认旧东西过期了”

**Web Worker 与跨线程通信** ---- 认识 Worker、SharedWorker、postMessage、结构化克隆、Transferable、SharedArrayBuffer 与 Atomics，知道何时把 CPU 重活搬出主线程，何时消息复制反而更贵

**WebSocket、SSE 与流** ---- 对比长轮询、SSE、WebSocket、ReadableStream 和实时连接的方向、心跳、重连、断线、背压与代理支持；实时不是把消息发快，而是把断线也设计进去

**浏览器安全边界** ---- 先建立同源、跨站、权限、Origin、Referer、用户手势与安全上下文的概念，为后面的认证与 Web 安全打地基

**重点解释** ---- 这一站学完，应能从浏览器开发者工具追踪一次请求：页面如何触发事件，请求如何构造，跨域如何检查，响应如何解析，状态如何保存，页面如何渲染

## 第五站：前端应用与用户界面

第五站是用户真正看得见的地方。React 和 Vue 都能把界面做出来，但全栈学习不该停在“组件会渲染”；你还要管理数据来源、请求状态、路由边界、错误恢复和与后端的契约。

**React 或 Vue 二选一** ---- React 见 [React 学习路线](/learning-paths/frontend/react)，Vue 见 [Vue 学习路线](/learning-paths/frontend/vue)；先选一条深入组件、响应式、生命周期和调试，再理解另一条的思想差异，避免框架集邮

**组件与组合边界** ---- 学习组件职责、输入输出、插槽或 children、受控与非受控、复合组件、组合式逻辑与可复用 Hook；组件不是把一整页切成十七块，而是让变化有合理的归宿

**状态分层** ---- 区分组件局部状态、表单状态、URL 状态、全局 UI 状态、服务端状态、缓存状态与持久化状态；接口数据不该因为“看起来全局”就被塞进一个巨型 store

**响应式与渲染机制** ---- 理解依赖收集、派生状态、批量更新、渲染阶段、提交阶段、重渲染原因与引用稳定性；知道框架何时帮你省事，何时只是把成本延期

**路由与导航** ---- 掌握嵌套路由、参数、查询、导航守卫、懒加载、错误边界、权限体验与刷新恢复；前端守卫负责体验，真正的权限拒绝必须在后端

**数据请求与缓存** ---- 规划 loading、success、empty、error、stale、refresh、分页、预取、失效、乐观更新和回滚；后续再深入请求库、缓存策略与取消机制

**竞态、重复提交与离线体验** ---- 处理旧请求覆盖新请求、按钮连点、网络抖动、断网重试、草稿恢复和乐观更新失败；用户按下提交后，系统要有比“请稍候”更完整的剧本

**表单与校验** ---- 区分即时校验、提交校验、前端提示、后端最终校验、字段级错误与全局错误；校验逻辑应尽量共享规则，但不能把浏览器校验当成安全边界

**可访问性与交互反馈** ---- 关注语义 HTML、键盘操作、焦点管理、ARIA、错误提示、加载状态、空状态和响应式布局；用户体验不是动画数量，而是用户知道现在发生了什么

**组件测试与开发体验** ---- 用用户视角验证渲染、输入、点击、异步和错误恢复，少测内部实现细节；测试工具可从 [Jest 学习路线](/learning-paths/testing/jest) 与 [全栈测试](/learning-paths/fullstack/testing) 继续

**重点解释** ---- 这一站的产出不是一套漂亮页面，而是一组能稳定消费接口、能处理失败、能在刷新后恢复、能让用户完成任务的前端应用

## 第六站：Node.js 运行时与核心能力

第六站把 JavaScript 搬到服务器。Node.js 不是“浏览器去掉 document 的版本”：V8 负责执行，libuv 负责事件循环与系统 I/O，Node 核心模块负责进程、文件、网络、流和二进制；建议配合 [Node.js 后端开发学习路线](/learning-paths/backend/nodejs) 深入。

**Node、V8 与 libuv** ---- 理解 JavaScript 执行层、Node 运行时层、操作系统 I/O 层和线程池的分工；知道哪些工作在主线程，哪些工作由系统或线程池协助完成

**进程与环境** ---- 掌握 process、命令行参数、环境变量、标准输入输出、退出码、信号、未捕获异常、未处理拒绝与优雅退出；服务可以重启，但数据和请求不能凭空消失

**文件系统与路径** ---- 了解异步与同步文件操作、文件描述符、目录、权限、临时文件、路径规范化和路径穿越；请求处理里随手同步读大文件，事件循环会当场罢工

**URL、网络与加密基础** ---- 学习 URL 解析、DNS、TCP、TLS、Socket、端口、证书、连接与超时的关系，理解 Node 的网络能力如何接上 HTTP 服务

**Buffer、编码与二进制** ---- 区分字节、字符、UTF-8、Base64、ArrayBuffer、TypedArray、DataView 和二进制协议；图片、压缩包、上传文件和加密数据不该被当作普通字符串揉

**Stream 与背压** ---- 掌握可读、可写、转换、管道、结束、错误、销毁、背压和流式响应；流的核心是控制内存与速度，不是把一个大文件切成很多小烦恼

**EventEmitter 与定时器** ---- 理解监听注册、移除、once、错误事件、监听器泄漏、计时器不精确与事件驱动控制流；事件越灵活，越要有清晰的生命周期

**子进程、工作线程与多进程** ---- 区分命令执行、独立进程、worker_threads、进程间消息、共享内存、CPU 密集任务和多实例扩展；计算、压缩、加密和大 JSON 解析不能无限占住主线程

**Node 原生 Web 能力** ---- 了解原生 HTTP、Web Streams、Web Crypto、Fetch、AbortSignal 与文件 URL 等现代能力，再决定是否需要额外框架；先认识底盘，才不会把框架的轮子当发动机

**依赖注入与资源释放** ---- 用显式装配管理数据库、缓存、时间、随机数、外部服务和测试替身，保证连接、监听器、流、定时器和任务能被关闭

**重点解释** ---- 这一站通关标准是：能解释一个 Node 请求经过哪些队列，能判断一段工作会不会阻塞事件循环，能让进程收到终止信号后把事情做完再下班

## 第七站：HTTP 服务与后端业务

第七站来到 API 服务大厅。Express、Fastify、NestJS 都能接住请求，但框架只负责一部分交通规则；路由、校验、业务、数据、错误和资源边界仍然需要你安排座位。

**HTTP 完整模型** ---- 掌握方法、状态码、Header、Cookie、缓存、内容类型、幂等、安全连接、重定向、代理与请求生命周期；HTTP 是全栈双方共同使用的母语

**Express、Fastify 与 NestJS** ---- 了解 Express 的自由、Fastify 的性能与插件边界、NestJS 的模块与依赖注入；可从 [NestJS 学习路线](/learning-paths/backend/nestjs) 进入更强约束的工程化路线

**路由与资源设计** ---- 按资源、版本和业务边界组织路径，处理路径参数、查询参数、方法匹配、嵌套路由和内容协商；URL 不要一会儿像名词，一会儿像命令行

**中间件与请求管线** ---- 组织请求 ID、日志、解析、跨域、认证、限流、压缩、超时、事务和错误处理，明确顺序、短路和异常传播；中间件不是调料瓶，什么都往里倒会变成一锅汤

**输入校验与输出序列化** ---- 校验类型、范围、格式、未知字段、嵌套结构和文件，控制响应字段、分页、日期、金额、BigInt、Decimal 与敏感信息；进入系统的数据要验货，离开系统的数据要打包

**控制器、服务与数据层** ---- 让控制器处理协议，服务处理业务，仓储或查询层处理持久化，基础设施负责外部系统；分层不是为了多建目录，而是为了让规则有唯一住址

**统一响应与错误处理** ---- 设计成功、校验失败、未认证、无权限、未找到、冲突、限流和未知错误的稳定结构，区分用户提示、程序错误码与内部日志；绝不把数据库堆栈原样寄给浏览器

**分页、过滤与排序** ---- 理解页码分页、游标分页、稳定排序、筛选组合、总数成本和大数据集边界；第一页快不代表第十万页也愿意配合

**文件上传与下载** ---- 处理 multipart、大小限制、扩展名、内容探测、临时文件、对象存储、断点、权限、病毒扫描、流式下载和响应头；上传接口是安全题，也是内存题

**进程生命周期与健康检查** ---- 实现启动校验、readiness、liveness、优雅关闭、连接池释放、任务停止和超时退出；“端口还在”不等于“服务健康”

**重点解释** ---- 这一站要能独立写出一个有版本、有校验、有错误、有日志、有认证入口的 API，并且能说明请求从路由到业务再到数据层的完整路径

## 第八站：数据库、ORM 与缓存

第八站是数据仓库。JavaScript 对象很松弛，数据库约束很严格；全栈工程师要学会在“开发方便”和“数据可靠”之间谈判，而不是让 ORM 替自己签合同。

**关系型数据库地基** ---- 学习表、行、列、主键、外键、约束、范式、反范式、事务与 SQL；[PostgreSQL 学习路线](/learning-paths/database/postgresql) 适合做主线数据库

**SQL 查询与数据建模** ---- 覆盖连接、聚合、子查询、窗口函数、批量写、分页、视图、触发器与存储过程的边界；能写查询只是开始，还要知道它在数据量增长后会怎样

**索引与执行计划** ---- 理解 B-tree、复合索引、覆盖索引、选择性、排序、范围查询、全文或 JSON 索引与 EXPLAIN；索引不是越多越好，它也要占空间、拖写入、增加维护费

**事务、锁与隔离级别** ---- 掌握原子性、一致性、隔离性、持久性，读现象、行锁、死锁、乐观锁、悲观锁和隔离级别；“两次查询都成功”不自动等于业务成功

**ORM、查询构建器与原生 SQL** ---- 比较 Prisma、Drizzle、TypeORM、Sequelize、Knex 与原生驱动在类型、迁移、关联、事务和透明度上的取舍；抽象应降低重复，不应遮住昂贵查询

**模型、迁移与数据修复** ---- 管理 schema、迁移版本、回滚、兼容发布、历史数据、数据迁移与备份；改字段前先问已有数据怎么办，数据库不会因为你删掉了模型文件就失忆

**连接池与资源上限** ---- 规划连接数、超时、空闲回收、事务释放、多进程连接总量和故障重连；应用实例乘以连接池大小，往往比直觉更快撞上数据库上限

**N+1 与批量访问** ---- 识别循环查库、关联预加载、批量查询、选择列和缓存穿透；接口慢时先看查询次数和执行计划，不要第一反应给 Node 再加几个 async

**MongoDB 与文档模型** ---- 了解文档、嵌入、引用、聚合、索引、副本集、事务、分片与一致性；[MongoDB 学习路线](/learning-paths/database/mongodb) 适合数据结构灵活、读写模式明确的场景

**Redis 与缓存模型** ---- 掌握字符串、哈希、列表、集合、有序集合、过期、淘汰、发布订阅、分布式锁与持久化；[Redis 学习路线](/learning-paths/database/redis) 继续深入缓存与并发工具

**缓存一致性与故障** ---- 设计 cache-aside、读写穿透、失效、预热、击穿、雪崩、脏数据、双写与最终一致性；缓存是加速器，不是第二个永远正确的数据库

**重点解释** ---- 这一站的验收不是“CRUD 能跑”，而是能说清数据模型、事务边界、索引理由、连接上限、失败恢复和缓存失效；数据可靠性优先于 ORM 的顺手

## 第九站：接口契约与跨层类型

第九站是前后端协作的合同办公室。接口只要被两个模块消费，就不再是某个人的私有实现；契约写得清楚，联调就像对表格，写得含糊，联调就像考古。

**REST 资源与 HTTP 语义** ---- 设计资源、方法、状态码、版本、幂等、分页、过滤、排序、批量操作和嵌套关系，保持 URL、字段和行为稳定；REST 不是把动词塞进路径，而是让资源与语义对齐

**统一响应与错误契约** ---- 约定成功结构、错误码、用户消息、字段错误、追踪 ID、分页元数据和空结果；机器要稳定的 code，人要看得懂的 message，两者不要互相冒充

**OpenAPI 与文档先行** ---- 用 OpenAPI 描述路径、参数、请求、响应、安全方案和错误，让 Swagger 或生成工具成为可验证的契约；文档不是发布后补的装饰，而是开发前的共同地图

**GraphQL 与查询型 API** ---- 理解 schema、resolver、查询深度、批量加载、缓存、权限和版本策略，知道 GraphQL 解决什么问题，也知道它不是自动消灭 N+1 的魔法

**tRPC 与类型共享** ---- 认识端到端类型推导、调用方体验、运行时校验、服务边界与独立部署的取舍；类型共享降低沟通成本，但不能代替网络、权限和版本设计

**Schema 与 DTO** ---- 分清数据库模型、领域模型、请求模型、响应模型和前端视图模型，避免把数据库列名直接当公共 API；一张表可以有多个对外形状

**JSON 边界与特殊值** ---- 处理日期时区、金额精度、BigInt、Decimal、二进制、枚举、空值、未知字段和循环引用；JSON 很通用，但它没有承诺替你保存一切

**共享包与 Monorepo** ---- 规划 types、schema、client、UI、配置和服务包的依赖方向，理解发布、构建、版本和独立部署边界；共享的应该是契约与稳定能力，不是所有内部细节

**兼容性与版本演进** ---- 区分加字段、删字段、改语义、改类型、改默认值的风险，学习向后兼容、弃用、v1/v2、灰度与迁移期；接口升级不能只通知“记得改一下”

**联调与 Mock** ---- 用 Mock、代理、沙箱、契约测试和真实集成测试支持前后端并行，按 URL、鉴权、请求体、响应体和环境五层排查“接口调不通”

**重点解释** ---- 这一站通关意味着：后端改接口时，前端能尽早知道；接口失败时，双方知道该看哪里；类型能辅助协作，但没有人把编译器当成安全审计员

## 第十站：认证、授权与 Web 安全

第十站是全栈应用的城门。登录只是确认“你是谁”，授权才决定“你能做什么”，安全还要继续追问“你提供的数据能不能伤害系统”。隐藏一个按钮，不能算权限控制，只能算按钮捉迷藏。

**密码与账户生命周期** ---- 学习密码哈希、盐、成本、登录失败限制、注册、验证、重置、注销、账户锁定和多因素认证；密码只应以不可逆验证材料存在，日志里也不该出现它

**Session、Cookie 与 JWT** ---- 对比服务端 Session、短期访问令牌、刷新令牌、Cookie 属性、内存存储与持久化，理解撤销、轮换、过期、重放和多设备会话

**OAuth 2.0 与 OpenID Connect** ---- 分清授权、认证、资源服务器、客户端、重定向、state、nonce、PKCE、scope 与 token 生命周期；不要因为“有一个登录按钮”就把协议名称都混成一锅

**认证流转与刷新并发** ---- 设计登录、携带凭证、后端验签、注入当前用户、401、刷新、请求重放、刷新失败和并发刷新排队；这条链路前后端必须提前约定

**RBAC、ABAC 与对象权限** ---- 区分角色、权限、资源范围、对象归属、租户、组织层级和服务间身份；前端权限负责体验，后端每一次资源访问都要做最终判断

**XSS 与输出安全** ---- 理解存储型、反射型、DOM 型 XSS、HTML 转义、textContent、CSP、可信类型与富文本净化；输入校验重要，输出上下文的安全编码同样重要

**CSRF、SameSite 与 CORS** ---- 认识 Cookie 自动携带、跨站请求、CSRF Token、SameSite、Origin、Referer、预检和凭证配置；CORS 解决读取限制，不等于 CSRF 防御

**注入与解析攻击** ---- 防范 SQL、NoSQL、命令、模板、表达式、路径、LDAP、日志和反序列化注入；参数化、白名单、最小权限和边界校验要落在服务端

**原型污染与对象安全** ---- 理解 prototype、constructor、对象合并、深层赋值、无原型对象、Map、冻结和安全解析；JavaScript 的原型灵活，是生产力也是攻击面

**SSRF、开放重定向与网络边界** ---- 限制服务器代发请求的目标、协议、内网地址、DNS 解析与重定向，校验回调地址和外部 URL；服务器能访问的地方，攻击者也可能想借你的手访问

**文件、路径与资源安全** ---- 防止路径穿越、任意文件读取、恶意上传、脚本执行、压缩炸弹、超大请求与资源耗尽；文件处理要隔离存储、限制大小、探测内容并控制下载权限

**安全响应头与传输保护** ---- 掌握 HTTPS、TLS、HSTS、CSP、X-Frame-Options、Referrer-Policy、Permissions-Policy、SRI 与安全 Cookie；响应头不是万能盾牌，但缺它们通常更像没带伞出门

**秘密、日志与供应链安全** ---- 保护密钥、证书、环境变量、Token、个人信息、支付数据与审计记录，落实依赖审计、锁文件、最小权限、密钥轮换和泄露响应

**限流、幂等与审计** ---- 保护登录、支付、上传、重置密码和昂贵接口，记录关键操作、请求 ID、操作者、对象与结果，避免日志泄露凭证

**重点解释** ---- 这一站不以“装了安全中间件”为毕业标准，而是能画出信任边界，指出每个输入由谁产生、谁验证、谁授权、失败如何记录与恢复

## 第十一站：Next.js、Nuxt 与同构应用

第十一站进入全栈框架的高架路。Next.js 与 Nuxt 把页面、服务端逻辑、路由、构建与部署放进同一个应用，效率很高；代价是运行位置更多，边界也更容易藏起来。

**框架选型与路线** ---- React 生态优先看 [Next.js 学习路线](/learning-paths/frontend/nextjs)，Vue 生态优先看 [Nuxt.js 学习路线](/learning-paths/frontend/nuxtjs)；先理解分离式前后端，再用同构框架提效，避免把约定当原理

**CSR、SSR、SSG 与 ISR** ---- 分清客户端渲染、服务端渲染、静态生成、增量生成、按需重验证和边缘渲染的请求时机、缓存位置与适用场景

**服务端与客户端边界** ---- 区分构建阶段、Node 服务器、边缘运行时、浏览器、Server Components、Client Components 与浏览器专属 API；window、数据库和密钥不能随便跨境

**路由处理与服务端动作** ---- 理解 Route Handlers、Server Actions、Nuxt server/api、服务端表单、请求上下文、重定向和错误边界；“组件里能调用”不等于“调用位置安全且可扩展”

**Hydration 与流式渲染** ---- 掌握服务端 HTML、客户端接管、hydration mismatch、Suspense、流式响应、部分渲染与加载边界；首屏快了，但如果接管时吵架，用户还是能看到页面打嗝

**数据缓存与重新验证** ---- 规划请求缓存、页面缓存、函数缓存、浏览器缓存、CDN 缓存、标签失效、时间重验证和主动刷新；缓存所有权必须明确，否则旧数据会在不同层互相甩锅

**中间件与边缘限制** ---- 了解重写、重定向、鉴权前置、地域路由、Edge Runtime 的 API 限制、冷启动与网络位置；边缘不是“更快的 Node”，它是另一种运行环境

**单体同构与服务拆分** ---- 比较前后端同仓、BFF、独立 API、微服务与 Serverless，按团队、部署、扩展和边界选择；为了一个登录页拆成七个服务，属于架构健身过度

**SEO、元数据与可分享性** ---- 处理服务端可见内容、标题、描述、结构化数据、社交卡片、国际化、站点地图与缓存；内容产品和后台应用的渲染策略不必穿同一套衣服

**重点解释** ---- 这一站要能回答“这段代码在哪里运行、什么时候运行、读到的是哪一份数据、缓存由谁失效、失败由谁接住”，而不是只会按框架脚手架的回车键

## 第十二站：实时通信、消息与后台任务

第十二站是全栈应用的后勤中心。请求-响应适合大多数业务，但通知、聊天、报表、同步、邮件和重计算不能永远堵在一次 HTTP 请求里；把重活搬走后，重试和一致性也会跟着搬来。

**轮询、SSE 与 WebSocket** ---- 比较单向推送、双向通信、连接数、代理、心跳、断线、重连、广播、背压和浏览器支持，按交互方向而不是潮流选技术

**连接生命周期** ---- 管理握手认证、连接上限、心跳、空闲清理、断开、重连、房间、在线状态与多标签页；连接表放在单机内存里，扩容后它会突然变得很健忘

**发布订阅与多实例广播** ---- 理解进程内事件、Redis Pub/Sub、消息代理、持久化消息和跨实例路由的差异；实时消息是否允许丢失，要在业务上先说清楚

**任务队列与消费者** ---- 学习生产者、队列、消费者、并发数、可见性超时、确认、失败、重试、延迟、优先级与死信；队列不是垃圾桶，每个任务都需要状态和归属

**定时任务与分布式调度** ---- 处理时区、夏令时、重复执行、任务锁、错过窗口、补偿和多实例竞争；凌晨零点在不同地区可能不是同一个凌晨零点

**至少一次与幂等消费** ---- 接受消息可能重复、乱序、延迟和重新投递，为邮件、支付、库存、通知和同步设计去重键、状态机与补偿动作

**事务 Outbox 与事件驱动** ---- 理解数据库事务与消息发送之间的间隙，用 Outbox、轮询发布、消息确认和重放降低丢消息风险；事件驱动不是“多发几个事件”，而是给变化建立可追踪记录

**工作流与长任务** ---- 拆分导入、导出、视频、AI、报表和批处理，提供进度、取消、重试、超时、断点和结果领取；让用户等待十分钟不是产品功能

**重点解释** ---- 这一站通关是：系统在断网、重启、重复消费、消费者变慢和消息延迟时，仍然能解释发生了什么，并把最终状态收敛到正确结果

## 第十三站：测试、调试与可观测性

第十三站来到质检和案发现场。测试让问题尽量早出现，调试告诉你问题当时发生了什么，可观测性负责在你不在电脑前时把线索送到门口；三者缺一，线上就只能靠猜。

**单元测试** ---- 覆盖纯函数、业务规则、校验、权限、状态机、错误和边界，优先测试稳定且高价值的行为；测试数量多不等于信心多

**组件与交互测试** ---- 验证用户看到的内容、输入、点击、键盘、异步加载、错误和可访问性，少绑定内部实现；组件测试应该像用户使用，不像窥探私生活

**接口与集成测试** ---- 检查路由、状态码、Header、认证、权限、数据库、事务、文件和错误结构，必要时使用真实数据库或容器依赖；Mock 太多，测试可能只证明 Mock 很配合

**契约测试** ---- 验证 OpenAPI、共享 schema、请求响应、错误码和版本兼容，让接口变更在联调前暴露；它是前后端之间的自动验收单

**端到端测试** ---- 用 Playwright 或 Cypress 覆盖注册、登录、核心 CRUD、支付或关键业务路径；E2E 数量要少而精，稳定性来自独立数据、可靠选择器和自动等待

**异步与失败测试** ---- 覆盖超时、取消、重试、竞态、队列重复、连接断开、第三方失败、迁移失败和优雅关闭；只测晴天路径，系统一遇下雨就会漏水

**性能与容量测试** ---- 观察吞吐、P50/P95/P99、并发、事件循环延迟、连接池、数据库、队列积压、CPU、内存和 GC；平均值很会安慰人，尾延迟才会在发布会上发言

**浏览器与 Node 调试** ---- 熟悉 Network、Console、Sources、Performance、Memory、Application、Node Inspector、CPU Profile、Heap Snapshot 与 trace；先收集证据，再修改代码，别凭截图猜病因

**结构化日志** ---- 记录时间、级别、请求 ID、trace ID、用户或租户、路由、状态码、耗时与依赖结果，过滤 Token、密码和个人敏感信息；日志是现场记录，不是情绪日记

**指标与分布式追踪** ---- 建立请求量、错误率、延迟、资源、缓存命中、数据库、队列、业务转化和依赖调用指标，理解 trace、span、采样与上下文传播

**错误监控与告警** ---- 捕获前端运行时错误、未处理拒绝、后端异常、任务失败和发布回归，设置可行动的告警；告警太多时，真正的事故会被噪音埋掉

**CI 质量门禁** ---- 让格式化、Lint、类型检查、单测、集成测试、构建、依赖审计和必要的 E2E 在 Pull Request 或发布流程中自动执行；绿色不是奖状，是允许继续前进的最低票

**重点解释** ---- 这一站的目标是建立证据链：问题能复现，失败能定位，线上有上下文，修复有回归，发布前有门禁；“我本地没问题”不属于证据类型

## 第十四站：全链路性能与可靠性

第十四站开始抠性能，但先别急着把变量名缩短。用户感知的速度由 DNS、连接、服务端、数据库、网络、解析、渲染和交互共同决定；只优化最顺眼的一层，瓶颈会像打地鼠一样换地方。

**前端用户体验指标** ---- 关注 TTFB、FCP、LCP、INP、CLS、长任务、错误率和真实用户监测；性能优化最终服务的是用户完成任务的时间，不是本地打开 DevTools 时的自我感动

**资源与包体积** ---- 规划代码分割、动态导入、Tree Shaking、依赖体积、预加载、预连接、字体、图片、视频、压缩和 CDN；首屏不需要的代码，不必抢第一排座位

**浏览器渲染性能** ---- 理解重排、重绘、合成、布局读取、批量 DOM、虚拟列表、懒加载、观察器和动画合成；transform 能帮忙，但不能替糟糕的数据流洗白

**网络与缓存性能** ---- 设计 HTTP 缓存、ETag、Cache-Control、CDN、边缘节点、压缩、HTTP/2 或 HTTP/3、请求合并与预取，权衡新鲜度、命中率和失效成本

**Node 事件循环性能** ---- 监控事件循环延迟，识别同步 I/O、CPU 计算、大 JSON、正则回溯、压缩、加密和日志阻塞，选择流、工作线程、子进程或任务队列

**服务端延迟分析** ---- 拆分 DNS、连接、TLS、排队、业务、数据库、缓存、外部依赖和序列化耗时，关注 P95/P99 与尾部放大；平均延迟很平静，不代表最后一批用户没有在等

**数据库性能** ---- 从执行计划、索引、N+1、分页、锁、连接池、批量操作和数据量增长分析查询，确认优化前后有测量；“加缓存”不是所有 SQL 的统一毕业论文

**缓存与热点保护** ---- 设计 TTL、预热、单飞、请求合并、限流、降级、熔断、过期抖动和热点隔离；缓存击穿时，最怕所有请求同时去叫醒数据库

**容量、背压与负载 shedding** ---- 设定队列长度、请求体、并发、连接、文件、内存和超时上限，在系统过载时拒绝低价值工作，保护核心路径

**可靠性模式** ---- 掌握超时、重试预算、熔断、舱壁隔离、幂等、降级、优雅关闭、健康检查、故障转移与恢复时间目标；可靠不是永不出错，而是出错后还能回到可解释状态

**重点解释** ---- 这一站要能用指标找到瓶颈、用实验验证收益、用容量边界保护系统；性能不是“跑分冠军”，而是在真实负载和故障里仍然守住体验

## 第十五站：部署、发布与生产运维

最后一站是交付站。代码写完只算做完作业，构建、迁移、发布、监控、回滚和备份都完成，才算把产品送到用户手里；生产环境不接受“我以为”。

**构建产物与运行环境** ---- 区分开发、测试、预发布、生产、构建期、启动期和请求期配置，明确浏览器公开变量与服务器秘密；前端变量一旦打进包里，就不再是秘密

**Docker 与进程管理** ---- 学习多阶段构建、最小镜像、非 root、信号转发、健康检查、日志输出、Node 进程和容器退出；容器不是把本地目录打包后祈祷

**前端托管与 CDN** ---- 规划静态资源、SPA 回退、SSR 服务、缓存头、域名、HTTPS、CDN、源站和预览环境；刷新不 404，是部署路线的第一道门槛

**后端反向代理** ---- 理解 Nginx 或平台网关的 TLS、代理头、压缩、请求体限制、超时、WebSocket 转发、限流和静态文件边界

**数据库迁移与发布顺序** ---- 让 schema 变更版本化、可评审、可重跑，处理先迁后发、先发后迁、兼容窗口、大表锁和数据迁移；删字段是动作片，不适合在高峰期即兴上映

**CI/CD 自动化** ---- 串起安装、缓存、Lint、类型检查、测试、构建、镜像、迁移、部署、冒烟、审批和回滚；自动化的价值是每次走同一条经过验证的路

**发布策略** ---- 了解滚动、蓝绿、金丝雀、功能开关、灰度、健康检查与版本标识，做到可观测、可暂停、可回滚；快速回滚比发布宣言更可靠

**日志、指标、追踪与告警** ---- 部署后继续看错误率、延迟、资源、事件循环、连接池、数据库、缓存、队列和业务指标，让告警与发布版本关联

**备份、恢复与灾难演练** ---- 设计数据库备份、对象存储版本、恢复点、恢复时间、异地副本、数据重放和演练记录；没有演练过的恢复方案，通常只是很有礼貌的愿望

**扩容与架构演进** ---- 从单体、单机、多进程、容器、副本、队列、缓存、读写分离到微服务逐步演进，按瓶颈和组织需求拆分；规模不是架构勋章，能解决当前问题才是

**重点解释** ---- 这一站通关是：你能让应用可重复构建、可安全发布、可观测运行、可快速回滚，并且知道数据、密钥、连接和用户请求在每个环节由谁负责

## 学习路径建议：从第一个闭环到可交付产品

不要同时打开 React、Vue、Nest、Next、Nuxt、Mongo、PostgreSQL、Redis、GraphQL 和 Kubernetes 的官网标签页。那不是全栈，是浏览器标签页的生存竞赛。按下面的顺序推进更稳：

**第一阶段：语言地基** ---- 完成第一站与第二站，能解释作用域、闭包、this、原型、Promise、事件循环、错误和内存；先用原生 JavaScript 做几个小型数据处理与异步任务练习

**第二阶段：前端应用** ---- 选 React 或 Vue，完成组件、路由、表单、请求、状态、错误、加载与响应式界面；目标是做出一个可刷新、可恢复、可操作的 CRUD 页面

**第三阶段：Node API** ---- 进入 [Node.js](/learning-paths/backend/nodejs)，用 Express、Fastify 或 NestJS 写出有分层、校验、统一错误、日志和优雅关闭的 REST API；先让后端独立站稳

**第四阶段：真实数据** ---- 以 PostgreSQL 为主线，补 SQL、模型、迁移、索引、事务、连接池，再按场景学习 MongoDB 和 Redis；不要在第一天就把三种数据库都请进群聊

**第五阶段：最小全栈闭环** ---- 打通注册或登录、认证、前端请求、CRUD、分页、错误提示和退出登录；这是从“分别会写”到“系统真的连起来”的关键一关

**第六阶段：契约与安全** ---- 加上 OpenAPI 或共享 schema，固定响应与错误格式，补 Cookie 或 Token 流转、权限、CORS、CSRF、XSS、限流、审计和秘密管理

**第七阶段：同构提效** ---- 在理解分离式原理后，React 进入 Next.js，Vue 进入 Nuxt；学习 SSR、缓存、服务端边界、Hydration、流式渲染与部署，而不是把框架当成后端黑盒

**第八阶段：生产能力** ---- 补测试分层、契约测试、E2E、CI、Docker、迁移、监控、性能、队列、实时和回滚；到这里，项目才从 Demo 走向可交付

**每阶段的学习节奏** ---- 先读路线确认地图，再进行对应主题的系统学习，随后做一个可验证的小闭环，最后记录失败路径与取舍；只收藏不实践，知识会像未提交的代码一样安静地消失

## 项目主线：用一个产品串起所有站点

建议围绕同一个“团队知识库或轻量协作平台”逐步升级：用户与组织、文章或任务、评论与搜索、文件、通知、审计、后台运营和部署。项目不必宏大，但要让每一站都有落点。

**版本一：能用** ---- 前端路由、表单、列表、详情、分页、Node API、数据库 CRUD 和基础错误处理

**版本二：可信** ---- 认证、刷新或 Session、角色与对象权限、参数校验、统一响应、迁移、索引、测试与日志

**版本三：好用** ---- 搜索、文件上传、乐观更新、缓存、实时通知、后台任务、失败重试与可取消操作

**版本四：能交付** ---- Docker、CI/CD、生产配置、HTTPS、监控、告警、性能预算、备份、灰度与回滚

**版本五：能解释** ---- 能画出一次请求从浏览器事件到接口、数据库、缓存、响应、渲染和日志追踪的全链路，并能指出每一层的失败方式与恢复动作

## 通关标准

**语言层通关** ---- 能解释作用域、闭包、this、原型、类型转换、Promise、事件循环、模块、迭代器、内存与错误传播；遇到框架代码，知道它背后调用的 JavaScript 机制

**前端层通关** ---- 能用 React 或 Vue 做出有路由、表单、请求、缓存、权限体验、加载错误状态和可访问交互的应用，不把所有数据塞进一个全局 store

**后端层通关** ---- 能用 Node.js 框架提供有版本、校验、认证、统一错误、日志、分页、文件与优雅关闭的 API，并能定位事件循环阻塞、N+1 和连接池问题

**数据层通关** ---- 能设计关系或文档模型，写出合理查询，解释索引、事务、隔离、锁、迁移、连接池、缓存一致性与恢复策略，而不是只会点 ORM 的生成按钮

**协作层通关** ---- 能用 OpenAPI、共享 TypeScript 类型或生成客户端建立接口契约，处理错误、分页、版本、兼容、Mock 与联调；接口变更不会靠群里一句“大家注意一下”维持

**安全层通关** ---- 能画认证授权流转，正确处理 Cookie、Token、OAuth、CORS、CSRF、XSS、注入、SSRF、文件上传、原型污染、秘密和供应链风险

**生产层通关** ---- 能完成测试、构建、Docker、迁移、CI/CD、监控、性能分析、备份、灰度与回滚；服务出问题时，知道先看指标、日志、追踪还是数据库，而不是先重启祈福

**全栈主线毕业** ---- 能独立交付一个带用户体系、权限、CRUD、搜索或分页、文件或任务、测试、监控和部署的完整产品，并清楚说明每个技术选择的代价

## 结语

JavaScript 全栈最迷人的地方，是同一套语言思维可以从点击事件一路走到数据库事务；最容易误导人的地方，也是这条路看起来太顺。浏览器有自己的规矩，Node 有自己的队列，数据库有自己的锁，生产环境还有自己的脾气。

所以这条路线不追求“把所有工具都点亮”，而追求把一条链路走通、走深、走到能解释：数据从哪里来，在哪被验证，谁有权限，哪里可能失败，失败后如何恢复，用户又如何知道结果。

先用 React 或 Vue 做出页面，再用 Node.js 写出接口；先理解分离式系统，再用 Next.js 或 Nuxt 合并体验；先把数据、认证、测试和部署跑通，再谈微服务、边缘和百万并发。**一门语言是红利，跨层边界才是全栈能力。**

当你能在前端、服务端、数据库和监控之间来回定位问题，还能在发布前给自己留一条回滚的路，恭喜：你不是“会一点前端、会一点后端”，而是开始成为一个让系统安心工作的 JavaScript 全栈工程师了。
