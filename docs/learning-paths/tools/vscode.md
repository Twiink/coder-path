# VS Code 学习路线

VS Code 是一间可以不断换家具的工作室：编辑器是房子，扩展是住户，语言服务器是那位负责智能的顾问，终端和调试器则负责把“看起来对”拉到“跑起来对”。它轻量，但不等于简单；插件一多，工作室也需要物业管理。

这份路线是 **通用基础 → 工具与工作流 → VS Code** 的独立学习地图。它不罗列所有快捷键，而是按编辑、语言智能、调试、Git、终端、远程、扩展、安全和性能建立完整使用模型。

**适合谁** ---- 想系统掌握 VS Code、多语言开发、远程开发、容器、调试、团队配置，或总觉得编辑器“明明装了插件却不聪明”的开发者

**先记住一件事** ---- VS Code 自己是壳，智能通常来自语言服务器、调试适配器、构建工具和扩展；找错责任人，编辑器会陪你一起迷路

**推荐总顺序** ---- 工作台与配置 → 快捷键与编辑 → 搜索导航 → 语言智能 → 终端任务 → Git → 调试测试 → 扩展 → 远程容器 → 性能与团队同步

**本页怎么用** ---- 先把高频流程练顺，再按语言和项目添加扩展；配置要能解释、能共享、能恢复，不要把编辑器养成只有自己认识的宠物。

## 第一站：工作台、配置与个人环境

第一次打开 VS Code，它会热情地把侧边栏、面板、状态栏和命令面板都介绍给你。认识这些房间，后面找功能就不用在菜单里考古。

**工作台区域** ---- 掌握活动栏、资源管理器、搜索、源码管理、运行调试、扩展、编辑器组、面板和状态栏

**命令面板** ---- 理解命令注册、搜索、快捷键入口和无鼠标操作

**设置层级** ---- 区分用户、远程、工作区、文件夹、语言特定设置和覆盖优先级

**配置文件** ---- 认识 settings、keybindings、tasks、launch、extensions 推荐和配置同步

**配置可审查性** ---- 规划哪些配置个人保留、哪些提交仓库、哪些包含环境或秘密

**配置档案** ---- 使用 Profiles 隔离语言、项目、主题、扩展和实验环境

**重点解释** ---- 这一站通关是能找到任何功能、解释设置生效层级，并让自己的工作环境可恢复而不依赖记忆

## 第二站：编辑、选择与快捷键

编辑器最喜欢重复动作，因为重复动作最适合交给快捷键。你只要让手指记住一次，VS Code 就会乐意替你多做一百次。

**光标与选择** ---- 掌握移动、扩展选择、词/行/括号选择、列选择和多光标

**重构式编辑** ---- 学习重命名、提取、移动行、批量替换、代码动作和符号级编辑

**查找与替换** ---- 理解文件内/全局、正则、大小写、整词、路径过滤和替换预览

**代码折叠与视图** ---- 认识折叠、面包屑、 minimap、sticky scroll、缩进指引和布局

**Emmet 与片段** ---- 了解缩写、用户片段、变量、作用域和团队共享边界

**快捷键定制** ---- 掌握键位冲突、上下文条件、键盘快捷方式查找和跨平台差异

**重点解释** ---- 这一站要能把高频编辑动作变成可重复流程，减少鼠标漫游和手工改错

## 第三站：搜索、导航与语言智能

编辑器真正聪明的时刻，不是它会变色，而是它知道符号从哪里来、要跳到哪里、改动会影响谁。语言服务器是这里的主角，VS Code 负责给它搭舞台。

**文件与符号导航** ---- 掌握快速打开、转到定义、声明、实现、引用、符号、调用层次和最近编辑位置

**语言服务器协议** ---- 理解 LSP、补全、悬停、诊断、格式化、重构和服务器生命周期

**类型与索引** ---- 了解项目根目录、配置、索引、类型环境、生成文件和多根工作区

**语义搜索** ---- 区分文本搜索、符号搜索、引用搜索、正则和语义重命名

**代码动作** ---- 掌握自动导入、修复、组织导入、提取、转换和语言扩展职责

**配置排查** ---- 处理解释器/SDK 选择、编译配置、路径别名、生成文件和版本不匹配

**重点解释** ---- 这一站通关是能判断“编辑器不智能”到底是索引、语言服务器、项目配置还是扩展的问题

## 第四站：终端、任务与开发流程

VS Code 里的终端像从工作室直接通往施工现场的门。任务系统则把常用命令编排成按钮，让构建、测试和开发服务器少一点手工仪式。

**集成终端** ---- 掌握终端配置、Shell、工作目录、环境变量、会话、拆分和多终端

**任务系统** ---- 了解任务定义、依赖、后台任务、问题匹配器、输入变量和默认任务

**调试前置任务** ---- 组织构建、启动、测试、监听、端口和调试会话的依赖

**输出与诊断** ---- 区分终端、输出、问题、调试控制台、日志和任务退出码

**工作区脚本** ---- 规划跨平台脚本、路径、环境、秘密和团队可复现流程

**命令行集成** ---- 认识 `code` 命令、标准输入、文件/目录打开和远程 URI

**重点解释** ---- 这一站要能把“编辑 → 构建 → 测试 → 运行”串成稳定流程，不让终端和编辑器各自过自己的日子

## 第五站：Git、差异与代码评审

源码管理面板像一位会提醒你“这行变了”的同事，但它不会替你判断改动是否正确。理解 Git 模型，再使用可视化操作，心里才不会悬着一只问号。

**变更与差异** ---- 查看未提交、暂存、冲突、内联差异、比较任意版本和变更导航

**提交与暂存** ---- 掌握部分暂存、提交信息、提交图、撤销和同步

**分支与冲突** ---- 处理切换、合并、冲突查看、冲突编辑器和中止流程

**历史与 Blame** ---- 了解时间线、提交详情、逐行归属和代码评审上下文

**扩展式 Git** ---- 认识 GitLens 等扩展能提供什么，以及额外索引与隐私边界

**审查习惯** ---- 建立提交前差异检查、秘密扫描、测试结果和工作区清洁确认

**重点解释** ---- 这一站通关是能在 VS Code 里读懂改动、处理冲突、完成提交前审查，而不是把源代码管理面板当成自动驾驶

## 第六站：断点、调试与测试

调试器是那位愿意陪你暂停时间的同事：它可以站在某一行等你，查看变量、调用栈和线程，再帮助你定位“事情究竟从哪一步开始变味”。

**调试适配器协议** ---- 理解 DAP、调试器、运行时、启动配置和语言扩展的职责

**断点与执行控制** ---- 掌握普通、条件、命中次数、日志断点、暂停、单步、跳出和继续

**变量与调用栈** ---- 了解作用域、监视、调用栈、线程、异步栈和表达式求值

**启动与附加** ---- 区分启动进程、附加进程、复合配置、端口、环境和权限

**测试集成** ---- 使用测试发现、运行、调试、筛选、覆盖率和失败导航

**远程调试** ---- 理解本地/远程路径映射、源码映射、容器、端口和符号版本

**重点解释** ---- 这一站要能从断点现场追踪实际执行路径，并知道调试器显示的代码、进程和环境是否真的是你以为的那一份

## 第七站：扩展、语言服务与自动化

扩展是 VS Code 的租客：有的负责语法，有的负责格式化，有的会申请访问文件、网络和命令。租客多了很热闹，物业规则也要跟上。

**扩展组成** ---- 认识 manifest、命令、菜单、贡献点、激活事件、Web/Node 扩展和工作区信任

**语言扩展** ---- 了解语法高亮、语言服务器、调试适配器、格式化器、Lint 和测试适配器

**扩展冲突** ---- 排查重复格式化、语言服务器竞争、快捷键覆盖、版本不兼容和激活顺序

**插件安全** ---- 关注权限、遥测、网络访问、文件读写、安装来源、更新和供应链

**自定义片段与任务** ---- 设计团队片段、代码动作、任务、调试模板和可维护边界

**开发扩展** ---- 了解 Extension API、激活、命令、Tree View、Webview、打包和发布

**重点解释** ---- 这一站通关是能判断一个扩展提供了什么、拿到了什么权限、出了问题如何禁用和定位

## 第八站：远程开发、容器与协作环境

远程开发会让 VS Code 搬到服务器、容器或 WSL 里工作。它很方便，但编辑器前端、扩展宿主、文件系统和终端可能已经住在不同地址。

**远程架构** ---- 理解本地 UI、远程服务、扩展宿主、文件协议和网络连接

**SSH 与 WSL** ---- 掌握远程目录、凭据、端口转发、环境安装、权限和断线恢复

**Dev Containers** ---- 了解镜像、容器、挂载、用户、扩展、转发、生命周期和可复现环境

**Codespaces/云环境** ---- 认识资源、凭据、网络、成本、持久化和团队模板

**远程调试与性能** ---- 关注路径映射、文件监听、同步、网络延迟、索引和 CPU/内存位置

**工作区信任** ---- 理解不可信仓库、任务、调试、扩展和自动执行的安全边界

**重点解释** ---- 这一站通关是能说清代码、终端、扩展、进程和数据分别在哪台机器，避免“我本地”变成一个没有地址的传说

## 第九站：性能、可访问性与团队治理

编辑器也会疲劳：工作区太大、扩展太多、索引太重，它就会开始喘气。与此同时，团队配置和可访问性决定了这间工作室是不是人人都能舒服使用。

**性能瓶颈** ---- 排查启动、扩展激活、文件监听、搜索、索引、语言服务器和大文件

**工作区治理** ---- 使用排除、忽略、单文件模式、稀疏目录和多根工作区控制范围

**扩展治理** ---- 管理推荐、版本、禁用、远程安装、信任和审计

**同步与备份** ---- 规划 Settings Sync、Profiles、配置仓库、机密分离和跨设备恢复

**可访问性** ---- 关注键盘导航、屏幕阅读器、高对比度、缩放、焦点和减少动画

**团队标准** ---- 共享格式化、Lint、任务、调试、扩展推荐和工作区约定

**重点解释** ---- 这一站要能让 VS Code 快、稳、可恢复、可共享，并且不把效率建立在某个人的私人配置上

## 学习路径建议：从编辑器到工作台

**第一阶段：编辑与导航** ---- 熟悉工作台、命令面板、快捷键、搜索和符号导航

**第二阶段：语言与流程** ---- 配好语言服务器、终端、任务、构建和测试

**第三阶段：Git 与调试** ---- 形成差异审查、分支协作、断点和失败定位习惯

**第四阶段：远程与治理** ---- 进入扩展安全、容器、远程开发、性能和团队配置

## 通关标准

**编辑通关** ---- 能快速导航、批量编辑、搜索、重构和恢复视图

**智能通关** ---- 能解释 LSP、项目配置、诊断、格式化和扩展职责

**流程通关** ---- 能用终端、任务、Git、测试和调试完成开发闭环

**环境通关** ---- 能管理扩展、工作区信任、远程、容器和配置同步

**治理通关** ---- 能排查性能、保护权限、共享配置并保持工作台可访问

## 结语

VS Code 是一间愿意听你安排的工作室：你给它清晰的项目、合适的语言服务和可靠的任务，它就能把重复劳动收拾得很整齐。只是别把所有扩展都请进来，也别把整个家装修成只有自己看得懂的样子。
