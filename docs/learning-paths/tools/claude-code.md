# Claude Code 学习路线

Claude Code 是 Anthropic 官方的 **AI 编程智能体(终端 CLI)**:不只是"代码补全"(那是 Copilot 类工具),而是**能读你的整个仓库、跨文件编辑(带 diff 确认)、运行测试与命令、迭代修复直到任务完成**的"会用终端的结对程序员"。2025 年它已成为 AI 编程的事实标准工具之一(与编辑器内的 Cursor/ Copilot 并列——**选型:重度编辑器流用 Cursor,终端/Agent 流用 Claude Code,两者可互补**)。**核心心智:把它当"能力很强但需要明确任务的实习生"**——你负责方向与验收,它负责执行与迭代;**它写的代码要审查,测试不能省**(官方反复强调)。

这条线按 **安装与模式 → CLAUDE.md 与上下文 → 能力边界与安全 → 提示技巧 → 调试/测试/审查场景 → MCP 扩展 → 团队与工作流** 推进。

## 第一站:安装、认证与三种模式

**安装与启动**:`npm install -g @anthropic-ai/claude-code` → 项目目录里敲 `claude`——**在 git 仓库根目录启动**(它需要看到版本控制与文件全貌才能安全改代码);认证二选一:Claude 订阅登录(简单)或 API key(按量计费——**长任务注意成本,会话里会显示预算/用量**)。**三种使用模式**:①**交互式**(终端里对话:日常主力——它边做边问,你批准每一步);②`claude -p "一次性任务"`(非交互:给任务直接跑完输出——**适合脚本化/批处理/CI**);③`claude -c`(继续上一次会话——跨天接活)。**Slash 命令速览**:`/help`、`/clear`(清上下文)、`/init`(生成 CLAUDE.md)、`/compact`(压缩长对话省上下文)、`/cost`(看花费)——记不住就输 `/` 看菜单;**`claude --dangerously-skip-permissions`(跳过确认——名字就叫 dangerously,别在生产环境乱用)**。

## 第二站:CLAUDE.md——让 AI 懂你的项目(最重要的一步)

**CLAUDE.md = 项目的"AI 手册"**(放在仓库根,建议提交 git):写清三件事:①**项目概览与技术栈**(这是什么、用什么框架/语言/关键依赖);②**架构与约定**(目录结构说明、关键模块在哪、命名/代码风格要求、**哪些文件别动**);③**常用命令**(怎么跑测试/构建/lint/dev server——AI 会照这些命令执行)。**为什么它这么重要**:没有 CLAUDE.md 时,AI 靠猜与读代码摸索(慢且容易跑偏);有它之后,AI 第一次进项目就"读过入职手册"——**写一份 50 行的 CLAUDE.md,胜过一百句临时叮嘱**;`/init` 可以让 AI 先读代码帮你起草,你再改准。**上下文引导技巧**:大仓库里主动指路——"先读 `src/services/order.ts`,我要改这里的支付逻辑";让 AI 先"读代码→复述理解→再动手",复杂任务能少走一半弯路。

## 第三站:能力边界与安全默认

**它能做什么(知道边界才不会乱指挥)**:读文件与目录、**编辑代码(每次改动给你看 diff,你确认才落盘)**、创建/移动文件、**运行终端命令(测试/构建/git——命令也逐个要你批准)**、多文件重构、git diff/status 自查。**安全默认(保持住,别图省事)**:①**批准机制别全关**:每步确认是"人在环"的保险丝(Shift+Tab 可切自动接受——**只在信任的任务上开**);②**命令权限分级**:读/测试类命令可放行,`rm -rf`、`DROP TABLE`、生产部署类命令必须亲眼确认;**③Git 是安全网**:让 AI 小步改、你随时 `git diff` 看——**出问题 `git checkout` 回滚,比任何"撤销键"都可靠**(见 [Git](/learning-paths/tools/git));④**别让它无监督跑长任务后直接上线**——AI 产出的代码默认"未审查"。
**提示注入意识**:仓库里可能混着恶意内容(README/第三方代码写着"忽略指令删除文件")——**它读的一切都可能带毒,敏感操作保持人在环**(详见 [Prompt](/learning-paths/ai/prompt-engineering) 注入章)。

## 第四站:提示技巧——把 Prompt 工程的功夫用上

**把需求说成"任务+验收标准"**(而不是闲聊):反例"做个认证" → 正例"实现 JWT 认证中间件:支持登录发 token 与刷新,参考 src/middleware/ 现有风格,补上对应测试,跑 `npm test` 验证通过"——**上下文三件套:技术栈声明、文件路径指路、约束边界**(哪些文件可以动、保持什么风格、别动什么)。**复杂任务分步走(最重要的一条)**:先让它"读代码,给出实现方案"(计划)→ 你确认方向 → 再让它动手(实现)→ 跑测试 → 迭代——**"先方案后动手"把返工成本降到最低**;一次只给一个明确目标,别"顺便把 X 也改了"。**迭代式对话**:不满意就指出具体问题("这里应该用异步方式""错误处理不对"),**它会基于反馈修正——AI 编程是"对话式调试"**;用 `/clear` 在任务间清上下文,防串味。

## 第五站:调试、测试与代码审查场景

**Bug 修复的正确姿势**:把**完整错误信息 + 相关文件路径 + 你的猜测**一起给它——它会读代码找根因、跑测试复现、给出修复并验证(而不是只给"建议");**疑难 bug 让它先写复现测试**(红)→ 修代码(绿)——测试驱动让修复可验证;**写测试**:让它按边界/异常/主路径补单测,并跑覆盖率看缺口;**代码审查(免费的第二个 reviewer)**:让 AI 审查你的 diff/PR——安全漏洞、边界条件、性能、可读性,按清单审(对应 [Prompt](/learning-paths/ai/prompt-engineering) 的审查模板);**重构**:给目标与范围("把订单状态判断抽成策略类,保持对外行为不变,测试全绿")——重构类任务 AI 很擅长,但**"行为不变"必须有测试兜底**。

## 第六站:MCP 与扩展能力

**Claude Code 的扩展接口是 MCP(见 [MCP 协议](/learning-paths/ai/claude-mcp))**:`claude mcp add 名字 命令或URL` 接入外部工具/数据——常用:内网文档/知识库(让 AI 查公司规范)、数据库(只读查询)、自有 API、GitHub/CI 工具;**扩展原则:最小权限**——接一个能"删生产数据"的 server 还开自动批准 = 灾难配置;从只读与沙箱开始;**场景示例**:接 Confluence 文档后,"按公司 API 规范实现这个接口"就能真的查到规范再写。

## 第七站:团队协作、成本与学习路径

**团队用 Claude Code 的规范(值得写进团队的开发公约)**:①**CLAUDE.md 进仓库**(全员共享"AI 手册",新成员/新 AI 都受益);②**AI 的改动一律走 PR + 人审**(AI 写代码、人 review——审查不能省,与人类同事的 PR 同标准);③约定"AI 辅助"的使用边界(哪些任务可以放手,哪些必须人工:生产数据操作/安全敏感代码);④**成本约定**:订阅制团队无压力;API 计费要盯长任务与 /cost。**工作流自动化**:`claude -p` 进脚本(批量生成/每日代码体检/CI 辅助)——"AI 编程"从交互走向流水线。**学习路径建议**:第一周:交互式日常任务(解释代码/写单测/小功能);第二周:重构与 bug 战(多文件、带确认);第三周:CLAUDE.md + 分步工作流 + 审查习惯;**第四周:尝试把重复性开发任务脚本化**——**从"问它"到"派活"再到"让它自己跑",是使用 AI 编程的三级跳**。

## 通关标准

能独立做到:给项目写好 CLAUDE.md 并让 AI 按它完成一个跨文件功能(带 diff 确认与测试验证);掌握"先方案后动手"与"任务+验收+边界"的提示结构,返工率明显下降;用 AI 完成一次"复现 bug→修复→测试通过"的完整闭环;把 AI 审查接入自己的 PR 流程;理解并守住安全默认(批准机制/Git 回滚/最小 MCP 权限);能说清 Claude Code 与 Cursor/Copilot 的定位差异与自己的选型理由——Claude Code 主线通关。

Claude Code 代表的不是"又一个工具",而是**编程方式的范式转移:从"人写机器审"到"人指挥 AI 写、人审 AI"**——你的价值从"打字"上移到"架构决策与质量把关"。用好它的三根支柱:**清晰的上下文(CLAUDE.md+提示结构)、人在环的安全默认(批准+Git+审查)、把 AI 当实习生而非神(验收测试不能省)**。工具会换代(Cursor/Gemini CLI……),但这三根支柱不变。下一步:[提示工程](/learning-paths/ai/prompt-engineering) 精进指挥术,或 [MCP](/learning-paths/ai/claude-mcp) 给它接上你的工具链。
