# Git 版本控制学习路线

Git 是代码世界那位记忆力极好、还随身携带后悔药的同事。它记住每次提交，允许分支并行，偶尔用冲突提醒大家“你们两位都改了同一行”；reflog 则像旧档案室，专门保存那些以为已经消失的历史。

这份路线是 **通用基础 → 工具与工作流 → Git 版本控制** 的独立学习地图。它不负责把命令背成咒语，而是帮助你建立对象、引用、三棵树、协作、历史和恢复模型，再把它们落到团队交付。

**适合谁** ---- 想从零掌握 Git、经常遇到分支冲突、需要做 Code Review、维护发布分支，或想知道“删除的提交到底去哪了”的开发者

**先记住一件事** ---- Git 的核心不是命令数量，而是提交快照、引用移动和对象可达性；命令只是和这套模型打交道的不同礼仪

**推荐总顺序** ---- 身份与配置 → 快照与三棵树 → 查看与提交 → 撤销与恢复 → 分支与合并 → 远程协作 → Rebase 与历史整理 → 历史考古 → 底层对象 → 团队发布

**本页怎么用** ---- 先建立心智模型，再练安全操作；涉及丢弃、重写、强推、删除和清理时，先确认作用范围与备份。Git 有后悔药，但不保证你每次都记得药放在哪。

## 第一站：身份、配置与仓库启程

Git 第一次见面会问姓名和邮箱，之后每个提交都会带着这张名片旅行。配置得清楚，未来的历史才不会出现“这位神秘开发者是谁”。

**身份与配置层级** ---- 理解系统、全局、用户、仓库、工作树和命令级配置，知道后加载的配置如何覆盖前面的配置

**默认分支与换行** ---- 掌握默认分支、文件模式、换行转换、大小写敏感和跨平台差异

**SSH 与凭据** ---- 了解 SSH 密钥、Agent、凭据助手、签名提交、主机指纹和 HTTPS 的取舍

**仓库初始化与克隆** ---- 区分初始化、克隆、裸仓库、镜像、远程地址和浅克隆

**忽略与属性** ---- 学习 ignore 规则、属性、换行、二进制、合并策略、LFS 和敏感文件边界

**重点解释** ---- 这一站通关是能让 Git 知道你是谁、仓库从哪里来、哪些文件不该进历史，以及凭据如何安全地到达远端

## 第二站：快照、对象与三棵树

Git 不把每次提交简单理解成“改了几行”，而是记录项目某一刻的快照。工作区、暂存区和提交历史像三张桌子，文件在它们之间搬来搬去。

**提交快照** ---- 理解提交、树对象、文件对象、父提交、内容寻址和相同内容复用

**工作区** ---- 认识当前文件、未跟踪、已修改、删除、冲突和文件模式

**暂存区** ---- 掌握 index、部分暂存、分块暂存、暂存区与下一次提交的关系

**HEAD 与引用** ---- 理解 HEAD、分支引用、标签、远程跟踪分支和 detached HEAD

**状态与差异** ---- 学习工作区/暂存区/提交之间的差异、路径过滤、二进制差异和重命名识别

**重点解释** ---- 这一站通关是能准确回答“改动现在在哪张桌子上”，不再把 `git add` 当成提交，也不把分支当作文件复制

## 第三站：日常循环与可读提交

日常 Git 像一套小型流水线：查看状态、选择改动、提交快照、检查历史。流程越稳定，团队越少靠猜测恢复现场。

**状态检查** ---- 掌握状态、未跟踪、忽略、冲突和当前分支确认，养成先看状态再动手的习惯

**选择性暂存** ---- 理解按文件、按块、按交互方式暂存，区分“本次要提交的意图”和“工作区全部变化”

**提交设计** ---- 学习原子提交、提交信息、范围、正文、修复提交和可回滚性

**差异审查** ---- 使用 diff、cached diff、路径筛选、空白检查和提交前自审

**日志与展示** ---- 掌握图形历史、提交范围、格式化输出、补丁、统计和路径历史

**重点解释** ---- 这一站要能让每个提交表达一个可理解的意图，未来的自己和同事都能看懂这次改动为何存在

## 第四站：撤销、恢复与后悔药地图

Git 的撤销工具很多，因为“后悔”也分不同品种：工作区改乱、暂存错了、提交信息错了、已经推送的历史想回头，不能用同一把锤子。

**工作区撤销** ---- 区分丢弃未暂存改动、恢复单个文件、恢复路径和不可恢复风险

**取消暂存** ---- 理解从 index 移出但保留工作区内容的操作

**修订提交** ---- 掌握 amend、补文件、改信息和只能用于未共享历史的边界

**reset 三种语义** ---- 理解 soft、mixed、hard 对 HEAD、index 和工作区的影响，先画三棵树再决定是否操作

**revert 反向提交** ---- 学习已共享历史的安全撤销、连续撤销、合并提交和审计记录

**reflog 与恢复** ---- 认识引用移动记录、悬空对象、恢复分支和对象过期时间

**重点解释** ---- 这一站通关是能按“是否已共享、想保留什么、要改写还是新增记录”选择撤销方式，而不是闭眼输入高危参数

## 第五站：分支、合并与冲突

分支是轻量的指针，不是复制一整个项目的搬家公司。它让多人并行工作，也会把不同意见集中到合并时的谈判桌上。

**分支模型** ---- 理解分支引用、创建、切换、跟踪、上游和 detached HEAD

**快进与三方合并** ---- 区分 fast-forward、merge commit、共同祖先和合并基准

**冲突模型** ---- 掌握文本冲突、删除/修改、重命名、二进制、子模块和冲突标记

**冲突解决** ---- 建立查看双方、理解意图、选择结果、检查差异、继续/中止的流程

**合并策略** ---- 了解 recursive/ort、合并驱动、策略选项、记录合并和保留历史形状

**分支命名与生命周期** ---- 设计功能、修复、发布、热修复分支和删除策略

**重点解释** ---- 这一站通关是能把冲突当成语义问题解决，而不是把某一侧内容机械地全部覆盖

## 第六站：远程仓库、评审与协作

远程仓库是团队共同的公告栏，但公告栏不会替你判断消息是否完整。fetch、pull、push、PR 和评审各自有职责，混在一起就容易开会开到天亮。

**远程与跟踪** ---- 理解 remote、远程跟踪分支、上游、fetch refspec、镜像和多远程

**fetch、pull 与 push** ---- 区分只更新本地远程信息、合并/变基拉取和推送引用的行为

**Pull Request 工作流** ---- 掌握小批量提交、描述上下文、检查、评审、修订和合并策略

**保护分支** ---- 了解必需评审、状态检查、线性历史、签名、强推限制和发布权限

**冲突与并行协作** ---- 处理分支落后、上游变化、长分支漂移、合并窗口和代码所有权

**CI 与提交检查** ---- 将测试、Lint、构建、秘密扫描、依赖审计和制品关联到提交

**重点解释** ---- 这一站要能让远程协作可审查、可追踪、可回滚，知道 push 成功不代表集成成功

## 第七站：Rebase、历史整理与发布

Rebase 像历史编辑师，会把提交重新排版；它很适合整理自己的草稿，但不该随意改写别人已经引用的公共故事。

**Rebase 模型** ---- 理解重放提交、改变父提交、冲突、空提交和新提交对象

**交互式整理** ---- 学习 pick、reword、edit、squash、fixup、drop、排序和拆分

**共享历史边界** ---- 掌握强推保护、force-with-lease、公共分支禁忌和恢复策略

**发布分支与标签** ---- 设计版本分支、annotated tag、发布说明、热修复和制品对应

**合并队列与线性历史** ---- 了解 squash、merge、rebase merge、队列重排和检查状态

**重点解释** ---- 这一站通关是能整理自己的历史、保护别人的引用，并让代码、标签和发布制品对得上号

## 第八站：历史考古与问题定位

历史不是博物馆摆设，它可以回答“这行是谁改的、为什么改、哪个提交引入了问题”。Git 会给线索，但不会替你完成推理。

**日志搜索** ---- 掌握按作者、时间、路径、消息、内容、范围和拓扑搜索

**blame 与行历史** ---- 了解逐行归属、重命名、复制检测、代码移动和误读风险

**bisect 二分定位** ---- 学习好/坏提交标记、自动化测试、不可复现问题和边界提交

**revert 与事故调查** ---- 将修复提交、版本、日志、部署和监控串成时间线

**补丁移植** ---- 认识 cherry-pick、冲突、重复提交、依赖顺序和跨分支修复

**历史质量** ---- 评估提交粒度、信息、合并噪音、敏感数据和不可追溯改动

**重点解释** ---- 这一站通关是能用历史证据定位回归、理解背景、移植修复，而不是把 blame 当成找人背锅器

## 第九站：对象库、钩子与高级边界

Git 的地下室里住着对象库、pack、索引、钩子和工作树。日常不必天天下去，但遇到仓库膨胀、钩子失效或历史恢复时，它们会亮灯。

**对象存储** ---- 理解 blob、tree、commit、tag、哈希、可达性和悬空对象

**pack 与垃圾回收** ---- 了解压缩、增量存储、索引、gc、repack、过期和大仓库成本

**钩子与自动化** ---- 掌握客户端/服务端钩子、提交检查、格式化、秘密扫描和可移植性

**worktree** ---- 认识多个工作树、共享对象库、分支占用和并行修复

**submodule 与 subtree** ---- 比较嵌套仓库、提交指针、同步、发布和依赖边界

**LFS 与大文件** ---- 理解指针文件、远程对象、克隆成本、历史清理和存储配额

**重点解释** ---- 这一站要能在仓库异常时知道对象、引用、钩子、工作树和大文件分别可能在哪一层出问题

## 第十站：团队治理、安全与交付

Git 终于从个人记事本升级为团队档案馆。档案馆最怕的不是写得多，而是权限混乱、秘密泄露、规则不一致和出了事故没人知道如何回放。

**提交签名与身份** ---- 了解 SSH/GPG 签名、验证、机器人提交、作者与提交者区别

**秘密与敏感历史** ---- 防范密钥提交、历史清理、凭据轮换、扫描和已泄露后的响应

**仓库权限** ---- 设计最小权限、保护分支、管理员、机器人、部署密钥和审计

**大仓库治理** ---- 关注稀疏检出、部分克隆、单仓/多仓、依赖、LFS 和构建缓存

**发布与回滚** ---- 将标签、提交、制品、迁移、部署、回滚和事故记录关联起来

**团队规范** ---- 建立分支策略、提交格式、评审门禁、冲突处理和历史保留周期

**重点解释** ---- 这一站通关是能让 Git 支撑安全协作和可恢复发布，知道版本控制最终服务的是团队记忆与交付可信度

## 学习路径建议：从三棵树到团队协作

**第一阶段：模型与日常** ---- 学会对象、引用、三棵树、状态、差异、暂存和提交

**第二阶段：恢复与分支** ---- 掌握撤销、reflog、分支、合并、冲突和远程跟踪

**第三阶段：协作与历史** ---- 进入 PR、评审、rebase、cherry-pick、bisect 和发布

**第四阶段：底层与治理** ---- 理解对象库、钩子、LFS、签名、权限、扫描和事故恢复

## 通关标准

**模型通关** ---- 能解释提交快照、对象、引用、HEAD、暂存区和工作区

**操作通关** ---- 能安全完成提交、分支、合并、撤销、恢复、拉取和推送

**协作通关** ---- 能处理评审、冲突、历史整理、保护分支和发布分支

**诊断通关** ---- 能用日志、blame、bisect、reflog 和对象模型定位问题

**治理通关** ---- 能保护秘密、权限、签名、制品和团队历史

## 结语

Git 像一位记性过分好的同事：你说过的话它都记着，走过的岔路也未必真的消失。别把它当命令抽屉，先和它建立对象、引用和三棵树的共同语言；这样即使冲突来敲门，Git 也会递给你一张地图，而不是只递一串红色报错。
