# Jest 学习路线

Jest 是 JavaScript 测试世界里那位装备齐全的巡检员：断言、Mock、覆盖率、快照和并行执行都自带，第一次上手像打开一个已经装好工具的抽屉。它可以帮你快速建立反馈，但也会让人误以为“测试就是把函数挨个点名”。真正要学的是如何用测试描述行为、隔离不确定性、保护边界，并让失败消息值得人读。

这是一条独立的 Jest 学习地图，从测试观、配置和断言走到异步、Mock、DOM、React、覆盖率、性能与 CI。每一站都覆盖最常用能力、少见边界和值得深挖的机制；代码示例保持克制，把重点放在测试对象、信心来源和维护成本。

路线按 **测试模型 → 断言 → 生命周期 → 异步 → Mock → DOM → 配置 → 覆盖率 → 稳定性 → 设计** 推进。

## 第一站：测试模型与项目配置

欢迎来到 Jest 的实验室。测试文件是实验记录，测试环境是培养皿，断言是验收标准；先让实验能稳定重现，再讨论怎么把报告做得像颁奖礼。

**测试金字塔** ---- 区分单元、集成、组件与端到端测试，理解速度、隔离、真实度和维护成本的取舍

**测试文件发现** ---- 掌握测试文件命名、目录、匹配规则和项目根目录，知道“测试没跑”与“测试通过”是两种完全不同的消息

**测试环境** ---- 区分 Node、jsdom 和自定义环境，理解浏览器 API 是否存在、全局状态如何初始化以及环境差异如何影响结果

**配置入口** ---- 认识配置文件、命令行参数、项目配置与多项目配置，保持本地、编辑器和 CI 的行为一致

**脚本与运行模式** ---- 组织全量、单文件、监听、失败重跑、名称过滤和更新快照等运行方式，让反馈速度服务于开发节奏

**重点在这** ---- 能回答一次测试由谁发现、在哪运行、依赖什么环境、报告落在哪里，而不是只会按下“运行测试”按钮

## 第二站：断言与行为表达

第二站是 Jest 的词汇教室。断言不是越多越勇，而是要把用户能观察到的行为说准确；测试写得像实现细节，重构一来就会集体请病假。

**基础匹配器** ---- 掌握严格相等、深比较、真假、空值、数值、字符串、数组、对象和属性断言，理解每个匹配器表达的证据范围

**浮点与近似** ---- 使用近似比较处理浮点误差，区分数值精度问题与业务容差，不让二进制小数背锅

**异常断言** ---- 正确测试同步抛错、异步拒绝、错误类型和消息；让测试证明失败是预期行为，而不是测试自己先摔倒

**部分匹配** ---- 用对象部分匹配、数组包含和属性断言关注契约核心，避免接口多一个字段就让无关测试全线报警

**否定断言** ---- 谨慎使用 `not`，确保被否定的状态足够明确；“不是这个”通常比“应该是什么”提供更少信息

**行为与实现** ---- 优先断言输出、状态变化、错误和对外调用，不绑定私有函数顺序、内部变量名和无意义的调用次数

**重点在这** ---- 每个断言都能解释“它证明了什么”，测试就从截图式记录升级成可维护的行为契约

## 第三站：生命周期、隔离与测试组织

第三站是实验室的清洁班。共享状态像没洗的培养皿，今天的测试可能污染明天的测试；Jest 给了生命周期钩子，但不会替你决定什么该共享。

**Setup 与 teardown** ---- 使用单测前后、每文件前后和全局初始化，明确资源创建、清理和失败时的收尾路径

**测试隔离** ---- 重置对象、模块、计时器、DOM、环境变量和临时目录，避免测试顺序改变结果

**describe 组织** ---- 按行为、场景和边界分组，保持测试树能帮助阅读；嵌套层级太深时，说明测试可能在写目录而不是写故事

**共享夹具** ---- 区分稳定的只读数据、每测重建的数据和昂贵外部资源，避免万能 beforeEach 变成隐藏依赖工厂

**模块状态** ---- 理解模块缓存、重置模块、隔离模块和导入时副作用，识别单例在测试间串台的原因

**随机与时间** ---- 固定随机种子、系统时间和时区，确保失败能重现；时间是测试里最会偷偷换衣服的变量

**重点在这** ---- 单个测试拿出来运行、换顺序运行、重复运行都应保持同一语义，隔离不是形式，是信心的地基

## 第四站：异步、Promise 与并发行为

第四站进入异步交通指挥室。Promise、定时器、事件回调和网络请求不会因为测试文件结束就自动排队；你要告诉 Jest 什么时候算完成，别让它在半路宣布“实验成功”。

**异步完成信号** ---- 掌握返回 Promise、async/await、回调完成通知和断言数量，避免异步失败跑到测试结束之后

**成功与失败路径** ---- 同时覆盖 resolve、reject、超时、取消和重试边界，区分业务错误与测试超时

**异步断言** ---- 让拒绝、异常和最终状态被真正等待与验证，不能只创建一个 Promise 然后对着它点头

**假定时钟** ---- 使用 fake timers 控制定时器、间隔、微任务和动画，理解它与真实 Promise 调度之间的交叉边界

**事件与订阅** ---- 测试事件触发、监听器移除、订阅关闭和重复回调，重点检查资源是否在异步结束后归还

**并发与竞态** ---- 覆盖请求乱序、重复提交、取消、去重和过期结果，别让测试只验证“网络永远按顺序到达”的童话

**重点在这** ---- 每个异步测试都能说清开始、完成、失败、取消和资源清理的时机

## 第五站：Mock、Spy 与依赖边界

第五站是替身剧场。Mock 可以让外部世界安静下来，也可以把测试变成一群只会配合的群众演员；替身应该隔离不确定性，不该篡改现实剧本。

**Spy 与 Mock** ---- 区分观察真实实现、替换实现、固定返回值和验证调用，选择与测试目标匹配的替身类型

**函数替身** ---- 覆盖返回、抛错、调用参数、调用次数和调用顺序，避免把“被调用一次”当作业务成功的全部证据

**模块 Mock** ---- 理解自动 Mock、工厂 Mock、部分 Mock、导入时机和 ESM/CJS 差异，防止替身根本没有接管目标模块

**网络边界** ---- 在请求层模拟成功、失败、慢响应、重复响应和异常数据，优先在接近真实边界的位置替换

**时间与随机替身** ---- 固定日期、随机数、ID 和 UUID，测试边界时要能控制输入，也要确保测试结束后恢复全局

**Mock 过度** ---- 识别过度 Mock、实现耦合、失真契约和“测试全绿但生产全哭”，该用真实小组件时不要把它拆成纸片

**重点在这** ---- 每个替身都能回答“隔离了哪个不确定性、保留了哪些真实行为、何时恢复现场”

## 第六站：快照、DOM 与组件测试

第六站是前端展厅。快照像自动拍照机，组件测试像让访客真的走一遍展厅；照片能发现大变化，却不能替代对交互和可访问性的检查。

**快照测试** ---- 理解快照生成、更新、审查和分片，识别大快照、无意义变更和无脑更新的风险

**DOM 查询** ---- 按角色、标签、文本、标签名和测试属性选择元素，优先模拟用户看到和操作的界面

**用户交互** ---- 测试点击、输入、键盘、焦点、表单提交、加载和错误状态，验证结果而不是内部 setState 次数

**React 组件** ---- 配合 Testing Library 理解渲染、查询、事件、异步等待、Context、Router 和表单边界

**可访问性** ---- 用角色、名称、键盘和焦点验证可访问行为，测试不是只为鼠标健康的用户服务

**浏览器 API** ---- 处理存储、观察器、媒体、尺寸、网络和导航等 jsdom 缺失或行为不同的能力，明确 Mock 范围

**重点在这** ---- 组件测试应像用户操作界面一样表达行为，既不把 DOM 当黑盒神话，也不把实现细节拆成零件清单

## 第七站：TypeScript、ESM 与工程配置

第七站来到工具链办公室。Jest 需要先理解你的模块、转译和路径别名，否则测试还没开跑，就先在导入语句门口迷路。

**JavaScript 转译** ---- 区分 Babel、SWC、ts-jest 和原生 ESM 的职责，理解测试转译与生产构建转译不一定相同

**TypeScript 边界** ---- 知道 Jest 运行测试不等于完成类型检查，安排独立的类型检查与测试流程，避免把类型错误藏在 Mock 后面

**ESM 与 CommonJS** ---- 理解静态导入、动态导入、模块 Mock、默认导出和互操作限制，识别模块系统不一致造成的诡异失败

**路径别名** ---- 让编译器、Jest、编辑器和打包工具共享解析规则，别让 `@/` 在 IDE 里是朋友、在 CI 里是陌生人

**多项目配置** ---- 为 Node、DOM、组件和服务端测试划分环境与匹配规则，减少全局配置互相踩脚

**环境变量** ---- 管理测试环境、时区、区域、Feature Flag 和凭据，使用安全的假数据，禁止加载生产秘密

**重点在这** ---- 能从“模块找不到、环境缺 API、Mock 不生效、类型没检查”判断是测试框架问题还是工具链边界问题

## 第八站：覆盖率、报告与持续集成

第八站是质量报表室。覆盖率是地图，不是奖杯；它能告诉你哪里没有走过，却不能保证走过的路没有坑。

**覆盖率维度** ---- 理解语句、分支、函数和行覆盖率，知道分支覆盖比单纯执行行数更能暴露决策盲区

**覆盖率阈值** ---- 按风险和模块设定门槛，避免全局一个数字逼大家给无价值代码涂色

**报告与排除** ---- 处理 source map、生成报告、排除类型声明与生成文件，确保统计对象与真实代码一致

**CI 运行** ---- 区分快速 PR 流程、完整主干流程、合并报告和失败重试，让反馈快而不牺牲可信度

**并行与分片** ---- 按文件、耗时和项目拆分测试，处理共享资源、顺序依赖和报告合并

**失败产物** ---- 保存日志、快照差异、DOM、截图和环境信息，让失败能复盘而不是只能重新点一次

**重点在这** ---- 报告要推动风险决策：哪里需要补测试、哪里应改设计、哪里只是统计噪音

## 第九站：稳定性、性能与诊断

第九站是 Jest 的体检中心。慢测试和 flaky 测试像办公室里一直响的烟雾报警器：久了大家会选择关掉它，而不是查火源。

**不稳定测试** ---- 排查时间、随机、网络、共享状态、并发、动画和环境差异，记录失败条件与重现步骤

**测试超时** ---- 区分真实慢、死锁、未等待 Promise、资源未关闭和机器拥塞，不用一味把超时时间拉到天荒地老

**测试性能** ---- 用耗时报告、缓存、并行、选择性运行和夹具优化反馈，先找最慢的层而不是全局加机器

**资源清理** ---- 关闭服务器、定时器、监听器、连接和文件句柄，处理“测试结束但 Node 进程不退出”的尾巴

**失败诊断** ---- 结合单测重跑、详细日志、调试器、快照差异和最小复现缩小问题，保留足够证据

**升级兼容** ---- 管理 Node、Jest、转译器、Testing Library 和框架版本，先看迁移说明再批量改配置

**重点在这** ---- 测试系统本身也要可观察、可解释、可优化；测试越快越稳，团队越敢改代码

## 第十站：测试设计与长期维护

最后一站是测试设计室。工具会更新，组件会重构，真正长寿的是测试是否抓住了行为、边界和风险；好的测试像安全带，不会替你开车，但能让你敢转弯。

**测试命名** ---- 用场景、条件和结果描述行为，避免“测试函数 1”这种对未来同事不太友好的密码

**边界优先** ---- 关注空值、极值、重复、乱序、失败、权限、超时和兼容性，不只测试那条阳光明媚的成功路径

**契约测试** ---- 对 API、事件、组件输入输出和序列化边界建立稳定契约，减少前后端与模块协作猜谜

**测试数据设计** ---- 使用最小、可读、可组合的数据，隔离敏感信息，让失败样本能直接说明问题

**重构友好** ---- 测行为、少测实现，合理使用公共辅助函数，控制快照和共享夹具的扩散

**删除与修复** ---- 识别重复、空洞、永远不失败和被替身包围的测试；测试数量多不等于信心多

**重点在这** ---- 能用一套测试解释系统的主要行为、风险与边界，并让下一位维护者敢于修改它

## 通关标准

**Jest 新手能写测试** ---- 能配置项目、写断言、测试异步函数并读懂失败信息。

**初级开发者能测模块** ---- 能组织生命周期、Mock 外部依赖、控制时间，并保持测试隔离。

**中级工程师能测前端系统** ---- 能处理 DOM、组件、网络、TypeScript、覆盖率、CI 和 flaky 测试。

**高级工程师能设计测试体系** ---- 能按风险划分测试层、治理性能与质量门禁，并让测试成为重构与发布的可靠证据。

## 结语

Jest 最方便的地方是工具齐全，最危险的地方也是工具齐全：Mock、快照和覆盖率都能让人很快产出数字。先问测试要保护什么，再选择怎么断言；先让异步和资源收尾正确，再追求并行速度。等你能从一次失败判断是代码、环境、替身还是测试设计出了问题，Jest 就不再只是跑测试的按钮，而是团队的反馈神经。
